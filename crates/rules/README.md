# Реестр правил

Номера блоков, предметов и атласа сохранены из разрешённого донорского коммита
`3992583213e1f00d95a3beef2bde43ae970192d4`: 265 именованных чисел, 87 определённых
блоков (включая варианты травы), 180 предметов. `src/provenance.json` содержит SHA256
исходных разрешённых файлов.

Перенесены только чистые таблицы и формулы §2: свойства, формы, добыча, инструменты,
предметы. Мир, симуляция, сетевой ABI и рендер донора не включаются. `Model` — местная
категория для данных, её числовые протокольные значения не назначены.

Основной API: `block`/`item`/`block_by_name`/`item_by_name` возвращают `Option`.
Неизвестный ID не становится воздухом; `properties(Cell)` возвращает консервативную
твёрдую/непрозрачную маску. Это осознанное отличие от донорского fallback.

`properties` учитывает состояние: слои снега, ориентацию, возраст посевов, рукава
передатчиков. Светимость и изменение LIT отделены от геометрии. Существующие функции
`blocks`/`items` для формул принимают raw `u32`; граница с миром использует `core_types::Cell`.

Проверки сравнивают **все** определения с эталонами, полученными отдельно исполнением
чистых исходных таблиц донора. CI их не обновляет. Для осознанного обновления:

```bash
source tools/env.sh
mkdir -p .local/rules-golden
rustc --edition=2024 crates/rules/tools/golden.rs -o .local/rules-golden/generate
.local/rules-golden/generate crates/rules/tests/data
cargo test --locked -p rules
```

Изменение эталонов требует отдельного объяснения поведения в коммите и DECISIONS.

## Подготовка поведения крафта и машин

Это фундамент для M8/M9/M11, не завершение этих этапов: симуляции машин, окон и сетевого
серверного применения здесь нет.

- `stack::ItemStack` — неизменяемое значение с проверяемыми ID, количеством и износом.
  Неизвестные предметы, переполненные стопки и неверный износ отвергаются. Вход из сети
  должен проходить `from_parts`; публичных полей для обхода проверки нет.
- `crafting::RecipeBook` — 96 обычных рецептов + специальная починка. После подготовки
  поиск, зеркало, обрезка, теги и бесформенное паросочетание не выделяют память.
- `recipes_producing` / `recipes_using` индексируют все рецепты и варианты тегов для NEI.
  Починка имеет переменный выход: индекс включает её для каждого предмета с прочностью.
- `CraftPlan::prepare_exact` создаёт отдельный план значений: сетка, слоты назначения,
  количество крафтов и остатки. Недостаток ресурсов/места не меняет исходные значения.
  `apply` проверяет исходные снимки и публикует весь локальный результат одновременно.
  Владелец мира должен включить изменения компонентов и явные дропы в одну транзакцию.
- `RemainderPolicy` явно выбирает отказ при переполнении либо сбор дропов; предмет
  результата никогда не теряется. Обычные вёдра возвращаются в освободившиеся клетки.
- `machine_recipes` сохраняет INFUSE 6, ENRICH 17, CRUSH 15 и PURIFY 6, а также плавку,
  вещества, кремень → кислород и энергию. Всего 73 представления рецептов/превращений
  для прямых и обратных запросов. Расход «за операцию» и «за тик» различается типом.

Эталоны отдельно получены из исходных донорских функций: 97 определений, 97 сеток и
результатов, 180 строк прямого/обратного NEI, 73 машинных записи. Пересоздание вручную:

```bash
source tools/env.sh
rustc --edition=2024 crates/rules/tools/recipe_golden.rs -o .local/rules-golden/recipes
.local/rules-golden/recipes crates/rules/tests/data
cargo test --locked -p rules
```

Проверки охватывают вместимость, атомарный отказ, устаревшие планы, возврат двух вёдер
рецепта дробилки, целочисленное округление починки и 10 000 поисков/NEI без аллокаций.
Они не подтверждают тайминги машин, сохранение инвентарей или готовность игрового UI.
