# Локальные долговечные сохранения

Формат хранит ограниченный версионированный снимок и последовательный WAL.
Файлы, заголовки и записи защищены BLAKE3. Длины проверяются до выделения памяти
по ограничениям поля и остатку сообщения; неограниченного serde-декодера нет.
Полностью записанная повреждённая запись — ошибка. При восстановлении можно
обрезать только неполный неподтверждённый хвост заголовка или содержимого.

`Store::append` возвращает результат после полной записи и `sync_all`.
Ответ фонового писателя — граница сетевого подтверждения. Изменения мира и
результаты действий лежат в одной записи; вместе восстанавливаются хеши входа,
права/бан, приватное точное состояние игрока и сроки задержек действий.
Файловая блокировка не позволяет открыть второго писателя.

Порядок снимка: сохранить и fsync предыдущий снимок; fsync временный новый;
атомарно заменить основной; fsync каталога; fsync WAL с привязкой к снимку;
атомарно заменить WAL и fsync каталога. При одинаковом номере записи и сбое между
двумя заменами выбирается предыдущий снимок с подходящей контрольной суммой,
после чего основной восстанавливается. Привязка не ослабляется. Под Windows
используется `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)` с узким описанным unsafe.

Необязательное ограниченное расширение INV1 хранит собственный инвентарь.
Отсутствие расширения в записях M6 означает пустой инвентарь; предметы не выдаются.
Неизвестные/повреждённые расширения отклоняются. Несовместимые версии генератора
или правил требуют явно заданной миграции; неподдерживаемый формат никогда не
открывается как новый мир. Приватные `generation.key` и `owner.identity` нужно
сохранять отдельно: им не место в снимке мира или сетевом протоколе.

WND1 хранит приватные курсор/сетку и привязку окна WBD1, RUN1 — ограниченные
долговечные журналы систем. Зарегистрированы kinds 1–7: survival, mobs, items,
machines, сохранённый height index, chat, неизменяемые item payloads. Каждый payload ограничен 8 MiB; вся запись
WAL по-прежнему ограничена 16 MiB, снимок — 512 MiB. Старые записи без расширений
читаются с пустыми дополнительными данными; неизвестные kinds и дубликаты
отклоняются. Сервер также отказывается открывать kind, для которого ещё не
подключён авторитетный владелец. LIV1 внутри приватного продолжения игрока
сохраняет HP, air/fire/death/regen/damage timers и combat/grace/cooldown.

Стек с типизированным payload хранит ненулевую 64-битную ссылку и имеет количество
один. Необязательный разреженный хвост XRF1 сохраняет ссылки в INV/WND/Chest/Furnace
и предметах; обычные стеки сохраняют прежние байты. Сервер проверяет все собственные
ссылки при восстановлении, включая вложенные сохранённые машины. Публичный кеш
контейнера не считается собственным предметом и не наполняет ledger при каждом
изменении заряда. Квота ledger учитывает полный размер его снимка до принятия
действия; одинаковое содержимое переиспользует ID и не удаляется при одной установке.

`SaveWorker::wal_bytes()` публикует размер последней долговечной версии WAL через
атомарный счётчик. Запрос файловых метаданных остаётся в потоке писателя; после
checkpoint счётчик отражает новый короткий WAL. Сервер проверяет порог 256 MiB
после каждой завершённой микрофазы и запрашивает checkpoint, сохраняя запас до
жёсткого лимита 512 MiB. Плановый checkpoint через 200 тиков также действует.
Это предотвращает заполнение журнала большой активной группой между двумя
плановыми снимками; лимиты записи и требования fsync не увеличены.
