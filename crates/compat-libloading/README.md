# Адаптер динамической загрузки

Это новый код Cubi под лицензией проекта, а не исходники `libloading` под другой
лицензией. Имя пакета/версия обеспечивают подстановку через `[patch.crates-io]`.
Поддерживается только API, используемый закреплёнными ash/wgpu/winit:
`Library::new/get`, заимствованный `Symbol`, Unix `Library::open` с флагами,
Windows `open_already_loaded`, нужные варианты ошибок. Полная совместимость
со всеми возможными потребителями upstream не заявляется.

Реальная загрузка делегирована `dlopen2 = 0.9.0` без default features, опубликованному
под MIT. Проверены `Cargo.toml.orig`, `Cargo.toml`, разделы лицензии в README/src/lib.rs
архива crates.io; SHA256:
`60768c353d76ba6dd1b6332a5dbbdd3bc2dddadc2935f4cc6a9d0f17ca8ecb6a`.
Его архив не содержит отдельного LICENSE-файла, но оба исходных объявления прямо
предоставляют MIT. Потребители и общедоступные сигнатуры API изучены из их пакетов
crates.io; исходники реализации ISC `libloading` не использовались и не копировались.

Windows API получения уже загруженного модуля дополнен коротким собственным
адаптером `GetModuleHandleExW`/`GetProcAddress`/`FreeLibrary` через MIT/Apache
`windows-sys`. Он владеет отдельной ссылкой загрузчика. Unix загрузка с явными
флагами использует собственный небольшой мост libc: при `RTLD_NOLOAD` glibc может
вернуть NULL без текста dlerror, а dlopen2 0.9.0 ошибочно разыменовывает такой NULL.
Мост проверяет оба указателя, владеет ссылкой загрузчика и закрывает её через
dlclose. Флаги передаются без изменения, поэтому проверка RenderDoc не загружает
чужую библиотеку. Тест со специально скомпилированной локальной C-библиотекой
проверяет состояния «файл есть, но не загружен», «удерживается другой ссылкой»
и «полностью выгружен»; проверка отсутствующего файла сама по себе недостаточна.
Типизированный символ заимствует библиотеку; проверяются размер типа, NUL в
именах/путях и ошибки загрузчика. Нулевые адреса символов и расширенный API
upstream для `Symbol<Option<T>>` не поддерживаются: текущие потребители их не
используют. Указатели нельзя вызывать после выгрузки.
