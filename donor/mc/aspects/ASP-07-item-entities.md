## 0. Главное для реализации

1. **Из блока** (`Block.dropStack`): центр клетки ±0.25 по каждой оси, по Y ещё −0.125; скорость `(U(−0.1, 0.1), 0.2,
   U(−0.1, 0.1))` — её даёт конструктор `ItemEntity`; задержка подбора **10**. Предмет подпрыгивает на **0.38** над точкой
   появления (пик на 4-м тике), падает за **10–12 тиков** и откатывается до **1.2** блока по оси. [src][расчёт]
2. **Бросок игрока** (`PlayerEntity.dropItem`): появляется в `глаза − 0.3` (стоя — ступни + 1.32), скорость
   `0.3` по взгляду (с учётом pitch) **+0.1 вверх ± 0.1** (треугольное распределение) и боковой разброс до 0.02; задержка
   **40**. Глядя прямо, предмет пролетает **≈ 3.3 блока** (2.6–4.0), а не «метра 2». Скорость игрока не наследуется. [src][расчёт]
3. **При смерти** — та же функция со случайным направлением: горизонтальная скорость `U(0, 0.5)` в случайную сторону,
   вверх 0.2, задержка 40. Вещи разлетаются **до 6.7 блока**. [src][расчёт]
4. **Сундук и печь** (`ItemScatterer`): для каждой ячейки — одна точка внутри клетки, стек режется на куски по **10–30**,
   скорость `(T(0, 0.115), 0.2 + T(0, 0.115), T(0, 0.115))`, **задержки подбора нет (0)**. [src]
5. **Физика** — каждый тик: вода → плавучесть, иначе гравитация **0.04**; если предмет внутри блока — выталкивание;
   затем `move` с той же AABB-коллизией, что у игрока; трение X/Z **0.98** в воздухе и **0.588** (0.6·0.98) на земле, Y — 0.98.
   **Лежащий без движения предмет двигается только раз в 4 тика** (`(age + id) % 4 == 0`). [src]
6. **Отскока от земли нет.** Строка `vy·−0.5` в коде есть, но на обычном блоке `onEntityLand` уже обнулил vy. Она работает
   только у предмета внутри блока (noClip). «Подпрыгивание» на земле — это покачивание при отрисовке. [src][вывод]
7. **Подбор**: коробка игрока расширена на `(1.0, 0.5, 1.0)` — центр предмета ближе **1.425** по X **и** по Z (квадрат,
   без проверки видимости: за угол по диагонали и через тонкие блоки достаёт), по высоте низ предмета в
   `(ступни − 0.75, ступни + 2.3)`. Нужна задержка 0. Частичный подбор
   разрешён. Анимация — копия предмета летит **3 тика** к точке `(x, (ступни + глаза)/2, z)` с ускорением `f = ((t+δ)/3)²`.
   Звук `random/pop`: громкость **0.2**, высота `2.0 + 1.4·(r1 − r2)`, обрезается до **2.0**, поэтому **половина хлопков
   — на 2.0**. [src]
8. **Слияние**: проверка, когда `age % 2 == 0`, если предмет в этом тике перешёл в другую клетку, иначе раз в **40** тиков.
   Поиск соседей в коробке `+0.5 / 0 / +0.5`, тот же предмет и компоненты. **Сумма должна быть ≤ максимума стека** — частичного
   слияния нет (40 + 40 не сольются). Больший стек поглощает меньший и остаётся на своём месте; задержка = max,
   возраст = **min**. [src]
9. **Деспаун**: `itemAge ≥ 6000` (ровно 5 мин тиков сущности). Возраст сбрасывает только слияние с более молодым
   предметом. Вне тикающих кусков возраст стоит. [src]
10. **Отрисовка**: вращение `(age + δ)/20 + offset` рад (оборот **6.28 с**), покачивание `sin((age + δ)/10 + offset)·0.1 + 0.1`
    (0…0.2 блока, период **3.14 с**). Блок — куб **0.25** с низом на 0.125 над землёй; плоский предмет — спрайт **0.5 × 0.5** толщиной
    **1/32** («экструзия»: лицо, изнанка и рёбра по краю непрозрачных пикселей). Центр у обоих на `0.25 + bob`. Копии: 1/2/3/4/5
    при 1 / 2–16 / 17–32 / 33–48 / 49+. Рисуется только ближе **16·clamp(дальность/8, 1, 2.5)** блоков (при 12 кусках — 24). [src][data]
11. **Кактус уничтожает предмет**: 5 касаний по 1 урону (здоровье 5). Касание засчитывается внутри `move`, поэтому лежащий на
    кактусе предмет теряет 1 раз в 4 тика и исчезает через **13–16 тиков** после посадки. [src][вывод]
12. Для нашего порядка тика предлагаю **подбор отдельной фазой после тика сущностей**, как у сервера Minecraft
    (`playerTick` идёт после `world.tick`). Тогда задержки 10/40 дают ровно 10/40 тиков, а не 11/41 (§5.6). [src][вывод]

## 2. Появление предмета

### 2.1 Из блока: `Block.dropStack(world, pos, stack)` [src]

Его вызывают ломание с дропом (`afterBreak` → `dropStacks`, ASP-04 §9 / ASP-06 §1.2), опад листвы, отваливание факела
или травы без опоры (`Block.replace` → `breakBlock(pos, true)`, ASP-04 §10). Каждый стек таблицы добычи — **отдельная
сущность** со своим случайным смещением.

- Позиция (низ коробки, центр по X/Z): `x = bx + 0.5 + U(−0.25, 0.25)`, `y = by + 0.5 + U(−0.25, 0.25) − 0.125`,
  `z = bz + 0.5 + U(−0.25, 0.25)`. `U(a, b) = a + rand·(b − a)` (`MathHelper.nextDouble`). Коробка 0.25³ целиком внутри
  сломанной клетки: X/Z от 0.125 до 0.875, низ от 0.125 до 0.625.
- Скорость — конструктор `ItemEntity(world, x, y, z, stack)`: `(rand·0.2 − 0.1, 0.2, rand·0.2 − 0.1)`, double.
- `setToDefaultPickupDelay()` → **10**. Владельца нет. Только при `doTileDrops` (у нас всегда).
- Вариант `dropStack(world, pos, direction, stack)` (выброс из грани: тыква и т. п.) на нашем пути не нужен: позиция на
  грани, скорость по нормали `0.1`.

Порядок ГСЧ: три смещения (мировой ГСЧ), две скорости X/Z (мировой). Потом свой ГСЧ сущности даёт `uniqueOffset =
rand·2π` и случайный yaw — yaw отрисовка не использует.

### 2.2 Из сущности: `Entity.dropStack(stack, yOffset)` [src]

Падающий блок, который не смог встать (ASP-05 §5.2): `new ItemEntity(x, y + 0, z, стек 1)` — позиция сущности (низ, центр),
скорость конструктора, задержка 10. Потом так же выпадает добыча мобов.

### 2.3 Бросок игрока: `PlayerEntity.dropItem(stack, throwRandomly, retainOwnership)` [src]

Общая часть:
1. Пустой стек — ничего (и взмаха нет).
2. `y = getEyeY() − 0.3F`: стоя `ступни + 1.32`, в приседе `+ 0.97`; X/Z — центр игрока. Предмет появляется **внутри
   коробки подбора** игрока, его защищает задержка.
3. Конструктор (его случайная скорость затем перезаписывается), `pickupDelay = 40`. Если `retainOwnership`, игрок
   записывается в `thrower`. На подбор `thrower` **не влияет**: подбор ограничивает только поле `owner`, а его ставит лишь
   `/give`.
4. Скорость:
   - **вперёд** (`throwRandomly = false`), всё во float, `sin/cos` по таблице Java (у нас точный `sin`, решение ASP-01/02):
     `vx = −sin(yaw)·cos(pitch)·0.3 + cos(k)·l`, `vz = cos(yaw)·cos(pitch)·0.3 + sin(k)·l`,
     `vy = −sin(pitch)·0.3 + 0.1 + (r1 − r2)·0.1`, где `k = rand·2π`, `l = 0.02·rand`, `r1, r2` — равномерные [0, 1).
     Итог по вертикали: `0.1 ± 0.1` с пиком распределения в 0.1;
   - **случайно** (`throwRandomly = true`): `f = rand·0.5`, `g = rand·2π`, `v = (−sin g·f, 0.2, cos g·f)`.
5. Звука нет [src: в `dropItem` и вокруг него нет `playSound`]. Взмах рукой — только у клиента, если что-то выпало.
6. **Скорость игрока не добавляется** [src]. На бегу (0.28 б/т) предмет со скоростью 0.3 почти не отрывается от игрока.

Кто вызывает:

| Событие | Вызов | Направление | Владелец (thrower) | Задержка |
|---|---|---|---|---|
| Q / Ctrl+Q в мире | `ServerPlayerEntity.dropSelectedItem(all)` → `dropItem(s, false, true)` | вперёд | да | 40 |
| Q / Ctrl+Q над слотом, клик со стеком вне окна | `ScreenHandler` THROW → `dropItem(s, true)` (ASP-08 §2.5) | вперёд | да | 40 |
| Закрытие окна: нет места в инвентаре | `PlayerInventory.offer` → `dropItem(s, false)` (ASP-08 §4) | вперёд | нет | 40 |
| Остаток Shift-крафта не влез | `dropItem(s, false)` (ASP-08 §2.2) | вперёд | нет | 40 |
| Смерть | `dropInventory` → `PlayerInventory.dropAll` → `dropItem(s, true, false)`: main 0…35, броня, вторая рука | случайно | нет | 40 |

Q в мире [src `MinecraftClient.handleInputEvents`]: `while (dropKey.wasPressed())` — каждое накопленное нажатие (автоповтор
ОС тоже, решение ASP-08). Ctrl — весь стек одной сущностью. Обработка идёт **до** проверки «используется предмет»,
поэтому Q работает и во время еды. Выброс берёт позицию и взгляд на начало тика: сервер видит прошлую позицию,
у нас это фаза 1 до движения.

### 2.4 Сундук и печь при разрушении: `ItemScatterer.spawn` [src]

`ChestBlock.onStateReplaced` → `ItemScatterer.onStateReplaced`; `AbstractFurnaceBlock.onStateReplaced` → `ItemScatterer.spawn`
(плюс опыт рецептов — опыт не берём). Это происходит при замене блока, **до** дропа самого блока (ASP-06 §1.2), в порядке
ячеек: сундук 0…26, печь 0 вход, 1 топливо, 2 результат.

Для каждой непустой ячейки:
1. Одна точка на ячейку: `x = floor(bx) + rand·0.75 + 0.125`, `y = floor(by) + rand·0.75`, `z = floor(bz) + rand·0.75 + 0.125`.
2. Пока стек не пуст — сущность из куска `rand(0…20) + 10` = **10–30 штук** в той же точке. 64 → обычно 3 сущности.
3. Скорость каждой: `(T(0, 0.11485), T(0.2, 0.11485), T(0, 0.11485))`, где `T(m, d) = m + d·(r1 − r2)` (треугольное).
4. **Задержка не ставится — 0**: содержимое можно подобрать сразу, даже в полёте. Сам сундук или печь выпадает через
   `dropStack` с задержкой 10.

Куски одного стека в одной точке потом снова сливаются, если сумма ≤ 64 (§6).

## 3. Тик `ItemEntity` по шагам [src `ServerWorld.tickEntity`, `ItemEntity.tick`, `Entity.baseTick`]

Перед тиком мир делает `resetPosition()` (prev = текущая позиция, от неё идёт интерполяция отрисовки) и **`age++`**.
Первый тик предмета идёт с `age = 1`.

| № | Шаг | Подробности |
|---|---|---|
| 1 | пустой стек → удалить | |
| 2 | `baseTick` | состояние воды: `updateWaterState` по **текущей** позиции — касание, высота жидкости над низом коробки, толчок потока (§4.4); всплеск при входе в воду (§4.4); огонь (у нас нет); **`y < дно − 64` → удалить** |
| 3 | `pickupDelay−−` | если `> 0` и `≠ 32767` |
| 4 | `prev = pos` | ещё раз, на ту же величину |
| 5 | сила | вода и высота жидкости `> 0.1F` → плавучесть; лава (нет) → то же с 0.95; иначе **`vy −= 0.04`** |
| 6 | внутри блока? | `noClip = !isSpaceEmpty(коробка, сжатая на 1e-7)`. Если да — `pushOutOfBlocks(x, середина коробки по Y, z)` (§4.5) |
| 7 | движение | только если `!onGround`, или `vx² + vz² > 1e-5F`, или `(age + id) % 4 == 0`: `move(v)` → трение `(f, 0.98, f)`, `f = onGround ? slip·0.98F : 0.98F` → если `onGround && vy < 0`, `vy ·= −0.5` |
| 8 | слияние | `movedCell` = сменилась клетка `floor(prev)` ↔ `floor(pos)` по любой оси; если `age % (movedCell ? 2 : 40) == 0` и предмет годен к слиянию — `tryMerge` (§6) |
| 9 | `itemAge++` | кроме «вечного» (−32768) |
| 10 | `updateWaterState` ещё раз | по новой позиции: **поток толкает второй раз за тик** |
| 11 | `itemAge ≥ 6000` → удалить | |

`id` — порядковый номер сущности (`Entity.getId`, общий счётчик). Он сдвигает фазу «раз в 4 тика» между предметами.

Где предмет стоит в общем порядке [src `ServerWorld.tick`, `EntityList`, `MinecraftServer.tickWorlds`, `ServerPlayerEntity.playerTick`]:
- на сервере пакеты игрока (ломание, Q, движение) обрабатываются **между** тиками; потом `world.tick`: запланированные тики,
  случайные тики, затем сущности по порядку появления (`Int2ObjectLinkedOpenHashMap`); потом сеть → `playerTick` → подбор;
- сущность, появившаяся во время обхода (предмет от падающего блока), в этом обходе не тикает (обход идёт по старой
  карте) — первый тик в следующем. Предмет от ломания, Q и запланированного или случайного тика блока тикает уже в этом
  тике мира.

Наш порядок (ASP-05 §11.1 + предложение §5.6): **1 ввод** (ломание → `drop_from_block`, Q → `throw`) → **2 игрок** (движение) →
**3 мир** (время, запланированные, случайные тики, затем сущности по снимку списка; новые — со следующего тика) →
**4 подбор**.

### 4.2 Падение, посадка, «отскок» [src `Entity.move`, `Block.onEntityLand`]

- `move` — та же коллизия, что у игрока (ASP-01/02 §3.4–3.5): Y, потом бо́льшая из X/Z, без ступеньки.
- Посадка: `verticalCollision` → `onGround = true` → `onEntityLand` блока обнуляет `vy`. После этого трение и проверка
  `vy < 0` не срабатывают — **на обычных блоках отскока нет**. Потолок обнуляет `vy` так же: брошенный вверх в тоннеле
  предмет «прилипает» к потолку и падает.
- Стена: заблокированная ось → эта компонента скорости 0. Предмет не отражается, а сползает вниз вдоль стены.
- `vy ·= −0.5` срабатывает, только если `move` не обновил `onGround`, то есть в режиме noClip, когда предмет внутри блока
  (§4.5). [вывод]
- Слизь и кровать (у нас нет) отражают сами в `onEntityLand`.

### 4.3 «Раз в 4 тика» и следствия [src шаг 7][вывод]

- Лежащий без горизонтальной скорости предмет вызывает `move` только в тиках с `(age + id) % 4 == 0`. В пропущенных тиках
  гравитация всё равно копится: `vy` = −0.04, −0.08, −0.12. В тике движения до −0.16 срезается полом, и `vy` снова 0.
- **Сломали блок под лежащим предметом** — предмет висит в воздухе **0–3 тика**, затем падает сразу с накопленной `vy` до −0.16.
- Пока предмет катится (`v² > 1e-5`), он движется каждый тик. Последние ~0.003 б/т гаснут уже в 4-тиковом ритме, но
  смещения меньше `√1e-7 ≈ 3.2e-4` за ход `move` вообще не применяет.

### 4.4 Вода [src `applyWaterBuoyancy`, `Entity.updateMovementInFluid`, `onSwimmingStart`]

- Высота жидкости: по клеткам коробки, сжатой на 0.001; для клетки воды верх = `y + высота` (источник с воздухом сверху —
  **8/9**, вода сверху — 1.0); `fluidHeight = max(верх − низ коробки)`.
- Плавучесть при касании и `fluidHeight > 0.1F`: X/Z × `0.99F`; если `vy < 0.06F`, то `vy += 5e-4F`. **Гравитации в воде нет**,
  дальше обычное трение ×0.98. Предел всплытия: `v = (v + 5e-4)·0.98` → **0.0245 б/т (0.49 б/с)**.
- Падение в глубокую воду почти не тормозится: с 1 блока над поверхностью предмет уходит на **≈ 11.8** блока вниз
  (6.7 с) и всплывает ≈ 26 с. В пруду глубиной 3 он ложится на дно и поднимается. [расчёт]
- У поверхности: как только вода над низом ≤ 0.1, включается гравитация 0.04 и сразу утапливает предмет. Предмет **качается**:
  в стоячей воде глубиной 1 низ коробки ходит между **0.39 и 0.79** над дном клетки (поверхность 0.889), период
  **≈ 70–80 тиков** (3.5–4 с). [расчёт]
- Поток (ASP-15): толчок `normalize(средний вектор потока)·0.014` добавляется **дважды за тик** (шаги 2 и 10). Если
  |vx|, |vz| < 0.003 и толчок меньше 0.0045, толчок растягивается до 0.0045.
- Вход в воду (касание после «не касался», не в первом тике): звук `entity.generic.splash` в категории AMBIENT, громкость
  `min(1, √(0.2vx² + vy² + 0.2vz²)·0.2)` (у падающего предмета ~0.05), высота `1 ± 0.4`; по **6** частиц `bubble` и `splash`
  на `floor(y) + 1` (ASP-13).

### 4.5 Выталкивание из блока [src `Entity.pushOutOfBlocks`]

Включается, когда коробка (сжатая на 1e-7) пересекает форму коллизии. Это блок, поставленный на предмет, песок,
упавший в его клетку, или поршни (нет).
1. Клетка — по `(x, середина коробки по Y, z)`; локальные координаты в ней.
2. Кандидаты по порядку **N, S, W, E, UP** (вниз — никогда); годится сосед, который **не полный куб** (`isFullCube` по
   форме коллизии: листва и стекло — полные). Выбирается ближайшая грань: расстояние до своей стороны клетки. Если ни одна
   не годится, остаётся **UP**.
3. `v ×= 0.75`, затем компонента по выбранной оси **заменяется** на `±(0.1 + rand·0.2)`, то есть 0.1–0.3.
4. `move` в noClip — простой перенос **сквозь блоки**, `onGround` не обновляется (остаётся прежним).

Что чувствуется [расчёт по воксельной модели, rand = 0.5]:
- блок поставили на лежащий предмет (центр в 0.2 от западной грани) — за 2 тика он выползает на запад, немного проседает в
  пол (−0.14), затем выпрыгивает вверх на 0.43 и через ~16 тиков ложится в ~0.6 блока от исходной точки;
- **закрытая яма или замурованный предмет**: пока предмет «стоит» (`onGround` от прежней жизни) и толкается вверх,
  `move` идёт раз в 4 тика: **+0.1…0.3 за 4 тика ≈ 1 блок/с вверх сквозь камень**, пока коробка не окажется в пустоте.

### 4.6 Касание блоков: кактус, огонь, лестница, пустота [src `Entity.checkBlockCollision`, `CactusBlock`, `ItemEntity.damage`]

- `checkBlockCollision` вызывается **только внутри `move`** (не в noClip): для каждой клетки коробки (от min + 1e-7 до
  max − 1e-7) — `onEntityCollision` блока.
- **Кактус**: `damage(cactus, 1)`. У предмета `health = (int)(health − урон)`, при ≤ 0 — удалить. Неуязвимости по
  времени нет. Итог — **5 касаний**:
  - пролетая вдоль бока (коллизия кактуса уже на 1/16 с каждой стороны) — по касанию за тик, **5 тиков**;
  - лёжа на верхушке (верх коллизии 15/16, коробка в клетке кактуса) — касание раз в 4 тика: первое при посадке,
    исчезает через **13–16 тиков** после неё. Решение пользователя: кактус с формой 14/16 × 15/16 и уроном — со срезом 4.
- Огонь и лава у нас нет. Справка: в огне урон 1 и поджог, в лаве 4 за тик (2 тика) и шипение. Огнеупорные предметы
  (`FIRE_RESISTANT`) не горят.
- **Лестница**: лазать умеет только `LivingEntity` (`isClimbing`). Для предмета лестница — пластина 3/16 у стены. В
  шахте 1×1 предмет в центре (0.375…0.625) пластины не касается и падает вниз. Если коробка перекрывает пластину,
  предмет ложится на её верхний торец.
- **Пустота**: `y < дно − 64` → удалить. У нас дно 0, и по ASP-01/02 §3.14 `Y < 0` твёрдое, поэтому правило — страховка на
  случай дыры: удалять при `y < −64`.
- Мёд, песок душ, паутина (множители скорости) у нас нет; формулу оставить общей.

## 5. Подбор

### 5.1 Кто и когда [src `PlayerEntity.tickMovement`]

Каждый тик игрока, если здоровье > 0 и не наблюдатель: коробка игрока `expand(1.0, 0.5, 1.0)` (без транспорта) → все
сущности, коробка которых **строго** пересекает её (`getOtherEntities`, порядок — по секциям; у нас по номеру появления) →
`onPlayerCollision` у каждой не удалённой. За тик можно подобрать **несколько** предметов, каждый со своим хлопком.

Геометрия (игрок 0.6 × 1.8, предмет 0.25): `|x_п − x_и| < 1.425` **и** `|z_п − z_и| < 1.425` — квадрат 2.85 × 2.85, а не
круг; по высоте `y_ступней − 0.75 < y_низа предмета < y_ступней + 2.3` (в приседе 1.5 → `+ 2.0`). **Проверки
видимости нет** [вывод из геометрии]:
- через полный блок толщиной 1 не достать: прижавшись к стене, до центра предмета за ней ровно 0.3 + 1 + 0.125 = 1.425,
  а сравнение строгое;
- через тонкий блок достаёт: сундук 14/16 — 1.3;
- в клетке по диагонали за углом достаёт, даже если обе соседние клетки — стены (Δ ≈ 0.43 по осям);
- предмет в яме на 1 ниже ступней — нет.

### 5.2 `ItemEntity.onPlayerCollision` [src]

Только на сервере. При `pickupDelay == 0` и (`owner` нет или это этот игрок):
1. `i = count` до подбора.
2. `PlayerInventory.insertStack(stack)` — **уменьшает стек предмета на месте**. Порядок ячеек — ASP-08 §1.2: выбранный слот
   (если там такой же и есть место) → вторая рука → 0…35 с местом → первая пустая. Изношенное — только в пустую,
   целиком. Подскок иконки 5 тиков ставит `addStack`.
3. Если хоть что-то влезло: `sendPickup(this, i)` — событие анимации и звука с **исходным** `i`; если стек опустел —
   удалить сущность. Если не влезло ничего — ни звука, ни анимации, предмет лежит.

**Частичный подбор**: на земле остаётся остаток, его возраст и задержка не меняются.
- В ванили клиент получает событие с исходным `i`, уменьшает свою копию на `i`, копия пустеет и исчезает. Остаток на
  сервере клиент не видит, пока сущность не пересинхронизируется (стек изменён на месте, `DataTracker` не помечен). [вывод]
- Это сетевой дефект, не ощущение. **Предлагаю не повторять**: остаток виден с новым числом.

### 5.3 Анимация полёта: `ItemPickupParticle` [src `ClientPlayNetworkHandler.onItemPickupAnimation`, `ItemPickupParticle`]

- Создаётся **копия** предмета (стек до уменьшения, позиция, `itemAge`, `uniqueOffset`). Копия не тикает: вращение и
  покачивание заморожены на её `itemAge` (+δ кадра).
- Цель — точка игрока `(x, (y + eyeY)/2, z)`: стоя `ступни + 0.81`, в приседе `+ 0.635`. Цель интерполируется между
  тиками (`lastTarget → target`).
- Кадр: `f = ((t + δ)/3)²`, `t` = 0, 1, 2 — тики жизни; позиция = `lerp(f, позиция копии, цель)`. На границах тиков
  доля пути **0, 1/9, 4/9**, к концу 3-го тика — 1. Это ускорение «втягивания». На тике `t == 3` анимация удаляется:
  она длится **3 тика (0.15 с)**.
- Рисуется тем же рендером предмета (копии стека, свет по клетке копии).
- В ванили новая частица попадает в список только в следующем тике частиц, поэтому возможен пропуск до 1 тика, когда
  предмета не видно нигде. **У нас анимацию начинать в том же кадре.**

### 5.4 Звук [src `onItemPickupAnimation`, `SoundSystem`; data `sounds.json`]

`entity.item.pickup` → `random/pop` без своих множителей. Звучит в **позиции предмета**, категория PLAYERS, громкость
**0.2**, высота `(r1 − r2)·1.4 + 2.0` ∈ [0.6, 3.4], которая обрезается в `SoundSystem` до **[0.5, 2.0]**:
- ровно **50 %** хлопков на 2.0;
- ~21 % ниже 1.5;
- минимум 0.6.

Затухание линейное до `max(0.2, 1)·16 = 16` блоков. Свой звук — CC0 «pop» (решение по звукам).

### 5.5 Подскок иконки [src `PlayerInventory.addStack/insertStack`, `ClientPlayNetworkHandler.onScreenHandlerSlotUpdate`; ASP-08 §6.4]

Ячейка, в которую легло, получает `bobbingAnimationTime = 5` и в HUD 5 тиков сжимается и вытягивается (формула в ASP-08).
Клиент ванили ставит подскок слотам хотбара и второй руки, когда число в ячейке выросло или ячейка была пуста. У нас то
же даёт `add_at` из ASP-08. В окне подскока нет.

Если подобранное легло в **выбранный** слот (держимый стек), предмет в руке «ныряет» — анимация смены, решение после
ASP-11 (идентичность стека — явный id в Rust).

### 5.6 Порядок фаз и точные задержки [вывод]

- В ванили: ломание (пакет) → в тике S предмет тикает (10 → 9) → … → в S+9 задержка 0 → в том же S+9 `playerTick` подбирает.
  Получается **10 тиков** (0.5 с) от ломания; у Q — 40 (2.0 с).
- Если оставить подбор внутри тика игрока (фаза 2, до сущностей), он увидит 0 только в S+10: **11/41 тиков**.
- **Предложение**: фаза 4 «подбор» после `tick_entities`. Она использует позицию игрока после его движения и
  предметы после их тика — как сервер. ASP-01/02 §3.2 п. 18 (подбор в `tickMovement`) верен для кода `PlayerEntity`, но на
  сервере этот код идёт после мира.

## 6. Слияние [src `ItemEntity.tryMerge`, `canMerge`, `merge`]

1. Период — шаг 8 тика (§3): `age % (сменил клетку в этом тике ? 2 : 40) == 0`. Летящий предмет проверяет часто, лежащий —
   раз в 2 с, в своей фазе.
2. Годность (`canMerge()` у обоих): жив, `pickupDelay ≠ 32767`, `itemAge ≠ −32768`, `itemAge < 6000`, `count < max`.
   **Полный стек (64) и неделимые (инструменты) не сливаются никогда.**
3. Соседи: предметы, коробка которых строго пересекает коробку этого, расширенную на `(0.5, 0, 0.5)`. Центры ближе
   **0.75** по X и по Z, коробки перекрываются по Y (|Δy| < 0.25).
4. Пара: одинаковый `owner` (у нас всегда нет) и `count₁ + count₂ ≤ max` второго, тот же предмет и компоненты (износ
   тоже). **Сумма больше максимума — пара пропускается**, частичного перелива нет.
5. Кто поглощает: если у другого меньше — этот берёт его; иначе (меньше или **равно**) другой берёт этот. Поглотитель
   **остаётся на своём месте со своей скоростью**; поглощённый исчезает мгновенно, без анимации. У нового стека
   `pickupDelay = max`, `itemAge = min`.
6. Если поглощён этот — обход прекращается; если поглотил — продолжает со следующими соседями.

Следствия:
- два куска по 40 так и лежат рядом;
- Q-броски «в одну точку» глядя прямо разлетаются на 2.6–4.0 блока и могут не слиться все. Надёжно сливаются брошенные
  под ноги или выпавшие из одного блока;
- куски одной ячейки сундука (10–30) сливаются, пока сумма ≤ 64.

## 7. Деспаун и возраст [src]

- `itemAge` +1 за тик (шаг 9), удаление при `≥ 6000`. Предмет живёт ровно **6000 тиков** своего тика. В незагруженных
  или не тикающих кусках сущности не тикают, и возраст стоит.
- Возраст меняют только:
  - слияние — `min`: свежий предмет, слившийся со старой кучей, «омолаживает» кучу;
  - `setNeverDespawn` (−32768);
  - `setCovetedItem` (−6000, пиглины);
  - `setDespawnImmediately` (5999 и бесконечная задержка — «призрак» `/give` для анимации).
  Подбор, частичный подбор и выгрузка возраст не сбрасывают: он сохраняется в NBT как short `Age`.
- `pickupDelay` хранится так же (short). Бесконечная `32767` не убывает, запрещает подбор и слияние.
- **Для отрисовки нужен отдельный счётчик.** Клиент ванили вращает предмет по своему `itemAge`, который слияние на сервере
  не трогает. Если вращать по логическому возрасту, после `min` при слиянии куча дёрнется. У нас: `spin_age` +1 каждый тик,
  у поглотителя не меняется.

## 8. Отрисовка [src `ItemEntityRenderer`, `ItemRenderer.renderItem`, `Transformation.apply`, `ItemModelGenerator`; data модели]

### 8.1 Формулы

Цепочка матриц от позиции `lerp(δ, prev, pos)` (низ коробки):
1. `T(0, bob + 0.25·s_y, 0)`, где `bob = sin((spin_age + δ)/10 + offset)·0.1 + 0.1`, `s_y` — масштаб Y модели «на земле»;
2. `R_y(angle)`, `angle = (spin_age + δ)/20 + offset` радиан. Положительный поворот вокруг +Y — против часовой стрелки
   при взгляде сверху [вывод];
3. смещения копий стека (§8.3);
4. трансформ модели «ground»: `T(translation/16)`, поворот XYZ (у нас 0), `S(scale)`;
5. `T(−0.5, −0.5, −0.5)` и геометрия модели в координатах 0…1.

`offset = uniqueOffset ∈ [0, 2π)` — один на сущность, сдвигает и вращение, и покачивание. Вращение ≈ 57°/с (оборот
**125.7 тика = 6.28 с**); покачивание ±0.1 вокруг 0.1 с периодом **62.8 тика = 3.14 с**.

### 8.2 Модели и размеры [data `item/generated.json`, `block/block.json`, `item/chest.json`]

| | Блок-предмет (куб) | Плоский предмет |
|---|---|---|
| «ground» | translation (0, 3, 0)/16, scale 0.25 | translation (0, 2, 0)/16, scale 0.5 |
| Размер | **0.25³** | **0.5 × 0.5**, толщина **1/32** (1 px = 1/32 блока, пиксели кубические) |
| Низ при bob = 0 | **+0.125** над ступнями (куб парит) | **0** (нижний ряд пикселей касается земли) |
| Центр | `+0.25 + bob` | `+0.25 + bob` |
| Глубина (`hasDepth`) | да | нет: `builtin/generated` печётся с `hasDepth = false` |

Что каким будет на нашем пути:
- **Кубы**: земля, дёрн, камень, булыжник, песок, гравий, брёвна (`cube_column`, ось Y), доски, верстак, печь, листва,
  глина, песчаник, руды, блоки железа и угля. Сундук — своя модель сундука с тем же «ground», что у блока. Кактус — модель
  кактуса: бока на 1/16 внутрь, тот же «ground». Снежный слой — плита 2/16 (`snow_height2`).
- **Плоские**: все `item/generated` и `item/handheld` — палки, уголь, сырое железо, слитки, самородки, кремень, яблоко,
  семена, глина-комок, кожа, вёдра, инструменты. У `handheld` «ground» наследуется, поэтому инструменты на земле того же
  размера. Плоские и некоторые блоки — факел, лестница, саженцы, цветы, трава-растение, папоротник: их модели предметов —
  `generated` с текстурой блока.
- Окраска: дёрн и листва-предмет красятся фиксированным цветом предмета, а не биомом. У нас — оттенок из палитры
  равнин; точные значения `ItemColors` ванили — [не проверено], нам не нужны.

### 8.3 Копии стека [src `getRenderedAmount`, `renderStack`]

| Число в стеке | 1 | 2–16 | 17–32 | 33–48 | 49+ |
|---|---|---|---|---|---|
| Копий | 1 | 2 | 3 | 4 | 5 |

- ГСЧ засевается `id предмета + износ`. Раскладка копий **одинакова для всех куч этого предмета** и не меняется во
  времени. Первая копия без смещения.
- Куб: копии 2…N смещены на `U(−0.15, 0.15)` по X, Y, Z (в повёрнутой системе, до масштаба). Нижние могут уйти в землю
  на 0.025.
- Плоский: вся пачка сначала сдвинута на `−0.0234375·(N−1)` по локальной Z, затем каждая следующая копия на
  **+0.046875** (1.5 px). Копии 2…N дополнительно смещены на `U(−0.075, 0.075)` по X и Y, по Z — нет. Пачка центрирована
  и видна сбоку как «стопка листов».

### 8.4 Экструзия спрайта [src `ItemModelGenerator`; подробно и с эталонами — ASP-11 §4.1, §11.3]

Плоский предмет — модель из лица и изнанки 16×16 (`z = 7.5/16 … 8.5/16`, изнанка с зеркальной UV) плюс полоски рёбер:
- одна полоска на (сторону, ряд или столбец), от min до max краёв, где соседний пиксель прозрачен (`α == 0`) или за краем;
- промежутки внутри полоски прячутся отсечением по альфе (< 0.1) или лежат внутри пластины;
- бок окрашен цветом краевого пикселя;
- на спрайт — не больше 66 квадов.

Принято после ASP-11: меш строит Rust-функция `extrude` с кэшем по номеру предмета; полоски обращены наружу —
причуду Java с LEFT/RIGHT не повторяем. **Тот же меш** — у предмета на земле: другой только трансформ `ground`
(§8.2) вместо `firstperson_*`.

### 8.5 Освещение [src `DiffuseLighting`, `WorldRenderer`, `EntityRenderer.getLight`; data `light.glsl`, `rendertype_entity_cutout.*`]

- **Свет из мира**: блочный и небесный свет клетки `floor(x, y + 0.2125, z)` (по «глазам» сущности) → лайтмап. Внутри
  блока будет 0, то есть чёрный.
- **Направленное затенение граней** (как у всех сущностей): два света в мировых осях (верхний мир): `L0 = norm(0.2, 1, −0.7)`,
  `L1 = norm(−0.2, 1, 0.7)`; яркость грани `min(1, 0.6·(max(0, L0·n) + max(0, L1·n)) + 0.4)`. Числа:
  - верх **1.0**, низ **0.4**;
  - боковые от **0.4 до 0.753** в зависимости от угла: ±Z 0.74, ±X 0.497.
  Нормали поворачиваются вместе с предметом, поэтому бока вращающегося куба «переливаются». Плоский спрайт мигает
  0.4 ↔ 0.75 **дважды за оборот** (лицо и изнанка получают одинаковую яркость).
- Слой: блоки-предметы — `entity_cutout` (отсечение альфы 0.1, без смешивания); прочие — `item_entity_translucent_cull`
  (тоже отсечение 0.1, плюс смешивание для полупрозрачных пикселей; у наших спрайтов альфа 0/255).
- Тень: круг радиуса **0.15**, непрозрачность `0.75·(1 − d²/256)` — исчезает к 16 блокам от камеры (настройка
  «тени сущностей»).

### 8.6 Дальность и отсечение [src `Entity.shouldRender`, `WorldRenderer.setupTerrain`]

`d² < (0.25·64·m)²`, где `m = clamp(дальность_кусков/8, 1, 2.5) × масштаб дальности сущностей` (по умолчанию 1.0).
При 8 кусках и меньше — **16 блоков**, при 12 (по умолчанию в ванили) — **24**, при 20+ — **40**. Дальше предметы не рисуются
вовсе (не тают, а пропадают). Ещё нужна видимость коробки, расширенной на 0.5, в пирамиде камеры.

## 9. Граничные случаи и мелочи

1. Стоишь вплотную к блоку и ломаешь его — предмет появляется в зоне подбора и через **0.5 с** сам влетает в тебя, даже
   не долетев до земли. Отойдёшь дальше 1.425 по оси — он ляжет.
2. Q глядя под ноги (pitch ≥ 60°) — предмет ложится в зоне подбора и **через 2 с подбирается сам**.
3. Q глядя вверх (pitch −90) — поднимается на 1.6 над рукой, падает обратно примерно на 22-м тике в зону подбора.
4. Ctrl+Q — весь стек одной сущностью, та же физика; пустой слот — ничего, нет взмаха.
5. Q, когда в руке последний предмет посреди ломания, сбрасывает ломание (в руке стало пусто, ASP-04 §0 п. 5). Q одного
   из 64 — нет: тот же предмет.
6. Содержимое сундука подбирается сразу — летит в игрока в первом же тике, если он рядом. Сам сундук — через 0.5 с.
7. Инвентарь полон — предмет лежит, звука нет. Есть место частично — подбирается часть, хлопок, остаток лежит.
8. Предмет за углом в диагональной клетке и за сундуком подбирается. За стеной в 1 полный блок — ровно на границе, нет.
   Сквозь пол (предмет в клетке под ногами) — нет.
9. Подбор идёт и при открытом окне инвентаря (мир не на паузе) — вещи появляются в окне.
10. Мёртвый игрок не подбирает.
11. Бросок в стену — без отражения: предмет падает вдоль стены. Бросок в потолок — `vy = 0` и падение.
12. Поставил блок на предмет или засыпал песком — предмет выползает к ближайшей открытой стороне или всплывает
    сквозь камень (§4.5).
13. Сломал блок под лежащим предметом — тот висит до 3 тиков (§4.3).
14. Предмет на краю блока не соскальзывает: любое перекрытие коробки с опорой держит его.
15. Слияние: полная куча 64 и инструменты не сливаются; 40 + 40 тоже. Поглощённая куча исчезает мгновенно.
16. Брошенный в глубокую воду уходит на 7–12 блоков и долго всплывает. На поверхности покачивается на ~0.4 с периодом ~4 с.
17. Отрисовка: блок-куб парит на 1/8 над землёй и «дышит» до 0.325; плоский касается земли нижним рядом пикселей.
18. Дальше 16–40 блоков (по настройке) предметов не видно.
19. Звук подбора в половине случаев одинаково высокий (обрезка 2.0); сливаясь в серию, хлопки звучат «трелью».
20. Броска без звука; падение и посадка предмета без звука.

## 12. Сценарий проверки человеком

Ровная площадка в равнине, пустой инвентарь, день. Включён хотбар.

1. Встать в 3 блоках от земли под прицелом, сломать её рукой. **Ожидаю**:
   - кубик в 1/4 блока выпрыгивает на ~0.4 блока над клеткой и через ~0.5 с ложится в пределах ~1 блока;
   - кубик парит чуть над травой, медленно вращается (оборот ~6 с) и плавно поднимается и опускается на ~0.2 блока
     (~3 с);
   - отскока от земли нет.
2. Подойти. **Ожидаю**: когда до кубика ~1.4 блока по прямой оси (по диагонали — до ~2), он за доли секунды «втягивается»
   в грудь с ускорением; короткий высокий хлопок; иконка земли в хотбаре на миг сплющивается и вытягивается.
3. Встать вплотную к блоку земли и сломать его, не двигаясь. **Ожидаю**: ~через полсекунды предмет сам влетает, не
   успев полежать.
4. Сломать 10 блоков земли, взять стек в руку, смотреть строго горизонтально, нажать Q. **Ожидаю**:
   - взмах руки; кубик летит вперёд и ложится в ~3–3.5 блоках;
   - сразу пойти к нему — первые ~2 с после броска он не подбирается (можно стоять на нём), потом подбирается сам.
5. Посмотреть строго под ноги, нажать Q 5 раз подряд и сразу отойти на 3 блока назад. **Ожидаю**: 5 кубиков под местом
   броска за ≤ 2 с превращаются в одну кучку из **двух** кубиков (стек 5). Подойти — подбирается 5 штук одним хлопком.
6. Ctrl+Q стеком 64 земли — **5** кубиков в куче; стеком 17 — **3**. Бросить палку: плоская картинка 0.5 блока,
   нижний край касается земли. Сбоку видна толщина в 1 пиксель с цветными краями; при вращении палка темнеет и светлеет.
7. Заполнить инвентарь целиком булыжником, оставив в одной ячейке 60 земли, бросить 10 земли и подойти. **Ожидаю**:
   подбираются 4 (хлопок), на земле остаётся куча из 6, она не исчезает.
8. Положить в сундук 27 стеков, сломать сундук рукой (~3.8 с), стоя рядом. **Ожидаю**: вещи брызгают из клетки на
   0.5–1.8 блока и почти сразу начинают влетать в игрока, пока есть место; сам сундук — чуть позже (~0.5 с).
9. Поставить блок прямо на лежащий предмет. **Ожидаю**: предмет за ~0.3–0.8 с выползает к ближайшему открытому боку,
   может подпрыгнуть и лечь рядом.
10. Бросить предмет в воду глубиной ≥ 3 с берега. **Ожидаю**: тонет до дна или на несколько блоков, затем медленно
    всплывает (~0.5 блока/с) и покачивается у поверхности.
11. (Со срезом 4.) Бросить предмет на кактус. **Ожидаю**: исчезает меньше чем за секунду.
12. Отойти от лежащего предмета на 30 блоков. **Ожидаю**: за ~24 блока (по нашей настройке) он пропадает из вида.

## 13. Что нужно от движка и как это ляжет

Решение: логика и мир — Rust (WASM), JS — ввод, рендер, UI.

- **E4 Сущности (главное)**. Хранилище предметов в Rust:
  - плотный массив с номерами появления (`id` — общий счётчик сущностей, нужен для фазы «раз в 4»);
  - простой пространственный индекс: сетка столбцов 4×4 или по кускам — для слияния и подбора;
  - тик по снимку длины (новые — со следующего тика, как `EntityList`);
  - удаление пометкой и уплотнением в конце тика;
  - `prev/pos` для интерполяции; `spin_age` для отрисовки.
  Предел — несколько сотен предметов. Стоимость за тик: одна развёртка коллизии (~10–30 форм), слияние раз в 2/40
  тиков. Тикать только в квадрате 8 кусков вокруг игрока — как решено для блок-сущностей и случайных тиков после
  ASP-10. Дальше предметы замирают, возраст стоит.
- **E2 Мир в главном потоке**:
  - те же формы коллизии, что у игрока (ASP-01/02 §11);
  - `full_cube(cell)` по форме коллизии;
  - `slip(cell)`;
  - `water_top(cell)` — 8/9, или 1.0 при воде сверху; поток — ноль до ASP-15;
  - `touch_damage(cell)` (кактус);
  - запрос «предметы в AABB».
- **E3 Цикл**: фазы §3 и п. 4 «подбор» после сущностей (решение §17). Отрисовка берёт `alpha` для позиции, вращения и
  покачивания.
- **E1**: правка блока в клетке предмета обрабатывается сама — выталкиванием (§4.5); ломание под предметом — 4-тиковым
  ритмом. Событий «блок изменился» сущностям не нужно.
- **E12 ГСЧ**: детерминированный ГСЧ Rust для точек и скоростей появления, `uniqueOffset`, силы выталкивания,
  размера кусков сундука — тесты с фиксированным зерном.
- **E7 UI**: подскок иконки — уже в ASP-08 (`bob[slot] = 5`). Событие подбора несёт номер ячейки.
- **E8 Ресурсы**: спрайты предметов 16×16 (палка, кирки, слитки уже есть в `familiar-craft/items`); недостающие (уголь,
  сырое железо, кремень, семена, яблоко, вёдра, инструменты) — нарисовать или найти CC0/CC-BY. Звук «pop» (CC0).
- **E9 Рука**: меш экструзии и кубы — общие с рукой (ASP-11 §4, §11.3: `extrude`, кэш по номеру предмета). Предмету на
  земле нужен только трансформ `ground` (§8.2) и свой инстансинг. Событие «подобрано в держимый стек» → «нырок» в руке
  (ASP-11).
- **E10 Звук и частицы**:
  - хлопок подбора: позиция предмета, 0.2, высота §5.4;
  - всплеск при входе в воду: тихий, 6 + 6 частиц (ASP-13);
  - анимация подбора — **не система частиц**, а 3-тиковая отрисовка копии предмета (§5.3), отдельным списком
    «летящих» в рендере предметов.
- **E11 Свет** (когда будет): выборка блочного и небесного света по клетке `y + 0.2125` для предмета.

Событие наружу из `Game::tick` (для JS):

```
ItemsView: на предмет [x, y, z, px, py, pz, spin_age, offset, model_id, copies, seed]   // f32/u32, без копий
PickupAnim: [snapshot предмета, from(x,y,z), player_id]     // JS ведёт 3 тика, цель — интерполированная точка игрока
Sound: Pop{pos}, Splash{pos, volume}
```

pub trait ItemWorld {
    fn shapes_in(&self, area: &Aabb, out: &mut Vec<Aabb>);
    fn full_cube(&self, c: IVec3) -> bool;
    fn slip(&self, c: IVec3) -> f32;               // 0.6 по умолчанию
    fn water_top(&self, c: IVec3) -> Option<f64>;  // абсолютный верх воды в клетке
    fn flow(&self, c: IVec3) -> DVec3;             // ASP-15; пока ноль
    fn touch_damage(&self, c: IVec3) -> f32;       // кактус 1.0, иначе 0
}

impl ItemEntity {
    fn new(id: u32, pos: DVec3, stack: ItemStack, rng: &mut Rng) -> Self {
        let vel = DVec3::new(rng.f64() * 0.2 - 0.1, 0.2, rng.f64() * 0.2 - 0.1); // скорость конструктора
        let offset = rng.f32() * std::f32::consts::TAU;
        Self { id, stack, pos, prev: pos, vel, on_ground: false, no_clip: false, age: 0, item_age: 0,
               spin_age: 0, pickup_delay: 0, health: 5, thrower: None, owner: None, offset,
               in_water: false, fluid_h: 0.0, removed: false }
    }
    pub fn aabb(&self) -> Aabb { Aabb::foot(self.pos, ITEM_W, ITEM_H) }

    /// Физическая часть тика (шаги 1–7 §3). Слияние и возраст — в `tick_items`.
    fn tick_physics(&mut self, w: &impl ItemWorld, rng: &mut Rng) {
        self.prev = self.pos;
        if self.stack.is_empty() { self.removed = true; return; }
        self.update_water(w);                                   // baseTick
        if self.pos.y < -64.0 { self.removed = true; return; }   // пустота: дно 0 − 64
        if self.pickup_delay > 0 && self.pickup_delay != NO_PICKUP { self.pickup_delay -= 1; }
        if self.in_water && self.fluid_h > WET {
            self.vel.x *= WATER_XZ; self.vel.z *= WATER_XZ;
            if self.vel.y < BUOY_CAP { self.vel.y += BUOY; }
        } else {
            self.vel.y -= GRAVITY;
        }
        self.no_clip = !space_empty(w, &self.aabb().shrink(1e-7));
        if self.no_clip { self.push_out(w, rng); }
        let h2 = self.vel.x * self.vel.x + self.vel.z * self.vel.z;
        if !self.on_ground || h2 > REST_H2 || (self.age + self.id) % 4 == 0 {
            self.move_self(w);                                  // AABB как у игрока; кактус внутри
            let f = if self.on_ground { (w.slip(self.slip_cell()) * 0.98f32) as f64 } else { DRAG_XZ };
            self.vel = DVec3::new(self.vel.x * f, self.vel.y * DRAG_Y, self.vel.z * f);
            if self.on_ground && self.vel.y < 0.0 { self.vel.y *= -0.5; } // только в noClip (§4.2)
        }
    }

    fn move_self(&mut self, w: &impl ItemWorld) {
        if self.no_clip { self.pos += self.vel; return; }        // сквозь блоки, onGround прежний
        let m = self.vel;
        let a = sweep(w, &self.aabb(), m);                       // ASP-01/02 §3.5: Y, бо́льшая из X/Z, другая
        if a.length_squared() > 1e-7 { self.pos += a; }
        let vert = m.y != a.y;
        self.on_ground = vert && m.y < 0.0;
        if (m.x - a.x).abs() >= 1e-5 { self.vel.x = 0.0; }
        if (m.z - a.z).abs() >= 1e-5 { self.vel.z = 0.0; }
        if vert { self.vel.y = 0.0; }                            // onEntityLand (пол и потолок)
        for c in self.aabb().cells_inside(1e-7) {               // checkBlockCollision
            let d = w.touch_damage(c);
            if d > 0.0 { self.health = (self.health as f32 - d) as i16; if self.health <= 0 { self.removed = true; return; } }
        }
    }

    fn push_out(&mut self, w: &impl ItemWorld, rng: &mut Rng) {
        let b = self.aabb();
        let p = DVec3::new(self.pos.x, (b.lo.y + b.hi.y) * 0.5, self.pos.z);
        let c = p.floor_i(); let l = p - c.as_dvec3();
        let mut best = (Dir::Up, f64::MAX);
        for d in [Dir::North, Dir::South, Dir::West, Dir::East, Dir::Up] {  // вниз — никогда
            if !w.full_cube(c + d.offset()) {
                let e = l[d.axis()];
                let dist = if d.positive() { 1.0 - e } else { e };
                if dist < best.1 { best = (d, dist); }
            }
        }
        let g = (rng.f32() * 0.2 + 0.1) as f64;
        self.vel *= 0.75;
        self.vel[best.0.axis()] = best.0.sign() * g;
    }

    fn slip_cell(&self) -> IVec3 { /* опорный блок (ASP-01/02 §3.10) с Y = floor(y − 0.999999) */ unimplemented!() }
    fn update_water(&mut self, w: &impl ItemWorld) { /* §4.4: высота над низом+0.001, толчок потока ×0.014 */ }

    fn mergeable(&self, max: u8) -> bool {
        !self.removed && self.pickup_delay != NO_PICKUP && self.item_age != NEVER_DESPAWN
            && self.item_age < DESPAWN && self.stack.count < max
    }
}

/// Фаза «мир → сущности» для предметов: физика, слияние, возраст (шаги §3 по порядку).
pub fn tick_items(items: &mut ItemStore, w: &impl ItemWorld, reg: &Registry, rng: &mut Rng) {
    let n = items.len();                                   // снимок: новые — со следующего тика
    for i in 0..n {
        if items[i].removed { continue; }
        items[i].age += 1;
        items[i].tick_physics(w, rng);
        if items[i].removed { continue; }
        let moved = items[i].prev.floor_i() != items[i].pos.floor_i();
        if items[i].age % if moved { 2 } else { 40 } == 0 { try_merge(items, i, reg); }
        let it = &mut items[i];
        if it.removed { continue; }
        if it.item_age != NEVER_DESPAWN { it.item_age += 1; }
        it.spin_age += 1;
        it.update_water(w);                                // второй толчок потока (§4.4)
        if it.item_age >= DESPAWN { it.removed = true; }
        items.reindex(i);                                  // пространственный индекс
    }
    items.compact();
}

fn try_merge(items: &mut ItemStore, i: usize, reg: &Registry) {
    let max = reg.max_stack(items[i].stack.item);
    if !items[i].mergeable(max) { return; }
    let zone = items[i].aabb().expand(0.5, 0.0, 0.5);
    for j in items.overlapping(&zone) {                    // по номеру появления
        if j == i || !items[j].mergeable(max) { continue; }
        let (a, b) = (&items[i], &items[j]);
        if a.owner != b.owner || !a.stack.same_item_and_components(&b.stack)
            || a.stack.count as u16 + b.stack.count as u16 > max as u16 { continue; } // перелива нет
        let (dst, src) = if b.stack.count < a.stack.count { (i, j) } else { (j, i) }; // равные — берёт другой
        let (n, d, age) = (items[src].stack.count, items[src].pickup_delay, items[src].item_age);
        let t = &mut items[dst];
        t.stack.count += n; t.pickup_delay = t.pickup_delay.max(d); t.item_age = t.item_age.min(age);
        items[src].removed = true;                         // spin_age поглотителя не меняется
        if src == i { break; }
    }
}

/// Фаза 4: подбор (после сущностей — §5.6).
pub fn pickup(pl: &Player, inv: &mut PlayerInventory, items: &mut ItemStore, reg: &Registry, ev: &mut Vec<GameEvent>) {
    if pl.health <= 0.0 { return; }
    let zone = pl.aabb().expand(1.0, 0.5, 1.0);
    for i in items.overlapping(&zone) {
        let it = &mut items[i];
        if it.removed || it.pickup_delay != 0 || it.owner.is_some_and(|o| o != pl.id) { continue; }
        let before = it.stack;
        if inv.insert(&mut it.stack, reg) {                // ASP-08: порядок слотов, подскок 5, частично — тоже true
            ev.push(GameEvent::PickupAnim { snapshot: it.snapshot_with(before), to: pl.id });
            ev.push(GameEvent::Pop { pos: it.pos });       // 0.2, clamp(2 + 1.4(r1−r2), 0.5, 2)
            if it.stack.is_empty() { it.removed = true; }
        }
    }
}

// ---------- появление ----------
pub fn drop_from_block(ids: &mut u32, cell: IVec3, stack: ItemStack, rng: &mut Rng) -> ItemEntity {
    let r = |rng: &mut Rng| rng.f64() * 0.5 - 0.25;
    let p = DVec3::new(cell.x as f64 + 0.5 + r(rng), cell.y as f64 + 0.5 + r(rng) - ITEM_H / 2.0, cell.z as f64 + 0.5 + r(rng));
    let mut e = ItemEntity::new(next(ids), p, stack, rng);
    e.pickup_delay = DELAY_BLOCK;
    e
}

pub enum Throw { Forward, Random }
pub fn throw_from_player(ids: &mut u32, pl: &Player, stack: ItemStack, how: Throw, owned: bool, rng: &mut Rng) -> ItemEntity {
    let p = DVec3::new(pl.pos.x, pl.eye_y() - 0.3f32 as f64, pl.pos.z);
    let mut e = ItemEntity::new(next(ids), p, stack, rng);     // скорость конструктора затем заменяется
    e.pickup_delay = DELAY_THROWN;
    if owned { e.thrower = Some(pl.id); }
    e.vel = match how {
        Throw::Random => {
            let f = rng.f32() * 0.5; let g = rng.f32() * std::f32::consts::TAU;
            DVec3::new((-g.sin() * f) as f64, 0.2f32 as f64, (g.cos() * f) as f64)
        }
        Throw::Forward => {                                    // всё во float, как в Java
            let (sp, cp) = (pl.pitch_rad().sin(), pl.pitch_rad().cos());
            let (sy, cy) = (pl.yaw_rad().sin(), pl.yaw_rad().cos());
            let k = rng.f32() * std::f32::consts::TAU; let l = 0.02 * rng.f32();
            let vy = -sp * 0.3 + 0.1 + (rng.f32() - rng.f32()) * 0.1;
            DVec3::new((-sy * cp * 0.3) as f64 + (k as f64).cos() * l as f64, vy as f64,
                       (cy * cp * 0.3) as f64 + (k as f64).sin() * l as f64)
        }
    };
    e
}

/// Содержимое сундука/печи (ItemScatterer): одна точка на ячейку, куски 10–30, без задержки.
pub fn scatter(ids: &mut u32, cell: IVec3, mut stack: ItemStack, rng: &mut Rng, out: &mut Vec<ItemEntity>) {
    let p = DVec3::new(cell.x as f64 + rng.f64() * 0.75 + 0.125, cell.y as f64 + rng.f64() * 0.75,
                       cell.z as f64 + rng.f64() * 0.75 + 0.125);
    let tri = |rng: &mut Rng, m: f64| m + 0.11485000171139836 * (rng.f64() - rng.f64());
    while !stack.is_empty() {
        let part = stack.split(rng.below(21) as u8 + 10);
        let mut e = ItemEntity::new(next(ids), p, part, rng);
        e.vel = DVec3::new(tri(rng, 0.0), tri(rng, 0.2), tri(rng, 0.0));
        out.push(e);                                           // pickup_delay = 0
    }
}

## 15. Рендер на нашей стороне (JS, WebGL2): предложение

1. **Модели** при старте:
   - **куб**: единичный меш 24 вершины, номер слоя текстуры на грань (верх, бок, низ — из реестра блоков; бревно —
     `cube_column`);
   - **особые**: кактус (бока на 1/16 внутрь), снежный слой 2/16, сундук — свой маленький меш;
   - **экструзия** для каждого плоского предмета — меш из `extrude` (ASP-11 §11.3, Rust) по альфа-маске спрайта из массива
     спрайтов предметов (`TEXTURE_2D_ARRAY` 16×16, ASP-11 §9.1 E8). Все меши — в один VBO со смещениями, ≤ 66 квадов на
     предмет.
   - Это общий модуль моделей: рука (ASP-11), предмет на земле, иконки блоков в атласе (ASP-08). Различается только
     трансформ `display`.
2. **Инстансинг**: раз в кадр Rust отдаёт `ItemsView` (§13), JS:
   - считает `lerp(prev, pos, alpha)` в f64 → смещение от камеры в f32, `angle`, `bob` (§8.1);
   - отсекает по дальности (предлагаю 24 блока, как ваниль при 12 кусках; настройка до 40) и пирамиде;
   - разворачивает копии (до 5, смещения по `seed = item_id + износ`, §8.3) в инстансы
     `{center: vec3, angle: f32, copy_off: vec3, model: u16, light: u8×2}`.
   Один `drawElementsInstanced` на модель. Сотня предметов — меньше 0.1 мс.
3. **Проход**: вместе с непрозрачным миром, отсечение по альфе 0.1 (как `entity_cutout`), запись глубины. Тот же
   проход для «летящих» копий анимации подбора: позиция `lerp(f, from, target)`, `f = ((t + alpha)/3)²`.
4. **Свет** (решение §17). Яркость в точке предмета — как принято для руки (ASP-11, до ASP-14): небо(время суток) ×
   видимость солнца из карты теней в центре предмета (1 выборка PCF на инстанс) + рассеянное небо. С ASP-14 —
   уровни неба и блока в клетке `y + 0.2125`. Затенение граней:
   - вариант А (рекомендую) — по нашему солнцу: `ndl` нормали грани и полусфера неба, как у блоков. Вращение само даёт
     «переливы»;
   - вариант Б — классика Minecraft: `min(1, 0.6·(L0·n⁺ + L1·n⁺) + 0.4)` (§8.5), отладочный режим.
5. **Тень**: кружок-декаль радиуса 0.15 под предметом, `0.75·(1 − d²/256)`, как в ванили. Или запись в ближний каскад
   теней — у куба 0.25 тень там почти невидима. Начать с кружка (P2).
6. **SSAO, пост**: предметы пишут нормаль и глубину как блоки, чтобы SSAO не «съел» их и не дал ореол. Проверить на
   скриншоте.
