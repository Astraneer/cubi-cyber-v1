## 0. Главное

1. **Закрытие окна с вещью в курсоре: вещь возвращается в инвентарь**, а не падает. На земле она оказывается только
   если в инвентаре нет места. Так же возвращается содержимое сетки 2×2: сначала курсор, потом клетки 0, 1, 2, 3.
   Сценарий в `checklist.md` (ASP-08, «он падает передо мной») и `catalog.md` INV-09 написаны неверно, их нужно
   поправить. [src] `ScreenHandler.onClosed` → `PlayerInventory.offerOrDrop`; `PlayerScreenHandler.onClosed` → `dropInventory`.
2. **Подобранный предмет сначала докладывается в выбранный слот, но только если там уже лежит такой же предмет и есть
   место.** Дальше идёт вторая рука, потом слоты 0…35 по порядку. Новый стек ложится в **первую пустую клетку по
   индексу**: хотбар слева направо, потом рюкзак. Выбранный слот для нового стека не важен.
   [src] `PlayerInventory.getOccupiedSlotWithRoomForStack`, `getEmptySlot`.
3. Действия ЛКМ и ПКМ срабатывают в **разные моменты**. При пустом курсоре — по **нажатию**. Если в курсоре что-то есть —
   по **отпусканию**: нажатие только начинает возможное перетаскивание. [src] `HandledScreen.mouseClicked/mouseReleased`.
4. Перетаскивание (QUICK_CRAFT) отдаёт каждой ячейке `floor(n/N)`, остаток остаётся в курсоре. Ячеек можно набрать
   **не больше, чем предметов в курсоре**. **Полный стек того же предмета тоже считается ячейкой** и забирает свою
   долю: он ничего не получает, но остальным достаётся меньше. Если ячейка одна, перетаскивание превращается в обычный клик.
5. Двойной клик (PICKUP_ALL, 250 мс, та же кнопка и тот же слот) собирает предметы в **два прохода с индекса 0**.
   Первый проход берёт неполные стеки, второй — полные. В этот порядок входит **сетка крафта**, слот результата
   пропускается. Работает, только если после первого клика курсор не пуст, а слот под ним пуст.
6. Shift-клик результата крафта кладёт его в хотбар **справа налево**, затем в рюкзак снизу вверх. Крафт повторяется,
   пока в слоте результата тот же предмет. Если результат влез частично, остаток **выбрасывается на землю**. Из сундука
   вещи тоже идут в хотбар справа налево. [src] `insertItem(…, fromLast=true)`.
7. Броня: слот принимает только свой тип (`getPreferredEquipmentSlot`), вмещает 1 предмет. Shift-клик брони из
   рюкзака или хотбара надевает её, только если **именно этот** слот брони пуст. Иначе предмет идёт обычным путём
   рюкзак ↔ хотбар.
8. У ПКМ, Q и Ctrl+Q на результате крафта нет «половины» и «одного»: берётся или выбрасывается **весь** результат одного
   крафта. [src] `CraftingResultInventory.removeStack` игнорирует количество.
9. Клик одинаковым неделимым предметом по такому же (две целые деревянные кирки) **ничего не делает**: обмена нет.
   Две кирки с разным износом меняются местами.
10. Колесо листает хотбар **на один слот за событие**. Вверх — влево, вниз — вправо, по кругу. Внутри окна колесо
    ничего не делает. Клавиши 1–9 в мире срабатывают в тике, колесо — сразу в кадре.

### 1.1 ItemStack [src] `item/ItemStack`, `item/Item`

| Что | Как в 1.21.1 |
|---|---|
| Пустой | `this == EMPTY` или предмет AIR или `count <= 0`. `getCount()` у пустого — 0, `getItem()` — AIR. |
| Предел стека | компонент `max_stack_size`; у обычного предмета по умолчанию 64 (`Item.DEFAULT_MAX_COUNT`). Абсолютный потолок — 99 (`MAX_MAX_COUNT`). У предмета с прочностью (`Settings.maxDamage`) предел 1, `damage = 0`. Пустое ведро — 16 [вики, сверить в ASP-06]. |
| Предел слота | `Slot.getMaxItemCount(stack) = min(inventory.getMaxCountPerStack() = 99, stack.max)`. Для слота брони — `min(1, …)`. |
| Складываемость `isStackable` | `max > 1` и (нет прочности или износ 0). Изношенный предмет не складывается. |

| `copyWithCount(n)` | копия с другим числом (у пустого — EMPTY). |
| «Тот же предмет» для сложения `areItemsAndComponentsEqual` | тот же Item и **равные карты компонентов** (износ, имя, чары…). Два пустых равны. |
| `areItemsEqual` | только Item, без компонентов. На нём держится условие цикла Shift-клика (§2.2). |
| `areEqual` | то же плюс равное количество. Используется для синхронизации. |
| Полоска прочности видна | `isDamaged()`: есть прочность и `damage > 0`. |
| Анимация «подскока» | поле `bobbingAnimationTime`. Его ставит в 5 `PlayerInventory.addStack` / `insertStack`, `inventoryTick` уменьшает на 1 за тик. |

У нас из компонентов пока нужен только **износ** (`damage`). Имя, чары и прочее — потом. Равенство компонентов =
равенство всех хранимых полей стека, кроме количества.

### 1.2 PlayerInventory [src] `entity/player/PlayerInventory`

Индексы «плоского» инвентаря (`getStack(i)`, `setStack(i)`):

| Индекс | Что |
|---|---|
| 0–8 | хотбар (`main[0..9]`), `selectedSlot` 0–8 |
| 9–35 | рюкзак 3×9 (`main[9..36]`), ряды сверху вниз: 9–17, 18–26, 27–35 |
| 36–39 | броня: 36 ноги (FEET), 37 поножи (LEGS), 38 грудь (CHEST), 39 голова (HEAD) = `36 + EquipmentSlot.entitySlotId` |
| 40 | вторая рука (`OFF_HAND_SLOT`) |

Методы и порядок:
- `getEmptySlot()` — первая пустая из `main[0..36]` (хотбар, потом рюкзак). Броня и вторая рука в поиск не входят.
- `getOccupiedSlotWithRoomForStack(s)` — где уже лежит такой же предмет и есть место. Порядок: **выбранный слот → 40 (вторая
  рука) → main 0…35**. Условие `canStackAddMore`: не пусто, тот же предмет, складываемый, `count < min(99, max)`.
- `addStack(s)` — один шаг: занятый слот с местом, иначе пустой. Кладёт `min(остаток, место)`, ставит подскок 5.
- `insertStack(s)` (подбор с земли, возврат при обмене): пустой стек → false.
  - **Изношенный** предмет — только в пустую клетку `main`, целиком. Нет места → false (в креативе предмет исчезает).
  - Иначе `addStack` повторяется, пока стек уменьшается. Возвращает «уменьшился ли» — при частичном подборе это true.
- `offerOrDrop(s)` = `offer(s, true)`: в цикле занятый слот с местом или пустой. Места нет — `dropItem(s, false)` (бросок
  вперёд, без владельца) и выход. Иначе туда кладётся `split(max − уже_лежит)`.
- `dropSelectedItem(all)` — из выбранного слота 1 штука или весь стек.
- `scrollInHotbar(a)`: `selected -= signum(a)`, затем по модулю 9. Шаг всегда 1, сколько бы ни пришло.
- `getSwappableHotbarSlot()` — для «средней кнопки» (PLC-04): первая пустая клетка хотбара начиная с выбранной, иначе
  первая без чар, иначе выбранная. В выживании средняя кнопка ищет предмет в инвентаре — это ASP-05.
- `dropAll()` при смерти: main, броня, вторая рука, каждый стек `dropItem(…, throwRandomly=true)` (ASP-12).

### 1.3 Slot и его варианты [src] `screen/slot/*`

Слот — описание «ячейка `index` такого-то хранилища, нарисована в точке (x, y) окна». Сам он вещи не хранит.

| Метод | Slot (обычный) | ArmorSlot | CraftingResultSlot | Вторая рука (анонимный, слот 45) |
|---|---|---|---|---|
| `canInsert(s)` | true | `slotType == getPreferredEquipmentSlot(s)` | **false** | true |
| `canTakeItems(p)` | true | true (кроме «проклятия несъёмности», у нас нет) | true | true |
| `getMaxItemCount()` | 99 (через инвентарь) | **1** | 99 | 99 |
| `canTakePartial(p)` | canTake && canInsert(свой стек) | так же | **false** → брать можно только целиком | так же |
| `takeStack(n)` | `inventory.removeStack(i, n)` | так же | **забирает весь стек**, n игнорируется | так же |
| `onTakeItem` | `markDirty` | так же | крафт: −1 из каждой непустой клетки, остатки (ведро) — ASP-09 | так же |
| `setStack` | запись + `markDirty` | + `onEquipStack` (звук надевания) | запись | + `onEquipStack(OFFHAND)` |
| Фон пустого | нет | силуэт шлема/нагрудника/поножей/ботинок | нет | силуэт щита |

Служебные пути Slot, на которых держатся действия:
- `insertStack(s, n)`: если `canInsert` — кладёт `min(n, s.count, предел − уже)`. В пустой слот — `setStack(s.split(k))`,
  в такой же — сложение. Возвращает остаток (тот же объект).
- `tryTakeStackRange(min, max)`: нельзя брать → пусто. Нельзя брать частично и `max < count` → пусто. Иначе
  `takeStack(min(min, max))`. Если слот опустел — `setStack(EMPTY)`.
- `takeStackRange(min, max)` = `tryTakeStackRange` + `onTakeItem`.

### 1.4 ScreenHandler (контейнер окна) [src] `screen/ScreenHandler`

Состояние: список слотов (`slots`, `id` = порядковый номер), **курсорный стек** `cursorStack` (не принадлежит ни одному
слоту), состояние перетаскивания `quickCraftStage` (0/1/2), `quickCraftButton` (0/1/2), `quickCraftSlots` (множество).

Общие функции:
- `insertItem(stack, start, end, fromLast)` — перекладывает стек в слоты `[start, end)`:
  1. Проход сложения, только если стек складываемый: по порядку (или с конца) в каждый слот с тем же предметом, до
     `slot.getMaxItemCount(уже_лежащий)`. `canInsert` здесь **не проверяется**.
  2. Если что-то осталось — проход по пустым в том же направлении: **первый** пустой слот с `canInsert` получает
     `min(остаток, предел)`, и проход **останавливается** (`break`).
  3. Возвращает «что-нибудь переложено».
- `canInsertItemIntoSlot(slot, s, allowOverflow)` — «можно ли кинуть сюда при перетаскивании». Пустой (или null) — да.
  Тот же предмет — `уже + (allowOverflow ? 0 : s.count) ≤ s.max`. С `allowOverflow = true` **полный стек проходит**.
  Чужой предмет — нет.
- `calculateStackSize(slots, mode, s)`: режим 0 → `floor(s.count / N)`, 1 → 1, 2 → `s.max`.
- `canInsertIntoSlot(s, slot)` — переопределяется. Игрок: false для результата крафта. Сундук: true.
- `onClosed(player)` — §4.

## 2. Действия: `onSlotClick(slot, button, action)` по шагам

Внешний метод только оборачивает `internalOnSlotClick` в отчёт о падении. Все ветки — внутри [src]
`ScreenHandler.internalOnSlotClick`. Особые номера слотов: **−999** — клик вне окна, **−1** — не по слоту.

### 2.0 Диспетчер (порядок проверок)
1. `action == QUICK_CRAFT` → §2.6.
2. Иначе, если перетаскивание не закончено (`quickCraftStage != 0`) → сбросить его, **само действие отбросить**.
3. PICKUP или QUICK_MOVE с кнопкой 0/1 → §2.1 / §2.2. Слот −999 обрабатывается первым и для обоих: Shift-клик вне окна
   с вещью тоже выбрасывает.
4. SWAP с кнопкой 0–8 или 40 → §2.3.
5. CLONE, если креатив, курсор пуст и слот ≥ 0 → §2.4.
6. THROW, если **курсор пуст** и слот ≥ 0 → §2.5.
7. PICKUP_ALL, если слот ≥ 0 → §2.7.

### 2.1 PICKUP (ЛКМ = кнопка 0, ПКМ = кнопка 1)
Слот −999 (вне окна): если в курсоре что-то есть — ЛКМ выбрасывает весь курсор, ПКМ — `split(1)`, то есть одну штуку.
Бросок `dropItem(…, retainOwnership=true)` — вперёд по взгляду, задержка подбора 40 тиков (ASP-07).

Слот < 0, но не −999 → ничего. Иначе обозначим S = стек слота, C = курсор:
1. Хук `onPickupSlotClick` (обучение) и хуки предметов-контейнеров (`onStackClicked`/`onClicked`, мешок). У нас
   их нет, ветка не срабатывает.
2. **S пуст:** если C не пуст — `C = slot.insertStack(C, ЛКМ ? C.count : 1)`. Сколько влезет: для брони — только
   свой тип и 1 штука; в результат — ничего.
3. **S не пуст и `canTakeItems`:**
   - C пуст → взять `ЛКМ ? S.count : (S.count + 1) / 2` (половина **с округлением вверх**: 64→32, 63→32 и 31 в слоте,
     1→1) через `tryTakeStackRange(n, ∞)`. Результат → C, затем `onTakeItem` (у результата крафта — расход сетки).
   - C не пуст и `slot.canInsert(C)`:
     - тот же предмет (с компонентами) → `insertStack(C, ЛКМ ? C.count : 1)`, сложение до предела слота;
     - иначе, если `C.count ≤ slot.getMaxItemCount(C)` → **обмен** S ↔ C. ПКМ тоже меняет местами.
     - иначе ничего (например, пачка не влезает в слот с пределом 1).
   - C не пуст и `canInsert` = false (результат крафта): если тот же предмет —
     `tryTakeStackRange(S.count, C.max − C.count)`. Результат берётся только целиком: не влезает → ничего.
     Влезает → C += S, `onTakeItem`.
4. S не пуст, но брать нельзя → ничего.
5. `slot.markDirty()`.

Важное следствие: тот же предмет с пределом 1 (две целые кирки) попадает в ветку сложения. Добавить можно
`min(1, 1 − 1) = 0`, поэтому **ничего не происходит**, и обмена нет.

### 2.2 QUICK_MOVE (Shift + ЛКМ/ПКМ)
1. Слот −999 → как PICKUP вне окна (§2.1).
2. Слот < 0 → ничего. `!slot.canTakeItems` → ничего.
3. `r = quickMove(slot)` (таблицы §1.5, §1.6). Пока `r` не пуст и **в слоте лежит тот же Item** (`areItemsEqual`, без
   компонентов) — снова `quickMove`. Цикл нужен для крафта «до упора»: после каждого `onTakeItem` в результате появляется
   новый предмет. Обычный слот после переноса пустеет, или следующий `insertItem` не находит места и возвращает EMPTY.
4. Кнопка (ЛКМ/ПКМ) на результат не влияет.

### 2.3 SWAP (цифры 1–9 → кнопка 0–8, F → кнопка 40)
H = `PlayerInventory.getStack(button)` — **ячейка инвентаря**, а не экранный слот. S = стек экранного слота.
1. Оба пусты → ничего.
2. H пуст, S нет → если `canTakeItems`: H ← S, `slot.onTake(count)`, слот пуст, `onTakeItem`. С результатом крафта
   это работает: результат уходит в хотбар, сетка тратится.
3. S пуст, H нет → если `canInsert(H)`: если `H.count > предел слота` — в слот уходит `H.split(предел)`, остальное
   остаётся (тыква в шлем). Иначе H целиком переходит в слот.
4. Оба не пусты → если `canTakeItems` и `canInsert(H)`: если H больше предела — в слот `H.split(предел)`, а старый S
   идёт в `insertStack` (не влез — бросок). Иначе простой обмен, `onTakeItem(S)`.
   На результат крафта с непустой ячейкой хотбара — ничего (`canInsert` = false).
5. Наведение на хотбарный слот и нажатие его же цифры — обмен с самим собой, ничего не меняется.

### 2.4 CLONE (средняя кнопка) — **только креатив**
Курсор пуст, в слоте что-то есть → курсор = копия с `max` штук. В выживании клиент шлёт CLONE по клавише выбора блока
(§2.8), сервер игнорирует. **Нам не нужно.**

### 2.5 THROW (Q / Ctrl+Q над слотом, ЛКМ вне окна при пустом курсоре)
Только если курсор пуст и слот ≥ 0: `n = button==0 ? 1 : S.count`, `takeStackRange(n, ∞)` → бросок вперёд с владельцем.
- Q — одна штука, Ctrl+Q — весь стек.
- На результате крафта и Q, и Ctrl+Q выбрасывают **весь результат одного крафта** и тратят сетку один раз.
- С вещью в курсоре Q не делает ничего.
- Клик вне окна с пустым курсором: клиент шлёт THROW со слотом −999, сервер отбрасывает (слот < 0). Ничего.

### 2.6 QUICK_CRAFT — перетаскивание
Кнопка упакована: `button = stage | mode << 2`. Стадии: 0 начало, 1 добавить слот, 2 конец. Режимы: 0 ЛКМ поровну,
1 ПКМ по одному, 2 СКМ полными стеками (только креатив).

Переход стадий: новая стадия должна совпадать с прежней или быть переходом 1→2, иначе сброс. Если курсор пуст — сброс.
- **Стадия 0**: режим запоминается. Режим 2 вне креатива → сброс. Иначе стадия = 1, множество ячеек очищается.
- **Стадия 1** (по одному пакету на слот): слот добавляется, если
  `canInsertItemIntoSlot(slot, C, true)` (пусто, или тот же предмет и **не переполнен**: полный стек подходит),
  `slot.canInsert(C)` (броня — только свой тип, результат — нет), `режим == 2 || C.count > число_уже_выбранных`,
  `canInsertIntoSlot(slot)`. Множество без повторов.
- **Стадия 2**:
  - ячеек 0 → сброс, ничего;
  - ячеек 1 → сброс и **обычный PICKUP по этой ячейке** с той же кнопкой (ЛКМ — всё, ПКМ — одну);
  - иначе: `orig = C.copy()`, `k = C.count`. Для каждой ячейки (условия стадии 1, но `C.count ≥ N`):
    `l` = сколько уже лежит, `m = min(orig.max, slot.getMaxItemCount(orig))`,
    `n = min(calculateStackSize(N, режим, orig) + l, m)`. В ячейку пишется `orig` с числом n, `k −= n − l`.
    Потом курсор = `orig` с числом k: 0 → пусто, в креативе может уйти в минус и тоже считается пустым.
  - Порядок обхода множества (HashSet) **на результат не влияет**: доля считается от исходного числа `orig.count`,
    а условие проверяет неизменный курсор.

Формула остатка (режим 0): `остаток = count − Σ_i (min(floor(count/N) + l_i, m) − l_i)`.

### 2.7 PICKUP_ALL (двойной клик)
Только если курсор C не пуст и слот (нажатый второй раз) **пуст** или из него нельзя брать.
1. Направление: кнопка 0 → с id 0 вперёд, иначе с последнего назад. Клиент шлёт только кнопку 0.
2. Проход 0 — только **неполные** стеки (`count != max`), проход 1 — любые.
3. Подходит слот, если в нём есть стек, `canInsertItemIntoSlot(slot, C, true)` (тот же предмет), `canTakeItems` и
   `canInsertIntoSlot(C, slot)` (у игрока — не результат).
4. Из каждого такого слота берётся `takeStackRange(S.count, C.max − C.count)` — можно частично. C растёт. Как только
   `C.count == C.max`, проходы кончаются.
5. В окне игрока порядок такой: сетка 1–4 → броня → рюкзак 9–35 → хотбар 36–44 → вторая рука. В сундуке: сундук 0–26 →
   рюкзак → хотбар. Брони это не касается: у неё предел 1, курсор с бронёй уже «полон».

### 2.8 Клиент: как мышь и клавиши превращаются в действия [src] `HandledScreen`

Нажатие кнопки (`mouseClicked`):
1. Сначала виджеты окна (кнопка книги рецептов). Обработали — больше ничего.
2. `doubleClicking = тот же слот (может быть null) && прошло < 250 мс && та же кнопка`.
3. Кнопка не ЛКМ/ПКМ (и не СКМ в креативе) → только «цифры и F, назначенные на кнопки мыши». По умолчанию таких нет,
   значит ничего.
4. `k` = id слота под мышью или −1. Если мышь вне прямоугольника окна → −999.
5. Если `k != −1` и перетаскивания ещё нет:
   - **курсор пуст** → действие сразу. Shift (и не −999) → QUICK_MOVE, при этом запоминается копия стека слота
     (`quickMovingStack`). −999 → THROW. Иначе PICKUP. Затем «отпускание не обрабатывать» (`cancelNextRelease`).
   - **курсор не пуст** → начинается перетаскивание: `cursorDragging = true`, запоминаются кнопка и режим (0/1/2), множество
     ячеек очищается. **Ничего не отправляется.**
6. Запоминаются слот, время и кнопка для двойного клика.

Движение с зажатой кнопкой (`mouseDragged`), если идёт перетаскивание: слот под мышью добавляется в множество при тех же
условиях, что в стадии 1. Остаток для курсора пересчитывается (`calculateOffset`).

Отпускание (`mouseReleased`), `k` — как при нажатии:
1. Если `doubleClicking`, слот есть, кнопка ЛКМ и `canInsertIntoSlot(EMPTY, slot)` (не результат):
   - с Shift: если `quickMovingStack` не пуст — QUICK_MOVE **по каждому** слоту того же хранилища, что и нажатый:
     можно брать, есть стек, тот же предмет;
   - без Shift: PICKUP_ALL по нажатому слоту.
   Затем двойной клик сбрасывается, время = 0.
2. Иначе:
   - отпущена **другая** кнопка, чем начала перетаскивание → перетаскивание отменяется, ничего не делается.
     Значит, ПКМ во время ЛКМ-перетаскивания его отменяет;
   - `cancelNextRelease` → ничего (отпускание после действия «по нажатию»);
   - есть перетаскивание и множество не пусто → три вида пакетов QUICK_CRAFT: стадия 0, по стадии 1 на каждый слот,
     стадия 2;
   - иначе, если курсор не пуст: Shift (и не −999) → QUICK_MOVE по слоту под мышью (переносится **стек слота**, курсор
     остаётся), иначе PICKUP по `k`. Если мышь не над слотом и не вне окна (`k = −1`), выйдет PICKUP(−1), то есть ничего.
3. Если курсор после этого пуст — время клика = 0. После клика, который опустошил курсор, двойной клик невозможен.
4. `cursorDragging = false`.

Клавиши в окне (`keyPressed`; автоповтор ОС тоже вызывает его, [src] `Keyboard.onKey` action 1 и 2):
1. Esc → закрыть. Клавиша инвентаря (E) → закрыть.
2. Курсор пуст и есть слот под мышью: F → SWAP 40; цифра i → SWAP i.
3. Под мышью **непустой** слот: клавиша выбора блока (если она на клавиатуре) → CLONE. Q → THROW
   (`Ctrl ? 1 : 0`).
4. Окно забирает все клавиши: ходьба, хотбар и прочее при открытом окне не работают. При открытии вызывается
   `KeyBinding.unpressAll()`, все удержания сброшены [src] `MinecraftClient.setScreen`.
5. Колесо в окне инвентаря/сундука ничего не делает: `HandledScreen` не переопределяет `mouseScrolled`.

## 3. Таблица действий (кнопка × курсор × слот → результат)

C — курсор, S — слот. «Тот же» — тот же предмет с теми же компонентами.

| Ввод | C | S | Результат |
|---|---|---|---|
| ЛКМ (нажатие) | пуст | пуст | ничего |
| ЛКМ (нажатие) | пуст | n | C = n, S пуст |
| ПКМ (нажатие) | пуст | n | C = ⌈n/2⌉, S = ⌊n/2⌋ |
| ЛКМ (отпуск) | c | пуст | S = min(c, предел), C = остаток |
| ПКМ (отпуск) | c | пуст | S = 1, C = c − 1 |
| ЛКМ (отпуск) | c | тот же n | S = min(n + c, предел), C = остаток |
| ПКМ (отпуск) | c | тот же n < предела | S = n + 1, C = c − 1 |
| ЛКМ/ПКМ (отпуск) | c | другой | обмен, если c ≤ предела слота, иначе ничего |
| ЛКМ/ПКМ (отпуск) | неделимый X | такой же X | ничего |
| ЛКМ/ПКМ (нажатие) | пуст | результат r | C = r целиком, сетка −1 |
| ЛКМ/ПКМ (отпуск) | тот же, c + r ≤ max | результат r | C = c + r, сетка −1 |
| ЛКМ/ПКМ (отпуск) | тот же, не влезает / другой | результат | ничего |
| любой | не броня / чужой тип | слот брони | ничего (если S не пуст и C не броня этого типа) |
| Shift+ЛКМ/ПКМ | любой | n | quickMove по §1.5/§1.6, курсор не трогается |
| ЛКМ (отпуск) вне окна | c | — | бросить c |
| ПКМ (отпуск) вне окна | c | — | бросить 1 |
| ЛКМ/ПКМ вне окна | пуст | — | ничего |
| клик по фону окна | любой | — | ничего |
| ЛКМ-тяга по N ячейкам | c | пустые/тот же | каждой ⌊c/N⌋ (с потолком), остаток в C, N ≤ c |
| ПКМ-тяга по N ячейкам | c | пустые/тот же | каждой +1, C = c − N, N ≤ c |
| тяга по одной ячейке | c | — | обычный клик ЛКМ/ПКМ по ней |
| двойной ЛКМ | после 1-го клика C ≠ ∅, S = ∅ | — | собрать в C до max (§2.7) |
| Shift + двойной ЛКМ | — | — | QUICK_MOVE всех таких же в том же хранилище (§2.8) |
| 1–9 над слотом | пуст | любой | SWAP с хотбаром i (§2.3) |
| 1–9 / F над слотом | не пуст | — | ничего |
| F над слотом | пуст | любой | SWAP со второй рукой |
| Q над слотом | пуст | n | бросить 1 (на результате — весь результат) |
| Ctrl+Q над слотом | пуст | n | бросить n |
| Q | не пуст | — | ничего |
| колесо | любой | — | ничего |
| СКМ | — | — | ничего (CLONE — креатив) |
| E, Esc | любой | — | закрыть (§4) |

## 4. Закрытие окна, смерть, разрыв дальности

Порядок при закрытии [src] `ClientPlayerEntity.closeHandledScreen` → `ServerPlayerEntity.onHandledScreenClosed` →
`currentScreenHandler.onClosed(player)`:
1. **Курсор:** если игрок жив и в игре — `offerOrDrop(cursor)`: тот же порядок, что при подборе (§1.2). Иначе
   `dropItem(cursor, false)`. Курсор очищается.
2. Окно игрока: результат крафта очищается (это не вещь, а «предложение»). Сетка 2×2 возвращается по клетке 0…3:
   жив — `offerOrDrop`, мёртв или вышел — `dropItem`. **Место ищется заново**, вещь не обязательно попадёт в ту же ячейку.
3. Сундук: курсор возвращается так же. `inventory.onClose` уменьшает счётчик смотрящих (звук закрытия при нуле, крышка).
   Содержимое сундука остаётся в нём.
4. Текущим окном снова становится окно игрока. Курсор мыши захватывается.

Когда окно закрывается само:
- игрок умер: `HandledScreen.tick` → `closeHandledScreen`, курсор и сетка падают, а не возвращаются (ASP-12);
- сундук дальше 8.5 блока (по коробке блока от глаз) или сломан — серверный тик, §1.6;
- открытие другого окна сначала закрывает текущее.

## 5. Хотбар и клавиши в мире

| Ввод | Что [src] | Когда |
|---|---|---|
| Колесо | `Mouse.onMouseScroll`: накопитель с обнулением при смене знака, целая часть → `scrollInHotbar(k)` → шаг ±1. Вверх (+) — слот −1 (влево), вниз — +1 (вправо), по кругу 0↔8. `mouseWheelSensitivity` 1.0, `discreteMouseScroll` false — по умолчанию. | сразу в событии (кадр) |
| 1–9 | `handleInputEvents`: `if (hotbarKeys[i].wasPressed()) selectedSlot = i`. Одно срабатывание за тик на клавишу. | в тике |
| Q / Ctrl+Q | `while (dropKey.wasPressed())` → `dropSelectedItem(Ctrl)` → если что-то выпало — взмах руки. Удержание Q с автоповтором ОС выбрасывает по штуке на каждый повтор. | в тике, все накопленные нажатия |
| F | пакет `SWAP_ITEM_WITH_OFFHAND`: обмен главной и второй руки, использование прерывается | в тике |
| E | открыть `InventoryScreen` (в креативе — креативный экран) | в тике |

Смена выбранного слота:
- **во время использования** (еда, лук): сервер при смене индекса и активной главной руке вызывает `clearActiveItem`, то есть
  использование прерывается [src] `ServerPlayNetworkHandler.onUpdateSelectedSlot`. Клиент дополнительно прерывает, если
  предмет в руке стал другим (`LivingEntity.tickActiveItemStack`). Для нас: **любая смена индекса прерывает
  использование**;
- **во время ломания:** если новый предмет в руке не совпадает с запомненным (предмет + компоненты), ломание начинается
  заново [src] `ClientPlayerInteractionManager.isCurrentlyBreaking`. Переключение на такой же стек (земля → земля в другом
  слоте, две одинаковые целые кирки) прогресс **не сбрасывает**;
- анимация «опустить/поднять» предмет в руке — ASP-11;
- имя предмета над хотбаром (HUD-03) [src] `InGameHud.tick`: если в руке пусто — 0. Если предмет или его имя
  отличается от прошлого тика — `fade = 40 × notificationDisplayTime (1.0)`. Иначе −1 за тик. Переключение между двумя
  слотами с одинаковым предметом имя **не показывает**. Прозрачность `min(255, fade·256/10)`: 30 тиков полностью,
  10 тиков затухает. Позиция по центру, `y = H − 59` (в выживании, +14 без полосок), белый с тенью, фон по умолчанию
  выключен (`backgroundForChatOnly`).

Подбор с земли (подробно — ASP-07): `ItemEntity` → `insertStack`. Порядок мест — §1.2, частичный подбор разрешён.
Иконка, куда легла вещь, подскакивает 5 тиков (§6.4).

Захват мыши: открытие окна отпускает курсор и ставит его **в центр окна**, закрытие — захватывает [src]
`Mouse.unlockCursor/lockCursor`. Клик, которым захватили мышь, **не бьёт**: `lockCursor` ставит `attackCooldown = 10000`,
и он обнуляется только после отпускания ЛКМ [src] `MinecraftClient.handleBlockBreaking`. Пока окно открыто, мир **не на
паузе** (`HandledScreen.shouldPause = false`).

## 6. Отрисовка (клиентские мелочи)

### 6.1 Масштаб GUI [src] `Window.calculateScaleFactor`, `setScaleFactor`
Авто (`guiScale = 0`): начиная с 1, масштаб растёт, пока `fbW / (i+1) ≥ 320` и `fbH / (i+1) ≥ 240` (целочисленное деление).
Ручное значение ограничено тем же максимумом. Размер в GUI-пикселях — `ceil(fb / scale)`.
1920×1080 → 4 (480×270); 1366×768 → 3; 1280×720 → 3; 2560×1440 → 6; 3840×2160 → 9; 800×600 → 2.
Координаты мыши в GUI: `x · scaledW / windowW`, дробные.

### 6.2 Раскладка окна
- Окно в центре: `x = (W − 176) / 2`, `y = (H − 166) / 2` (целочисленно). Книгу рецептов не берём (§14), она сдвигала бы `x`.
- Фон экрана: вертикальный градиент `0xC0101010` → `0xD0101010` поверх мира [src] `Screen.renderInGameBackground`.
  У окон-контейнеров без размытия.
- Окно игрока (`inventory.png`, 176×166): рамки слотов 18×18 вокруг иконки (x−1, y−1). Кукла игрока — в рамке (26,8)–(75,78),
  размер 30. Она смотрит на мышь: корпус `180 + atan((cx − mx)/40)·20°`, голова — то же ·40°, наклон `−atan((cy − my)/40)·20°`
  [src] `InventoryScreen.drawEntity`. Заголовок «Создание» в (97, 6), 0x404040, без тени. Надписи «Инвентарь» в этом окне нет.
- Сундук — §1.6.
- Зона наведения слота — **18×18**: `[x−1, x+17) × [y−1, y+17)`. Между слотами мёртвых зон нет [src] `isPointWithinBounds`.
- «Вне окна» — вне прямоугольника фона. Клик в рамку окна мимо слота = −1, то есть ничего.

### 6.3 Слот и его содержимое [src] `HandledScreen.drawSlot`, `DrawContext.drawItemInSlot`
- Пустой слот с фоном — силуэт (броня, щит).
- Иконка 16×16 в (slot.x, slot.y). Блок рисуется 3D-моделью с трансформом `gui`: поворот [30, 225, 0], масштаб 0.625
  [data] `models/block/block.json`, свет «side». Плоский предмет — спрайт 16×16, свет «front» [data] `models/item/generated.json`.
  Модель масштабируется ×16 вокруг центра (x+8, y+8) [src] `DrawContext.drawItem`.
- **Число:** только если `count != 1`. Белое с тенью (тень = цвет ×0.25, сдвиг +1,+1 → 0x3F3F3F). Правый край у
  x+17: `x + 17 − ширина`, `y + 9`. У цифры ширина 6 (глиф 5 + 1) [data] шрифт `ascii.png`, высота строки 9.
  «64» начинается с x+5.
- **Полоска прочности** (если износ > 0): чёрный 13×2 в (x+2, y+13), поверх цветная `step×1` в верхнем ряду (y+13).
  `step = clamp(round(13 − damage·13/max), 0, 13)`; цвет: `f = (max − damage)/max`, `hsv(f/3, 1, 1)`. При f ≥ 0.5 зелёный
  255, красный `255·(2 − 2f)`; при f < 0.5 красный 255, зелёный `255·2f` (усечение к int) [src] `Item.getItemBarStep/Color`,
  `MathHelper.hsvToArgb`.
- **Подсветка под мышью:** белый 16×16 `0x80FFFFFF` поверх слота **после** иконки и числа, проверка глубины выключена, так
  что подсвечиваются и иконка, и число [src] `drawSlotHighlight` + порядок отрисовки; вид — [не проверено]. Подсветка есть
  и у пустого слота, и при вещи в курсоре.
- Предпросмотр перетаскивания (ячеек > 1): в каждой выбранной ячейке — курсорный предмет с будущим числом и белая
  заливка `0x80FFFFFF` под иконкой. Если упёрлось в предел — число **жёлтое** (= предел). Пока выбрана одна ячейка, она
  рисуется пустой.

### 6.4 Курсорный стек, тултип, хотбар
- Курсорный стек — над всем (z 232), центр в мыши: левый верх иконки = мышь − (8, 8). Системная стрелка видна поверх.
  При перетаскивании по ≥ 2 ячейкам число — остаток; остаток 0 — жёлтый «0».
- Тултип [src] `HandledScreen.drawMouseoverTooltip`, `DrawContext.drawTooltip`, `TooltipBackgroundRenderer`,
  `HoveredTooltipPositioner`. Показывается, только если **курсор пуст** и под мышью непустой слот.
  - Строки: имя (цвет редкости, у наших предметов белый). У инструментов и брони — пустая строка, «В ведущей руке:» (серый),
    «2 урона», «1.2 скорости атаки» (тёмно-зелёный). С F3+H — «Прочность: x / y», id, число компонентов (тёмно-серый).
  - Позиция: мышь + (12, −12). Вылезает вправо → `x = max(x − 24 − w, 4)`. Вниз → `y = H − h − 3`.
  - Высота строки 10, у одной строки h = 8. После первой строки +2. Белый текст с тенью.
  - Фон `0xF0100010` от (x−3, y−3) до (x+w+3, y+h+3) плюс однопиксельные полосы снаружи без углов. Рамка внутри:
    верх `0x505000FF`, низ `0x5028007F`, бока — градиент между ними.
- Хотбар HUD [src] `InGameHud.renderHotbar`:
  - полоса 182×22 в (W/2 − 91, H − 22), рамка выбора 24×23 в (W/2 − 92 + 20·sel, H − 23);
  - иконки в (W/2 − 88 + 20·i, H − 19);
  - вторая рука — ячейка 29×24 слева в (W/2 − 120, H − 23), иконка в (W/2 − 117, H − 19), только если там что-то есть;
  - подскок при подборе: `f = bob − tickDelta`, при f > 0 масштаб `(1/g, (g+1)/2)` вокруг (x+8, y+12), `g = 1 + f/5`.
    Сразу после подбора — (0.5, 1.5), за 5 тиков приходит к 1. Только в HUD, в окне подскока нет.
- Шрифт: растровый 8 px, подъём 7, интервал 9. Ширина глифа — по картинке + 1 [data] `font/include/default.json`.
  Кириллица — `nonlatin_european.png`. **Шрифт Mojang брать нельзя**, нужен свой (§12, §14).

## 7. Граничные случаи (что чувствует игрок)

1. ПКМ по стеку из 1 забирает его целиком. ПКМ по 63 даёт 32 в курсоре и 31 в слоте.
2. ПКМ с курсором по стеку того же предмета, который уже полон (64), — ничего. По другому предмету — обмен, как ЛКМ.
3. Обмен невозможен, если курсорная пачка больше предела слота: стек земли в слот брони не ставится вообще (canInsert).
4. Две одинаковые целые кирки (мечи, шлемы) друг на друга — ничего. С разным износом — обмен.
5. Изношенные инструменты никогда не складываются и при подборе ложатся только в пустую ячейку.
6. Перетаскивание:
   - со стеком 3 можно «зацепить» максимум 3 ячейки;
   - полный стек того же предмета считается ячейкой, но ничего не получает;
   - чужой предмет, результат и броня (для не-брони) не цепляются;
   - другая кнопка во время тяги отменяет её.
7. Двойной клик по слоту, куда сейчас что-то положили (курсор опустел), не срабатывает. Тройной клик не
   повторяет сбор (время обнуляется).
8. Двойной клик берёт и из сетки крафта, и тогда результат пересчитывается.
9. Shift-клик:
   - из рюкзака при полном хотбаре не делает ничего;
   - частично заполненный стек уходит частично, остаток остаётся на месте;
   - Shift-клик вне окна с вещью в курсоре выбрасывает её, как ЛКМ.
10. Shift-клик результата при почти полном инвентаре: последний частичный крафт выбрасывает излишек на землю.
11. Shift-клик брони, когда этот слот брони занят, — предмет уходит в хотбар или рюкзак, а не меняется местами.
12. Цифра над слотом результата при занятой ячейке хотбара — ничего. При пустой — результат в хотбар, сетка −1.
13. Q над результатом выбрасывает весь результат одного крафта. Q с вещью в курсоре — ничего.
14. Закрытие с вещью в курсоре при полном инвентаре — вещь летит вперёд, как при Q: `dropItem(…, false)`, без владельца.
15. Удержание Q (в мире и над слотом) с автоповтором — выбрасывает по одной. Удержание цифры над слотом —
    обмен туда-обратно на каждом повторе.
16. Пока окно открыто, игрок не ходит (клавиши отпущены), но мир тикает: можно получить урон, предметы подбираются
    в инвентарь.
17. Подбор во время открытого окна идёт в инвентарь, курсор не трогается.
18. Сундук под сплошным блоком не открывается. При отходе дальше ~8.5 блока окно закрывается, курсор возвращается.

## 8. Чего нет в исходнике / не ясно

1. **Вид подсветки поверх числа.** По коду подсветка рисуется после числа без проверки глубины → число тоже белеет.
   Глазами не сверено [не проверено].
2. **Shift + двойной клик** работает только при непустом `quickMovingStack`, а он перезаписывается при каждом Shift-нажатии.
   При пустом курсоре, если первый Shift-клик опустошил слот, второй ничего не добавит. Работает при вещи в курсоре или
   если в слоте что-то осталось. Это причуда кода. Повторять её дословно или упростить — решение (§14).
3. Нормализация колеса в браузере: `WheelEvent.deltaY` в пикселях (Chrome ≈ 100 за щелчок, зависит от масштаба
   ОС) или строках (Firefox, `deltaMode = 1`, ≈ 3). Нужен свой делитель и проверка на машине пользователя [не проверено].
4. Повторный захват мыши после Esc: браузер не считает Esc жестом пользователя, `requestPointerLock` в обработчике Esc
   может не сработать. Закрытие через E захватывает сразу [не проверено, проверить в Chrome/Firefox].
5. Ctrl+W (закрыть вкладку) перехватить нельзя. Ctrl+Q в Windows-браузерах обычно свободен, в Firefox/Linux закрывает
   программу [вики/не проверено].
6. Точные локализованные строки (ru_ru) в коде не лежат: «Создание», «Сундук», «Инвентарь», «В ведущей руке:» — по памяти
   [не проверено]. У нас свои строки.
7. Свет GUI для блоков (две лампы `enableGuiDepthLighting`) — точные множители граней не выписаны. Для иконок хватит
   приближения «верх 1.0, левая 0.8, правая 0.6» [не проверено].
8. Сенсорный режим (`touchscreen`) в `HandledScreen` есть, для телефона потом — как образец: удержание 500 мс, перенос
   по одной. Сейчас не нужен.
9. Сеть, ревизии и синхронизация (`ClickSlotC2SPacket`, `revision`) нам не нужны: одна модель в одном процессе.

## 9. Сценарии проверки человеком

Подготовка: креатив не нужен. Дать себе отладочной клавишей 64 земли, 10 булыжника, 3 бревна, 2 деревянные кирки (одна
целая, одна изношенная), железный шлем, сундук. Масштаб GUI — авто.

1. **Клики.** Открываю E. Курсор мыши в центре экрана, ходьба остановилась. ЛКМ по 64 земли — весь стек на курсоре, слот
   пуст. ПКМ по пустому слоту — там 1, на курсоре 63. ЛКМ по нему — 64 в слоте, курсор пуст. ПКМ по 64 — на курсоре 32,
   в слоте 32. ПКМ по стеку 63 — 32 на курсоре, 31 в слоте.
2. **Перетаскивание.** Беру 64 земли, зажимаю ЛКМ и веду по 4 пустым слотам. Ещё до отпускания в каждом видно «16» на
   белом фоне, на курсоре «0» жёлтым. Отпускаю — по 16, курсор пуст. ПКМ-тяга по 5 слотам с 64 — +1 в каждом, на курсоре 59.
   Со стеком из 2 тяну по 5 слотам — цепляются только первые 2.
3. **Двойной клик.** Доски: 10 в хотбаре, 20 в сетке крафта, 64 и 5 в рюкзаке. Беру ЛКМ 10 и сразу второй раз кликаю по
   тому же (теперь пустому) слоту. На курсоре 64: забраны 20 из сетки и 5 из рюкзака (неполные идут первыми), 29 взято
   из полного стека, в нём осталось 35.
4. **Shift-клик.** Shift+клик по земле в хотбаре — улетает в первый подходящий слот рюкзака (сверху слева). Обратно —
   в хотбар. При полном хотбаре Shift-клик из рюкзака ничего не делает.
5. **Цифры, F, Q.** Навожу на булыжник в рюкзаке, жму 3 — он меняется с 3-й ячейкой хотбара. Навожу на землю, жму Q —
   выпала одна, летит вперёд; Ctrl+Q — весь стек. С вещью в курсоре Q и цифры не работают. Колесо в окне не листает хотбар.
6. **Вне окна.** С 64 землёй на курсоре кликаю ПКМ мимо окна три раза — падают 3 штуки по одной. ЛКМ — остальное.
7. **Закрытие.** Беру 20 земли на курсор, кладу бревно в сетку 2×2, жму E. Земля **вернулась в инвентарь**: в стек земли,
   где есть место (выбранный слот проверяется первым), иначе в первую пустую ячейку (хотбар слева). Бревно тоже
   вернулось, ничего не выпало. Забиваю инвентарь, повторяю — выпадает вперёд.
8. **Крафт.** 3 бревна в сетку, Shift-клик по результату — 12 досок одним стеком в **правой** ячейке хотбара
   (если она была пуста), сетка пуста. ПКМ по результату с одним бревном забирает все 4 доски, а не 2.
9. **Кирки.** Целую кирку кладу на такую же целую — ничего. На изношенную — меняются местами. У изношенной
   под иконкой полоска: зелёная, при половине прочности жёлто-зелёная, у почти сломанной красная и короткая.
10. **Броня.** Землю в слот шлема не положить. Shift+клик по шлему в рюкзаке — шлем в слоте головы, слышен звук
    надевания. Второй шлем Shift+кликом идёт в хотбар (слот занят). Цифра над слотом шлема с землёй в этой ячейке
    хотбара — ничего.
11. **Сундук.** ПКМ по сундуку — окно 9×3 над инвентарём, крышка открывается за полсекунды, звук. Shift+клик по стеку
    в сундуке — уходит в **крайнюю правую** ячейку хотбара. Shift+клик из хотбара — в первую ячейку сундука слева сверху.
    Отхожу на ~9 блоков — окно закрывается само. Ставлю блок на сундук — больше не открывается.
12. **Хотбар в мире.** Колесо вниз — рамка вправо, с 9-й переходит на 1-ю. Цифра 5 — сразу 5-я. Над хотбаром ~1.5 с видно
    имя предмета, потом оно за 0.5 с гаснет. Переключение между двумя ячейками с землёй имя не показывает.
13. **Подбор.** В руке (ячейка 5) 10 булыжника, в ячейке 1 тоже булыжник. Подбираю 30 булыжника — всё легло в ячейку 5,
    её иконка коротко сплющилась и подпрыгнула. Подбираю доски (их нет в инвентаре) — легли в первую пустую ячейку
    хотбара слева, а не в выбранную.
14. **Масштаб.** На 1920×1080 окно инвентаря занимает ~704×664 экранных пикселей, пиксели рисунка чёткие, квадратные.

## 11. Rust-набросок модели (своими словами, не перевод Java)

```rust
// ---------- стек ----------
pub type ItemId = u16;
pub const AIR: ItemId = 0;

pub trait ItemInfo {                       // реестр предметов (ASP-06)
    fn max_count(&self, id: ItemId) -> i32;            // 64 / 16 / 1
    fn max_damage(&self, id: ItemId) -> u16;           // 0 = без прочности
    fn equip_slot(&self, id: ItemId) -> Option<Equip>; // броня → её место, щит → Offhand
}
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Equip { Feet = 0, Legs = 1, Chest = 2, Head = 3, Offhand = 4 }

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct ItemStack { pub item: ItemId, pub count: i32, pub damage: u16 }

impl ItemStack {
    pub const EMPTY: Self = Self { item: AIR, count: 0, damage: 0 };
    pub fn is_empty(&self) -> bool { self.item == AIR || self.count <= 0 }
    pub fn id(&self) -> ItemId { if self.is_empty() { AIR } else { self.item } }
    pub fn n(&self) -> i32 { if self.is_empty() { 0 } else { self.count } }
    /// «можно сложить»: тот же предмет и те же компоненты (у нас — износ)
    pub fn same_kind(&self, o: &Self) -> bool {
        self.id() == o.id() && ((self.is_empty() && o.is_empty()) || self.damage == o.damage)
    }
    pub fn with_count(&self, c: i32) -> Self { if self.is_empty() { Self::EMPTY } else { Self { count: c, ..*self } } }
    pub fn split(&mut self, c: i32) -> Self { let k = c.min(self.n()); let out = self.with_count(k); self.count -= k; out }
    pub fn max(&self, r: &dyn ItemInfo) -> i32 { r.max_count(self.item) }
    pub fn damaged(&self, r: &dyn ItemInfo) -> bool { r.max_damage(self.item) > 0 && self.damage > 0 }
    pub fn stackable(&self, r: &dyn ItemInfo) -> bool { self.max(r) > 1 && !self.damaged(r) }
}

// ---------- инвентарь игрока ----------
pub const OFFHAND: usize = 40;
pub struct PlayerInventory {
    pub main: [ItemStack; 36],      // 0..9 хотбар, 9..36 рюкзак
    pub armor: [ItemStack; 4],      // 0 ноги .. 3 голова  (плоские индексы 36..40)
    pub offhand: ItemStack,         // 40
    pub selected: usize,            // 0..9
    pub bob: [u8; 41],              // подскок иконки, тики (клиентская мелочь, но живёт рядом)
}

impl PlayerInventory {
    pub fn at(&mut self, i: usize) -> &mut ItemStack {
        match i { 0..=35 => &mut self.main[i], 36..=39 => &mut self.armor[i - 36], _ => &mut self.offhand }
    }
    fn cap(s: &ItemStack, r: &dyn ItemInfo) -> i32 { s.max(r).min(99) }
    fn has_room(e: &ItemStack, s: &ItemStack, r: &dyn ItemInfo) -> bool {
        !e.is_empty() && e.same_kind(s) && e.stackable(r) && e.n() < Self::cap(e, r)
    }
    /// куда докладывать: выбранный → вторая рука → main по порядку
    pub fn slot_with_room(&mut self, s: &ItemStack, r: &dyn ItemInfo) -> Option<usize> {
        let sel = self.selected;
        if Self::has_room(&self.main[sel], s, r) { return Some(sel); }
        if Self::has_room(&self.offhand, s, r) { return Some(OFFHAND); }
        (0..36).find(|&i| Self::has_room(&self.main[i], s, r))
    }
    pub fn empty_slot(&self) -> Option<usize> { (0..36).find(|&i| self.main[i].is_empty()) }

    fn add_at(&mut self, i: usize, s: &mut ItemStack, r: &dyn ItemInfo) {
        let slot = self.at(i);
        if slot.is_empty() { *slot = s.with_count(0); }      // «пустая копия» того же предмета
        let k = s.n().min(Self::cap(slot, r) - slot.count);
        if k > 0 { slot.count += k; s.count -= k; self.bob[i] = 5; }
    }
    /// подбор/возврат: true, если стек уменьшился (частично — тоже true)
    pub fn insert(&mut self, s: &mut ItemStack, r: &dyn ItemInfo) -> bool {
        if s.is_empty() { return false; }
        if s.damaged(r) {                                   // изношенное — только в пустую, целиком
            return match self.empty_slot() {
                Some(i) => { self.main[i] = *s; s.count = 0; self.bob[i] = 5; true }
                None => false,
            };
        }
        let before = s.n();
        loop {
            let prev = s.n();
            match self.slot_with_room(s, r).or_else(|| self.empty_slot()) {
                Some(i) => self.add_at(i, s, r),
                None => break,
            }
            if s.is_empty() || s.n() == prev { break; }
        }
        s.n() < before
    }
    /// закрытие окна, возврат сетки: что не влезло — бросок вперёд без владельца
    pub fn offer_or_drop(&mut self, mut s: ItemStack, r: &dyn ItemInfo, ev: &mut Vec<InvEvent>) {
        while !s.is_empty() {
            let Some(i) = self.slot_with_room(&s, r).or_else(|| self.empty_slot()) else {
                ev.push(InvEvent::Drop { stack: s, throw: Throw::Forward, owned: false }); break;
            };
            let room = s.max(r) - self.at(i).n();
            let mut part = s.split(room);
            self.insert_at(i, &mut part, r);               // как insert, но в конкретную ячейку
        }
    }
    fn insert_at(&mut self, i: usize, s: &mut ItemStack, r: &dyn ItemInfo) { /* add_at до упора; изношенное — запись целиком */ }
    pub fn scroll(&mut self, amount: f64) {
        let d = amount.signum() as i32;
        self.selected = ((self.selected as i32 - d).rem_euclid(9)) as usize;
    }
    pub fn take_selected(&mut self, all: bool) -> ItemStack {
        let s = &mut self.main[self.selected];
        let n = if all { s.n() } else { 1 };
        if s.is_empty() { ItemStack::EMPTY } else { s.split(n) }
    }
}

#[derive(Clone, Copy, PartialEq)] pub enum Store { Player, Craft, Result, Block }

/// всё, что окно трогает, передаётся снаружи (без заимствований внутри Menu)
pub struct Stores<'a> {
    pub player: &'a mut PlayerInventory,
    pub craft: &'a mut [ItemStack; 4],
    pub result: &'a mut ItemStack,
    pub block: Option<&'a mut [ItemStack]>,
}
pub struct Ctx<'a> {
    pub reg: &'a dyn ItemInfo,
    pub craft: &'a dyn Fn(&[ItemStack; 4]) -> ItemStack,   // ASP-09: результат по сетке
    pub alive: bool,
    pub creative: bool,
    pub ev: &'a mut Vec<InvEvent>,
}

pub struct Menu {
    pub kind: MenuKind,
    pub slots: Vec<SlotDef>,
    pub cursor: ItemStack,
    qc_stage: u8, qc_mode: u8, qc_slots: Vec<u16>,          // множество: без повторов, порядок не важен
}

impl Menu {
    // --- доступ к ячейке слота ---
    fn get(&self, st: &Stores, id: usize) -> ItemStack { /* по store/index */ unimplemented!() }
    fn put(&self, st: &mut Stores, id: usize, s: ItemStack, cx: &mut Ctx) {
        // записать; Armor/Offhand: если стал другим и это экипировка своего места — ev Equip;
        // Craft: *st.result = (cx.craft)(st.craft)   (onContentChanged)
    }
    fn can_insert(&self, id: usize, s: &ItemStack, cx: &Ctx) -> bool {
        match self.slots[id].kind {
            Kind::Result => false,
            Kind::Armor(e) => cx.reg.equip_slot(s.item) == Some(e),
            _ => true,
        }
    }
    fn can_take(&self, _id: usize) -> bool { true }        // проклятия нет
    fn limit(&self, id: usize, s: &ItemStack, cx: &Ctx) -> i32 {
        let base = if matches!(self.slots[id].kind, Kind::Armor(_)) { 1 } else { 99 };
        base.min(s.max(cx.reg))
    }
    fn takes_partial(&self, id: usize, st: &Stores, cx: &Ctx) -> bool {
        self.can_take(id) && self.can_insert(id, &self.get(st, id), cx)
    }
    /// взять из слота (результат — всегда целиком) + после взятия onTakeItem
    fn take_range(&self, st: &mut Stores, id: usize, min: i32, max: i32, cx: &mut Ctx) -> ItemStack {
        let mut s = self.get(st, id);
        if s.is_empty() || !self.can_take(id) { return ItemStack::EMPTY; }
        if !self.takes_partial(id, st, cx) && max < s.n() { return ItemStack::EMPTY; }
        let want = if self.slots[id].kind == Kind::Result { s.n() } else { min.min(max) };
        let out = s.split(want);
        self.put(st, id, if s.is_empty() { ItemStack::EMPTY } else { s }, cx);
        self.on_take(st, id, &out, cx);
        out
    }
    fn on_take(&self, st: &mut Stores, id: usize, _taken: &ItemStack, cx: &mut Ctx) {
        if self.slots[id].kind == Kind::Result {
            // ASP-09: −1 из каждой непустой клетки, остатки рецепта; затем пересчёт результата
            for c in st.craft.iter_mut() { if !c.is_empty() { c.count -= 1; } }
            *st.result = (cx.craft)(st.craft);
            cx.ev.push(InvEvent::CraftTaken { times: 1 });
        }
    }
    /// положить из `src` в слот не больше `n`, вернуть остаток (Slot.insertStack)
    fn insert_into(&self, st: &mut Stores, id: usize, mut src: ItemStack, n: i32, cx: &mut Ctx) -> ItemStack {
        if src.is_empty() || !self.can_insert(id, &src, cx) { return src; }
        let mut have = self.get(st, id);
        let k = n.min(src.n()).min(self.limit(id, &src, cx) - have.n());
        if have.is_empty() { let part = src.split(k); self.put(st, id, part, cx); }
        else if have.same_kind(&src) { src.count -= k; have.count += k; self.put(st, id, have, cx); }
        src
    }

    pub fn click(&mut self, st: &mut Stores, slot: i32, button: i32, a: Action, cx: &mut Ctx) {
        if a == Action::QuickCraft { return self.quick_craft(st, slot, button, cx); }
        if self.qc_stage != 0 { self.qc_reset(); return; }        // недоделанная тяга глотает действие
        match a {
            Action::Pickup | Action::QuickMove if button == 0 || button == 1 => {
                if slot == -999 {                                  // вне окна
                    if !self.cursor.is_empty() {
                        let s = if button == 0 { std::mem::take(&mut self.cursor) } else { self.cursor.split(1) };
                        cx.ev.push(InvEvent::Drop { stack: s, throw: Throw::Forward, owned: true });
                    }
                } else if slot < 0 { /* ничего */ }
                else if a == Action::QuickMove {
                    let id = slot as usize;
                    if !self.can_take(id) { return; }
                    let mut r = self.quick_move(st, id, cx);
                    while !r.is_empty() && self.get(st, id).id() == r.id() { r = self.quick_move(st, id, cx); }
                } else { self.pickup(st, slot as usize, button == 0, cx); }
            }
            Action::Swap if (0..9).contains(&button) || button == 40 => self.swap(st, slot as usize, button as usize, cx),
            Action::Clone if cx.creative && self.cursor.is_empty() && slot >= 0 => {
                let s = self.get(st, slot as usize);
                if !s.is_empty() { self.cursor = s.with_count(s.max(cx.reg)); }
            }
            Action::Throw if self.cursor.is_empty() && slot >= 0 => {
                let id = slot as usize;
                let n = if button == 0 { 1 } else { self.get(st, id).n() };
                let s = self.take_range(st, id, n, i32::MAX, cx);
                if !s.is_empty() { cx.ev.push(InvEvent::Drop { stack: s, throw: Throw::Forward, owned: true }); }
            }
            Action::PickupAll if slot >= 0 => self.pickup_all(st, slot as usize, button, cx),
            _ => {}
        }
    }

    fn pickup(&mut self, st: &mut Stores, id: usize, left: bool, cx: &mut Ctx) {
        let s = self.get(st, id);
        let c = self.cursor;
        if s.is_empty() {
            if !c.is_empty() { self.cursor = self.insert_into(st, id, c, if left { c.n() } else { 1 }, cx); }
        } else if self.can_take(id) {
            if c.is_empty() {
                let n = if left { s.n() } else { (s.n() + 1) / 2 };
                self.cursor = self.take_range(st, id, n, i32::MAX, cx);
            } else if self.can_insert(id, &c, cx) {
                if s.same_kind(&c) { self.cursor = self.insert_into(st, id, c, if left { c.n() } else { 1 }, cx); }
                else if c.n() <= self.limit(id, &c, cx) { self.put(st, id, c, cx); self.cursor = s; }
            } else if s.same_kind(&c) {                          // результат крафта в непустой курсор
                let t = self.take_range(st, id, s.n(), c.max(cx.reg) - c.n(), cx);
                self.cursor.count += t.n();
            }
        }
    }

    fn quick_move(&mut self, st: &mut Stores, id: usize, cx: &mut Ctx) -> ItemStack { /* таблицы §1.5 / §1.6 через insert_item */ unimplemented!() }
    /// ScreenHandler.insertItem: сложение по диапазону, затем ОДИН первый пустой
    fn insert_item(&self, st: &mut Stores, s: &mut ItemStack, from: usize, to: usize, rev: bool, cx: &mut Ctx) -> bool { unimplemented!() }
    fn swap(&mut self, st: &mut Stores, id: usize, hb: usize, cx: &mut Ctx) { /* §2.3 */ }
    fn pickup_all(&mut self, st: &mut Stores, id: usize, button: i32, cx: &mut Ctx) { /* §2.7: два прохода */ }

    fn quick_craft(&mut self, st: &mut Stores, slot: i32, button: i32, cx: &mut Ctx) {
        let (prev, stage, mode) = (self.qc_stage, (button & 3) as u8, ((button >> 2) & 3) as u8);
        self.qc_stage = stage;
        if (prev != 1 || stage != 2) && prev != stage { return self.qc_reset(); }
        if self.cursor.is_empty() { return self.qc_reset(); }
        match stage {
            0 => { self.qc_mode = mode;
                   if mode == 2 && !cx.creative { return self.qc_reset(); }
                   self.qc_stage = 1; self.qc_slots.clear(); }
            1 => { let id = slot as usize; let c = self.cursor;
                   if self.drag_ok(st, id, &c, cx) && (self.qc_mode == 2 || c.n() > self.qc_slots.len() as i32)
                      && !self.qc_slots.contains(&(id as u16)) { self.qc_slots.push(id as u16); } }
            2 => {
                if self.qc_slots.len() == 1 {
                    let id = self.qc_slots[0] as i32; let m = self.qc_mode as i32;
                    self.qc_reset(); return self.click(st, id, m, Action::Pickup, cx);
                }
                if !self.qc_slots.is_empty() {
                    let orig = self.cursor; let nslots = self.qc_slots.len() as i32;
                    let share = match self.qc_mode { 0 => orig.n() / nslots, 1 => 1, _ => orig.max(cx.reg) };
                    let mut left = orig.n();
                    for &sid in &self.qc_slots.clone() {
                        let id = sid as usize;
                        if !self.drag_ok(st, id, &self.cursor, cx) { continue; }
                        let l = self.get(st, id).n();
                        let m = orig.max(cx.reg).min(self.limit(id, &orig, cx));
                        let n = (share + l).min(m);
                        left -= n - l;
                        self.put(st, id, orig.with_count(n), cx);
                    }
                    self.cursor = orig.with_count(left);
                }
                self.qc_reset();
            }
            _ => self.qc_reset(),
        }
    }
    /// canInsertItemIntoSlot(…, true) && canInsert && не результат
    fn drag_ok(&self, st: &Stores, id: usize, c: &ItemStack, cx: &Ctx) -> bool {
        let s = self.get(st, id);
        let fits = s.is_empty() || (s.same_kind(c) && s.n() <= c.max(cx.reg));
        fits && self.can_insert(id, c, cx) && self.slots[id].kind != Kind::Result
    }
    fn qc_reset(&mut self) { self.qc_stage = 0; self.qc_slots.clear(); }

    /// закрытие (§4)
    pub fn close(&mut self, st: &mut Stores, cx: &mut Ctx) {
        let c = std::mem::take(&mut self.cursor);
        let back = |s: ItemStack, st: &mut Stores, cx: &mut Ctx| {
            if cx.alive { st.player.offer_or_drop(s, cx.reg, cx.ev) }
            else if !s.is_empty() { cx.ev.push(InvEvent::Drop { stack: s, throw: Throw::Forward, owned: false }) }
        };
        back(c, st, cx);
        if let MenuKind::Player = self.kind {
            *st.result = ItemStack::EMPTY;
            for i in 0..4 { let s = std::mem::take(&mut st.craft[i]); back(s, st, cx); }
        }
        // MenuKind::Chest: сообщить блок-сущности «смотрящих −1» (E6)
    }
}
```

`Default` для `ItemStack` = EMPTY, поэтому работает `mem::take`. Пустые стеки с `count = 0` и любым `item` считаются
пустыми, но при записи в слот лучше нормализовать их в EMPTY: тогда `same_kind` и сравнения проще.

## 12. UI на нашей стороне (E7): предложение

**Слой.** Отдельный `<canvas id="ui">` поверх WebGL-канваса, того же размера в **устройственных пикселях**
(`clientWidth × devicePixelRatio`). Контекст 2D, `imageSmoothingEnabled = false`. Всё рисуется в GUI-пикселях
через `setTransform(scale, 0, 0, scale, 0, 0)`. Холст пропускает мышь (`pointer-events: none`), пока окно закрыто.
Для текста, перетаскивания и слоёв это проще DOM и гарантирует пиксельную сетку. Перерисовка — каждый кадр, пока
окно открыто (~60 слотов — дёшево). HUD — при изменении (слот, число, подскок, затухание имени).

**Масштаб.** Формула §6.1 по устройственным пикселям канваса, авто по умолчанию, в настройках 1…max. При смене размера
окна — пересчёт и пересборка атласа иконок.

**Иконки.**
- Блоки: один раз (и при смене масштаба) отрисовать каждый блок нашим WebGL в офскрин-кадр размером `16·scale` на
  иконку, с трансформом `gui` (поворот X 30°, Y 225°, масштаб 0.625, ортография). Свет граней: верх 1.0, бока 0.8/0.6
  [не проверено]. Потом прочитать в `ImageBitmap`-атлас. Иконки получатся в разрешении экрана, как в игре, а не
  растянутые 16×16.
- Плоские предметы (палка, уголь, слиток, инструменты) — спрайт 16×16 из нашего атласа, растяжение «по ближайшему».

**Шрифт.** Растровый 8 px с кириллицей и пропорциональными ширинами (атлас + таблица ширин, интервал +1, строка 9).
Тень: тот же текст ×0.25 яркости со сдвигом (1, 1). Нужные цвета: белый, 0x404040, жёлтый, серый, тёмно-зелёный,
тёмно-серый. Их заранее перекрасить в кэш (`globalCompositeOperation = "source-in"`). Шрифт Mojang брать нельзя:
нужен свободный (CC0/OFL) пиксельный с кириллицей, выбор — §14.

**Ввод.**
- Кнопки мыши: браузер `button` 0 ЛКМ, **1 средняя, 2 правая**; у MC 0/1/2 = ЛКМ/ПКМ/СКМ. Перевод: `{0:0, 2:1, 1:2}`.
- Отключить `contextmenu` и автопрокрутку средней кнопкой (`preventDefault` в `mousedown` для `button == 1`).
- Двойной клик — свой таймер 250 мс по `event.timeStamp`. Браузерный `dblclick` не использовать.
- Shift и Ctrl брать из `event.shiftKey` / `event.ctrlKey` в момент события. Q/цифры принимать и с `event.repeat`,
  как MC (решение §14).
- Колесо: накопитель как в `Mouse.onMouseScroll`, вход нормализовать: `deltaMode` 0 → `−deltaY/100`, 1 → `−deltaY/3`.
  Знак инвертирован: в браузере вниз положительно. Шаг ±1 за накопленную единицу [не проверено, §8].
- Захват мыши: E/Esc в мире → `document.exitPointerLock()`, окно открыто, мышь видна (браузер не умеет ставить её в центр;
  до первого `mousemove` наведения нет). Закрытие по E → `requestPointerLock()` в том же `keydown`. Закрытие по Esc →
  если захват не удался, показать «клик — продолжить», и этот клик не должен бить (аналог `attackCooldown`, §5).
- Пока окно открыто, все игровые клавиши отпущены (`unpressAll`), мир тикает.

**Автомат окна** (JS, по §2.8):

```js
// btn уже в нумерации MC (0 ЛКМ, 1 ПКМ, 2 СКМ); k: id слота | -1 | -999
down(btn, x, y) {
  const slot = slotAt(x, y), now = ev.timeStamp;
  this.dbl = slot === this.lastSlot && now - this.lastTime < 250 && btn === this.lastBtn;
  this.cancelRelease = false;
  if (btn <= 1) {
    const k = outside(x, y) ? -999 : slot ? slot.id : -1;
    if (k !== -1 && !this.dragging) {
      if (cursorEmpty()) {
        if (k !== -999 && shift) { this.qmStack = slot?.stack ?? null; click(k, btn, QUICK_MOVE); }
        else click(k, btn, k === -999 ? THROW : PICKUP);
        this.cancelRelease = true;
      } else { this.dragging = true; this.dragBtn = btn; this.dragSet.clear(); }
    }
  }
  this.lastSlot = slot; this.lastTime = now; this.lastBtn = btn;
}
move(x, y) { if (this.dragging) { const s = slotAt(x, y); if (s && dragAccepts(s, this.dragSet.size)) this.dragSet.add(s.id); } }
up(btn, x, y) {
  const slot = slotAt(x, y), k = outside(x, y) ? -999 : slot ? slot.id : -1;
  if (this.dbl && slot && btn === 0 && !slot.isResult) {
    if (shift) { if (this.qmStack) for (const s of sameStoreSameItem(slot, this.qmStack)) click(s.id, 0, QUICK_MOVE); }
    else click(slot.id, 0, PICKUP_ALL);
    this.dbl = false; this.lastTime = -1e9;
  } else if (this.dragging && btn !== this.dragBtn) { this.dragging = false; this.dragSet.clear(); this.cancelRelease = true; return; }
  else if (this.cancelRelease) { this.cancelRelease = false; return; }   // как в MC: ранний выход
  else if (this.dragging && this.dragSet.size) {
    click(-999, pack(0, this.dragBtn), QUICK_CRAFT);
    for (const id of this.dragSet) click(id, pack(1, this.dragBtn), QUICK_CRAFT);
    click(-999, pack(2, this.dragBtn), QUICK_CRAFT);
  } else if (!cursorEmpty()) {
    const sh = k !== -999 && shift;
    if (sh) this.qmStack = slot?.stack ?? null;
    click(k, btn, sh ? QUICK_MOVE : PICKUP);
  }
  if (cursorEmpty()) this.lastTime = -1e9;
  this.dragging = false;
}
```

4. Подсветка слота под мышью.
