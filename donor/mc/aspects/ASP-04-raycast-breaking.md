Механики: RAY-01, BRK-01, BRK-02, BRK-03, BRK-06 (вызов взмаха), CAM-08 (рамка); касается BRK-04/05/07 (событие ломания).

**[java]** — посчитано настоящей Java 8 (float32 тот же, IEEE), **[вывод]** — следует из нескольких мест исходника,

## 0. Главное для реализации

1. **Луч** — от `standingEyeHeight` (1.62 / 1.27 сразу, без сглаживания камеры), длина **4.5**, DDA по клеткам, в каждой клетке
   проверяется **outline-форма** блока (не коллизия), жидкости пропускаются. Цель годится, только если **точка попадания** ближе
   4.5 строго. Логика тика берёт луч в **начале тика** с текущей позицией (`tickDelta = 1`), рамка — **каждый кадр** с
   интерполированной позицией. [src]
2. **Ломание** — машина состояний в `ClientPlayerInteractionManager`; прогресс `+= delta` каждый тик удержания, **начиная с тика
   нажатия**. `delta = скорость / твёрдость / (можно добыть ? 30 : 100)`; в воздухе ÷5, глаза под водой ×0.2. [src]
3. **Время = число тиков удержания с накоплением во float32.** Из-за округления бревно рукой ломается за **61** тик, а не 60;
   камень рукой — 151, булыжник рукой — 201, угольная руда рукой — 301, верстак рукой — 76. [java] Каталог (BRK-02) даёт 60/150 —
   это идеальная арифметика, не игра.
4. **Задержка между блоками при удержании — 6 тиков, не 5**: 5 тиков `blockBreakingCooldown` + 1 тик «начала» (`attackBlock`)
   без прогресса. Период цепочки = N + 6. Кулдаун **убывает только пока ЛКМ держат на блоке** и не сбрасывается отпусканием:
   если последним сломан немгновенный блок, то следующий немгновенный — когда бы ни начали — получает N + 5. Мгновенные блоки
   (трава, цветы, факел) при удержании ломаются **по одному за тик**, кликом — в обход кулдауна. [src][вывод]
5. **Смена цели или предмета в руке** (сравнение «предмет + компоненты», без количества) — прогресс с нуля, +1 тик начала.
   Отпускание ЛКМ или уход прицела с блока — `cancelBlockBreaking`: трещины пропадают в тот же тик. [src]
6. **Трещины**: стадия `(int)(progress·10)`, 0…9, видна при `progress > 0`; рисуется повтором геометрии блока с текстурой
   `destroy_stage_N`, смешивание «×2» (`DST_COLOR, SRC_COLOR`), polygon offset (−1, −10), без записи глубины. [src]
7. **Взмах** при удержании вызывается **каждый тик** и перезапускается, как только прошла половина (3 из 6 тиков): рука машет
   **каждые 4 тика (0.2 с)** короткой дугой; одиночный клик — полный взмах 6 тиков (0.3 с). [src][вывод] Каталог (BRK-06: ~0.3 с
   при удержании) неточен.
8. **Рамка**: рёбра outline-формы, чёрный α 0.4, ширина `max(2.5, ширина_кадра/1920·2.5)` px, линии — экранные квадраты в шейдере,
   слегка придвинуты к камере. [src]
9. **Клиент удаляет блок сам** (предсказание) с флагом «перестроить меш в главном потоке» и сам играет событие 2001 (звук + 64
   крошки). Сервер у нас не нужен, но его допуски описаны в §12. [src]

## 1. Порядок операций: кадр и тик

### 1.1 Кадр (`GameRenderer.renderWorld`) [src]
1. События мыши/клавиш приходят от окна в любой момент кадра: мышь сразу меняет `yaw/pitch` **и** `prevYaw/prevPitch` на ту же
   величину (`Entity.changeLookDirection`, ×0.15 °/пиксель), кнопки копят нажатия в `KeyBinding.timesPressed`.
2. `updateCrosshairTarget(tickDelta_кадра)` — луч с интерполированной позицией глаз и текущим взглядом → `client.crosshairTarget`.
3. Рендер мира: … → трещины («destroyProgress») → **рамка** («outline») по `crosshairTarget`, если тип BLOCK → …

### 1.2 Тик клиента (`MinecraftClient.tick`) — часть, касающаяся аспекта [src]
1. `itemUseCooldown--` (если > 0).
2. `gameRenderer.updateCrosshairTarget(1.0)` — луч **с текущей позицией** (конец прошлого тика) и текущим взглядом.
3. `interactionManager.tick()` → `syncSelectedSlot` (сообщить серверу слот).
4. Если открыт экран — `attackCooldown = 10000`, и `handleInputEvents` **не вызывается** (ломание заморожено, см. §11).
5. `handleInputEvents()`:
   1. клавиши 1–9 → `selectedSlot` сразу (колесо меняет слот ещё раньше, в обработчике события);
   2. если игрок использует предмет (ест) — нажатия ЛКМ/ПКМ выбрасываются;
   3. иначе **по каждому накопленному нажатию ЛКМ** — `doAttack()` (результат «сломал мгновенно» копится в `bl3`);
   4. нажатия ПКМ → `doItemUse()` (не работает, пока `isBreakingBlock()` — ASP-05);
   5. **`handleBlockBreaking(экран закрыт && !bl3 && ЛКМ зажата && курсор захвачен)`**.
6. `attackCooldown--` (если > 0).
7. `worldRenderer.tick()` (счётчик `ticks`, раз в 20 тиков — удалить записи трещин старше 400 тиков).
8. `world.tickEntities()` → тик игрока: `lastAttackedTicks++`, `baseTick` (`lastHandSwingProgress = handSwingProgress`),
   затем `tickMovement`: сначала `tickNewAi` → `tickHandSwing`, потом `travel` — движение (onGround, вода — ASP-02/03).

Следствие: ломание в тике T видит `onGround` и «глаза в воде» **после движения тика T−1**, а взмах, запущенный в T, впервые
отрисуется после `tickHandSwing` того же T.

## 2. Луч взгляда (RAY-01)

### 2.1 Начало и направление [src `Entity.getCameraPosVec`, `getRotationVec`, `getRotationVector`]
- Начало: `lerp(t, prevX, x)`, `lerp(t, prevY, y) + standingEyeHeight`, `lerp(t, prevZ, z)` (double).
  `standingEyeHeight` — по позе **мгновенно**: стоя 1.62F, присед 1.27F, плавание 0.4F (`PlayerEntity.POSE_DIMENSIONS`).
  Камера опускается плавно (ASP-01), а луч — сразу: при нажатии Shift рамка на долю секунды «не совпадает» с крестиком.
- Направление (единичный вектор): `g = −yaw·π/180`, `f = pitch·π/180`; `dir = (sin g·cos f, −sin f, cos g·cos f)`.
  yaw 0 → +Z (юг), yaw 90 → −X, pitch +90 → вниз. Синус/косинус — таблица на 65536 значений (`MathHelper.sin`), погрешность
  ~1e-4 рад — нам не важна.
- При `t = 1.0` берутся текущие `yaw/pitch` без интерполяции; для игрока интерполяция и так даёт текущее значение, потому что
  мышь двигает `prev` вместе с `yaw`.

### 2.2 Дальность [src `EntityAttributes`, `PlayerEntity.createPlayerAttributes`, `ServerPlayerEntity`, `GameRenderer.findCrosshairTarget`]
- `player.block_interaction_range` = **4.5** (зажим 0…64); `player.entity_interaction_range` = **3.0**.
- Креатив: модификаторы +0.5 (блоки → 5.0) и +2.0 (сущности → 5.0).
- Длина луча = `max(блоки, сущности)` = 4.5 в выживании.
- Итог проверяется по **точке попадания**: `|hit − eye|² < range²` строго (`Vec3d.isInRange`); иначе результат превращается
  в MISS (`ensureTargetInRange`). Грань ровно на 4.5 — промах.

### 2.3 Обход клеток (DDA) [src `BlockView.raycast` (static)]
1. Если начало == конец — MISS.
2. Отрезок удлиняется на **1e-7 своей длины в обе стороны** (`lerp(−1e-7, …)`): начало чуть «до» глаз, конец чуть дальше 4.5.
3. Первая клетка — `floor` удлинённого начала; **сначала проверяется клетка самих глаз**.
4. Для каждой оси: `step = sign(Δ)`, `tDelta = step/Δ` (доля отрезка на клетку), `tMax = tDelta·(до ближайшей границы)`
   (`1 − frac` при шаге +, `frac` при шаге −).
5. Цикл, пока хоть один `tMax ≤ 1.0`: шаг по оси с меньшим `tMax`; при равенстве порядок: `x<y ? (x<z ? X : Z) : (y<z ? Y : Z)` —
   т. е. при ничьей X проигрывает Y/Z, Y проигрывает Z.
6. В каждой новой клетке — проверка формы (ниже); первая клетка с попаданием — ответ. Иначе MISS (точка = конец луча).

### 2.4 Проверка клетки [src `BlockView.raycast(RaycastContext)`, `raycastBlock`, `VoxelShape.raycast`, `Box.raycast`]
- Форма: `RaycastContext.ShapeType.OUTLINE` → `getOutlineShape` (рамка). Жидкость: `FluidHandling.NONE` — форма жидкости пустая.
  Луч проходит сквозь воду и выбирает дно. (Ведро использует `SOURCE_ONLY`/`ANY` — ASP-03/вёдра.)
- `VoxelShape.raycast(start, end, pos)` (исходные, не удлинённые концы):
  - пустая форма → нет попадания; длина² < 1e-7 → нет;
  - **«внутри»**: если точка `start + 0.001·Δ` лежит внутри формы — попадание в этой точке, грань = противоположная главной оси
    направления (`Direction.getFacing(Δ).getOpposite()`), флаг `insideBlock = true`. Так выбирается блок, в котором стоят глаза
    (например, верхняя половина высокой травы);
  - иначе по коробкам формы: для каждой оси, где `|Δ| > 1e-7`, берётся **плоскость входа** (min при Δ>0, max при Δ<0),
    `t = (плоскость − start)/Δ`; засчитывается, если `0 < t < лучший_t` (начальный 1.0) и две другие координаты в
    `(min − 1e-7, max + 1e-7)`. Грань — грань входа (Δx>0 → WEST, <0 → EAST; Δy>0 → DOWN, <0 → UP; Δz>0 → NORTH, <0 → SOUTH).
    Точка = `start + t·Δ`.
- `getRaycastShape` может подменить только **грань** (у нас пустая у всех блоков — композтер, котёл и т. п. не нужны).
- Клетки обходятся по порядку, поэтому форма, «торчащая» в соседнюю клетку, ловится лишь в своей клетке — у блоков пути такого нет.

### 2.5 Сущности [src `GameRenderer.findCrosshairTarget`, `ProjectileUtil.raycast`, `Entity.canHit`]
- После блока ищется сущность на отрезке до блока (коробка игрока, растянутая по лучу, +1 во все стороны), берётся ближайшая
  ближе блока; потом своя дальность 3.0.
- `canHit`: по умолчанию **false** → выпавшие предметы (`ItemEntity`) **не мешают** лучу; **падающий блок** (`FallingBlockEntity`)
  — true: летящий песок перехватывает луч (важно для ASP-05/07). Мобов у нас пока нет.

### 2.7 Где какой луч используется [src]
- **Логика тика** (`doAttack`, `handleBlockBreaking`, `doItemUse`) — `crosshairTarget`, посчитанный в начале тика с `t = 1`.
  Внутри тика он не пересчитывается: второй клик того же тика по мгновенно сломанному блоку видит «воздух» (см. §4.2).
- **Рамка** — луч кадра (интерполированная позиция). При ходьбе рамка может на кадр отличаться от того, что ломает логика —
  у Minecraft так же.

## 3. Рамка выделения (CAM-08) [src `WorldRenderer.drawBlockOutline`, `drawCuboidShapeOutline`, `RenderLayer.LINES`, `RenderPhase`; data `shaders/core/rendertype_lines.vsh`]

- Рисуется, если: камера — игрок, HUD не скрыт (F1), игроку разрешено менять мир (`allowModifyWorld`; в приключении — только
  если предмет может ломать/ставить), цель BLOCK, блок не воздух и внутри границы мира. При MISS рамки нет.
- Геометрия: **рёбра outline-формы** (`forEachEdge` — объединённые рёбра составной формы; у куба 12), в мировых координатах
  блока, **без расширения** (в старых версиях было +0.002 — в 1.21.1 нет).
- Цвет: **(0, 0, 0, 0.4)**, смешивание обычное по альфе (`TRANSLUCENT_TRANSPARENCY`), запись цвета и глубины, тест глубины
  включён (рёбра за другими блоками скрыты), отсечение граней выключено, туман применяется (`linear_fog`).
- Толщина: `LineWidth = max(2.5, ширина_кадра_px / 1920 · 2.5)` пикселей. В шейдере каждая линия — **квадрат в экранных
  координатах**: концы отрезка проецируются, сдвиг перпендикулярно экранному направлению на ±LineWidth/2 px.
- Смещение к камере (против мерцания с гранью): модель-вид умножается на **0.99975586** (= 1 − 1/4096, `VIEW_OFFSET_Z_LAYERING`)
  и в шейдере ещё на **1 − 1/256** (`VIEW_SHRINK`). Итог ≈ ×0.99585 от камеры: на 4.5 блока рамка ближе на ~0.019.
- Порядок: трещины, затем рамка (в том же проходе «после сущностей»).
- WebGL2: `gl.lineWidth > 1` не поддерживается — делать так же, как Minecraft: рёбра квадратами в вершинном шейдере.

## 4. Ломание: состояние и шаги (BRK-01, BRK-03)

### 4.1 Состояние [src]
`ClientPlayerInteractionManager`:
- `currentBreakingPos` (начально −1,−1,−1) — **не сбрасывается** ни при поломке, ни при отмене;
- `selectedStack` — предмет в руке на момент начала;
- `currentBreakingProgress: f32`;
- `blockBreakingSoundCooldown: f32` — счётчик тиков прогресса для звука удара;
- `blockBreakingCooldown: i32` — задержка между блоками (5);
- `breakingBlock: bool`.

`MinecraftClient`: `attackCooldown: i32` — запрет ломания после удара в воздух (10) и при открытом экране (10000).

«Тот же блок» (`isCurrentlyBreaking(pos)`): `pos == currentBreakingPos` **и** предмет в главной руке «тот же» —
`ItemStack.areItemsAndComponentsEqual(рука, selectedStack)`: тип и компоненты (прочность, чары, имя), **без количества**.
Флаг `breakingBlock` в этой проверке **не участвует**.

### 4.2 `doAttack()` — на каждое нажатие ЛКМ [src `MinecraftClient.doAttack`]
1. `attackCooldown > 0` → ничего (даже взмаха нет).
2. Цель BLOCK и блок не воздух → `attackBlock(pos, грань)`; если блок после этого воздух (мгновенно сломан) → вернуть «сломал»
   (`bl3`). Взмах.
3. Цель BLOCK, но блок уже воздух (второй клик в том же тике) — **проваливается в ветку MISS** (так написан `switch`).
4. MISS: в выживании `attackCooldown = 10`; `resetLastAttackedTicks()` (опускание предмета в руке, ASP-11). Взмах.
5. ENTITY: атака (вне аспекта). Взмах.

### 4.3 `handleBlockBreaking(held)` — раз в тик [src]
1. Если `!held` → `attackCooldown = 0` (отпускание снимает задержку после удара в воздух).
2. Если `attackCooldown > 0` или игрок использует предмет → **ничего** (ни прогресса, ни отмены).
3. Если `held` и цель BLOCK и блок не воздух → `updateBlockBreakingProgress(pos, грань)`; если вернулось true —
   **крошка на грани** (`addBlockBreakingParticles`) и **взмах** (`swingHand`).
4. Иначе → `cancelBlockBreaking()`.

`held` = экран закрыт, ЛКМ зажата, курсор захвачен (Pointer Lock), и в этом тике не было мгновенной поломки кликом.

### 4.4 `updateBlockBreakingProgress(pos, грань)` [src]
1. `syncSelectedSlot()`.
2. **`blockBreakingCooldown > 0` → уменьшить на 1, вернуть true** (крошки и взмах идут, прогресса нет).
3. Креатив: сломать сразу, `blockBreakingCooldown = 5`, true.
4. «Тот же блок» (§4.1):
   1. блок стал воздухом → `breakingBlock = false`, вернуть false;
   2. `progress += calcBlockBreakingDelta(...)` — **delta пересчитывается каждый тик** (прыжок, вода, смена условий действуют
      на этот тик);
   3. если `soundCooldown % 4 == 0` → звук удара (`hitSound`, громкость `(v+1)/8`, высота `p·0.5`, в блоке); `soundCooldown++`;
   4. если `progress ≥ 1.0` → `breakingBlock = false`, **сломать** (`breakBlock`, §9), `progress = 0`, `soundCooldown = 0`,
      **`blockBreakingCooldown = 5`**;
   5. трещины: `setBlockBreakingInfo(id, pos, стадия)`; вернуть true.
5. Иначе (другой блок или другой предмет) → `return attackBlock(pos, грань)` — **в этот тик прогресса нет**.

### 4.5 `attackBlock(pos, грань)` — начало [src]
1. Запрет (приключение) или вне границы мира → false.
2. Креатив → сломать, `blockBreakingCooldown = 5`.
3. Если **не** (`breakingBlock` и «тот же блок»):
   1. если что-то ломалось — серверу ABORT для старой позиции;
   2. `onBlockBreakStart` (нотный блок и т. п.; у наших блоков пусто) — только при `progress == 0`;
   3. если `delta ≥ 1` → **сломать мгновенно** (`blockBreakingCooldown` **не** ставится);
   4. иначе: `breakingBlock = true`, `currentBreakingPos = pos`, `selectedStack = рука`, `progress = 0`, `soundCooldown = 0`,
      `setBlockBreakingInfo(id, pos, −1)` — старые трещины этого игрока исчезают сразу.
4. Вернуть true. **Кулдаун 5 тиков здесь не проверяется** — клик по мгновенному блоку ломает его всегда.

### 4.6 `cancelBlockBreaking()` [src]
Только если `breakingBlock`: ABORT серверу, `breakingBlock = false`, `progress = 0`, `setBlockBreakingInfo(id, pos, −1)`
(трещины пропадают в тот же тик), `resetLastAttackedTicks()` (предмет в руке «опустится и поднимется», ASP-11/TOOL-04).
`blockBreakingCooldown`, `soundCooldown`, `currentBreakingPos` **не трогаются**.

### 4.7 Тик за тиком (N — число тиков прогресса из таблицы §6) [вывод из §4.2–4.6]

**A. Первый блок (кулдаун 0), нажал и держу:**

| Тик | Что происходит |
|---|---|
| 1 (нажатие) | `doAttack` → `attackBlock`: начало, прогресс 0, взмах. Затем `handleBlockBreaking` → тот же блок → `progress = delta`, звук удара №1, крошка, стадия 0 видна |
| 2…N−1 | `progress += delta`, крошка каждый тик, звук на тиках прогресса 1, 5, 9, …, стадия растёт |
| N | `progress ≥ 1` → блок сломан (§9), кулдаун 5 |

От тика нажатия до поломки — (N − 1)·50 мс; от физического нажатия добавляется 0…50 мс ожидания тика.

**B. Цепочка при удержании** (блок сломан в тике Tb, прицел сразу на следующем блоке):

| Тик | Что происходит |
|---|---|
| Tb+1…Tb+5 | кулдаун 5→0: прогресса нет, **крошки на новом блоке и взмах идут** |
| Tb+6 | «другой блок» → `attackBlock`: начало, прогресс 0, трещин нет |
| Tb+7 | первый тик прогресса: стадия 0, звук удара |
| Tb+6+N | поломка |

Период = **N + 6** тиков; видимая пауза «блок исчез → трещины на следующем» = 7 тиков (0.35 с). Пример: земля рукой — 21 тик
(1.05 с) на блок.

**C. После паузы** (ломал блок, отпустил, через любое время нажал на другой немгновенный блок): тик 1 — начало +
кулдаун 5→4; тики 2–5 — кулдаун 4→0; тики 6…N+5 — прогресс. Итого **N + 5**. Кулдаун «ждёт» следующего удержания.

**D. Мгновенные блоки** (`delta ≥ 1`: трава, цветы, саженцы, факел; с инструментом — например снег-блок железной лопатой):
- кликом — ломаются в тике клика всегда (кулдаун не проверяется и не ставится);
- удержанием — каждый тик `attackBlock` нового блока под прицелом → **один куст за тик**, если вести прицелом; после обычного
  блока сначала отрабатывает оставшийся кулдаун (до 5 тиков).
- Мгновенная поломка кликом выставляет `bl3` → в этом тике `handleBlockBreaking(false)`: `attackCooldown = 0`, отмена (пустая).

**E. Клик в воздух, потом держу и навожу на блок**: `attackCooldown = 10`, убывает в конце каждого тика (10 → 0 к концу
тика 10, тик клика — 1-й). В тиках 1–10 `handleBlockBreaking` ничего не делает; в тике 11 — начало (или остаток
кулдауна 5 по правилу C), первый прогресс — в тике 12 (≈ 0.55 с после клика). Отпустить и нажать снова — сразу.

**F. Клик короче тика** (нажал и отпустил между тиками): `doAttack` начинает, затем `handleBlockBreaking(false)` отменяет —
прогресса **ноль**, только взмах.

### 4.8 Почему 61, а не 60 [java]
`delta` бревна рукой = 1/2/30 = 0.016666668f (округлено вверх); после 60 сложений во float32 прогресс = **0.9999997** < 1 → нужен
61-й тик. Земля: delta 0.06666667f, 15 сложений дают ровно 1.0 → 15. Правило: **накапливать прогресс в f32 тем же порядком**,
тогда тики совпадут с Java. Формула `ceil(1/delta)` даёт 60 и неверна для части блоков.

## 5. Скорость ломания (BRK-02) [src `AbstractBlock.calcBlockBreakingDelta`, `PlayerEntity.getBlockBreakingSpeed`, `PlayerInventory.getBlockBreakingSpeed`, `Item.getMiningSpeed`, `ToolComponent`, `ToolMaterial.createComponent`]

```
delta = твёрдость == −1 ? 0                       // бедрок: не ломается никогда
      : скорость / твёрдость / (можно_добыть ? 30 : 100)     // всё во float32, именно в этом порядке
```
- Твёрдость 0 → деление на ноль даёт +∞ → `≥ 1` → мгновенно (так и в Java).
- `можно_добыть` (`canHarvest`) = блок не `requiresTool` **или** инструмент «правильный для дропа».
- `скорость` (`getBlockBreakingSpeed`), по шагам:
  1. скорость предмета: `ToolComponent.getSpeed` — первое правило **со скоростью**, чей тег содержит блок; иначе 1.0. У кирки/
     топора/лопаты/мотыги два правила: «не дропает» по `incorrect_for_<ярус>_tool` (**без скорости**) и «скорость яруса + дропает»
     по `mineable/<инструмент>`. Поэтому **скорость яруса действует и на слишком твёрдую руду** (деревянная кирка по железной
     руде: 2.0), но делитель 100 и без дропа. Рука и неподходящий инструмент — 1.0. Ярусы: дерево 2, камень 4, железо 6,
     алмаз 8, золото 12. Меч: паутина 15, `sword_efficient` (листва, трава, цветы) 1.5. Ножницы (листва 15) — вне пути;
  2. если скорость > 1 — `+ player.mining_efficiency` (чары «Эффективность»; у нас 0);
  3. спешка (`Haste`): `×(1 + 0.2·(уровень+1))`; усталость (`Mining Fatigue`): ×0.3 / 0.09 / 0.0027 / 8.1e-4 — только упомянуть;
  4. `× player.block_break_speed` (1.0);
  5. **глаза под водой** (`isSubmergedIn(WATER)`: Y глаз ниже поверхности воды в клетке глаз) → `× player.submerged_mining_speed`
     = **0.2** (зачарование «Подводник» поднимает — вне объёма);
  6. **не на земле** (`!isOnGround()`) → **÷5**.
- Под водой, не касаясь дна: ×0.2 и ÷5 → в 25 раз медленнее.
- Присед, бег, ходьба на скорость не влияют.

Теги [data]: `mineable/pickaxe` — камень, булыжник, руды, печь, песчаник; `mineable/axe` — `#logs`, `#planks`, верстак,
`short_grass`, `tall_grass`, `#saplings`; `mineable/shovel` — земля, дёрн, песок, гравий, глина, снег; `mineable/hoe` — листва;
`needs_stone_tool` — железная руда (не угольная); `incorrect_for_wooden_tool` = `needs_stone/iron/diamond_tool`.
`requiresTool` [src `Blocks`]: камень, булыжник, руды, печь, песчаник, снег-блок.

## 7. Трещины (стадии 0–9)

**Расчёт** [src `ClientPlayerInteractionManager.getBlockBreakingProgress`]: `stage = progress > 0 ? (int)(progress·10) : −1`
(float). Обновляется в каждом тике прогресса и при начале (−1). При поломке прогресс обнуляется → −1 → трещины убраны.
Примеры [java/numpy]: земля рукой по тикам прогресса — 0,1,2,2,3,4,4,5,6,6,7,8,8,9, на 15-м сломано; бревно рукой — стадия k
появляется на тиках 1, 6, 12, 18, 24, 30, 36, 42, **49**, 55, поломка на 61.

**Когда сбрасываются**: отпускание ЛКМ, уход прицела на воздух/за 4.5, клик по другому блоку, смена цели при удержании,
смена предмета в руке (другой тип/компоненты), поломка. Не сбрасываются: открытый экран (замирают до закрытия, §11).

**Хранение** [src `WorldRenderer.setBlockBreakingInfo`, `tick`]: запись на **каждого ломающего** (по id сущности): стадия
0…9 — поставить/перенести, иначе удалить. Если на блоке несколько записей, рисуется **наибольшая стадия**. Записи без
обновления > 400 тиков удаляются (раз в 20 тиков). Дальность показа — 32 блока (расстояние² ≤ 1024 от камеры).

**Отрисовка** [src `WorldRenderer.render` «destroyProgress», `BlockRenderManager.renderDamage`, `OverlayVertexConsumer`,
`RenderLayer` «crumbling», `RenderPhase`; data `rendertype_crumbling.fsh`]:
- только для блоков с обычной моделью (`BlockRenderType.MODEL`); геометрия — **та же модель блока** с отсечением закрытых граней
  (видны трещины только на открытых гранях);
- текстура — `textures/block/destroy_stage_N.png`, без размытия и mipmap; UV — **плоская проекция позиции в координатах блока**
  на плоскость грани (масштаб 1: одна текстура 16×16 на грань полного блока; у меньших моделей — её кусок). Посчитано по
  кватернионам граней [вывод]: верх `u = x, v = z`; низ `u = x, v = −z`; юг (+Z) `u = x, v = −y`; север `u = −x, v = −y`;
  восток (+X) `u = z, v = −y`; запад `u = −z, v = −y` (повтор текстуры; верх текстуры у верха боковой грани; знак u на
  E/W глазами не проверен — для шумовой текстуры неважно);
- цвет вершин белый, без освещения и тумана; во фрагментном шейдере `alpha < 0.1` → discard;
- смешивание `src·DST_COLOR + dst·SRC_COLOR` = **2·tex·фон** (серый 0.5 не меняет блок, темнее — темнит, светлее — осветляет),
  альфа `ONE, ZERO`; запись **только цвета**, глубина не пишется; **polygon offset (−1, −10)**.
- Блок-сущности (сундук, P2) получают трещины другим путём (`VertexConsumers.union`) — пока не нужно.

**Что видит клиент от сервера**: свои трещины клиент рисует сам; сервер шлёт стадии **другим** игрокам в радиусе 32
(`ServerWorld.setBlockBreakingInfo` пропускает самого ломающего), считая их по времени: `delta·(тиков_с_начала + 1)`. Для
нас (один игрок) — не нужно.

## 8. Взмах руки (BRK-06) [src `LivingEntity.swingHand`, `tickHandSwing`, `getHandSwingDuration`, `getHandSwingProgress`, `PlayerEntity.tickNewAi`, `LivingEntity.baseTick`]

- Длительность `D = 6` тиков (спешка: `6 − (1+ур.)`, усталость: `6 + 2·(1+ур.)`).
- `swingHand`: запускает заново (`ticks = −1`, `swinging = true`), только если взмаха нет, **или прошла половина**
  (`ticks ≥ D/2 = 3`, целочисленно), или `ticks < 0`.
- Тик игрока: `last = progress`; если `swinging`: `ticks++`, при `ticks ≥ D` — `ticks = 0`, `swinging = false`;
  `progress = ticks / D`.
- Отрисовка: `p(t) = last + Δ·t`, где `Δ = progress − last`, и если `Δ < 0` — `Δ += 1` (переход через конец).
- **Когда вызывается** при ломании: в `doAttack` (каждый клик — по блоку, в воздух, по сущности) и в `handleBlockBreaking`
  **каждый тик**, когда `updateBlockBreakingProgress` вернул true: тики прогресса, тик начала и **тики кулдауна между блоками**.
  Не вызывается: удержание ЛКМ в воздухе (только один взмах от клика), открытый экран, `attackCooldown > 0`.
- **Частота при удержании** [вывод]: значения `progress` по тикам `0, 1/6, 2/6, 3/6, 0, 1/6, …` — перезапуск каждые **4 тика
  (0.2 с)**. Видимая дуга: 0→⅙→⅓→½ за три тика и ½→1 **за один тик** (быстрый возврат), затем снова. Одиночный клик — полный
  взмах `0, ⅙, …, ⅚, 0` = **6 тиков (0.3 с)**.
- Сопутствующее (ASP-11/TOOL-04): `cancelBlockBreaking` и клик в воздух делают `resetLastAttackedTicks()` → предмет в руке
  опускается и поднимается по `кулдаун³` (рука — 5 тиков, кирка 1.2 уд/с — 16.7 тика). Во время самого ломания сброса нет.

## 9. Что происходит при поломке

Клиент (предсказание; `ClientPlayerInteractionManager.breakBlock`) [src]:
1. Отказ, если приключение, предмет не может ломать (`Item.canMine`: меч в креативе — нет; в выживании всё может), блок —
   воздух или командный блок.
2. `Block.onBreak` → `spawnBreakParticles` → **мировое событие 2001** (`WorldEvents.BLOCK_BROKEN`) с id старого состояния:
   `WorldRenderer.processWorldEvent` играет **звук разрушения** в центре блока, громкость `(v+1)/2`, высота `p·0.8` (у групп
   пути v = p = 1 → 1.0 / 0.8), и `addBlockBreakParticles` — сетка частиц по коробкам outline-формы, шаг 0.25 (минимум 2 по оси):
   **4×4×4 = 64 `BlockDustParticle`** для куба, скорость от центра. Подробности частиц и звуков — ASP-13.
3. `setBlockState(pos, состояние_жидкости_в_клетке /* обычно воздух */, NOTIFY_ALL_AND_REDRAW = 11)`: флаг 8 = «перестроить
   секции в главном потоке» — секции блока ±1 по каждой оси помечаются важными. В ванили по умолчанию (`prioritizeChunkUpdates =
   NONE`, «Threaded») важные тоже строятся асинхронно; синхронно — только в режимах «Semi-blocking»/«Fully blocking». [src
   `WorldRenderer.updateBlock`, `GameOptions`]
4. `Block.onBroken` (у наших блоков пусто).

Во время ломания (каждый тик удержания на блоке): **крошка** `addBlockBreakingParticles(pos, грань)` — одна частица в
случайной точке грани, на 0.1 снаружи outline-коробки, `move(0.2)`, `scale(0.6)`; **звук удара** — каждые 4 тика прогресса
(§4.4). [src]

Сервер (`ServerPlayerInteractionManager.tryBreakBlock`) [src] — у нас в той же Rust-логике, в том же тике:
`onBreak` → `removeBlock` → `onBroken` → износ `postMine` (ASP-06: −1, если твёрдость ≠ 0) → если `canHarvest` — `afterBreak`:
статистика, истощение 0.005 (голода у нас нет), **`dropStacks`** по таблице добычи с инструментом (ASP-06), предмет появляется
в центре ±0.25 (ASP-07).

## 10. Растения, трава и блок над сломанным [src `PlantBlock`, `TallPlantBlock`, `AbstractTorchBlock`, `Block.replace`, `World.breakBlock`, `SugarCaneBlock`]

- Растения (`breakInstantly` = твёрдость 0): трава, папоротник, мёртвый куст, цветы, саженцы, факел — **ломаются за 1 тик**
  любым предметом; износа нет (твёрдость 0). Трава-растение даёт семена пшеницы с шансом 12.5% (ножницами — саму траву) [data
  `loot_table/blocks/short_grass.json`] — ASP-06.
- **Блок над сломанным**: при `setBlockState` соседи получают обновление. Растение проверяет опору (`canPlaceAt`: под ним
  `#dirt` или пашня; факел — прочный центр верхней грани) и возвращает воздух → `Block.replace` → `world.breakBlock(pos,
  drop=true)`: **событие 2001** (звук и крошки по его форме: трава-растение 3×4×3 = 36, цветок и факел 2×3×2 = 12),
  **дроп по таблице без инструмента**, затем воздух. Всё —
  **в том же тике**, цепочкой обновлений.
  - На клиенте Minecraft этот шаг пропускает (`!world.isClient`) — трава висит в воздухе до ответа сервера. У нас логика одна —
    убирать сразу.
  - Высокая трава: снизу опора пропала → нижняя половина → воздух → верхняя тоже (её сосед снизу больше не та же трава).
  - Сахарный тростник/кактус — через **запланированный тик +1** (цепочка вверх по тику на блок) — вне пути.
  - Песок/гравий над — падение через запланированный тик (+2), ASP-05.
  - Листва над бревном — пересчёт `distance` и опад по случайным тикам, ASP-06 (BLK-04).
- Дёрн (`grass_block`) под сломанной травой не меняется; сам дёрн дропает землю (ASP-06).

## 11. Граничные случаи и мелочи

1. **Блок, на котором стоишь** — ломается как любой. Падение на 1 блок занимает 5 тиков движения (скорость
   −0.0784 → −0.155 → −0.231 → −0.304 → −0.377, путь 1.145 > 1; ASP-02) и **целиком прячется в 6-тиковой паузе** цепочки:
   копая вниз с зажатой ЛКМ, следующий блок начинает трескаться уже на земле, без ÷5. [вывод] Если оторвался от земли (прыжок,
   падение) во время прогресса — тики в воздухе идут с ÷5.
2. **Цель вне досягаемости**: клик → MISS → взмах + `attackCooldown = 10`. Уход прицела за 4.5 (или на небо) во время ломания →
   `cancelBlockBreaking` (трещины пропали). Вернувшись **на тот же блок тем же предметом** при зажатой ЛКМ, прогресс идёт сразу
   с нуля **без тика начала** (`currentBreakingPos` не сбрасывается, а проверка «тот же блок» не смотрит на `breakingBlock`).
   То же — если на место сломанного поставили новый блок и снова бьёшь по нему, не меняя предмет. [вывод]
3. **Смена слота во время ломания** (колесо — сразу, 1–9 — в начале обработки ввода тика): другой тип предмета/компоненты →
   «другой блок» → `attackBlock`: прогресс 0, трещины заново, +1 тик начала, без кулдауна. Переключение между **одинаковыми**
   предметами (две пустые руки, две новые деревянные кирки) — прогресс **продолжается**. Подбор предмета в выбранный пустой
   слот во время ломания рукой — тоже сброс. Изменение количества в стеке — не сброс. [src]
4. **Инструмент сменился на лучший** — `delta` пересчитывается каждый тик, но смена слота сама сбрасывает прогресс (п. 3).
5. **Открыт экран** (инвентарь E, чат): `handleInputEvents` не вызывается — трещины **замирают** на текущей стадии. После
   закрытия кнопки отпущены (`KeyBinding.unpressAll` при открытии) → следующий тик `cancelBlockBreaking`. [src]
6. **Esc / потеря фокуса / выход из Pointer Lock**: `held` требует захваченного курсора → отмена в ближайшем тике (ASP-01).
7. **Еда/использование предмета**: нажатия ЛКМ выбрасываются, ломание не идёт и не отменяется. Наоборот, ПКМ не работает,
   пока `isBreakingBlock()` (ASP-05: общий путь). [src]
8. **Несколько кликов за тик**: каждый — отдельный `doAttack` с одним и тем же `crosshairTarget`; второй по уже сломанному
   мгновенному блоку уходит в ветку MISS (`attackCooldown = 10`, сброс кулдауна атаки). [src]
9. **Голова внутри блока** (верхняя половина высокой травы, позже — ступор в песке): луч попадает в него сразу (`insideBlock`),
   грань — против взгляда. Стоя в высокой траве, сначала срезаешь её. [src]
10. **Трава-растение ниже глаз**: outline 13/16 высоты — луч над кустом проходит к блоку за ним; рамка у травы — коробка
    12×13×12/16. [src]
11. **Сквозь воду** — луч выбирает дно; ломание дна с головой под водой ×0.2. [src]
12. **Бедрок** (твёрдость −1): `delta = 0` — трещин нет совсем (стадия −1), звук удара и крошки есть. [src]
13. **Мгновенный блок после обычного при удержании** — ждёт остаток кулдауна (до 5 тиков); после мгновенного кулдауна нет.
14. **Прицел на падающий блок** — сущность перехватывает луч: ломание отменяется, клик = атака сущности (ASP-05/07).
15. **Креатив** (отладочный полёт): дальность 5.0, каждый блок мгновенно, между блоками при удержании кулдаун 5. [src]

## 13. Чего нет в исходнике / не ясно

## 14. Сценарий проверки человеком

Подготовка: выживание, новая сессия, выбран **пустой слот 9**, слот 8 тоже пуст (подобранное ложится в слоты 1…); ровная
поляна у дерева; звук включён; частота кадров любая. Между пунктами ЛКМ отпускать. Важная мелочь: если до этого сломан
обычный (не мгновенный) блок, следующий обычный блок начинает трескаться на **~0.25 с позже** — это не задержка ввода, так в
Minecraft (§4.7 C); ожидаемые времена ниже уже это учитывают.

1. **Рамка.** Навести на дёрн в 2 блоках: тонкая полупрозрачная чёрная рамка по рёбрам куба, ~2–3 px, не мерцает при
   движении. Навести на траву-растение: рамка — небольшая коробка ниже верха клетки. Медленно отходить назад от стены: рамка
   пропадает, когда до точки на грани ~4.5 блока от глаз.
2. **Бревно рукой** (первое ломание сессии). Держу ЛКМ: трещины проходят 10 стадий равномерно (~каждые 0.3 с), тук-тук
   ~5 раз в секунду, рука часто машет короткими взмахами (~5 раз в секунду), с грани сыплются крошки. Блок исчезает через
   **~3 с** с хрустом и облачком кусочков; бревно попадает в хотбар.
3. **Земля подряд.** Не отпуская ЛКМ, копаю 5 блоков земли перед собой: первый — **~1 с** (0.75 + пауза после бревна), каждый
   следующий — **~1.05 с**; между исчезновением блока и первыми трещинами на следующем — пауза **~0.35 с**, в ней рука
   продолжает махать и сыплются крошки, но тука нет. Всего ~5.2 с.
4. **Камень рукой.** Держу ЛКМ: **~7.8 с** (7.55 + пауза), блок исчезает, **ничего не выпало**.
5. **Отпускание.** Начинаю бить бревно: трещины появляются не сразу, а через ~0.25 с (пауза после камня). На середине отпускаю
   ЛКМ — трещины пропадают сразу, рука делает «опустить-поднять». Нажимаю снова — трещины с нуля и **сразу**, без паузы.
6. **Прыжок.** Держу ЛКМ на земле и подпрыгиваю: пока в воздухе, трещины почти стоят; ломание заметно дольше 0.75 с.
7. **Копаю под собой.** Смотрю вниз, держу ЛКМ: проваливаюсь на блок; следующий начинает трескаться через миг (~0.1 с) после
   приземления, ритм ровный: дёрн ~1.1 с, дальше земля ~1.05 с на блок, без замедления от падения.
8. **Трава.** Последним сломан обычный блок. Нажимаю ЛКМ на куст травы и веду прицелом по полю: первый куст срезается **сразу**
   (нажатие — это клик), затем пауза ~0.25 с, дальше — **по кусту за тик**, сплошной полосой. Задержался на месте — начинает
   копаться дёрн под травой.
9. **Трава над землёй.** Ломаю дёрн, на котором растёт трава: трава исчезает **в тот же момент**, со своим шорохом и
   зелёными крошками; иногда выпадают семена.
10. **Слот.** Бью бревно рукой (слот 9), на середине колесом перехожу на пустой слот 8 — трещины **продолжаются**; на слот с
    бревном — начинаются заново.
11. **Клик в воздух.** Кликаю в небо и, не отпуская, навожу на бревно: трещины появляются примерно через полсекунды.

Ожидаемое везде: никаких рывков меша — блок пропадает в тот же кадр, что и звук разрушения; соседний кусок без щелей.

## 16. Что нужно от движка и как это ляжет в архитектуру

Решение: логика и мир — Rust (WASM), JS — ввод, рендер, UI (`mc/decisions.md`).

**E2 — луч в Rust (главный поток)**. Сейчас `World::raycast` (`src/world.rs`) считает любой не-воздух/не-воду полным кубом,
сравнивает с дальностью вход в клетку (`t <= max`, включительно) и не отдаёт точку. Нужно: таблица outline-форм по id блока
(список коробок в 1/16; §2.6), проверка формы в клетке как в §2.4 (включая «внутри» и допуск 1e-7), удлинение отрезка на 1e-7,
порядок ничьих как в §2.3, дальность по точке попадания **строго** `< 4.5`, ответ `{pos, face, point, inside}` в f64. Отдельно —
таблица collision-форм (ASP-02), не путать.

**E3 — порядок тика** (`src/game.rs`, `web/game/loop.js`): JS за кадр копит число нажатий ЛКМ/ПКМ, состояние «зажато»,
флаги «экран открыт» и «Pointer Lock», выбранный слот, текущие yaw/pitch → `Game::tick(input)`. В Rust в начале тика: луч с
текущей позицией глаз (`t = 1`) → ввод (§1.2 п. 5) → `handleBlockBreaking` → движение игрока → взмах. Для рамки — отдельный
вызов в кадре `pick(alpha, yaw, pitch)` с интерполированными глазами.

**E1 — изменяемый мир**: `set_block(..., AIR)` уже отдаёт затронутые куски. Нужно: до удаления сохранить старый блок (для
звука/частиц/дропа), удалить, обновить соседей (растения без опоры — §10, в том же тике), **синхронно перестроить меш куска
и соседей ±1 по X/Z в этом же кадре** (как «Semi-blocking»; кусок 16×128×16 — до 4 кусков на углу). Это ключевое ощущение.

**E8 — ресурсы**: 10 своих текстур трещин 16×16 (серые с альфой, без mipmap), свои звуки групп (удар/разрушение) — по
решению: свободные паки CC0/CC-BY.

**Рендер (JS)**: (а) рамка — рёбра коробок формы, экранные квадраты шириной `max(2.5, W/1920·2.5)` px, rgba(0,0,0,0.4), сдвиг к
камере ×0.99975586·(1−1/256), тест глубины on; (б) проход трещин — открытые грани выбранного блока (или вся outline-форма для
полных блоков), UV по §7, blend `gl.blendFuncSeparate(DST_COLOR, SRC_COLOR, ONE, ZERO)`, `depthMask(false)`,
`polygonOffset(−1, −10)`, discard при α < 0.1. Рисовать после непрозрачного мира, до воды/частиц; наши SSAO/пост-обработка не
должны «съедать» трещины — проверить отдельно.

**E9 — рука**: Rust отдаёт `swing_progress` и `last_swing_progress` (+ `attack_cooldown_progress` для опускания предмета),
JS интерполирует по §8. Модель руки — ASP-11; в срезе 1 хватит куба-руки.

**E10 — звук и частицы**: события из тика: `HitSound{pos, group}` (раз в 4 тика прогресса), `Crumb{pos, face, block}` (каждый
тик удержания), `Broken{pos, old_block}` (звук разрушения + 64 частицы). Частицы — кусочки текстуры блока (ASP-13).

**E4 (позже)**: лучу нужны сущности — падающий блок перехватывает луч; выпавшие предметы — нет.

## 17. Набросок на Rust (своими словами, не копия Java)

```rust
// ---------- Луч по блокам с формами ----------
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Face { Down, Up, North, South, West, East } // −Y +Y −Z +Z −X +X

#[derive(Clone, Copy)]
pub struct Aabb { pub min: [f64; 3], pub max: [f64; 3] } // в долях блока, 0..1

pub struct Hit { pub pos: [i32; 3], pub face: Face, pub point: [f64; 3], pub inside: bool }

const EPS: f64 = 1e-7;

/// Грань, в которую «смотрит» вектор (наибольшая проекция), как Direction.getFacing.
fn facing(d: [f64; 3]) -> Face {
    let c = [(d[1] * -1.0, Face::Down), (d[1], Face::Up), (-d[2], Face::North),
             (d[2], Face::South), (-d[0], Face::West), (d[0], Face::East)];
    let mut best = (f64::MIN_POSITIVE, Face::North);
    for (v, f) in c { if v > best.0 { best = (v, f); } }
    best.1
}
fn opposite(f: Face) -> Face { use Face::*; match f { Down=>Up, Up=>Down, North=>South, South=>North, West=>East, East=>West } }

/// Попадание отрезка a→b в форму клетки `cell` (коробки `shape`).
fn hit_shape(cell: [i32; 3], shape: &[Aabb], a: [f64; 3], b: [f64; 3]) -> Option<Hit> {
    if shape.is_empty() { return None; }
    let d = [b[0] - a[0], b[1] - a[1], b[2] - a[2]];
    if d[0] * d[0] + d[1] * d[1] + d[2] * d[2] < 1e-7 { return None; }
    let o = [cell[0] as f64, cell[1] as f64, cell[2] as f64];
    // Начало (чуть сдвинутое вдоль луча) уже внутри формы — блок, в котором стоят глаза.
    let p = [a[0] + d[0] * 0.001, a[1] + d[1] * 0.001, a[2] + d[2] * 0.001];
    let inside = shape.iter().any(|s| (0..3).all(|k| p[k] - o[k] >= s.min[k] && p[k] - o[k] < s.max[k]));
    if inside { return Some(Hit { pos: cell, face: opposite(facing(d)), point: p, inside: true }); }
    // Плоскость входа по каждой оси, ближайшее попадание по всем коробкам.
    let mut best_t = 1.0;
    let mut best_face = None;
    for s in shape {
        for k in 0..3 {
            let (plane, face) = if d[k] > EPS { (o[k] + s.min[k], [Face::West, Face::Down, Face::North][k]) }
                                else if d[k] < -EPS { (o[k] + s.max[k], [Face::East, Face::Up, Face::South][k]) }
                                else { continue };
            let t = (plane - a[k]) / d[k];
            if !(t > 0.0 && t < best_t) { continue; }
            let ok = (0..3).filter(|&j| j != k).all(|j| {
                let c = a[j] + t * d[j] - o[j];
                c > s.min[j] - EPS && c < s.max[j] + EPS
            });
            if ok { best_t = t; best_face = Some(face); }
        }
    }
    best_face.map(|face| Hit { pos: cell, face, inside: false,
        point: [a[0] + best_t * d[0], a[1] + best_t * d[1], a[2] + best_t * d[2]] })
}

/// Цель взгляда: DDA по клеткам, outline-формы, жидкости насквозь, дальность по точке попадания.
pub fn pick(world: &World, eye: [f64; 3], dir: [f64; 3], reach: f64) -> Option<Hit> {
    let end = [eye[0] + dir[0] * reach, eye[1] + dir[1] * reach, eye[2] + dir[2] * reach];
    // Удлинить отрезок на 1e-7 его длины в обе стороны — только для обхода клеток.
    let lerp = |t: f64, x: f64, y: f64| x + t * (y - x);
    let s: [f64; 3] = std::array::from_fn(|k| lerp(-EPS, eye[k], end[k]));
    let e: [f64; 3] = std::array::from_fn(|k| lerp(-EPS, end[k], eye[k]));
    let mut c = [s[0].floor() as i32, s[1].floor() as i32, s[2].floor() as i32];
    let test = |c: [i32; 3]| hit_shape(c, outline(world.get_block(c[0], c[1], c[2])), eye, end);
    let mut hit = test(c);
    if hit.is_none() {
        let d: [f64; 3] = std::array::from_fn(|k| e[k] - s[k]);
        let step: [i32; 3] = std::array::from_fn(|k| if d[k] > 0.0 { 1 } else if d[k] < 0.0 { -1 } else { 0 });
        let td: [f64; 3] = std::array::from_fn(|k| if step[k] == 0 { f64::MAX } else { step[k] as f64 / d[k] });
        let mut tm: [f64; 3] = std::array::from_fn(|k| {
            let fr = s[k] - s[k].floor();
            td[k] * if step[k] > 0 { 1.0 - fr } else { fr }
        });
        while hit.is_none() && (tm[0] <= 1.0 || tm[1] <= 1.0 || tm[2] <= 1.0) {
            // Ничья: X уступает Y/Z, Y уступает Z.
            let k = if tm[0] < tm[1] { if tm[0] < tm[2] { 0 } else { 2 } } else if tm[1] < tm[2] { 1 } else { 2 };
            c[k] += step[k];
            tm[k] += td[k];
            hit = test(c);
        }
    }
    // Годится только точка строго ближе дальности.
    hit.filter(|h| (0..3).map(|k| (h.point[k] - eye[k]).powi(2)).sum::<f64>() < reach * reach)
}

// ---------- Ломание: машина состояний (тик 20 Гц) ----------
#[derive(Clone, Copy, PartialEq)]
pub struct ToolKey { pub item: u16, pub damage: u16 } // «тот же предмет»: тип + компоненты, без количества

pub struct Mining {
    pos: [i32; 3],      // последняя начатая позиция; не сбрасывается при отмене и поломке
    tool: ToolKey,
    progress: f32,      // именно f32: 61 тик для бревна рукой
    hits: f32,          // счётчик для звука удара
    cooldown: i32,      // 5 после обычной поломки; убывает только при удержании на блоке
    active: bool,
}

pub enum Ev { Start([i32; 3]), Crack([i32; 3], i8), HitSound([i32; 3]), Crumb([i32; 3], Face), Broken([i32; 3], u8), Swing }

pub struct Ctx<'a> { pub world: &'a mut World, pub hand: ToolKey, pub on_ground: bool, pub eyes_in_water: bool }

fn delta(ctx: &Ctx, block: u8) -> f32 {
    let h = hardness(block);                 // f32; −1 — неломаемый
    if h < 0.0 { return 0.0; }
    let mut f = tool_speed(ctx.hand, block); // 1.0 рукой / не тем, иначе скорость яруса
    if ctx.eyes_in_water { f *= 0.2f32; }
    if !ctx.on_ground { f /= 5.0; }
    f / h / if can_harvest(ctx.hand, block) { 30.0 } else { 100.0 } // h = 0 → +∞ → мгновенно
}

impl Mining {
    fn same(&self, pos: [i32; 3], hand: ToolKey) -> bool { self.pos == pos && self.tool == hand }

    /// Начало (клик или новая цель при удержании). true — блок сломан сразу.
    fn start(&mut self, ctx: &mut Ctx, pos: [i32; 3], ev: &mut Vec<Ev>) -> bool {
        if self.active && self.same(pos, ctx.hand) { return false; }
        let b = ctx.world.get_block(pos[0], pos[1], pos[2]);
        if delta(ctx, b) >= 1.0 { self.break_block(ctx, pos, ev); return true; }
        *self = Mining { pos, tool: ctx.hand, progress: 0.0, hits: 0.0, cooldown: self.cooldown, active: true };
        ev.push(Ev::Crack(pos, -1));
        ev.push(Ev::Start(pos));
        false
    }

    /// Тик удержания на блоке. true — показать крошку и взмахнуть.
    fn hold(&mut self, ctx: &mut Ctx, pos: [i32; 3], ev: &mut Vec<Ev>) -> bool {
        if self.cooldown > 0 { self.cooldown -= 1; return true; }
        if !self.same(pos, ctx.hand) { self.start(ctx, pos, ev); return true; }
        let b = ctx.world.get_block(pos[0], pos[1], pos[2]);
        if b == AIR { self.active = false; return false; }
        self.progress += delta(ctx, b);
        if self.hits % 4.0 == 0.0 { ev.push(Ev::HitSound(pos)); }
        self.hits += 1.0;
        if self.progress >= 1.0 {
            self.active = false;
            self.break_block(ctx, pos, ev);
            self.progress = 0.0;
            self.hits = 0.0;
            self.cooldown = 5;
        }
        let stage = if self.progress > 0.0 { (self.progress * 10.0) as i8 } else { -1 };
        ev.push(Ev::Crack(pos, stage));
        true
    }

    fn cancel(&mut self, ev: &mut Vec<Ev>) {
        if self.active { self.active = false; self.progress = 0.0; ev.push(Ev::Crack(self.pos, -1)); }
        // + сброс кулдауна атаки для руки (ASP-11)
    }

    fn break_block(&mut self, ctx: &mut Ctx, pos: [i32; 3], ev: &mut Vec<Ev>) {
        let old = ctx.world.get_block(pos[0], pos[1], pos[2]);
        ev.push(Ev::Broken(pos, old));            // звук разрушения + 64 частицы (событие 2001)
        ctx.world.set_block(pos[0], pos[1], pos[2], AIR); // + обновить соседей: растения без опоры (§10), дроп (ASP-06/07)
    }
}

/// Шаг ввода атаки в тике: clicks — нажатий ЛКМ с прошлого тика, held — зажата и курсор захвачен, экран закрыт.
pub fn attack_tick(m: &mut Mining, attack_cd: &mut i32, ctx: &mut Ctx, target: Option<&Hit>,
                   clicks: u32, held: bool, ev: &mut Vec<Ev>) {
    let mut broke_now = false;
    for _ in 0..clicks {
        if *attack_cd > 0 { continue; }
        match target {
            Some(h) if ctx.world.get_block(h.pos[0], h.pos[1], h.pos[2]) != AIR => {
                broke_now |= m.start(ctx, h.pos, ev);
            }
            _ => { *attack_cd = 10; } // воздух или уже сломанный (+ сброс кулдауна атаки)
        }
        ev.push(Ev::Swing);
    }
    let held = held && !broke_now;
    if !held { *attack_cd = 0; }
    if *attack_cd <= 0 {
        match target {
            Some(h) if held && ctx.world.get_block(h.pos[0], h.pos[1], h.pos[2]) != AIR => {
                if m.hold(ctx, h.pos, ev) { ev.push(Ev::Crumb(h.pos, h.face)); ev.push(Ev::Swing); }
            }
            _ => m.cancel(ev),
        }
    }
    if *attack_cd > 0 { *attack_cd -= 1; }
}
```

Взмах (в тике игрока, после ввода): `Swing` → если `!swinging || ticks >= 3 || ticks < 0 { ticks = -1; swinging = true }`;
затем `last = progress; if swinging { ticks += 1; if ticks >= 6 { ticks = 0; swinging = false } }; progress = ticks / 6`.
