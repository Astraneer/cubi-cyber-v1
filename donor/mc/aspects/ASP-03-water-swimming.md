# ASP-03 Вода, плавание и воздух

Этап 2, разбор исходников Minecraft Java **1.21.1**. Механики каталога: MOV-10, MOV-11 (как сила), MOV-12 (ссылка на
ASP-12), BLK-08 (ссылки), CAM-02 (подводный FOV), часть HUD-02 (пузыри — ASP-12). Код игры здесь не пишется.

Пометки: **[src]** — прочитано в зеркале Yarn `Soumeh/1.21.1-Deobfuscated`, коммит `414d1696…` (пути от
`minecraft/src/net/minecraft/`); **[data]** — `misode/mcmeta` 1.21.1 (`sounds.json`, `shaders/include/fog.glsl`,
`worldgen/biome/*.json`, теги); **[расчёт]** — независимая модель тика по формулам из [src] (f32 там, где Java во float;
скрипт `wsim.py` у исследователя в scratchpad); **[вывод]** — следует из нескольких мест кода; **[не проверено]** —
нужно смотреть в игре. Ссылки на соседние аспекты: ASP-01-02 (тик, коллизия, бег, FOV, глаза), ASP-04 (ломание ×0.2),
ASP-07 (предметы в воде), ASP-12 (воздух, утопление, пузыри HUD), ASP-15 (текучая вода и вёдра — параллельно).

Граница с ASP-15: здесь вода — **среда для игрока**: где она, какой высоты, как меняет движение, камеру и звук. Откуда
берутся уровни, течение и вектор потока клетки (`FlowableFluid.getVelocity`) — ASP-15; здесь — только как этот вектор
превращается в толчок игрока. Пока воды-потока нет, толчок равен нулю.

## 0. Главное коротко

1. **Три разных «в воде»** [src]: *касание* (`touchingWater`: коробка, сжатая на 0.001, задевает воду ниже её
   поверхности) — включает водную физику; *глаза в воде* (`isSubmergedIn(WATER)`: точка глаз ниже поверхности в своей
   клетке) — воздух, ломание ×0.2, оверлей, привыкание зрения; *камера в воде* (`Camera.getSubmersionType`, по
   сглаженной камере) — FOV ×0.857 и туман. Для решений о беге и плавании берётся флаг глаз **прошлого тика**.
2. **Высота воды в клетке** [src `FlowableFluid.getHeight`]: вода сверху → 1.0, иначе `level/9`; источник с воздухом
   над ним — **8/9 = 0.8888889**. Поверхность нашего моря — **48.889**; меш кладёт верх на 49.0, шейдер `water.js`
   опускает его на 0.12 → видно на 48.88 (почти совпадает; свести к одной константе — §16 п.1).
3. **Движение в воде** [src `LivingEntity.travel`]: ускорение **0.02F** (на дне тоже — наземного нет), после `move`
   скорость ×(**0.8F**, 0.8F, 0.8F), при беге/плавании по горизонтали ×**0.9F**; гравитация — **−0.005** за тик
   (g/16), а при беге (и плавании кролем) **гравитации нет вовсе**. Ветка «−0.003 у нуля» в коде недостижима.
4. **Space в воде** [src `LivingEntity.tickMovement`]: при касании и высоте воды > 0 — всегда `swimUpward` **+0.04F**
   (даже стоя на дне в воде по колено); обычный прыжок 0.42 — только на земле при высоте воды ≤ 0.4 (у неподвижных
   источников не бывает). **Shift** — `knockDownwards` **−0.04F** каждый тик касания.
5. **Эталоны** [расчёт]: тону без ввода **0.5 б/с**; Space — **3.5 б/с** вверх; Shift — **4.5 б/с** вниз; W —
   **1.96 б/с** (по дну так же); кроль — **3.92 б/с**, вертикаль по взгляду до −6.34 б/с вниз и +4.84 вверх;
   у поверхности с Space голова качается над водой (период ~0.7 с, ноги −0.73…+0.24 от поверхности).
6. **Выход на берег** [src]: при упоре в стену в воде, если коробка, поднятая на ~0.6, **свободна от блоков и не
   задевает ни одной клетки с водой**, `vy = 0.3F`. На берег в 1 блок — выбираешься с Space+W без прыжка; в 2 блока —
   нельзя; без Space — нельзя.
7. **Кроль** [src `Entity.updateSwimming`, `PlayerEntity.travel/updatePose`]: начало — бег + глаза в воде (прошлый
   тик) + вода в клетке ступней; держится, пока бег и касание; поза 0.6×0.6, глаза 0.4; вертикаль тянется к `look_y`
   с коэффициентом 0.06 (0.085, если смотришь вниз круче ~11.5°); вверх тянет, только если над ступнями на 0.9 ещё
   вода или зажат Space. Причуда: на дне без W кроль не срывается.
8. **Течение** [src `Entity.updateMovementInFluid`]: у **игрока** вектор потока клеток **усредняется, но не
   нормируется** (каталог MOV-11 неточен), ×0.014; у мелкой воды (< 0.4) вклад клетки ×высоту; стоя — не меньше
   0.0045. Применяется в начале тика, до ввода.
9. **Камера** [src `GameRenderer.getFov`, `BackgroundRenderer`]: FOV ×**0.85714287** сразу (без сглаживания), и для
   руки; туман сфера, начало **−8**, конец **96 · max(0.25, привыкание)**, плавный (smoothstep), цвет — `water_fog_color`
   биома (у всех наших — **0x050533**), осветлённый по привыканию; привыкание растёт **+1/тик до 600** (60 % за первые
   5 с) и падает −10/тик вне воды. Оверлей `underwater.png` с альфой 0.1.
10. **Звук и частицы** [src][data]: всплеск при входе (громкость по скорости, ≥ 0.25 — «тяжёлый», с ~13.5 блока),
    13 пузырей + 13 брызг; звук плавания по пройденному пути (каждые 1.67 блока по горизонтали, очень тихий); вход и
    выход из-под воды, подводная петля с нарастанием 2 с и спадом 1 с, редкие добавки. Глушения звуков под водой в Java
    нет.
11. **fallDistance**: касание воды обнуляет его каждый тик и в тике входа — урона от падения в воду нет с любой высоты
    (ASP-12 §3.1).

## 2. Состояние «в воде»: определения

### 2.1 Высота воды в клетке [src `FlowableFluid.getHeight`, `FluidState.getHeight`]

- Клетка с водой той же жидкости **над ней** → высота **1.0**.
- Иначе `level / 9` (float): источник и падающая вода — level 8 → **0.8888889F**; текучая — 1/9…7/9 (ASP-15).
- Верх воды в клетке `y`: `y + высота`. У нас (море 48, вода в клетках `h+1 … 48`): верхняя клетка 48 —
  поверхность **48.8888889**, все ниже — полные.
- Формы коллизии у воды нет (`FluidBlock.getCollisionShape` пустая для игрока; «ходить по воде» нельзя). Луч сквозь
  воду — ASP-04; ставить блок в воду (заменяемая) — ASP-05. Это и есть BLK-08.

### 2.2 Касание и высота воды над низом коробки [src `Entity.updateMovementInFluid(WATER, 0.014)`]

1. Если кусок вокруг не загружен — касания нет (у нас всегда загружен, §3.14 ASP-02).
2. Коробка тела, **сжатая на 0.001** со всех сторон; перебор клеток `floor(min) … ceil(max) − 1` по трём осям.
3. Клетка воды, у которой верх `y + высота ≥ minY` (сжатой коробки), — «мокрая»: `касание = да`,
   `fluid_h = max(fluid_h, верх − minY)`.
4. Тут же копится вектор потока (§7). Результат: флаг касания и `fluid_h` — «сколько воды над ступнями внутри
   коробки» (может быть > 1.8 в глубине — это число, а не доля).

Следствия [вывод]: стоя на берегу на уровне выше воды — касания нет (клетка воды ниже `floor(minY)`); прислонившись к воде
сбоку вплотную — нет (сжатие 0.001); стоя на дне воды по колено — да, `fluid_h = 0.888`.

### 2.3 Глаза в воде [src `Entity.updateSubmergedInWaterState`]

- Точка глаз `y + eye(поза)` (1.62 / 1.27 / 0.4 — **несглаженная** высота позы), клетка `floor(x), floor(eyeY), floor(z)`.
- «Под водой», если в этой клетке вода и её верх **строго больше** `eyeY`. Список тегов жидкости при глазах
  (`submergedFluidTag`) пересчитывается здесь, в `baseTick`.
- Метод сначала **запоминает прошлое** значение тега в поле `submergedInWater`, потом пересчитывает. Игрок к тому же
  в начале `PlayerEntity.tick` копирует тег в своё поле `isSubmergedInWater` (до `baseTick`). Значит:

| Флаг | Что это | Кто читает |
|---|---|---|
| `touching` (касание) | §2.2, текущая позиция начала тика | водная ветка `travel`, Shift вниз, Space-всплытие, срыв бега «касание без погружения», кроль держится, fallDistance = 0 |
| `eye_now` = `isSubmergedIn(WATER)` | глаза в воде, текущая позиция начала тика | воздух и утопление (ASP-12), ломание ×0.2 (ASP-04), привыкание зрения, оверлей, `getUnderwaterVisibility` |
| `eye_lag` = `isSubmergedInWater()` | глаза в воде **тиком раньше** | старт бега (двойное W, Ctrl), порог «иду вперёд», срыв бега, старт кроля, звуки входа/выхода, подводная петля и добавки |
| камера в воде | §9.1, по сглаженной интерполированной камере, каждый кадр | FOV ×0.857, туман и его цвет, небо |

Причуду «тиком позже» предлагаю повторить: она бесплатна (одно поле) и детерминирована.

## 4. Движение в воде

### 4.1 `LivingEntity.travel`, водная ветка [src]

Условие ветки: `touching` (шаг 2) и `shouldSwimInFluids` (не полёт) и не «ходит по жидкости». Все «на земле» — от
прошлого `move`.

1. `y0 = y`; трение по горизонтали `f = бег ? 0.9F : 0.8F`; ускорение `a = 0.02F`.
2. Атрибут `water_movement_efficiency` (у нас 0; «Подводная ходьба» сапог) и «Грация дельфина» — **пропускаются**
   (их ветки дают `f → 0.546`, `a → скорость ходьбы`, `f = 0.96`; не нужны).
3. `updateVelocity(a, ввод)`: как на суше (нормализация только при длине > 1, поворот по yaw). Наземного
   ускорения `0.216/p³` в воде **нет** даже на дне: по дну идёшь так же медленно, как плывёшь.
4. `move(скорость)` — обычная коллизия ASP-02 (защита края с Shift работает и на дне).
5. Если упор сбоку и лестница/лианы (`isClimbing`) — `vy = 0.2` **до** трения (после шагов 6–7 станет 0.155;
   лестницы в объёме, MOV-13).
6. `скорость ×= (f, 0.8F, f)`.
7. **Гравитация** (`applyFluidMovingSpeed(g = 0.08, падал = vy ≤ 0 до move)`): если **бег** — ничего; иначе
   `vy −= g/16 = 0.005`. Особая ветка «`vy = −0.003`» требует одновременно `|vy − 0.005| ≥ 0.003` и
   `|vy − 0.005| < 0.003` — **недостижима** при g = 0.08 [вывод; так же отмечено в cubi-core].
8. **Выход на берег** — §5.

Рекуррентность без ввода: `v ← 0.8·v − 0.005` → предел −0.025 б/т. Обнуление `< 0.003` в начале тика (шаг 10)
даёт старт `0, −0.005, −0.009, −0.0122, …`.

### 4.2 Space, прыжок и Shift [src `LivingEntity.tickMovement`, `ClientPlayerEntity.tickMovement`]

Space зажат (`jumping`), `wet = touching && fluid_h > 0`, `h = getSwimHeight() = 0.4` (у игрока всегда: глаза позы ≥ 0.4):

- если `!wet` или (`onGround` и `fluid_h ≤ 0.4`) → обычный прыжок `vy = 0.42F` (+0.2 по yaw при беге), если
  `onGround` и `cooldown == 0`, затем `cooldown = 10`. Ветка «`wet && fluid_h ≤ 0.4` без земли» в коде есть, но
  **мертва**: во внешнем условии без земли туда не попасть [вывод];
- иначе (`wet` и (не на земле или `fluid_h > 0.4`)) → **`swimUpward`: `vy += 0.04F`** — каждый тик, без кулдауна.
- Отпустил Space → `cooldown = 0`.

Следствия [вывод][расчёт]:
- У неподвижных источников (высота 0.889 над дном) обычного прыжка в воде нет вовсе: даже в воде по колено Space —
  всплытие. Подскок со дна по колено — **до 1.16** над дном за ~10 тиков, потом обратно; не 1.25 прыжка.
- Обычный прыжок из воды бывает только в тонкой текучей воде (≤ 0.4, ASP-15): тик прыжка уже водный
  (`0.42 → ×0.8 − 0.005 = 0.331` против 0.3332 на суше) — почти как на суше [расчёт приблизительный].
- **Shift**: в `ClientPlayerEntity.tickMovement` до `LivingEntity.tickMovement` — `vy −= 0.04F` при касании. Space и
  Shift вместе гасят друг друга → тонешь как без ввода. Shift ещё и приседает (ввод ×0.3), если не кроль.

### 4.3 Точность [src]

- Позиция и скорость — double; `0.8F, 0.9F, 0.02F, 0.04F, 0.3F, 0.6F, 0.42F, 0.98F` — float, расширяемые до double:
  0.800000011920929, 0.8999999761581421, 0.019999999552965164, 0.03999999910593033, 0.30000001192092896,
  0.6000000238418579. `g/16 = 0.005`, `0.014`, `0.0045000000000000005`, `0.06`, `0.085`, `0.4` — double.
- Ввод ×0.98F (float). `look_y = −sin(pitch)` во float (`getRotationVector`; у нас — точный sin, решение после ASP-01).

## 5. Выход на берег («выпрыгивание») [src `LivingEntity.travel`, `Entity.doesNotCollide`, `WorldView.containsFluid`]

После трения и гравитации (§4.1 шаг 7), если в этом `move` был **упор сбоку** (`horizontalCollision`, допуск 1e-5):

1. Пробная коробка = текущая коробка, сдвинутая на `(vx, vy + 0.6F − (y − y0), vz)` — то есть на высоту
   **`y0 + 0.6 + vy`** (над позицией начала тика) и вбок на оставшуюся скорость. По заблокированной оси скорость уже
   обнулена в `move`, поэтому вбок коробка в стену не уходит, а просто поднимается вдоль неё.
2. Годится, если коробка **не пересекает формы блоков** (касание гранью — не пересечение) **и не задевает ни одной
   клетки с водой**: `containsFluid` смотрит клетки `floor(min) … ceil(max) − 1` и проверяет только «есть ли жидкость»,
   **без высоты поверхности**.
3. Годится → `vy = 0.3F`.

Следствия [вывод][расчёт, §13.5]:
- Для берега на уровне `top` над клеткой воды `top − 1`: подъём сработает, когда `y0 + 0.6 + vy ≥ top`, то есть
  ступни на ~0.4–0.5 ниже края. Это достижимо только всплывая с Space (или кролем у самой поверхности).
- Срабатывает 1–2 тика подряд (0.3 → 0.34 с учётом Space), тело выходит из воды и долетает на берег по инерции.
- Берег в 2 блока: подъёмы тоже срабатывают, но ступни не выше ~0.1 под краем — **не вылезти** (как в ванили).
- Без Space ступни сидят ниже → пробная коробка задевает свою же клетку воды → **не срабатывает**. Из воды по колено
  на берег в 1 блок без Space тоже не выйти (ступенька 0.6 < 1).
- Работает и под водой у любой стены, но там пробная коробка всегда мокрая — значит, только у поверхности.

## 6. Бег и плавание кролем

### 6.1 Бег в воде [src `ClientPlayerEntity.tickMovement`, `isWalking`, `canStartSprinting`]

Дополняет ASP-01-02 §2.9.
- «Иду вперёд» (`isWalking`): при `eye_lag` — **любое** движение вперёд (> 1e-5, даже присев); иначе `вперёд ≥ 0.8`.
- **Двойное W**: если (`onGround` **или** `eye_lag`) и фронт нажатия и можно начать.
- **Ctrl**: если (**нет касания** или `eye_lag`) и можно начать и Ctrl зажат.
- **Срыв**, если не плывёшь кролем: нет «вперёд», или жёсткий упор, или **касание без `eye_lag`** (по колено, на
  поверхности). Проверка идёт в том же тике сразу после старта → в воде по колено бег **не включить вовсе**.
- **Срыв, если плывёшь кролем**: только (не на земле **и** без Shift **и** нет «вперёд») **или** нет касания.
  Упор в стену и выныривание головы кроль не срывают. Причуды [вывод]: на дне без W, или с Shift без W, кроль
  держится — лежишь на дне в позе плавания.
- Голода нет → `canSprint` всегда да. Флаг бега даёт FOV ×1.15 (ASP-01 §2.5) и в воде тоже.

### 6.2 Начало и конец кроля [src `Entity.updateSwimming`, `PlayerEntity.updateSwimming/updatePose/isSwimming`]

- Не плыл → начинает, если `бег && eye_lag && вода в клетке floor(ступней)` (и не полёт, не верхом).
- Плыл → продолжает, пока `бег && touching`.
- Поза в конце тика: кроль → **SWIMMING 0.6×0.6, глаза 0.4**; коробка меняется вокруг ступней (сжимается сверху).
  Пробу места делает `canChangeIntoPose` (коробка позы, сжатая на 1e-7, без форм блоков; вода не мешает).
- Кроль кончился → желаемая STANDING (или CROUCHING при Shift); нет места на 1.8 → CROUCHING; нет и на 1.5 → остаётся
  SWIMMING. В воде это просто низкая поза, медлительности нет (`isCrawling` = поза кроля **без** касания воды).
  Вылез из подводного лаза высотой 1 на сушу с потолком 1 — ползком, ввод ×0.3 [вывод].
- Тайминг [расчёт]: Ctrl+W под водой → бег на тике 1, кроль на тике 2, поза в конце тика 2, камера с тика 3:
  1.62 → 1.01 → 0.705 → 0.5525 → 0.4763 → 0.4381 → 0.4191 (90 % за ~3.3 тика). Отпустил W в толще → бег снят сразу,
  кроль — тиком позже, поза STANDING, камера 0.4 → 1.01 → 1.315 → 1.4675 → 1.5438 → 1.5819 → 1.6009.
- Покачивание камеры в кроле — ноль (`stride` цель 0); модель игрока наклоняется `leaningPitch` ±0.09/тик (только
  для третьего лица и других игроков; от первого лица камера не наклоняется) [src].

### 6.3 Вертикаль кроля по взгляду [src `PlayerEntity.travel`]

Перед водной веткой, если плывёшь кролем: `d = look_y = −sin(pitch)`; `e = d < −0.2 ? 0.085 : 0.06` (порог — взгляд
вниз круче 11.54°). Если `d ≤ 0` **или** Space **или** в клетке `floor(y + 0.9)` над ступнями есть вода →
`vy += (d − vy)·e`.

- Смотришь вниз или вперёд — тянет всегда. Смотришь вверх — тянет, только пока над ступнями на 0.9 ещё вода
  (коробка кроля 0.6 — значит, «над головой ещё 0.3 воды») или зажат Space.
- Гравитации нет (бег, §4.1 шаг 7) → при взгляде ровно вперёд глубина держится.
- Устойчивая вертикаль `m = d·e / (1 − 0.8·(1 − e))` [расчёт]: вниз `0.31716·d` б/т, вверх `0.24194·d` б/т.
- У поверхности со взглядом вверх кроль останавливается, когда над ступнями +0.9 уже воздух, и доплывает инерцией:
  со взглядом −30° ступни на **0.25 под поверхностью, глаза 0.15 над ней** (голова и камера над водой, касание есть,
  кроль продолжается). Со взглядом −10° — ступни 0.61 под, глаза 0.21 под [расчёт].

## 7. Течение как сила [src `Entity.updateMovementInFluid`, `FlowableFluid.getVelocity/isFlowBlocked`]

Вектор потока клетки даёт ASP-15 (`FluidState.getVelocity`: сумма разностей высот с 4 соседями, при падающей воде
у стены — сильно вниз, затем **нормирован**: длина 1 или 0; у источника, окружённого источниками, — 0). Здесь — как
он толкает игрока:

1. В обходе клеток §2.2 для каждой мокрой клетки берётся её вектор; если текущий `fluid_h` (максимум **на этот
   момент обхода**, порядок x → y → z по возрастанию) **< 0.4**, вектор ×`fluid_h`. Счётчик мокрых клеток `n++`.
2. Если сумма ненулевая: делить на `n` (среднее по **всем** мокрым клеткам, и стоячим тоже).
3. **Игрок — не нормируется** (только не-игроки: предметы ASP-07, мобы). Затем ×**0.014**.
4. Если `|vx| < 0.003` и `|vz| < 0.003` и длина толчка < **0.0045** → растянуть толчок до 0.0045 (так он переживёт
   обнуление малых скоростей в шаге 10).
5. `скорость += толчок` — в `baseTick`, до ввода, прыжка и `travel`.

Иллюстрация [расчёт; если все клетки дают единичный вектор]: снос стоящего в воде `0.014/(1 − 0.8) = 0.07 б/т`
(**1.4 б/с**); против течения W даёт `0.0056/0.2 → 0.56 б/с`, кролем `0.0056/0.1 → 1.12 б/с`. Водопад у стены
толкает вниз ~0.014 б/т — Space всё равно поднимает (~2.1 б/с); у свободно висящего столба стороны не блокированы,
вниз он не тянет (вектор в основном ноль, у самой поверхности бассейна — наружу) → вверх ~3.5 б/с. Точные векторы и
уровни — ASP-15.

Наш мир сейчас: вся вода — источники, поток ноль. Единственный ненулевой случай у источников — сосед-воздух над
водой (уступ между водоёмами разной высоты), в стабильном мире ванили его не бывает; до ASP-15 возвращаем ноль.

## 8. Падение в воду и fallDistance [src `checkWaterState`, `LivingEntity.fall`, `Entity.move`]

- Касание воды — `onLanding()` → `fallDistance = 0`: каждый тик в `baseTick` и в тике входа (в `fall()` после

## 9. Камера под водой

### 9.1 Камера в воде [src `Camera.getSubmersionType`]

- Позиция камеры = интерполированные ступни + `lerp(last_cam_y, cam_y)` (сглаженная высота глаз, ASP-01). Клетка
  `floor(камеры)`: вода и `камера.y < y_клетки + высота` (строго) → WATER. Иначе проверяются 5 точек плоскости near
  на лаву и рыхлый снег (у нас нет).
- Это **отдельный** признак от «глаз в воде» (§2.3): при смене позы и между тиками они могут расходиться на кадры.

### 9.2 FOV [src `GameRenderer.getFov`]

- Камера в воде (или лаве) → угол ×`lerp(fovEffectScale, 1, 0.85714287)`; при «Эффектах FOV» 1.0 — **70 → 60°**.
- Множитель применяется **в каждом кадре без сглаживания**: картинка «сжимается» скачком, когда камера пересекает
  поверхность (сглаживается только множитель бега, ASP-01 §2.5).
- Та же функция даёт FOV руки (`changingFov = false`: база 70, но подводный множитель тоже) — **рука под водой 60°**
  (совпадает с ASP-11 §0 п.3).
- Кроль: бег 1.15 × вода 0.857 → **≈ 69°** — почти как стоя на суше.

### 9.3 Привыкание зрения [src `ClientPlayerEntity.tickMovement/getUnderwaterVisibility`]

- `vis_ticks`: при `eye_now` +1 за тик (зритель +10), иначе −10; зажим 0…600.
- `vis = 0`, если глаза не в воде; `1`, если `vis_ticks ≥ 600`; иначе `0.6·clamp(t/100) + 0.4·clamp((t − 100)/500)`.
- Значит: 60 % — за первые **5 с**, остальное — за 25 с; вынырнул на 3 с — всё сбросилось.

| `vis_ticks` | 1 | 20 | 42 | 60 | 100 | 200 | 300 | 400 | 500 | 600 |
|---|---|---|---|---|---|---|---|---|---|---|
| `vis` | 0.006 | 0.12 | 0.252 | 0.36 | 0.60 | 0.68 | 0.76 | 0.84 | 0.92 | 1.00 |
| конец тумана, блоков | 24 | 24 | 24.2 | 34.6 | 57.6 | 65.3 | 73.0 | 80.6 | 88.3 | **96** |

### 9.4 Туман [src `BackgroundRenderer.applyFog`; data `fog.glsl`]

- Камера в воде: начало **−8**, конец **96 · max(0.25, vis)**; биомы с тегом `has_closer_water_fog` (болото,
  мангры) ×0.85 — у нас их нет. Если конец > дальности прорисовки → конец = дальность и форма «цилиндр».
- Форма по умолчанию — **сфера**: расстояние = длина вектора от камеры. Смешивание
  `mix(цвет, цвет_тумана, smoothstep(start, end, dist))` (имя `linear_fog`, но функция — smoothstep); при
  `dist ≥ end` — полностью туман. Из-за `start = −8` у самой камеры уже есть туман: 1.7 % при конце 96 и 16 % при
  конце 24 (сразу после нырка) [расчёт].
- Небо [src `WorldRenderer.renderSky`]: под водой небо рисуется с тем же туманом (почти полностью туман), солнце и
  луна — шейдером без тумана (видны сквозь поверхность), звёзды — с выключенным туманом [вывод; вид не проверен].
  Облака рисуются с туманом — не видны. Цвет очистки экрана = цвет тумана.
- Дальше 96 блоков под водой ничего не видно → рендеру можно не рисовать дальние плитки, пока камера в воде [вывод].

### 9.5 Цвет тумана [src `BackgroundRenderer.render`; data `worldgen/biome/*.json`]

- База — `water_fog_color` биома в клетке камеры. У всех биомов нашего генератора (океан, река, пляж, пустыня,
  саванна, заснеженные равнины, тайга, берёзовый лес, лес, равнины, пики, горы) — **0x050533** = (5, 5, 51)/255.
  (Тёплый 0x041F33, тёплый-умеренный 0x041633, болото 0x232317 — у нас нет.)
- Смена биома: цвет плавно переходит за **5000 мс реального времени** (не тиков).
- Осветление по привыканию: `c ← c·(1 − vis) + c·(1/max(r,g,b))·vis` — при `vis = 1` ярчайший канал = 1.
  Для 0x050533: `vis 0` → (0.020, 0.020, 0.200) тёмно-синий; `vis 0.6` → (0.067, 0.067, 0.680); `vis 1` →
  (0.098, 0.098, 1.0) ярко-синий [расчёт]. В ванили это значения sRGB без тонмаппинга.
- **Ночь в формуле не участвует**: цвет подводного тумана в 1.21.1 не темнеет ночью (только «горизонт» у дна мира
  y < −63 и тёмное небо босса) [src; как это выглядит — не проверено].

### 9.6 Оверлей на экране [src `InGameOverlayRenderer.renderUnderwaterOverlay`, `LightmapTextureManager.getBrightness`]

- Рисуется после руки, в пространстве руки (без покачивания), если **`eye_now`** и не зритель; F1 его не прячет.

  (с учётом ночи) — ночью и в пещере оверлей темнее.
- Текстура Mojang не берём — своя (мягкий шум/рябь, тайлится).

### 9.7 Высота глаз и покачивание

- Глаза позы: 1.62 стоя, 1.27 присев, **0.4 кроль**; сглаживание ×0.5/тик (ASP-01 §2.7), цифры — §6.2.

## 10. Звуки и частицы (что вызывает вода; система — ASP-13)

### 10.1 Всплеск при входе [src `Entity.onSwimmingStart`; data `sounds.json`]

- Когда: касание появилось (не было в прошлом состоянии) и это не первый тик сущности; зритель — без всплеска.
- Громкость `g = min(1, √(0.2·vx² + vy² + 0.2·vz²) · 0.2)` (скорость в момент проверки). `g < 0.25` →
  `entity.player.splash` (2 варианта), иначе `entity.player.splash.high_speed` (1). Высота `1 + (r − r)·0.4`.
  Категория игрока, позиция игрока. Вход шагом с пляжа — едва слышно (~0.02).
- Частицы: по `1 + ширина·20` = **13** `bubble` и **13** `splash` на высоте `floor(y) + 1`, x/z — равномерно в
  ±ширина (±0.6) от центра. Пузырю передаётся `(vx, vy − r·0.2, vz)`, брызгам — скорость игрока.
- Событие `GameEvent.SPLASH` (скалк) — не нужно.

### 10.2 Звук плавания и шаги в воде [src `Entity.move`, `PlayerEntity.playStepSound`]

- Путь `distanceTraveled += √(dx² + dz²)·0.6` (вертикаль не считается, кроме лестниц); звук, когда путь превысил
  `следующий = floor(путь) + 1` → раз в **1.67 блока по горизонтали**. Тонуть или всплывать — беззвучно.
- В воде, не на земле (или в кроле на дне) → `entity.player.swim` (14 вариантов), громкость
  `min(1, √(0.2·vx² + vy² + 0.2·vz²)·0.35)`, высота `1 ± 0.4·(r − r)`.
- Идёшь по дну (на земле, не кроль) → шаг блока дна заменён: звук плавания + тихий шаг блока (громкость группы ×0.05,
  высота ×0.8).
- Громкость [расчёт]: плыву W 0.098 б/т → **0.015**; кролем → 0.031 (−36…−30 дБ) — в ванили плавание очень тихое.
  Ритм: W — раз в 0.85 с, кролем — раз в 0.43 с.
- Shift на дне (на земле) — без звуков (`getMoveEffect` = NONE), как на суше.

### 10.3 Под водой [src `ClientPlayerEntity.updateWaterSubmersionState`, `AmbientSoundLoops`, `AmbientSoundPlayer`; data]

| Событие | Когда | Звук, громкость из `sounds.json` | Как |

## 14. Граничные случаи, которые чувствует игрок

1. **Голова над водой, ноги в воде** (по колено, на поверхности): медленно (1.96), бег не включить и он слетает,
   Space — всплытие/подскок, не прыжок; тумана и FOV нет; воздух не тратится; кроль не начать — сначала нырни.
2. **Вода по колено (1 блок)**: всё как п.1; подскок до 1.16; на берег в 1 блок — только Space+W (подъём 0.3).
3. **Вода глубиной 2**: стоя на дне, глаза под водой — туман, воздух тратится, можно начать кроль.
4. **У поверхности с Space** голова «подпрыгивает» над водой с периодом ~0.7 с и размахом ~1 блок — камера
   ощутимо качается (так в ванили) [расчёт; сверить ощущение].
5. **Ныряние с высоты**: урона нет; уходишь на 3–9 блоков (§8); тяжёлый всплеск с ~13.5 блока.
6. **Кроль**: лёг (камера вниз на 1.22 за ~0.25 с), 3.92 б/с, направление — взгляд; у поверхности голова может быть
   над водой (взгляд вверх) или под (почти ровно); в стену — не срывается; без W в толще — встаёшь; без W на дне —
   лежишь (причуда).
7. **Подводный лаз высотой 1** — только кролем; остановился внутри — поза остаётся низкой (места нет), скорость
   обычная водная 1.96. Вылез на сушу под потолком 1 — ползком ×0.3.
8. **Shift под водой** тянет вниз и приседает (камера 1.27); на дне — защита края работает.
9. **FOV скачком** при пересечении поверхности камерой; туман сразу тёмный и близкий (24 блока), светлеет за 5–30 с;
   вынырнул на 3 с — снова «слепой».
10. **Смена позы** (кроль ↔ стоя) двигает камеру за ~4 тика, а «глаза» для воздуха и тумана меняются сразу и
    раньше: кадр-другой камера и логика расходятся.
11. **Нарисованная гладь и физическая поверхность** должны совпадать: если разойдутся, камера в полосе между ними
    окажется «под гладью без тумана» или «в тумане над гладью». Сейчас 48.88 против 48.889 — 9 мм, незаметно (§16 п.1).
12. Звук: плавание почти не слышно; вход/выход под воду — заметные «бульк» и «вдох»; петля нарастает 2 с.
13. Водопад (ASP-15): у стены тянет вниз, но Space поднимает; свободный столб не тянет.
14. Лестница в воде: упор → подъём ~0.16 б/т (`vy = 0.2` до трения; MOV-13).

## 16. Чего нет в исходнике / не ясно

1. **Высота нарисованной поверхности.** Наш меш кладёт верх воды на `y + 1` (`mesh.rs`, плитки `SEA + 1`), шейдер
   `water.js` опускает верх константой 0.12 → 0.88; ванила — 8/9 − 0.001 с двусторонним верхом (`FluidRenderer`).
   Физика, камера, предметы (ASP-07) — 8/9. Сейчас расхождение 9 мм; с текучей водой (ASP-15, высота на вершину)
   нужна одна функция высоты в Rust для меша, физики и камеры (§20 п.1).
2. **Подводный вид в нашем рендере.** `water.js` умеет смотреть на гладь снизу (окно Снелла), но тумана толщи для
   блоков под водой, FOV и оверлея нет. Ванильный туман — sRGB без HDR; как перенести его в наш HDR/AgX — задача
   владельца рендера («Вода и небо»).
3. **Ночь под водой**: по коду цвет тумана от времени суток не зависит — как это смотрится, не проверено.
4. **Небо и солнце из-под воды** — вывод по шейдерам, не проверено глазами.
5. **Качание у поверхности с Space** (размах ~1 блок) и **глубина нырка** — только расчёт моей модели; нужен взгляд в
   ванили или у нас.
6. **Громкость плавания 0.015–0.03** — по формуле; может оказаться неслышной в наших звуках (ASP-13).
7. **Шаговые звуки по дну**: `stepOnBlock` берёт блок «приземления» (y − 0.2) — для полного дна это дно; иное (плиты
   под водой) — не разбирал.
8. Порядок обхода клеток для «×`fluid_h` при < 0.4» — причуда зависит от порядка x → y → z; повторять ли — ASP-15.
9. Первый тик после появления в воде (`firstUpdate`) — без всплеска; появление в мире — срез 1.
10. Лодки, пузырьковые столбы, лава, рыхлый снег, «Подводное дыхание», «Грация дельфина», черепаший шлем — вне объёма.

## 17. Сценарий проверки человеком

Подготовка: отладка «телепорт», часы до 1 с, мир с морем у пляжа. FOV 70, «Эффекты FOV» 100 %.

1. **Вход с пляжа.** Бегу (Ctrl+W) с пляжа в воду по колено. Ожидаю: тихий всплеск; бег срывается сразу (FOV
   сужается за ~0.2 с); иду медленно — 10 блоков за ~5.3 с (на суше 2.4 с). Ctrl и двойное W бег не включают.
2. **Space по колено.** Зажимаю Space. Ожидаю: не прыжок, а медленный подскок примерно на блок, ритм ~0.85 с.
   Упёршись в берег в 1 блок с Space+W — выхожу на берег за ~0.85 с без отдельного прыжка. Берег в 2 блока — нет.
3. **Тону.** Захожу на глубину ≥ 5 и стою. Ожидаю: тону медленно (~0.5 б/с, 10 блоков за ~20 с). Как глаза уходят под
   воду: FOV скачком сужается, звук входа, через 2 с — подводный гул, тёмно-синий туман близко (~24 блока); за 5 с
   видимость ~58 блоков, за 30 с — ~96, туман синеет. На экране лёгкая рябь, «плывёт» при повороте. Справа над
   хотбаром — пузыри (ASP-12).
4. **Всплытие.** Зажимаю Space. Ожидаю: подъём ~3.5 б/с (10 блоков ~3 с); у поверхности голова выныривает и
   качается вверх-вниз (~0.7 с), звук выхода, гул затихает за 1 с. Отпускаю Space — через ~0.7 с снова под водой.
5. **Shift.** Под водой Shift — погружаюсь быстро (~4.5 б/с), камера чуть ниже (присед). Space+Shift — тону как без
   клавиш.
6. **Кроль.** Под водой Ctrl+W (или двойное W). Ожидаю: тело ложится, камера опускается за ~0.25 с; скорость
   ~3.9 б/с (10 блоков ~3 с); FOV почти как на суше. Смотрю вниз 45° — ухожу вниз заметно быстрее; вверх — поднимаюсь;
   у поверхности со взглядом вверх голова над водой, кроль продолжается. Плыву в стену — кроль не срывается. Отпускаю
   W в толще — встаю (камера поднимается за ~0.3 с). Опустился на дно и отпустил W — остаюсь лежать.
7. **Лаз.** Под водой коридор высотой 1 блок: стоя не войти, кролем — проплываю; внутри отпустил W — не встаю.
8. **Берег кролем.** Плыву кролем у поверхности (взгляд чуть вверх) в берег в 1 блок — выскакиваю на берег и встаю.
9. **Прыжок в воду.** С высоты 10 в воду глубиной 2 — урона нет, всплеск. С 20 — «тяжёлый» всплеск; в глубокой воде
   ухожу на ~7–9 блоков, потом медленно тону.
10. **Дно.** Иду по дну: медленно, камера покачивается слабее, вместо шагов — тихое «бульканье» раз в ~0.85 с.
11. **Ломание.** Под водой на дне бью землю — заметно медленнее (×0.2, ASP-04).

## 18. Что нужно от движка и как это ляжет

- **E2 Мир в главном потоке (главное):** к запросам ASP-01/02 (формы коллизии) добавить жидкость:
  - `fluid(x, y, z) -> Option<Fluid { level: 1..=8, falling }>` — пока `block == WATER` → источник 8; уровни и
    падение — из байта состояния (u16-ячейка, решение после ASP-05) в ASP-15;
  - `fluid_height(x, y, z)` — 1.0 при воде сверху, иначе `level/9`;
  - `fluid_velocity(x, y, z) -> [f64; 3]` — нормированный вектор клетки (имя и функция — ASP-15 §7; сейчас ноль);
  - `any_fluid(box)` — для выхода на берег (по клеткам, без высоты).
  Объём за тик: касание ≤ 12 клеток, глаза 1, проба берега ≤ 12, кроль 1 — пренебрежимо.
- **E3 Цикл:** шаги §3 внутри фазы «игрок» ASP-05 §11.1; поле `eye_lag` и счётчик `vis_ticks` — в `Player`. В
  `view(alpha)` Rust отдаёт: позицию камеры, `submersion` (по интерполированной камере), `fov_scale` (0.857),
  `underwater_vis`, `fog_end`, `fog_color` (биом в клетке камеры, переход 5 с — по времени кадра в JS),
  `overlay` (`eye_now`) и яркость для оверлея (свет клетки глаз — когда будет E11; до него — небесная яркость).
- **E4 Сущности:** поза SWIMMING (коробка 0.6, глаза 0.4) рядом с CROUCHING из ASP-02; та же проба места.
- **E7 UI:** пузыри — ASP-12; оверлей воды — полноэкранный квад после руки.
- **E8 Ресурсы (свои, CC0/CC-BY):** текстура оверлея (тайлящаяся рябь 4×4); звуки: всплеск ×2, тяжёлый всплеск,
  плавание (4–8 вариантов), вход под воду ×3, выход ×3, подводный гул (петля), добавки (пузыри, вода — обязательно;
  редкие — по желанию).
- **E10 Звук и частицы:** события из `Game::tick`: `Splash { pos, vol, heavy }`, `Swim { vol }`,
  `UnderwaterEnter/Exit { pos }`, `UnderwaterLoop { gain }` (громкость петли считает Rust по тикам: +1/40, −2/40),
  `UnderwaterAddition { kind }`; частицы `bubble`, `splash`, `underwater` (взвесь — общая случайная выборка вокруг
  игрока, решение после ASP-10).
- **Рендер (владелец «Вода и небо»):** режим «камера в воде» — FOV ×0.857 для мира и руки; туман толщи для всех
  проходов (сфера, smoothstep от −8 до `fog_end`, цвет `fog_color`); очистка/небо цветом тумана, солнце и луна без
  тумана; гладь снизу (уже есть); отсечение дальних плиток дальше `fog_end`. Высота глади — §20 п.1.
- **cubi-core** (справка): там та же водная рекуррентность без кроля и без позы 0.6 (`WaterMotion.luau`) и выход на
  берег по «сухой» пробе — подтверждает §4–§5.

## 19. Rust-набросок (своими словами)

```rust
// water.rs — игрок в воде по Java 1.21.1. Дополняет player.rs из ASP-01-02 §12.

#[derive(Clone, Copy)]
pub struct Fluid { pub level: u8, pub falling: bool }      // 1..=8; источник — 8

/// Что нужно физике от мира про жидкость (E2). Реализует World.
pub trait Fluids {
    fn fluid(&self, x: i32, y: i32, z: i32) -> Option<Fluid>;
    fn fluid_velocity(&self, _x: i32, _y: i32, _z: i32) -> [f64; 3] { [0.0; 3] }   // ASP-15 §7
    fn fluid_height(&self, x: i32, y: i32, z: i32) -> f32 {
        match self.fluid(x, y, z) {
            None => 0.0,
            Some(_) if self.fluid(x, y + 1, z).is_some() => 1.0,
            Some(f) => f.level as f32 / 9.0,
        }
    }
    fn any_fluid(&self, b: &Aabb) -> bool { cells(b).any(|(x, y, z)| self.fluid(x, y, z).is_some()) }
}

#[derive(Clone, Copy, PartialEq)]
pub enum Pose { Stand, Crouch, Swim }      // 1.8/1.62, 1.5/1.27, 0.6/0.4

// fl = floor → i32; cells(b) — клетки floor(lo)…ceil(hi)−1; len/norm/scale — векторные помощники.
pub struct Wet { pub touching: bool, pub fluid_h: f64, pub eye_now: bool, pub eye_lag: bool,
                 pub swimming: bool, pub vis_ticks: u16,
                 pub first: bool }                        // true при появлении: в первом тике нет всплеска

const F08: f64 = 0.8f32 as f64;  const F09: f64 = 0.9f32 as f64;  const F002: f64 = 0.02f32 as f64;
const F004: f64 = 0.04f32 as f64; const F03: f64 = 0.3f32 as f64;  const F06: f64 = 0.6f32 as f64;

impl Player {
    /// Начало тика игрока: §3 шаги 1–4 (воздух — ASP-12 сразу после).
    fn water_base_tick(&mut self, w: &(impl Solids + Fluids), ev: &mut Events) {
        let was_lag = self.wet.eye_lag;
        self.wet.eye_lag = self.wet.eye_now;                       // флаг прошлого тика
        if self.wet.eye_lag != was_lag { ev.push(if self.wet.eye_lag { Ev::UnderEnter } else { Ev::UnderExit }); }
        self.check_water(w, ev);
        self.wet.eye_now = self.eye_in_water(w);
        let feet_wet = w.fluid(fl(self.pos[0]), fl(self.pos[1]), fl(self.pos[2])).is_some();
        self.wet.swimming = if self.wet.swimming { self.sprinting && self.wet.touching }
                            else { self.sprinting && self.wet.eye_lag && feet_wet };
        self.wet.first = false;
    }

    /// §2.2 + §7: касание, высота воды над ступнями, толчок потока, всплеск, fall = 0.
    fn check_water(&mut self, w: &impl Fluids, ev: &mut Events) {
        let b = self.aabb().shrink(0.001);
        let (mut h, mut wet, mut push, mut n) = (0.0f64, false, [0.0f64; 3], 0u32);
        for (x, y, z) in cells(&b) {
            if w.fluid(x, y, z).is_none() { continue; }
            let top = y as f64 + w.fluid_height(x, y, z) as f64;
            if top < b.lo[1] { continue; }
            wet = true;
            h = h.max(top - b.lo[1]);
            let mut f = w.fluid_velocity(x, y, z);
            if h < 0.4 { for c in &mut f { *c *= h; } }          // причуда: h — максимум на этот момент обхода
            for i in 0..3 { push[i] += f[i]; }
            n += 1;
        }
        if len(push) > 0.0 {
            for c in &mut push { *c = *c / n as f64 * 0.014; }    // игрок: без нормировки
            if self.vel[0].abs() < 0.003 && self.vel[2].abs() < 0.003 && len(push) < 0.0045 {
                push = scale(norm(push), 0.0045);
            }
            for i in 0..3 { self.vel[i] += push[i]; }
        }
        self.wet.fluid_h = h;
        if wet {
            if !self.wet.touching && !self.wet.first { ev.push(Ev::Splash(splash_volume(self.vel))); }
            self.fall = 0.0;
        }
        self.wet.touching = wet;
    }

    fn eye_in_water(&self, w: &impl Fluids) -> bool {
        let ey = self.pos[1] + self.pose.eye() as f64;
        let (x, y, z) = (fl(self.pos[0]), fl(ey), fl(self.pos[2]));
        w.fluid(x, y, z).is_some() && y as f64 + w.fluid_height(x, y, z) as f64 > ey
    }

    /// §4.2: вызывается вместо наземного прыжка в LivingEntity.tickMovement.
    fn jump_or_swim_up(&mut self, jump: bool) {
        if !jump { self.jump_cd = 0; return; }
        let wet = self.wet.touching && self.wet.fluid_h > 0.0;
        if !wet || (self.on_ground && self.wet.fluid_h <= 0.4) {
            if self.on_ground && self.jump_cd == 0 { self.jump(); self.jump_cd = 10; }
        } else {
            self.vel[1] += F004;                                  // swimUpward, без кулдауна
        }
    }

    /// §6.3 + §4.1 + §5. Вызывается из travel(), если wet.touching.
    fn travel_water(&mut self, w: &(impl Solids + Fluids), jump: bool, shift: bool) {
        if self.wet.swimming {
            let d = -(self.pitch.to_radians().sin()) as f64;
            let e = if d < -0.2 { 0.085 } else { 0.06 };
            let above = w.fluid(fl(self.pos[0]), fl(self.pos[1] + 0.9), fl(self.pos[2])).is_some();
            if d <= 0.0 || jump || above { self.vel[1] += (d - self.vel[1]) * e; }
        }
        let falling = self.vel[1] <= 0.0;                          // нужно только для мёртвой ветки
        let y0 = self.pos[1];
        let fr = if self.sprinting { F09 } else { F08 };
        self.accelerate(F002 as f32);                              // без наземного 0.216/p³
        let m = self.vel;
        self.mv(w, m, shift);                                      // коллизия ASP-02, флаги h_hit/on_ground
        self.vel = [self.vel[0] * fr, self.vel[1] * F08, self.vel[2] * fr];
        if !self.sprinting { self.vel[1] -= 0.08 / 16.0; }          // при беге гравитации нет
        let _ = falling;
        if self.h_hit {
            let probe = self.aabb().moved([self.vel[0], self.vel[1] + F06 - (self.pos[1] - y0), self.vel[2]]);
            // пусто = ни одна форма блока не пересекает probe (касание гранью не в счёт)
            if w.empty(&probe) && !w.any_fluid(&probe) { self.vel[1] = F03; }
        }
    }

    /// Для кадра: камера в воде, FOV, туман.
    pub fn water_view(&self, w: &impl Fluids, cam: [f64; 3]) -> WaterView {
        let (x, y, z) = (fl(cam[0]), fl(cam[1]), fl(cam[2]));
        let under = w.fluid(x, y, z).is_some() && cam[1] < y as f64 + w.fluid_height(x, y, z) as f64;
        let vis = self.underwater_vis();                          // 0, если !eye_now; кривая §9.3
        WaterView { under, fov_scale: if under { 0.85714287 } else { 1.0 },
                    fog_start: -8.0, fog_end: 96.0 * vis.max(0.25), vis, overlay: self.wet.eye_now }
    }
}
```
