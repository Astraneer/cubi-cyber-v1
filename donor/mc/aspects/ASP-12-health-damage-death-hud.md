## 0. Главное коротко

1. **Окно неуязвимости.** Полный удар ставит `timeUntilRegen = 20`. Пока счётчик **> 10**, новый урон проходит только если он
   **больше прошлого**, и проходит **разницей**. Такой «добор» идёт **без отбрасывания, без звука, без крена направления**
   и без нового красного мигания у модели. Значит, любой урон, который повторяется каждый тик (кактус, стена), бьёт
   **раз в 10 тиков**: в тике T, потом T+10, T+20 [src `LivingEntity.damage`, `ServerPlayerEntity.tick`, `MinecraftServer.tickWorlds`].
2. **`lastDamageTaken` — сырой урон до брони**, а не то, что сняло. Разница тоже проходит через броню.
3. **Урон от падения не учитывает последний тик.** В тике приземления `Entity.fall` считает урон по уже накопленной
   `fallDistance` (f32) и обнуляет её, а смещение самого этого тика не прибавляет. Поэтому реальные высоты сдвинуты:
   сход с 3 блоков — 0, с 4 — 1 (½ ♥), с 10 — 7, с 23 — **19** (остаётся ½ ♥), с 24 — 21 (смерть). Прыжок с края даёт больше:
   с 3 блоков — уже 2 [расчёт, §3.1, §16].
4. **Броня не снижает урон от падения, удушья в стене, утопления и пустоты** и не изнашивается от него
   [data `tags/damage_type/bypasses_armor.json`]. **Кактус и удар игрока броня снижает и за это тратится**: каждая надетая
   часть теряет `(int)max(1, урон/4)` за каждый прошедший удар. Формула: `урон × (1 − clamp(броня − урон/(2 + toughness/4),
   броня·0.2, 20)/25)`. Железный комплект (15): меч 6 → 3.12, крит 9 → 5.22, кактус 1 → 0.42 [src `DamageUtil.getDamageLeft`].
5. **Отбрасывание 0.4 бывает только от источника с позицией** — у нас это удар игрока. Падение, стена, утопление, кактус и пустота
   в теге `no_knockback`: не толкают и не меняют направление крена камеры [data `tags/damage_type/no_knockback.json`].
6. **Атака:** множитель `0.2 + h²·0.8`, где `h = clamp((тиков_с_прошлого_взмаха + 0.5)/(20/скорость_атаки), 0, 1)`.
   Счётчик сбрасывает **любой взмах руки** (на сервере `swingHand`), промах по воздуху и смена предмета. Крит ×1.5 —
   h > 0.9, падаем (`fallDistance > 0`, не на земле), не бег, не вода, не лестница. Бег при h > 0.9 — добавочное
   отбрасывание 0.5 по взгляду атакующего и срыв бега [src `PlayerEntity.attack`, `tick`; `ServerPlayerEntity.swingHand`].
7. **Обратная связь:** `hurtTime` 10 тиков — модель красная (30 % красного поверх текстуры), камера кренится по кривой
   `sin(((hurtTime − tickDelta)/10)⁴·π)·14°` с пиком 14° через ~1.6 тика; звук «hit» (3 варианта, pitch 0.8–1.2).
   Сердца после урона мигают **3 раза по 3 тика за 1 с**, потерянная часть видна белой; при ≤ 4 HP сердца каждый тик
   дрожат на 0/1 пикселя [src `GameRenderer.tiltViewWhenHurt`, `InGameHud.renderStatusBars/renderHealthBar`].
8. **Воздух:** 300; голова под водой — −1/тик; на −20 → 0 и урон 2 (утопление). Первый урон через **320 тиков (16 с)**,
   дальше каждые 20 тиков; смерть с 20 HP — на 500-м тике (25 с). На воздухе +4/тик: 0 → 300 за 75 тиков [src `LivingEntity.baseTick`].
9. **Смерть:** весь инвентарь, **включая броню и вторую руку**, выпадает на месте: каждый стек со своей случайной скоростью
   до 0.5 б/т в случайную сторону и 0.2 вверх, задержка подбора 40 тиков. Экран смерти: кнопки неактивны 20 тиков,
   Esc не закрывает, мир не на паузе. Возрождение — на точке мира, случайная колонка в радиусе 10, полное здоровье,
   пустой инвентарь, **60 тиков неуязвимости** [src `PlayerInventory.dropAll`, `PlayerEntity.dropItem`, `DeathScreen`,
   `PlayerManager.respawnPlayer`, `ServerPlayerEntity`].
10. **Регенерация [наше]:** предлагаю 1 HP (½ ♥) каждые 40 тиков, когда 100 тиков (5 с) не было урона. Это ровно
    стартовая точка пользователя (1 ♥ за 4 с), вдвое быстрее ванильной «сытой» (1 HP/80 т) и в 4 раза медленнее
    ванильной «насыщенной» (1 HP/10 т). Еда: 32 тика, по окончании `heal(питание)`; есть можно, только если HP < 20 (§8, §9).

## 1. Порядок операций в тике (сводно)

Ванила разносит игрока на клиент и сервер. У нас одна симуляция в Rust, и она должна давать то же, что видит игрок
в ванили. Сверено с порядком сервера: `MinecraftServer.tickWorlds` сначала тикает миры (там `ServerPlayerEntity.tick`
уменьшает `timeUntilRegen`), потом соединения (`playerTick` → `PlayerEntity.tick` → опасности `baseTick`). Пакеты
движения (падение, кактус) и атаки обрабатываются между тиками [src].

Предлагаемый порядок для `game.rs` (фазы ASP-05 §11.1):

| Шаг | Что | Источник |

| 0. Начало тика | `time_until_regen −1` (если > 0); `spawn_protect −1`; `cam_hurt_time −1`, `hud_regen −1` (клиентские счётчики) | `ServerPlayerEntity.tick`; `LivingEntity.baseTick` клиента |
| 1. `tick_use` | ЛКМ по игроку → `attack` (§6); любой взмах → `last_attacked_ticks = 0`; ПКМ с едой → начать есть, если можно (§9); отпустил ПКМ → прервать | `MinecraftClient.doAttack/doItemUse`, `ClientPlayerInteractionManager.attackEntity` |

## 2. Приём урона: `LivingEntity.damage` (и обёртки игрока)

### 2.1 По шагам [src `ServerPlayerEntity.damage` → `PlayerEntity.damage` → `LivingEntity.damage`]

1. `isInvulnerableTo(source)` — креатив; правила игры `fallDamage`, `drowningDamage` (по умолчанию включены) → отказ.
2. **Защита после входа/возрождения:** `joinInvulnerabilityTicks` = 60 и уменьшается каждый тик. Пока > 0 — отказ, кроме
   источников из `bypasses_invulnerability` (пустота, `/kill`). Исключение ванили: на выделенном сервере с PvP урон от падения
   проходит. Для нас — отказ для всего, кроме пустоты.
3. Удар от игрока при выключенном PvP или по союзнику по команде → отказ (`shouldDamagePlayer`). У нас PvP включён везде.
4. Мёртв (HP ≤ 0) → отказ.
5. Сложность: множитель только для урона **от моба** (`scaling: when_caused_by_living_non_player` у всех наших типов):
   лёгкая `min(a/2 + 1, a)`, сложная `a·1.5`, мирная 0. На PvP и окружение не влияет. Если итог 0 — отказ (`PlayerEntity.damage`).
6. Щит, урон по шлему от падающих блоков — вне объёма.
7. **Окно** (`timeUntilRegen > 10`; тега `bypasses_cooldown` в 1.21.1 нет, обходов нет):
   - `amount ≤ lastDamageTaken` → **отказ** (вернуть `false`);
   - иначе `applyDamage(amount − lastDamageTaken)`, `lastDamageTaken = amount`; это **добор**, `full = false`.
   Вне окна: `lastDamageTaken = amount`, `timeUntilRegen = 20`, `applyDamage(amount)`, `hurtTime = maxHurtTime = 10`; `full = true`.
8. `applyDamage`: броня (§4, если тип не в `bypasses_armor`) → эффекты и зачарования (у нас нет) → поглощение (нет) →
   `health −= остаток`, запись в журнал урона (`DamageTracker`, для сообщения о смерти).
9. Только при `full`: событие «урон» для всех клиентов (`sendEntityDamage` → у клиента `onDamaged`: `hurtTime = 10`,
   звук урона); если тип не `no_knockback` — `takeKnockback(0.4, атакующий − жертва)` и `tiltScreen` (запомнить
   `damageTiltYaw`, §7.2).
10. HP ≤ 0 → тотем (вне объёма) → при `full` звук смерти → `onDeath` (§10). Иначе при `full` — звук урона.
11. Вернуть `true`. Атака (§6) по этому `true` решает, тратить ли прочность оружия и играть ли звук удара.

## 3. Источники урона подробно

### 3.1 Падение [src `Entity.move`, `Entity.fall`, `LivingEntity.fall/handleFallDamage/computeFallDamage`, `PlayerEntity.handleFallDamage`]

Накопление идёт **каждый тик внутри `move`, после коллизий** и после того, как выставлен `onGround`:
- `on_ground` (вертикальное столкновение при движении вниз):
  1. если `fallDistance > 0` — блок под ногами получает «приземление». По умолчанию это `handleFallDamage(fallDistance, 1.0)`;
     у сена, кровати, слизи свои множители, но они вне объёма;
  2. `fallDistance = 0`.
- иначе, если смещение по Y за тик отрицательное: `fallDistance −= (f32)dy`;
- если смещение по Y **положительное** — сервер (он считает урон) обнуляет `fallDistance`
  (`ServerPlayNetworkHandler.onPlayerMove`: после `handleFall` при `Δy > 0` → `onLanding`; клиент так не делает, совпадает
  с ASP-01-02 §3.11). Значит, считается спуск **от последней высшей точки**: подпрыгнул на 1.25 и упал на 1.25 + h —
  накоплено 1.25 + h. Крит на подъёме прыжка невозможен: `fallDistance = 0`.
- Смещение тика приземления **не входит** в сумму: урон считается по сумме прошлых тиков.

`LivingEntity.fall` до этого: если ещё не касается воды — проверить воду (`checkWaterState`) **в новой позиции**. Коробка
касается воды → `fallDistance = 0` (`onLanding`). Поэтому слой воды в 1 блок спасает с любой высоты, даже если за один
тик пролетаешь сквозь воду до дна.

Сброс `fallDistance = 0` [src]: касание воды (`checkWaterState`, каждый `baseTick` и при приземлении); лестница/лианы
(`applyClimbingSpeed` каждый тик, пока `isClimbing`); полёт (`abilities.flying` — наш отладочный полёт тоже должен
сбрасывать); медленное падение/левитация (нет); езда (нет). Быстрое падение: если за тик смещение `|Δ|² ≥ 1`
(≥ 1 блока/тик, с 16-го тика падения при сходе) и `fallDistance ≠ 0`, бросается луч по отрезку движения. Он ищет блоки из
`#fall_damage_resetting` (лестница, лианы, строительные леса, ягодный куст, паутина) и **воду**. Попал → `fallDistance = 0`.

Урон: `g = fallDistance − safe_fall_distance` (f32, 3.0), `урон = ceil(g · 1.0F · fall_damage_multiplier 1.0)`. Если > 0 —
звук `entity.player.small_fall` (урон ≤ 4) или `big_fall` (> 4), громкость 1, pitch 1; звук падения группы блока на
`floor(y − 0.2)` с громкостью ×0.5 и pitch ×0.75; затем `damage(fall, урон)`. Частицы блока (сервер): при `fallDistance > 3`
число `(int)(150 · min(0.2 + k/15, 2.5))`, где `k = ceil(fallDistance − 3)`, разброс 0.15. Точка — у края блока приземления,
если стоишь над соседней клеткой. Подробно — ASP-13.

от высшей точки до остановки. Бег вниз по лестнице давал урон за всю лестницу. Помогло только приземление «по опоре под
ступнями» в тот же момент, что и `onGround` движения. У нас движение и урон в одном Rust-тике. Накопление и урон делать
**внутри того же `move`, по тому же флагу `on_ground` коллизии**, а не отдельной проверкой высоты.

### 3.2 Кактус [src `CactusBlock`, `Entity.checkBlockCollision`]

- После каждого `move` (каждый тик, даже без смещения) перебираются **ячейки**, которые пересекает коробка игрока, сжатая на
  1e-7. Ячейка с кактусом → `damage(cactus, 1)`.
- Форма коллизии кактуса — 1…15 px по X/Z и 0…15 px по Y, а ячейка полная. Поэтому, упёршись в бок, коробка заходит в
  ячейку на 1/16 и получает урон. Стоя сверху, ноги на высоте 15/16 тоже внутри ячейки.
- Темп: урон каждый тик, но окно пропускает его раз в 10 тиков: ½ ♥ за 0.5 с, 20 HP за 190 тиков.
- Отбрасывания нет (`no_knockback`). Броня снижает: железо 15 → 0.42 за удар, кожа 7 → 0.74; каждая часть −1 прочности
  за удар. Регенерация [наше] не начнётся, пока стоишь в кактусе.

### 3.3 Удушье в блоке [src `Entity.isInsideWall`, `LivingEntity.baseTick`, `AbstractBlock.Settings.suffocates`, `Blocks`]

- Коробка **0.48 × 1e-6 × 0.48** (ширина 0.6 × 0.8) с центром в точке глаз: стоя y + 1.62, присев 1.27.
- Душит блок, если он не воздух, «удушающий» и его **форма коллизии пересекается** с этой коробкой. По умолчанию удушающий =
  `blocksMovement && isFullCube`. Явно не душат листва и стекло (`suffocates(never)`). У нас душат: камень, земля, трава, песок,
  гравий, брёвна, доски, руды, верстак, печь, снежный блок, глина, песчаник, бедрок. Не душат: листва, кактус и сундук
  (не полный куб), факел, лестница, растения, вода, снежный слой.
- Каждый тик в `baseTick` (сервер): внутри → `damage(in_wall, 1)`, проходит раз в 10 тиков. Иначе — проверка границы мира
  (у нас нет).
- Песок на голову (ASP-05 §5.5): выталкивание `pushOutOfBlocks` работает только по сторонам, вверх не толкает. В яме 1×1,
  засыпанной песком, игрок задохнётся: ½ ♥ раз в 0.5 с.

## 4. Броня [src `LivingEntity.applyArmorToDamage/damageEquipment`, `PlayerEntity.damageArmor`, `DamageUtil.getDamageLeft`]

Порядок внутри `applyDamage(amount)` для типа, который не обходит броню:
1. **Износ** (`damageArmor`) — до снижения, от того `amount`, что пришёл (полный урон или разница): `n = (int)max(1, amount/4)`.
   Каждая надетая часть (ноги, поножи, грудь, голова) получает `ItemStack.damage(n)`; при `damage ≥ maxDamage` часть ломается
   (звук `item.break`, частицы — ASP-06 §1.3). Износ только при `amount > 0`.
2. **Снижение:** `f = 2 + toughness/4`; `g = clamp(броня − amount/f, броня·0.2, 20)`; итог `amount · (1 − g/25)`.
   Все операции f32. `броня = floor(атрибут armor)` (сумма очков частей, зажим 0…30); `toughness` у кожи и железа 0.
   Зачарования оружия на «эффективность брони» у нас не нужны.
3. Защитные зачарования, сопротивление — нет.

Очки и прочность (ASP-06 §2.7): кожа 1/3/2/1 = 7, железо 2/6/5/2 = 15; прочность железа 165/240/225/195, кожи 55/80/75/65.
Сопротивление отбрасыванию у обоих 0.

Примеры [расчёт f32]:

| Урон | Без брони | Кожа 7 | Железный нагрудник 6 | Железо 15 | Износ на часть |
|---|---|---|---|---|---|
| 1 (кулак, кактус) | 1 | 0.74 | 0.78 | 0.42 | 1 |
| 4 (деревянный меч) | 4 | 3.2 | 3.36 | 1.92 | 1 |
| 6 (железный меч) | 6 | 5.04 | 5.28 | 3.12 | 1 |
| 7 | 7 | 6.02 | 6.3 | 3.78 | 1 |
| 9 (крит меча, каменный/железный топор) | 9 | 8.1 | 8.46 | 5.22 | 2 |

Железный комплект против железного меча с полным кулдауном: 20 / 3.12 → 7 ударов. Удары раз в 12 тиков, это
больше окна, так что каждый проходит целиком: смерть через 72 тика (3.6 с). Без брони — 4 удара за 36 тиков (1.8 с).
Нагрудник выдерживает 240 ударов до 7.99 урона.

## 5. Отбрасывание [src `LivingEntity.takeKnockback`, `LivingEntity.damage`, `PlayerEntity.attack`]

`takeKnockback(strength, x, z)`, где (x, z) — направление **на** источник:
1. `strength ×= 1 − knockback_resistance` (у нас 0). Если ≤ 0 — ничего.
2. Пока `x² + z² < 1e-5` — случайное направление `(rand − rand)·0.01` (источник в той же точке).
3. `d = normalize(x, 0, z) · strength`; `v = (v.x/2 − d.x, on_ground ? min(0.4, v.y/2 + strength) : v.y, v.z/2 − d.z)`.

Кто вызывает:
- `damage` при полном ударе, если тип не `no_knockback`: `strength = 0.4F` (в double 0.4000000059604645),
  направление = позиция атакующего − жертва → толкает **от атакующего**;
- `attack` при прошедшем ударе, если `k = attack_knockback (0 у игрока) + 1 при беговом ударе` > 0: `takeKnockback(k·0.5,
  sin(yaw), −cos(yaw))` → толкает **по взгляду атакующего**. Вторая половинка снова делит скорость пополам.
  Потом у атакующего `v ×= (0.6, 1, 0.6)` и бег выключается.
- взмах меча (sweep): 0.4 по взгляду каждому задетому.

Числа для стоящей цели [расчёт]: обычный удар — гор. 0.4 б/т от атакующего, `vy = min(0.4, −0.0784/2 + 0.4) =
0.3608000052`; беговой удар — гор. `0.2·от_атакующего + 0.5·взгляд` ≈ 0.7 б/т, `vy = 0.4`. Полёт без ввода: обычный —
приземление через ~10 тиков в ~2.7 блока, всего ~2.9; беговой — ~11 тиков, ~5.0 и ~5.3 блока; высота 0.96 / 1.15.

**Ощущение ванильного мультиплеера** [вывод из `PlayerEntity.attack`, `LivingEntity.travel`, `Entity.isLogicalSideForUpdatingMovement`,
`ClientPlayNetworkHandler`]. Отбрасывание игрока сервер считает по **своей копии** скорости и пакетом **заменяет** скорость
клиента. Своя копия у сервера — это физика без ввода, гор. ≈ 0. После удара `attack` возвращает её назад. Поэтому в ванили:
(а) бегущая цель не сохраняет половину своей скорости — её движение сбрасывается, гор. ≈ ровно 0.4 (0.7);
(б) замедление атакующего ×0.6 касается только серверной копии и игроку почти не заметно. Срыв бега доходит через флаг
`sprinting`, который сервер присылает и своему игроку («сброс бега», W-tap). Рекомендация: для цели-игрока брать
`v.xz` в формуле равным 0, `v.y` — своим. У атакующего срывать бег, ×0.6 не применять. Это вопрос ощущения — проверить
человеком (§14), решение — §19.

## 6. Атака игроком (PvP) [src `PlayerEntity.attack`, `getAttackCooldownProgress(PerTick)`, `resetLastAttackedTicks`, `tick`;
`ServerPlayerEntity.swingHand`; `MinecraftClient.doAttack`; `ClientPlayerInteractionManager.attackEntity`]

### 6.1 Кулдаун
- `период = 20 / attack_speed` тиков (f32). `h(base) = clamp((last_attacked_ticks + base)/период, 0, 1)`. В уроне `base = 0.5`,
  в индикаторе HUD `base = 0`.
- `last_attacked_ticks +1` в конце каждого тика игрока. **Сброс в 0**: атака, промах по воздуху (`doAttack` MISS), отмена
  ломания, **любой взмах руки на сервере** (`ServerPlayerEntity.swingHand` — копание каждые 4 тика, ставление блока),
  смена **типа** предмета в главной руке (износ не считается).
- Числа [расчёт]: рука 4.0 → период 5, `h > 0.9` при t ≥ 5; меч 1.6 → 12.5, h > 0.9 при t ≥ 11, h = 1 при t ≥ 12;
  кирка 1.2 → 16.7 (15/17); лопата 1.0 → 20 (18/20); топор 0.8 → 25 (23/25), железный топор 0.9 → 22.2 (20/22).
- Промах по воздуху ставит ещё `attackCooldown = 10` клиента: 10 тиков нельзя снова начать атаку кликом. Это ASP-04 `doAttack`.

### 6.2 Урон по шагам
1. `f = attack_damage` игрока: 1 + оружие (ASP-06 §2.5: рука 1, деревянный/каменный/железный меч 4/5/6, топоры 7/9/9,
   кирки 2/3/4, лопаты 2.5/3.5/4.5). Зачарований нет (`g = 0`).
2. `h = h(0.5)`; `f ×= 0.2 + h²·0.8`; **сброс кулдауна**.
3. Если f > 0:
   - `strong = h > 0.9`; **беговой** = бежит и strong → звук `attack.knockback`;
   - **крит** = strong и `fallDistance > 0` и не на земле и не лестница и не в воде и не слепота и не верхом и цель живая и
     **не бег** → `f ×= 1.5`;
   - **взмах меча** = strong, не крит, не беговой, на земле, `horizontalSpeed − prevHorizontalSpeed < movement_speed`
     (= 0.6·гор. смещение за тик < 0.1, т. е. медленнее 0.167 б/т: стоя или крадучись; при ходьбе 0.216 б/т — нет), в руке меч.
4. `target.damage(player_attack от атакующего, f)` (§2). Отказ (окно) → звук `attack.nodamage`, **прочность не тратится**.
5. Прошёл: добавочное отбрасывание (§5); взмах — каждой живой сущности в коробке цели, расширенной на (1, 0.25, 1),
   ближе 3 блоков к атакующему, кроме него и цели: урон `1 · h`, отбрасывание 0.4, звук `attack.sweep`, частица.
   Дальше звуки: крит → `attack.crit` + частицы крита; не крит и не взмах → `attack.strong` (h > 0.9) или `attack.weak`.
   Износ оружия: меч −1, инструмент −2 (ASP-06 §1.3). Частицы «сердечки урона» при снятом > 2 HP — `(int)(снято·0.5)` (ASP-13).
6. Дальность: луч по сущностям 3.0 от глаз (ASP-04 §2.5). Сервер принимает атаку, если цель в `3.0 + 1.0` от глаз.

Примеры железного меча (6) по t тикам после прошлого взмаха [расчёт f32]: 0 → 1.21; 2 → 1.39; 4 → 1.82; 6 → 2.50;
8 → 3.42; 10 → 4.59; 11 → 5.26; 12+ → 6.0; крит 9.0.

### 6.3 Индикатор под прицелом [src `InGameHud.renderCrosshair`, `GameOptions.attackIndicator` = CROSSHAIR по умолчанию]
- Позиция (W/2 − 8, H/2 + 9), фон 16×4 и полоска шириной `(int)(h(0)·17)` px, пока h(0) < 1.
- Если под прицелом живая сущность, h(0) ≥ 1 и период > 5 тиков — значок «полный» 16×16. У руки (период 5) значок не показывается.
- Опускание предмета в руке по кулдауну — ASP-11 (TOOL-04).

### 7.1 Модель: красная вспышка [src `LivingEntityRenderer.getOverlay`, `OverlayTexture`; data шейдер `rendertype_entity_cutout_no_cull.fsh`]

  подкрашивается ли рука].

### 7.2 Крен камеры [src `GameRenderer.tiltViewWhenHurt`, `ServerPlayerEntity.tiltScreen`, `PlayerEntity.animateDamage`]
- `t = hurtTime − tickDelta`; если t < 0 — ничего. `s = sin((t/10)⁴ · π)`; угол `a = −s · 14° · damageTiltStrength` (опция,
  по умолчанию 1.0).
- Матрица применяется к виду **до** поворота камеры, и к миру, и к руке: `Ry(−g) · Rz(a) · Ry(g)`, где
  `g = damageTiltYaw = atan2(dz, dx)·180/π − yaw` — направление на атакующего относительно взгляда. Удар сбоку — крен
  вбок, спереди — кивок.
- Кривая [расчёт] по t: 10 → 0°, 9.5 → 7.7°, 9 → 12.4°, **8.41 → 14° (пик)**, 8 → 13.4°, 7 → 9.6°, 6 → 5.5°, 5 → 2.7°,
  4 → 1.1°, 3 → 0.4°, ≤ 2 → ~0. Резкий удар за 1.6 тика и затухание за ~5 тиков.
- `damageTiltYaw` меняется **только при уроне с отбрасыванием** (у нас — удар игрока). Падение, кактус, стена и вода крутят
  вокруг **прошлого** направления. Новый игрок начинает с 0 — чистый крен вбок [вывод].
- Смерть: дополнительно `Rz(40 − 8000/(min(deathTime + td, 20) + 200))` — от 0 до **3.64°** за 1 с. FOV делится на
  `(1 − 500/(f + 500))·2 + 1`: при FOV 70 к 20-му тику **65.0** [src `getFov`].
- Наш счётчик: `cam_hurt_time = 10` при любом снижении HP. Уменьшать в начале следующего тика, рисовать
  `cam_hurt_time − α`. Так кривая стартует от нуля, как у ванильного клиента.

### 7.3 Звуки [data `sounds.json`; src `PlayerEntity.getHurtSound`, `LivingEntity.getSoundPitch`]
- Урон: `entity.player.hurt` (3 файла `damage/hit1..3`), громкость 1.0, pitch `(r − r)·0.2 + 1` (0.8–1.2, треугольное).
  Утопление — `entity.player.hurt_drown` (4). Только при полном ударе.
- Смерть: `entity.player.death` (те же hit-файлы) вместо звука урона.
- Падение: `small_fall` (≤ 4 урона) / `big_fall` (> 4), плюс звук падения группы блока ×0.5 громкости, ×0.75 pitch.
- Атака: `attack.strong` / `weak` / `crit` / `knockback` / `sweep` / `nodamage` (у каждого 0.6–0.7 в `sounds.json`).
- Еда: `entity.generic.eat` (3), отрыжка `entity.player.burp` 0.5, pitch 0.9–1.0.
- Звука лопания пузыря воздуха в 1.21.1 нет. Свои звуки — CC0/CC-BY по этим группам (`decisions.md`).

### 7.4 Сердца: мигание, белые потерянные, тряска [src `InGameHud.renderStatusBars/renderHealthBar`, `ClientPlayerEntity.updateHealth`]
Клиентский счётчик (у нас `hud_regen`): снижение HP → 20, рост → 10, −1 каждый тик (`updateHealth`, `LivingEntity.baseTick`).
Состояние HUD: `lastHealthValue`, `renderHealthValue` (белые «призраки»), `lastHealthCheckTime` (реальные мс),
`heartJumpEndTick`, `ticks` (тики HUD).

Каждый кадр:
1. `i = ceil(hp)`. `blink = heartJumpEndTick > ticks && ((heartJumpEndTick − ticks)/3) % 2 == 1` — вычисляется **до**
   обновления ниже.
2. Если `i < lastHealthValue` и `hud_regen > 0` → `lastHealthCheckTime = сейчас`, `heartJumpEndTick = ticks + 20`.
   Если `i > lastHealthValue` и `hud_regen > 0` → то же, `+10`.
3. Если с `lastHealthCheckTime` прошло > 1000 мс → `renderHealthValue = i` (и сброс времени). Затем `lastHealthValue = i`.
4. Сердце `l` (0…9, слева направо, x = W/2 − 91 + 8l, y = H − 39):
   - если `i ≤ 4` → `y += rand(0..1)`; генератор засевается `ticks · 312871` — дрожь меняется раз в тик;
   - рамка (`container`; при `blink` — `container_blinking`, белая);
   - при `blink` и `2l < renderHealthValue` — белое сердце (`full_blinking` / `half_blinking` при `2l + 1 == renderHealthValue`);
   - при `2l < i` — красное (`full` / `half`) поверх.
   Белые видны только в «светлых» фазах: так показывается потерянная часть.
5. Фазы мигания по оставшимся тикам [расчёт]: урон (20) `...###...###...###..` — 3 вспышки по 3 тика; лечение (10)
   `##...###..`. Рамка мигает и при лечении. При натуральной регенерации ванили сердца коротко моргают на каждом
   +1 HP. «Волна» сердец бывает только с эффектом «Регенерация» — нам не нужна.
6. Тонкость: призрак обновляется, только если 1 с не было изменений. При кактусе (каждые 0.5 с) или утоплении
   (каждую 1 с) белым видна вся потеря с начала серии [вывод].
7. Ещё тонкость: при уроне 0.42 (кактус в железе) `ceil(hp)` может не измениться — сердца не мигнут, а камера кренится.

## 8. Регенерация [наше] (без голода)

Ванильная справка [src `HungerManager.update`, `PlayerEntity.canFoodHeal`, `tickMovement`; правило `naturalRegeneration`]:

| Режим ванили | Условие | Темп | 1 → 20 HP |
|---|---|---|---|
| насыщенная | еда 20 и насыщение > 0 | `heal(min(насыщение, 6)/6)` раз в 10 т (до 1 HP / 0.5 с), тратит насыщение | 9.5 с, пока есть насыщение |
| сытая | еда ≥ 18 | 1 HP раз в 80 т (4 с) | 76 с |
| мирная сложность | — | 1 HP раз в 20 т | 19 с |
| голод 0 | — | урон 1 раз в 80 т | — |

Таймер ванили растёт, пока условие выполнено, и при `≥ порога` лечит и обнуляется; при невыполнении — обнуляется. От урона
ваниль не зависит. В PvP её быстрым делает насыщение (стейк — 12.8 насыщения ≈ 8 HP по 1 HP / 0.5 с).

Предложение под решение пользователя («1 ♥ за 4 с после 5 с без урона»):

| Вариант | Задержка после урона | Темп | 10 → 20 HP после удара | Комментарий |
|---|---|---|---|---|
| **A (рекомендую)** | 100 т (5 с) | **1 HP / 40 т** | 5 + 20 = **25 с** | ровно стартовая точка; шаг ½ ♥ как в ванили, каждое +1 HP мигает рамкой |
| B | 100 т | 2 HP / 80 т | 25 с | то же в среднем, шаг 1 ♥ — рывками, реже мигание |
| C (медленнее) | 100 т | 1 HP / 80 т | 45 с | как ванильная «сытая»; еда важнее |

Правило A по шагам: «урон» = любой `damage`, который вернул `true` (включая добор). Он ставит `last_hurt_tick = now`.
В конце тика игрока: если `hp > 0 && hp < max && now − last_hurt_tick > 100` — `regen_timer += 1`, при `≥ 40` `heal(1)`
и `regen_timer = 0`; иначе `regen_timer = 0`. Удар в тике T → лечение на T+140, T+180, … Еда таймер не трогает.
Регенерация идёт и во время еды. Под водой без воздуха и в кактусе не начнётся: урон приходит чаще 5 с.

## 12. Граничные случаи, которые чувствует игрок

1. Прыжок с уступа в 3 блока бьёт на 1 ♥, а шаг с того же уступа не бьёт — подъём прыжка входит в падение (§3.1).
2. Сход с 23 блоков при полном здоровье — выжил с ½ ♥; с 24 — смерть. Прыжок с 23 — смерть.
3. Вода в 1 блок глубиной спасает с любой высоты. Лестница по пути сбрасывает падение, даже если пролетел сквозь неё
   быстрее блока за тик.
4. Броня не помогает при падении, утоплении и засыпании. Кактус и мечи она ослабляет, но сама тратится — 1 прочности
   на часть за каждый укол кактуса.
5. Серия слабых ударов кулаком сразу после сильного удара мечом урона не даёт; более сильный удар в окне снимает
   только разницу — без отбрасывания и звука.
6. Кактус и стена бьют ровно раз в 0.5 с, утопление — раз в 1 с; сердца каждый раз мигают, белым видна вся потеря серии.
7. При ≤ 2 ♥ сердца дрожат.
8. Удар в прыжке на спуске — крит ×1.5 (звук и частицы крита); удар на бегу — сильнее отбрасывает и срывает бег, но крита
   не бывает. Махание киркой и ставление блоков сбрасывают кулдаун атаки.
9. Удар по цели в окне — звук «nodamage», меч не тратится.
10. Еду при полных сердцах съесть нельзя [наше]. Начатая еда доедается, даже если сердца заполнились. Еда не прерывается уроном,
    но пока ешь, ударить нельзя, а идёшь в 5 раз медленнее — в PvP есть рискованно.
11. После смерти вещи, броня и вторая рука разлетаются (до 6.7 блока) и 2 с недоступны для подбора. 3 с после
    возрождения нельзя получить урон — защита от добивания на точке спавна.
12. Регенерация [наше] не идёт, пока стоишь в кактусе или тонешь (урон чаще 5 с).

## 13. Чего нет в исходнике / не ясно

1. **Поза DYING у игрока**: `ServerPlayerEntity.onDeath` не вызывает `LivingEntity.onDeath`, где ставится поза, а клиент
   `onDeath` для игрока не вызывает. Видимо, поза у игрока не меняется [вывод; проверить в игре с F5 или вторым игроком].
2. **Серверная копия скорости игрока** при отбрасывании (§5) — вывод из нескольких классов. Ощущение «отбрасывание
   заменяет бег цели» надо подтвердить живой проверкой в ванили.
3. **Красная вспышка руки от первого лица** — не проверял `HeldItemRenderer` [не проверено].
4. **Физика выпавшего предмета** и точный разлёт — ASP-07 (принят); здесь только ссылка на его числа.
5. **Сообщения о смерти** с вариантами падения (`fall_variants`: «упал с высоты», «упал с лестницы») — логика
   `DamageTracker.getFallDeathMessage` не разобрана; нам достаточно одной строки на тип.
6. **Шрифт и рисунки HUD** — свои (E8). Цвета и пиксели ванильных спрайтов не переносим.
7. **Сеть для PvP** вне этапа 2. Аспект описывает правила для авторитетной симуляции (Rust). Задержку сети и
   «кто прав» решает будущий сетевой аспект.
8. Ванильные цифры падения в §3.1 получены **расчётом по коду**, а не замером в игре. Обычная фраза вики «23 блока — смерть»
   говорит о `fallDistance` 23, а не о высоте уступа [вики, не сверено]. Проверка в ванили: шаг с 23 — должно остаться ½ ♥.

## 14. Сценарий проверки человеком

Подготовка: отладочные команды (только в отладочной сборке): «выдать предмет», «поставить HP», «поставить столб N блоков».
Для PvP до сети — **манекен** (сущность-игрок с HP и коробкой 0.6×1.8, без ИИ, E4).

1. **Падение.** Столбы высотой 3, 4, 6, 10, 23, 24, сходить шагом с края на траву.
   3 — ничего, только приземление. 4 — ½ ♥, короткий «хруст» и «ух». Камера резко кренится вбок на ~0.1 с и плавно
   возвращается за ~0.3 с. Сердца трижды мигают за 1 с, потерянная половинка видна белой во вспышках. 6 — 1.5 ♥.
   10 — 3.5 ♥, звук «тяжёлого» падения. 23 — остаётся ½ ♥, сердца дрожат. 24 — смерть.
2. **Прыжок с 3 блоков** (разбег и прыжок с края) — 1 ♥.
3. **Вода.** Сход с 23 в воду глубиной 1 блок — урона нет.
4. **Броня.** Надеть 4 железные части: над сердцами 7 целых и 1 половинка значка брони. Повторить п. 1 (4 и 10) — урон тот же,
   прочность брони не изменилась.
5. **Кактус.** Встать вплотную. Без брони: −½ ♥ ровно раз в 0.5 с, не отталкивает, каждый раз крен и «ух». В железе: сердца
   убывают втрое медленнее (½ ♥ примерно за 3 укола), у каждой части брони −1 прочности за укол.
6. **Удушье.** Стоя в яме 1×1 глубиной 2, уронить на себя песок: −½ ♥ раз в 0.5 с, вбок не выталкивает. Со стеклом или листвой
   в голове урона нет.
7. **Утопление.** Нырнуть и стоять на дне: справа над хотбаром 10 пузырей, каждые 1.5 с один лопается (короткий кадр «лопания»).
   Примерно через 16 с первый урон — 1 ♥ и «бульканье», дальше раз в секунду. Всплыть: пузыри за ~4 с вернутся и пропадут.
8. **Регенерация.** Получить урон и ждать: 5 с ничего, затем каждые 2 с +½ ♥ с коротким белым миганием рамок. С 5 ♥ до 10 ♥
   примерно за 25 с.
9. **Еда.** При 8 ♥ держать ПКМ с яблоком: ~0.4 с тишина, потом чавканье и крошки 6 раз, ходьба почти стоит. Через 1.6 с —
   отрыжка и +2 ♥ сразу. Отпустить ПКМ раньше — яблоко цело. При 10 ♥ ПКМ с яблоком — ничего.
10. **Смерть.** Упасть с 24 с полным инвентарём и в броне: тёмно-красный экран «Вы умерли!», мир за ним виден. Камера
    чуть наклоняется и приближается. Кнопка «Возродиться» 1 с серая. Вокруг места смерти веером разлетелись все вещи
    и броня. Нажать: появляешься у точки спавна с 10 ♥, без вещей, выбран первый слот. Первые 3 с кактус не ранит.
    Вернуться: вещи лежат (подобрать можно).
11. **Удар по манекену.** Кулаком часто (кулдаун кулака 0.25 с): урон проходит не чаще раза в 0.5 с, удары между ними —
    звук «мимо»: окно неуязвимости 10 тиков. Железным мечом с полной полоской под прицелом —
    манекен −3 ♥, отлетает на ~3 блока. Частые удары мечом — слабые («шлепок»), полоска под прицелом не успевает заполниться.
    Удар на бегу — отлетает на ~5 блоков, бег срывается. Прыжок и удар на спуске — звёздочки крита, −4.5 ♥.
    Сразу после удара мечом ударить кулаком — урона нет, звук «мимо».

Ожидаемые числа для пп. 1–2, 5, 7–11 — §16.

## 17. Rust-набросок (своими словами, не копия Java)

```rust
// health.rs — здоровье и урон игрока; f32 там, где Java хранит float (HP, урон, fallDistance).

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DamageKind { Fall, InWall, Drown, Cactus, PlayerAttack, OutOfWorld }

impl DamageKind {
    /// tags/damage_type/bypasses_armor — броня не снижает и не тратится.
    pub fn bypasses_armor(self) -> bool { !matches!(self, Self::Cactus | Self::PlayerAttack) }
    /// tags/damage_type/no_knockback — из нашего объёма толкает только удар игрока.
    pub fn knockback(self) -> bool { self == Self::PlayerAttack }
    pub fn bypasses_spawn_protect(self) -> bool { self == Self::OutOfWorld }
}

pub struct Source { pub kind: DamageKind, pub attacker: Option<u32>, pub pos: Option<[f64; 3]> }

pub struct Health {
    pub hp: f32,
    pub max: f32,                // 20
    pub time_until_regen: i32,   // окно: 20 при полном ударе, «> 10» — в окне
    pub last_damage_taken: f32,  // сырой урон последнего прошедшего удара
    pub hurt_time: i32,          // 10 → 0: модель красная (полные удары)
    pub cam_hurt_time: i32,      // 10 при любом снижении HP: крен своей камеры
    pub hud_regen: i32,          // 20 при снижении, 10 при росте — для мигания сердец
    pub tilt_yaw: f32,           // damageTiltYaw, градусы относительно взгляда
    pub death_time: i32,
    pub air: i32,                // 300
    pub spawn_protect: i32,      // 60 после входа/возрождения
    pub last_hurt_tick: u64,
    pub regen_timer: u32,
}

pub struct Armor { pub points: f32, pub toughness: f32 } // сумма по надетым частям

pub fn armor_left(dmg: f32, armor: f32, toughness: f32) -> f32 {
    let f = 2.0f32 + toughness / 4.0;
    let g = (armor - dmg / f).max(armor * 0.2).min(20.0);
    dmg * (1.0 - g / 25.0)
}
pub fn armor_wear(dmg: f32) -> i32 { (dmg / 4.0).max(1.0) as i32 }

/// Java MathHelper.ceil(double): отрицательные дробные → к нулю.
fn jceil(x: f64) -> i32 { let i = x as i32; if x > i as f64 { i + 1 } else { i } }
pub fn fall_damage(fall_distance: f32) -> i32 {
    let g = fall_distance - 3.0f32;                 // safe_fall_distance
    jceil((g * 1.0f32) as f64 * 1.0).max(0)          // × множитель блока × fall_damage_multiplier
}

pub enum Ev { Hurt { drown: bool }, Death, Knock { v: [f64; 3] }, ArmorWear(i32), FallSound { big: bool } }

impl Health {
    /// LivingEntity.damage + PlayerEntity/ServerPlayerEntity.damage. Возвращает «урон прошёл».
    pub fn damage(&mut self, src: &Source, amount: f32, me: &mut Body, armor: &Armor, now: u64, ev: &mut Vec<Ev>) -> bool {
        if self.hp <= 0.0 || amount <= 0.0 { return false; }
        if self.spawn_protect > 0 && !src.kind.bypasses_spawn_protect() { return false; }
        let full = self.time_until_regen <= 10;
        let dealt = if full {
            self.last_damage_taken = amount;
            self.time_until_regen = 20;
            self.hurt_time = 10;
            amount
        } else {
            if amount <= self.last_damage_taken { return false; }
            let d = amount - self.last_damage_taken;
            self.last_damage_taken = amount;
            d
        };
        // applyDamage: износ от пришедшего урона, затем снижение.
        let mut left = dealt;
        if !src.kind.bypasses_armor() {
            ev.push(Ev::ArmorWear(armor_wear(dealt)));
            left = armor_left(dealt, armor.points.floor(), armor.toughness);
        }
        let before = self.hp;
        self.hp = (self.hp - left).max(0.0);
        if self.hp < before { self.cam_hurt_time = 10; self.hud_regen = 20; }
        self.last_hurt_tick = now;
        if full {
            if let (true, Some(p)) = (src.kind.knockback(), src.pos) {
                let (dx, dz) = (p[0] - me.pos[0], p[2] - me.pos[2]);
                me.take_knockback(0.4f32 as f64, dx, dz);
                self.tilt_yaw = ((dz.atan2(dx)).to_degrees() as f32) - me.yaw;
            }
            ev.push(if self.hp <= 0.0 { Ev::Death } else { Ev::Hurt { drown: src.kind == DamageKind::Drown } });
        }
        true // при hp == 0 вызывающий запускает on_death (§10)
    }

    pub fn heal(&mut self, n: f32) {
        if self.hp > 0.0 {
            let before = self.hp;
            self.hp = (self.hp + n).min(self.max);
            if self.hp > before { self.hud_regen = 10; }
        }
    }

    /// Начало тика: счётчики (шаг 0 §1).
    pub fn tick_begin(&mut self) {
        for c in [&mut self.time_until_regen, &mut self.spawn_protect, &mut self.cam_hurt_time, &mut self.hud_regen] {
            if *c > 0 { *c -= 1; }
        }
    }

    /// Хвост baseTick (шаг 2a §1), после опасностей: модельный hurtTime и счётчик смерти.
    pub fn base_tick_end(&mut self) -> bool {
        if self.hurt_time > 0 { self.hurt_time -= 1; }
        if self.hp <= 0.0 { self.death_time += 1; }
        self.death_time == 20 // убрать тело: частицы смерти, курсор и сетка 2×2 падают (§10.1)
    }

    /// Воздух (baseTick). Возвращает урон утопления этого тика.
    pub fn tick_air(&mut self, head_in_water: bool) -> Option<f32> {
        if head_in_water {
            self.air -= 1;
            if self.air == -20 { self.air = 0; return Some(2.0); } // + 8 пузырей
        } else if self.air < 300 {
            self.air = (self.air + 4).min(300);
        }
        None
    }

    /// [наше] вариант A: после 100 тиков без урона — 1 HP каждые 40 тиков.
    pub fn tick_regen(&mut self, now: u64) {
        if self.hp > 0.0 && self.hp < self.max && now - self.last_hurt_tick > 100 {
            self.regen_timer += 1;
            if self.regen_timer >= 40 { self.heal(1.0); self.regen_timer = 0; }
        } else {
            self.regen_timer = 0;
        }
    }

    pub fn can_eat(&self) -> bool { self.hp < self.max } // [наше] вместо «голод не полон»
}

/// LivingEntity.takeKnockback над вектором скорости v; (x, z) — направление НА источник.
pub fn knockback(v: &mut [f64; 3], on_ground: bool, strength: f64, resist: f64, mut x: f64, mut z: f64, rng: &mut Rng) {
    let s = strength * (1.0 - resist);
    if s <= 0.0 { return; }
    while x * x + z * z < 1.0e-5f32 as f64 { x = (rng.f64() - rng.f64()) * 0.01; z = (rng.f64() - rng.f64()) * 0.01; }
    let l = (x * x + z * z).sqrt();
    v[0] = v[0] / 2.0 - x / l * s;
    v[2] = v[2] / 2.0 - z / l * s;
    if on_ground { v[1] = (v[1] / 2.0 + s).min(0.4); }
}

impl Body {
    /// Для цели-игрока — как в ванильном MP (§5, решение §19): считаем по «серверной копии» скорости с гор. 0.
    /// Копия живёт до конца тика, поэтому базовые 0.4 и беговые 0.5 одной атаки складываются на ней (0.2·от + 0.5·взгляд),
    /// а итог заменяет скорость тела. `kb_copy = None` в начале каждого тика.
    pub fn take_knockback(&mut self, strength: f64, x: f64, z: f64) {
        if self.is_player {
            let mut c = self.kb_copy.unwrap_or([0.0, self.vel[1], 0.0]);
            knockback(&mut c, self.on_ground, strength, self.knockback_resistance, x, z, &mut self.rng);
            self.kb_copy = Some(c);
            self.vel = c;
        } else {
            knockback(&mut self.vel, self.on_ground, strength, self.knockback_resistance, x, z, &mut self.rng);
        }
    }

    /// Хвост Entity.move после коллизий (контракт с ASP-02): вода → падение → кактус.
    pub fn after_move(&mut self, dy: f64, w: &World, hp: &mut Health, armor: &Armor, now: u64, ev: &mut Vec<Ev>) {
        if !self.touching_water && w.box_touches_water(self.aabb()) { self.touching_water = true; self.fall_distance = 0.0; }
        if self.on_ground {
            if self.fall_distance > 0.0 {
                let d = fall_damage(self.fall_distance);
                if d > 0 {
                    ev.push(Ev::FallSound { big: d > 4 });
                    let src = Source { kind: DamageKind::Fall, attacker: None, pos: None };
                    hp.damage(&src, d as f32, self, armor, now, ev);
                }
            }
            self.fall_distance = 0.0;
        } else if dy < 0.0 {
            self.fall_distance -= dy as f32; // смещение тика приземления сюда не попадает
        } else if dy > 0.0 {
            self.fall_distance = 0.0; // правило сервера: любое движение вверх обнуляет
        }
        if w.cells_of(self.aabb().deflate(1e-7)).any(|b| b == CACTUS) {
            let src = Source { kind: DamageKind::Cactus, attacker: None, pos: None };
            hp.damage(&src, 1.0, self, armor, now, ev);
        }
    }
}

/// PlayerEntity.attack: урон и флаги до target.damage.
pub struct Swing { pub damage: f32, pub strong: bool, pub crit: bool, pub sprint_kb: bool, pub sweep: bool }
pub fn cooldown(last_attacked_ticks: i32, attack_speed: f64, base: f32) -> f32 {
    let per = (1.0 / attack_speed * 20.0) as f32;
    ((last_attacked_ticks as f32 + base) / per).clamp(0.0, 1.0)
}
pub fn swing(a: &Attacker) -> Swing {
    let h = cooldown(a.last_attacked_ticks, a.attack_speed, 0.5);
    let mut f = a.attack_damage * (0.2 + h * h * 0.8);
    let strong = h > 0.9;
    let sprint_kb = a.sprinting && strong;
    let crit = strong && a.fall_distance > 0.0 && !a.on_ground && !a.climbing && !a.in_water && !a.sprinting;
    if crit { f *= 1.5; }
    let sweep = strong && !crit && !sprint_kb && a.on_ground && a.hspeed_delta < a.movement_speed && a.holds_sword;
    Swing { damage: f, strong, crit, sprint_kb, sweep }
}
```

## 19. Что решить

Пользователю (ощущение):
1. **Темп регенерации:** вариант A (½ ♥ каждые 2 с после 5 с без урона) — рекомендую как старт; B или C — если A покажется
   быстрым для PvP.
2. **Еда при полных сердцах:** нельзя (рекомендую, как ванильный «полный голод») или можно всегда (впустую).
3. **Отбрасывание «как в ванильном мультиплеере»:** цель-игрок теряет свою скорость, атакующий не замедляется ×0.6,
   бег срывается (рекомендую) — или «честная» физика с сохранением половины скорости.
4. **Экран смерти:** вторая кнопка («Главное меню» / «Выйти» / нет). Счёт не показываем.
