## 1. Звуковая система Minecraft: как звук доходит до ушей

### 1.1 Путь одного звука [src]

1. Игровой код вызывает `world.playSound(источник, x, y, z, событие, категория, громкость, высота)` или
   `entity.playSound(событие, громкость, высота)`.
   - Свой игрок (`ClientPlayerEntity.playSound`) играет **сразу у себя**, в точке **ступней** `(x, y, z)`, категория PLAYERS.
   - Позиция «у блока» (`World.playSound(…, BlockPos, …)`, `playSoundAtBlockCenter`) — центр клетки `(x+0.5, y+0.5, z+0.5)`.
   - `ClientWorld.playSound(…, useDistance)`: если `useDistance` и дальше 10 блоков — задержка `расстояние/40` с (скорость звука
     40 б/с; только гром и т. п.). **Во всех событиях нашего объёма `useDistance = false`.**
2. Создаётся `PositionedSoundInstance` (громкость, высота, позиция, `attenuation = LINEAR`, `relative = false`) со своим
   генератором случайных чисел.
3. `SoundManager.play` → `SoundSystem.play` (клиентский поток звука):
   1. по id события берётся `WeightedSoundSet` (список вариантов из `sounds.json`); **вариант выбирается случайно по весу**:
      `j = nextInt(сумма весов)`, идём по списку, вычитая веса, берём первый с `j < 0`. Вариант может быть ссылкой на
      другое событие (`type: event`) — тогда выбор рекурсивный. Веса по умолчанию 1 — **все варианты равновероятны** [src
      `WeightedSoundSet.getSound`; data];
   2. итоговая громкость `vol = громкость_события × volume_файла`, высота `pitch = высота_события × pitch_файла`
      [src `AbstractSoundInstance.getVolume/getPitch`];
   3. **дальность** `att = max(vol, 1) × attenuation_distance_файла` (по умолчанию 16) — громкость больше 1 только
      **удлиняет** слышимость, а не делает громче;
   4. громкость источника `gain = clamp(vol × громкость_категории, 0, 1)` (категория MASTER здесь не умножается — она
      громкость слушателя `AL_GAIN` listener); высота `clamp(pitch, 0.5, 2.0)` [src `getAdjustedVolume/getAdjustedPitch`];
   5. если `gain == 0` или мастер 0 — звук пропускается;
   6. берётся свободный источник OpenAL (§1.4); нет свободного — **звук молча теряется** (старые не вытесняются);
   7. источнику: `AL_PITCH = pitch`, `AL_GAIN = gain`, модель затухания `AL_LINEAR_DISTANCE` с
      `AL_REFERENCE_DISTANCE = 0`, `AL_ROLLOFF_FACTOR = 1`, `AL_MAX_DISTANCE = att`; позиция; `relative` (для UI и музыки —
      без затухания, `AttenuationType.NONE`). Буфер (ogg, загружен целиком) → `play` [src `Source.setAttenuation`].
4. Слушатель — **камера**: позиция `camera.getPos()` (глаза, интерполяция кадра), «вперёд» и «вверх» — оси поворота камеры.
   Обновляется **каждый кадр** перед отрисовкой (`MinecraftClient.render` → `updateListenerPosition`), без покачивания вида.
5. Позиция обычного звука **не следует** за источником (кроме `MovingSoundInstance`: в нашем объёме — фон под водой, он
   относительный). Шаг, сыгранный у ступней, остаётся на месте, игрок уходит от него.

Формула громкости, которую слышит игрок (OpenAL, линейная модель с ref = 0, rolloff = 1):

    слышно = master × clamp(vol × cat, 0, 1) × max(0, 1 − d / att),   d = |позиция − камера|,   att = max(vol, 1) × 16

| d, блоков | 0 | 1.62 (свои ступни) | 2 | 4 | 8 | 12 | 16 |
|---|---|---|---|---|---|---|---|
| множитель | 1.0 | 0.899 | 0.875 | 0.75 | 0.5 | 0.25 | 0 |

**Свой шаг**: громкость 0.15, расстояние от ушей до ступней 1.62 → `0.15 × 0.899 = 0.135` [расчёт]. Удар по блоку перед
лицом (центр в ~2.5 блока): `0.25 × 0.844 = 0.211`; разрушение — `1.0 × 0.844 = 0.844`.

Направление: стерео-панорама OpenAL Soft по углу к оси «вперёд». Опция «Направленный звук» (HRTF) в Java по умолчанию
**выключена** [src `SoundEngine.setDirectionalAudio`, `GameOptions.directionalAudio = false`]. Эффекта Доплера нет (скорости
источникам не задаются). Приглушения под водой в Java нет (оно есть в Bedrock) [src: фильтров в `Source` нет].
Контекст OpenAL создаётся с **ограничителем выхода** (`ALC_OUTPUT_LIMITER_SOFT = 1`) — сумма многих звуков не клиппует [src `SoundEngine.init`].

### 1.2 Категории [src `SoundCategory`]

MASTER, MUSIC, RECORDS, WEATHER, BLOCKS, HOSTILE, NEUTRAL, PLAYERS, AMBIENT, VOICE; все по умолчанию 1.0.
В нашем объёме используются:

| Категория | Что звучит |
|---|---|
| MASTER | громкость слушателя; клик кнопки UI (`master(…, 0.25)`, без позиции) |
| BLOCKS | удар, разрушение, ставление блока; печь; сундук; выливание ведра |
| PLAYERS | шаги, плавание, всплеск, урон, смерть, падение, подбор, поломка инструмента, жевание, отрыжка, броня, набор ведра |
| NEUTRAL | **последний** звук съедания (`LivingEntity.eatFood`, причуда: остальная еда — PLAYERS) |
| AMBIENT | под водой: вход, выход, фон, редкие добавки; всплеск предмета (ASP-07) |
| HOSTILE, WEATHER, MUSIC | позже (мобы, погода, музыка) |

### 1.3 Звуковые группы блоков и множители событий [src `BlockSoundGroup`, вызовы; data `sounds.json`]

У группы — `volume v`, `pitch p` и пять событий: break, step, place, hit, fall. Множители — **у вызова**, не в группе:

| Событие | Кто вызывает | Где | Громкость | Высота | Категория |
|---|---|---|---|---|---|
| шаг | `Entity.playStepSound` | ступни | `v × 0.15` | `p` | PLAYERS |
| второй шаг (снежный слой, ковёр; в воде) | `playSecondaryStepSound` | ступни | `v × 0.05` | `p × 0.8` | PLAYERS |
| удар (раз в 4 тика прогресса) | `ClientPlayerInteractionManager.updateBlockBreakingProgress` | центр блока | `(v+1)/8` | `p × 0.5` | BLOCKS |
| разрушение (событие 2001) | `WorldRenderer.processWorldEvent` | центр блока | `(v+1)/2` | `p × 0.8` | BLOCKS |
| ставление | `BlockItem.place` | центр нового блока | `(v+1)/2` | `p × 0.8` | BLOCKS |
| падение с уроном (блок под ногами) | `LivingEntity.playBlockFallSound` | ступни | `v × 0.5` | `p × 0.75` | PLAYERS |

У всех групп пути `v = p = 1`, у METAL `p = 1.5` (ASP-06). Значит, у нас: шаг 0.15/1.0, удар **0.25/0.5**, разрушение и
ставление 1.0/0.8, падение блока 0.5/0.75; металл: удар 0.25/0.75, разрушение 1.0/1.2.

**Файлы событий** [data `sounds.json`, только структура]: у каждой группы два набора записей — «dig» и «step».
- break и place = набор **dig** группы (4 варианта);
- step, hit и fall = набор **step** группы (4–6 вариантов). Удар — это **шаг, сыгранный на октаву ниже и вчетверо тише
  обычного удара**: файлы шагов должны хорошо звучать на скорости 0.5.

| Группа | Наши блоки | dig (break/place) | step (step/hit/fall) | Особое |

| GRAVEL | **земля**, гравий, **глина** | gravel ×4 | gravel ×4 | земля звучит гравием — как в MC |

| WOOD | брёвна, доски, верстак, сундук, факел | wood ×4 | wood ×6 | |

| SNOW | снежный слой, снежный блок | snow ×4 | snow ×4 | |

Итого своих наборов: **dig** 7 (grass, gravel, stone, wood, sand, snow, cloth) + **step** 8 (те же + ladder) + стекло.

### 1.4 Ограничение числа звуков [src `SoundEngine`, `SoundSystem.tick`]

- OpenAL сообщает число моно-источников `n` (у OpenAL Soft обычно 255 [не проверено]). Потоковых
  `j = clamp(floor(√n), 2, 8)` = 8, обычных `k = clamp(n − j, 8, 255)` = **247**.
- Источник занят не меньше **20 тиков** после старта (`soundEndTicks = ticks + 20`), даже если звук короче: потолок ≈ 247
  обычных звуков в секунду.
- Переполнение: новый звук не играет (в разработческой сборке — предупреждение). Вытеснения по приоритету или расстоянию
  **нет**. Звук за пределом слышимости всё равно занимает источник (громкость 0).
- Дублирование одинаковых звуков ничем не ограничено (можно наложить 20 одинаковых ударов).

### 1.5 Пауза и тик звука [src `MinecraftClient.tick/render`, `SoundSystem.tick`]

Порядок клиентского тика: … ввод (удар, разрушение, ставление) → `world.tickEntities` (шаги, всплеск, падение) →
`soundManager.tick(paused)` (громкость «живых» звуков, отложенные звуки) → `world.tick` → `doRandomBlockDisplayTicks`
(печь, факел, вода) → `particleManager.tick`. Кадр: `updateListenerPosition(camera)` → отрисовка.
Меню паузы: `soundManager.pauseAll()` — играющие звуки замирают и потом продолжаются; новые звуки меню (клик) играют.

## 2. Шаги, плавание, всплеск

### 2.1 Шаги [src `Entity.move`, `stepOnBlock`, `calculateNextStepSoundDistance`, `PlayerEntity.playStepSound/getMoveEffect`]

В `Entity.move` после коллизии, флагов `onGround` и `fall` (ASP-02 §3.4, шаг 11):

1. `moveEffect = NONE`, если летит (`abilities.flying`) или **стоит на земле с Shift** (`isOnGround && isSneaky`); иначе ALL.
   При NONE дальше ничего: ни расстояния, ни шагов (и `horizontalSpeed` не растёт — ASP-01).
2. `speed += |v|·0.6`; опорная клетка `stepping = getPosWithYOffset(1e-5)`, клетка приземления `landing = getPosWithYOffset(0.2)`:
   при наличии опорного блока (ASP-02 §3.10) берутся его X/Z — **на краю звучит тот блок, на котором реально стоишь**.
3. Вертикаль в расстояние входит только на лазаемом блоке (лестница); иначе `Δy = 0`.
4. `distanceTraveled += f32(√(Δx² + Δy² + Δz²)) × 0.6` (f32).
5. Если `distanceTraveled > nextStepSoundDistance` и блок `stepping` не воздух:
   - шаг засчитан, если `onGround` (или лазает, или в позе приседа с `Δy == 0`) **и не плывёт** (`!isSwimming`);
     тогда звук шага по блоку `landing`, `nextStepSoundDistance = floor(distanceTraveled) + 1`;
   - иначе, если касается воды: `next = floor(d) + 1` и звук плавания (§2.2).
6. Если `stepping` — воздух (в прыжке): шагов нет, `next` не обновляется.

Звук шага у игрока (`PlayerEntity.playStepSound`):
- в воде (касается) — звук плавания + **второй шаг** блока под ногами (0.05, высота ×0.8);
- если в клетке **над** опорой блок из `#combination_step_sound_blocks` (ковры, **снежный слой**, мох-ковёр…) — шаг этого
  блока (0.15) + второй шаг опоры (0.05, ×0.8): по снегу на траве слышен снег и тихая трава [data тег];
- если над опорой блок из `#inside_step_sound_blocks` (кувшинка, рыхлый снег… — у нас нет) — только он;
- иначе — шаг группы опоры, громкость 0.15, высота `p`.

Темп [расчёт, f32, установившаяся скорость ASP-02]:

| Движение | б/тик | +расстояние/тик | Интервалы, тиков | Шагов в секунду |
|---|---|---|---|---|
| ходьба 4.31718 б/с | 0.215859 | 0.12952 | 7 и 8 (ср. 7.72) | **2.59** |
| бег 5.61234 б/с | 0.280617 | 0.16837 | 5 и 6 (ср. 5.94) | **3.37** |
| присед на земле | — | 0 | — | **0** (moveEffect NONE) |

Один шаг = 1/0.6 = **1.667 блока** пути. Прыжок **на месте** беззвучен: вертикаль не считается, звука приземления без
урона нет. Прыжок **с разбега**: расстояние копится в воздухе, в **тике приземления** `onGround` уже истинно — шаг звучит
сразу при касании (один, сколько бы порогов ни перешли).

### 2.2 Плавание и всплеск [src `Entity.playSwimSound`, `onSwimmingStart`, `checkWaterState`; `LivingEntity.fall`]

- **Звук плавания** `entity.player.swim` (14 вариантов): громкость `min(1, √(0.2·vx² + vy² + 0.2·vz²) × 0.35)`, высота
  `1 + (r − r)·0.4` (0.6–1.4, треугольное); каждые 1.667 блока горизонтального пути, пока касается воды и не стоит на дне
  (или стоит — тогда вместе со вторым шагом). Очень тихо [расчёт]: плывёт 0.1 б/т → 0.016; 0.3 б/т и вверх 0.05 → 0.05.
- **Всплеск** при первом касании воды (`checkWaterState`, не в первом тике сущности; вызывается и из `fall` внутри `move`,
  т. е. со скоростью этого перемещения): `g = min(1, √(0.2·vx² + vy² + 0.2·vz²) × 0.2)`; `g < 0.25` → `entity.player.splash`
  (2 варианта), иначе `entity.player.splash.high_speed` (1); высота `1 ± 0.4` (треугольное); категория PLAYERS.
  Частицы: `1 + 0.6·20 = 13` **BUBBLE** и 13 **SPLASH** в точках `(x ± 0.6·r, floor(y) + 1, z ± 0.6·r)`; пузырям скорость
  игрока и вниз до −0.2, брызгам — скорость игрока.
- Касание воды обнуляет `fallDistance` — урона и звуков падения нет.

| Падение в воду с высоты, блоков (без начальной скорости) | 0.5 | 1 | 2 | 3 | 5 | 10 | 15 | 20 | 30 |
|---|---|---|---|---|---|---|---|---|---|
| модуль vy входа, б/т [расчёт] | 0.304 | 0.377 | 0.517 | 0.652 | 0.844 | 1.139 | 1.355 | 1.506 | 1.782 |
| громкость всплеска | 0.061 | 0.075 | 0.103 | 0.130 | 0.169 | 0.228 | 0.271 | 0.301 | 0.356 |
| звук | splash | splash | splash | splash | splash | splash | **high_speed** | high_speed | high_speed |

### 2.3 Под водой [src `ClientPlayerEntity.updateWaterSubmersionState`, `AmbientSoundLoops`, `AmbientSoundPlayer`]

- Глаза ушли под воду: `ambient.underwater.enter` (3; в `sounds.json` громкость файла 0.5) у ступней, AMBIENT, 1.0/1.0;
  запускается фоновая петля `ambient.underwater.loop` (файл 0.65), **относительная** (без позиции), громкость
  `timer/40`, `timer` +1 за тик под водой (полная через **2 с**), −2 за тик над водой (затухание за **1 с**), затем стоп.
  Каждый вход создаёт новую петлю; старая дозатухает сама.
- Глаза вышли: `ambient.underwater.exit` (3; файл 0.3).
- Пока под водой, каждый тик бросок `f`: `< 0.0001` — «ультраредкая» добавка, `< 0.001` — «редкая», `< 0.01` — обычная
  (пузыри и вода, 8 вариантов): обычная добавка в среднем раз в **5 с**; относительные, AMBIENT.
- Звука лопания пузыря воздуха (HUD) в 1.21.1 нет (ASP-12).

### 2.4 Частицы шагов и падения

- **Бег** (`Entity.baseTick` каждый тик): если бежит, не касается воды, не в позе приседа, жив — блок `landing`
  (y − 0.2); если он не «невидимый» (воздух — невидимый: в прыжке частиц нет) — **1 частица BLOCK** в тик в точке
  `(x ± 0.3·r, y + 0.1, z ± 0.3·r)` (на краю — прижата к клетке опоры), скорость `(−4·vx, 1.5, −4·vz)` (дальше
  нормализуется конструктором частицы, §4.2: фактически вверх-назад 0.06–0.18 б/т + 0.1 вверх) [src `spawnSprintingParticles`].
- **Приземление с уроном** (`LivingEntity.fall`, сервер): если `fallDistance > 3` и блок не воздух — частицы BLOCK блока
  приземления: `k = ceil(fallDistance − 3)`, число `(int)(150 · min(0.2 + k/15, 2.5))`, все в одной точке (ступни; если
  опора — соседняя клетка, точка сдвигается к её краю), скорость по осям `N(0, 0.15)` → конструктор нормализует.
  Идут через `world.addParticle` — действует предел 32 блока (§4.6).

## 4. Частицы Minecraft

### 4.1 Общая частица `Particle` [src `Particle`, `BillboardParticle`, `SpriteBillboardParticle`]

Поля: позиция и прошлая позиция (f64), скорость (f64), коробка `0.2 × 0.2` (`scale(k)` — `0.2k`), `age`, `maxAge`,
`gravityStrength`, `velocityMultiplier = 0.98`, цвет RGBA, `collidesWithWorld = true`, флаги `onGround`, `stopped`.
По умолчанию `maxAge = (int)(4 / (r·0.9 + 0.1))` = **4…40 тиков**, среднее ≈ **9.8**, медиана 7, 90 % — не больше 21
[расчёт] — большинство крошек живёт меньше полсекунды, редкие — до 2 с.

Конструктор со скоростью `(vx, vy, vz)` **перемешивает её** (так создаются почти все наши частицы):

    v += (rand·2 − 1)·0.4 по каждой оси;   d = (rand + rand + 1)·0.15;   v = v/|v| · d·0.4;   vy += 0.1

Итог: модуль случайной части **0.06…0.18** б/тик в направлении, близком к заданному, плюс 0.1 вверх [расчёт:
при нулевой заданной скорости vy ∈ [−0.08, 0.28], горизонталь ≈ 0.095 в среднем].

Тик (каждый игровой тик, если не пауза):
1. `prev = pos`;
2. `if age++ >= maxAge` → умерла;
3. `vy −= 0.04 × gravityStrength`;
4. `move(v)`: если коллизия включена и шаг < 100 блоков — коллизия коробки частицы с блоками **тем же решателем, что у
   сущностей** (`Entity.adjustMovementForCollisions`); сдвиг; **если вертикаль запрошена (|dy| ≥ 1e-5), а пройдено
   меньше 1e-5 — частица навсегда `stopped`** (дальше `move` ничего не делает): легла на землю или **упёрлась в потолок —
   так и висит под ним до смерти**; `onGround` = упёрлась вниз; заблокированная ось X/Z — скорость по ней 0;
5. `v ×= velocityMultiplier`; на земле `vx, vz ×= 0.7`.

Отрисовка: квадрат, повёрнутый **как камера** (плоскость экрана, не «лицом к точке»), углы `±size` (сторона `2·size`),
позиция `lerp(tickDelta, prev, pos)`. Свет — из карты освещения в клетке частицы (блок + небо, `getLightmapCoordinates`);
шейдер `particle`: `цвет = текстура × цвет_вершины × lightmap`, **отброс при α < 0.1**, линейный туман. Нормалей и
затенения граней нет [data `shaders/core/particle.vsh/fsh`].

Листы текстур и порядок [src `ParticleTextureSheet`, `ParticleManager.renderParticles`, `WorldRenderer.render`]:
`TERRAIN_SHEET` (атлас блоков; смешивание включено, запись глубины) → `PARTICLE_SHEET_OPAQUE` (атлас частиц, без смешивания)
→ `PARTICLE_SHEET_LIT` → `PARTICLE_SHEET_TRANSLUCENT` → `CUSTOM`. **Все частицы нашего объёма — «вырезанные»** (TERRAIN и
OPAQUE, отброс по альфе): сортировки нет. Рисуются **после** полупрозрачного слоя (воды) с тестом и записью глубины —
поэтому в «красивой» графике частицы под водой сверху не видны (их закрывает глубина воды) [src; вывод].

### 4.2 Крошки блока `BlockDustParticle` [src `BlockDustParticle`, `ParticleManager.addBlockBreakParticles/addBlockBreakingParticles`]

- Спрайт — текстура «частицы» модели блока: у трава-блока — **земля** [data `models/block/grass_block.json`], у брёвен —
  бок, у печи — лицо, у верстака — лицо, у сундука — доски, у кактуса — бок, у факела — факел, у листвы и растений —
  их текстура.
- Кусок спрайта **1/4 × 1/4** (4×4 текселя из 16×16) со случайным непрерывным сдвигом `[0, 3/4)` по U и V (U зеркален).
- Цвет `0.6 × оттенок блока` (листва и трава-растение — цвет биома; **трава-блок без оттенка** — земляная крошка), α = 1.
- Размер `size = 0.1·(r·0.5 + 0.5)·2 / 2` = **0.05…0.1** (квадрат 0.1–0.2 блока); гравитация 1.0; срок 4…40.
- Свет: в клетке частицы; если там 0 (внутри камня) — свет клетки самого блока.

**Разрушение** (событие 2001, `addBlockBreakParticles`): для каждой коробки формы обводки — сетка
`max(2, ceil(размер/0.25))` по осям: куб **4×4×4 = 64**, частица в центре ячейки, заданная скорость — смещение ячейки от
центра коробки (`±0.125`, `±0.375`) → перемешивание конструктором. Числа по формам: трава-растение 3×4×3 = 36,
цветок и факел 2×3×2 = 12, снежный слой 1 — 4×2×4 = 32, сундук и кактус — 64 [расчёт по формам ASP-04/05].
Средняя начальная `vy` [расчёт]: верхние ячейки ≈ 0.16, нижние ≈ 0.02; горизонталь ≈ 0.08–0.095. Пример полёта
(vy₀ = 0.15): подъём до +0.2 блока за 3 тика, ниже старта — на 7-м.

**Удар** (каждый тик удержания на блоке, `addBlockBreakingParticles(pos, грань)`): точка — случайная в пределах коробки
обводки, сжатой на 0.1 с краёв, и вынесенная **на 0.1 наружу** от грани удара; скорость 0 → конструктор → `move(0.2)`
(горизонталь ×0.2, `vy = (vy − 0.1)·0.2 + 0.1`) → `vy` 0.064…0.136, горизонталь ≤ 0.036; `scale(0.6)` → размер 0.03…0.06,
коробка 0.12. Прыгают на ~0.08 блока и падают; у нижней грани (копаю потолок) — сразу упираются в блок и **висят**.
Крошки удара и разрушения добавляются в менеджер **напрямую** — без предела 32 блока и без режима «меньше частиц».

## 5. Граничные случаи и мелочи, которые чувствует игрок

1. Присед на земле — шагов нет совсем, даже при движении; в воздухе с Shift шагов тоже нет (не на земле).
2. Прыжок на месте беззвучен; прыжок с разбега — шаг в момент касания.
3. На краю блока звучит опорный блок, а не то, что под центром.
4. Снежный слой на траве: «снег + тихая трава»; полный снежный блок — только снег.
5. Земля и глина звучат гравием; кактус — тканью; стекло — камнем, кроме разрушения.
6. Удар по блоку — шаговый звук на октаву ниже (0.5), тихий (0.25); первый — на первом тике прогресса, дальше каждые
   0.2 с; бедрок — удары и крошки бесконечно.
7. Разрушение и ставление — одни файлы, высота 0.8 (чуть ниже «естественной»).
8. Трава-блок рассыпается **земляными** крошками; листва — зелёными (цвет биома × 0.6).
9. Копаю потолок — крошки упираются и висят под блоком до конца жизни; на полу крошки замирают, не скользят.
10. Свой звук звучит из ступней (на 1.62 ниже ушей): в наушниках по центру, на ~10 % тише «у лица».
11. Звук блока справа — справа; на 8 блоках вдвое тише; на 16 — тишина.
12. Подбор: половина хлопков на высоте 2.0 (обрезка), остальные ниже — «пиу-пиу» разной высоты (ASP-07).
13. Всплеск тихий: даже с 10 блоков громкость 0.23; с 15+ блоков — «тяжёлый» всплеск.
14. Под водой фон нарастает 2 с, после выныривания стихает 1 с.
15. Пауза: звуки замирают и продолжаются; частицы стоят.
16. 20 разрушений в секунду (мгновенная трава) не «душат» звук: лимит 247.
17. Крошки и пыль падения могут залетать в соседние блоки? — нет: коллизия как у сущностей; но FLAME и UNDERWATER без
    коллизии и проходят сквозь блоки.
18. Частицы под водой сверху не видны (ванильная причуда отрисовки «после воды»); пузыри, вылетевшие из воды, лопаются сразу.

## 6. Чего нет в исходнике / не ясно

1. **Число источников OpenAL** зависит от драйвера; 255 → 247 + 8 — обычное значение OpenAL Soft [не проверено].
2. **Закон панорамы** OpenAL Soft (стерео без HRTF) не совпадает побитно с `PannerNode` WebAudio (`equalpower`) —
   на слух близко; HRTF в Java по умолчанию выключен [не проверено на слух].
3. **Относительная громкость файлов** Mojang (пиковая, RMS) нам недоступна и не нужна: свои файлы выравниваем на слух и
   замером (§7.4). Числа громкости событий из Java применяются **поверх** нашей нормализации.
4. Характер звука урона `damage/hit1..3` (глухой удар или голос) — не прослушан [не проверено]; кандидаты — оба варианта.
5. Точный вид частиц в 1.21.1 «Fabulous» (частицы в отдельной цели, видны под водой) — не разбирали; берём «Fancy».
6. Свет частиц в нашем движке без lightmap (до ASP-14) — своя замена (§8.3).
7. Декодирование `.ogg` в Safari — [не проверено]; на этапе ПК (Chrome/Firefox/Edge) Ogg Vorbis работает.
8. Firefox и `AudioListener.positionX` (AudioParam) — поддержка ограничена (MDN «Limited availability»); нужен
   запасной путь `setPosition/setOrientation` [не проверено по версиям].

## 8. Наша архитектура (E10)

### 8.1 Разделение

- **Rust** (логика, `cargo test`): когда и с какими числами звучит событие (шаги, удары, падение, вода, еда, печь, сундук…),
  всё случайное в формулах высоты и громкости — **отдельным ГСЧ эффектов** (чтобы звуки и частицы не сдвигали ГСЧ дропа и
  эталонные тесты); система частиц целиком (спавн, физика с коллизией, срок, кадр спрайта) и буфер экземпляров.
- **JS**: WebAudio (выбор варианта по весу, категории, затухание, панорама, пул голосов, пауза, разблокировка), отрисовка
  частиц одним-тремя инстансными вызовами.

### 8.2 Звук: WebAudio

Граф: `AudioBufferSourceNode (playbackRate = pitch)` → `GainNode (gain)` → `PannerNode` → `GainNode категории` →
`GainNode master` → `DynamicsCompressorNode` (ограничитель, как `ALC_OUTPUT_LIMITER_SOFT`) → `destination`.

- **Затухание — встроенным `PannerNode` по формуле MC**: `distanceModel = "linear"`, `refDistance = 0`,
  `maxDistance = att`, `rolloffFactor = 1` — спецификация WebAudio даёт ровно `1 − d/att` с зажимом. `panningModel =
  "equalpower"` по умолчанию; HRTF — настройка «Направленный звук» (как опция Java). Доплера в WebAudio нет — и не нужен.
  Альтернатива «своя формула» (`GainNode` + `StereoPannerNode`, пересчёт каждый кадр) — проще тестировать в Rust, но без
  HRTF; брать только если `PannerNode` где-то ведёт себя иначе.
- `playbackRate` меняет высоту и длительность вместе — так же работает `AL_PITCH` в OpenAL.
- **Слушатель** — камера кадра (интерполированная), без покачивания; оси из yaw/pitch (`game.view(alpha)`).
  Позиции считать **от «звукового начала»** (клетка, сдвигаемая раз в ~1000 блоков), чтобы float32 WebAudio не терял
  точность на 16 км. `positionX/forwardX…` — если есть, иначе `setPosition/setOrientation`.
- Громкость голоса `clamp(vol × cat, 0, 1)`; `att = max(vol, 1) × attenuation_файла`; высота `clamp(pitch, 0.5, 2)`.
  Если `d ≥ att` — голос **не создаём** (в MC он играет с нулём; для звуков < 2 с разницы не слышно).
- **Пул**: до 128 одновременных голосов (MC — 247); полон — новый звук отбрасывается (как в MC). Голос удаляется по `onended`.
- **Разблокировка**: `AudioContext` создаётся при старте (будет `suspended`), `resume()` — в обработчике клика, который
  захватывает мышь (жест пользователя). Пока контекст не `running`, звуки **не копятся**, а отбрасываются (иначе после клика
  прозвучит вся очередь разом).
- **Загрузка**: при старте `fetch` + `decodeAudioData` всех файлов (декодирование работает и до разблокировки); не
  загруженный вариант — пропуск.
- **Пауза** (Esc, потеря фокуса — ASP-01): два контекста — «мир» (`suspend()` на паузе, `resume()` после) и «интерфейс»
  (клики меню, не замирает). Альтернатива в одном контексте — остановить голоса и перезапустить с `offset`.
- Петли (фон под водой): один долгоживущий голос `loop = true`, громкость каждый тик из Rust (`underwater_fade 0…1`).

Интерфейс Rust → JS (раз за кадр после тиков):

    game.take_sounds() → Float32Array, по 8 чисел на звук:
      [event_id, category, x, y, z (от звукового начала; NaN = относительный), volume, pitch, flags]
    game.underwater_ambience() → 0…1   // громкость петли

### 8.3 Частицы: Rust + инстансинг WebGL2

- Хранилище в Rust: кольцевой буфер (вытеснение старейшей при 16 384), структура частицы как в §4.1 (f64 позиции,
  `stopped`, `on_ground`, коробка), тип (`BlockDust`, `Crumb`, `ItemCrack`, `Bubble`, `Splash`, `Underwater`, `Flame`,
  `Smoke`, `FallingDust`, `Poof`).
- Тик — **фаза 5 «эффекты»** после мира (как в MC: случайный показ блоков → тик частиц; новые частицы — в конец, двигаются
  со следующего тика). Коллизия — тот же решатель AABB, что у сущностей (ASP-02/07), запрос формы блока E2.
- Предел 32 блока от камеры — для всех, кроме крошек удара и разрушения; настройка «Частицы: все/меньше/минимум» — позже.
- После тика Rust пишет буфер экземпляров (в памяти WASM, JS берёт `Float32Array` без копирования):
  `prev xyz, cur xyz` (f32 от начала отрисовки), `size`, `uv0, uv1` (кусок 1/4 или весь спрайт), `layer` (слой массива
  текстур), `rgba8`, `age, maxAge`, `kind` (кривая размера и свечения).
- Вершинный шейдер: `p = mix(prev, cur, alpha) + (corner.x·right + corner.y·up)·size(kind, (age+alpha)/maxAge)`;
  `right/up` — оси камеры (плоскость экрана, как MC). Фрагментный: текстура × цвет, `discard` при α < 0.1, туман общей функцией.
- Текстуры: крошки блоков — тот же массив атласа блоков (`sampler2DArray`, слой из `layer(b, face)` «частица модели»);
  предметы — массив спрайтов предметов (ASP-07/11); свои спрайты частиц (дым 8 кадров, пламя, пузырь, брызги 4 кадра,
  пыль) — маленький массив, рисуем сами (E8). 2–3 вызова отрисовки, без сортировки.
- Свет (до ASP-14): как у предметов и руки — небо + видимость солнца из карты теней **в центре частицы** (выборка в
  вершинном шейдере); FLAME — сама светится (растёт к концу жизни); после ASP-14 — блочный свет клетки.
- Порядок прохода: после cutout, с тестом глубины. Предложение: **до воды** — тогда пузыри и пыль под водой видны сквозь
  воду (лучше ванили «Fancy»); вариант «как в ванили» — после воды. Запись глубины: да (как MC); если SSAO в post.js даст
  ореолы — без записи.
- Цена: худший обычный случай — быстрое копание травы (36–64 частиц в тик, живут ~10 тиков) ≈ 400–700 живых;
  падение — до 375 разом. Буфер 16 384 × 48 Б = 768 КБ, загружается раз за тик.

pub fn step_effects(p: &mut Player, w: &World, fx: &mut Fx, moved: [f64; 3]) {
    if p.flying || (p.on_ground && p.sneaking) { return; }           // moveEffect NONE
    let climb = w.is_climbable(p.stepping_pos());
    let dy = if climb { moved[1] } else { 0.0 };
    let len = ((moved[0] * moved[0] + dy * dy + moved[2] * moved[2]).sqrt()) as f32;
    p.dist_traveled += len * 0.6;                                     // f32, как в Java
    if p.dist_traveled <= p.next_step || w.is_air(p.stepping_pos()) { return; }
    let feet = p.pos;
    if (p.on_ground || climb) && !p.swimming {
        let landing = p.landing_pos();                               // опора по X/Z, y = floor(y − 0.2)
        let above = landing.up();
        if p.touching_water {
            fx.swim_sound(p);
            fx.play_step(w.group(landing), feet, 0.05, 0.8);           // второй шаг
        } else if w.is_combination_step(above) {                     // снежный слой
            fx.play_step(w.group(above), feet, 0.15, 1.0);
            fx.play_step(w.group(landing), feet, 0.05, 0.8);
        } else {
            fx.play_step(w.group(landing), feet, 0.15, 1.0);
        }
        p.next_step = p.dist_traveled.floor() + 1.0;
    } else if p.touching_water {
        p.next_step = p.dist_traveled.floor() + 1.0;
        fx.swim_sound(p);
    }
}

// Частица: перемешивание скорости конструктором и тик.
pub fn spawn_vel(rng: &mut Rng, v: [f64; 3]) -> [f64; 3] {
    let mut v = [v[0] + rng.sym(0.4), v[1] + rng.sym(0.4), v[2] + rng.sym(0.4)];
    let d = (rng.f64() + rng.f64() + 1.0) * 0.15;
    let n = (v[0] * v[0] + v[1] * v[1] + v[2] * v[2]).sqrt();
    for c in &mut v { *c = *c / n * d * 0.4; }
    v[1] += 0.1;
    v
}

impl Particle {
    pub fn tick(&mut self, w: &World) -> bool {                      // false — умерла
        self.prev = self.pos;
        let alive = self.age < self.max_age; self.age += 1;
        if !alive { return false; }
        self.vel[1] -= 0.04 * self.gravity as f64;
        if !self.stopped {
            let want = self.vel;
            let got = if self.collides { w.collide_box(self.aabb(), want) } else { want };
            self.translate(got);
            if want[1].abs() >= 1e-5 && got[1].abs() < 1e-5 { self.stopped = true; } // легла или упёрлась в потолок
            self.on_ground = want[1] != got[1] && want[1] < 0.0;
            if want[0] != got[0] { self.vel[0] = 0.0; }
            if want[2] != got[2] { self.vel[2] = 0.0; }
        }
        for c in &mut self.vel { *c *= self.drag as f64; }
        if self.on_ground { self.vel[0] *= 0.7; self.vel[2] *= 0.7; }
        true
    }
}

pub fn break_particles(fx: &mut Fx, pos: [i32; 3], block: Block, boxes: &[Aabb]) {
    for b in boxes {
        let size = [b.dx().min(1.0), b.dy().min(1.0), b.dz().min(1.0)];
        let n = size.map(|s| ((s / 0.25).ceil() as i32).max(2));
        for i in 0..n[0] { for j in 0..n[1] { for k in 0..n[2] {
            let f = [(i as f64 + 0.5) / n[0] as f64, (j as f64 + 0.5) / n[1] as f64, (k as f64 + 0.5) / n[2] as f64];
            let at = [pos[0] as f64 + b.min[0] + f[0] * size[0], pos[1] as f64 + b.min[1] + f[1] * size[1],
                      pos[2] as f64 + b.min[2] + f[2] * size[2]];
            fx.spawn_block_dust(at, [f[0] - 0.5, f[1] - 0.5, f[2] - 0.5], block, pos);
        }}}
    }
}

export function createAudio(manifest) {
  const world = new AudioContext({ latencyHint: "interactive" }), ui = new AudioContext();
  const out = world.createDynamicsCompressor(); out.connect(world.destination);   // ограничитель
  const master = world.createGain(); master.connect(out);
  const cats = {}; for (const c of ["blocks", "players", "neutral", "ambient"]) { cats[c] = world.createGain(); cats[c].connect(master); }
  const buffers = new Map(); let voices = 0; const MAX = 128;
  function play(ev, catVolume) {                 // ev: {id, cat, x, y, z, vol, pitch, relative}
    if (world.state !== "running" || voices >= MAX) return;
    const list = buffers.get(ev.id); if (!list) return;
    const v = pickWeighted(list);                // равные веса по умолчанию
    const vol = ev.vol * v.volume, pitch = Math.min(2, Math.max(0.5, ev.pitch * v.pitch));
    const att = Math.max(vol, 1) * (v.att || 16);
    if (!ev.relative && distToListener(ev) >= att) return;
    const src = world.createBufferSource(); src.buffer = v.buffer; src.playbackRate.value = pitch;
    const g = world.createGain(); g.gain.value = Math.min(1, Math.max(0, vol * catVolume[ev.cat]));
    src.connect(g);
    if (ev.relative) g.connect(cats[ev.cat]);
    else {
      const p = new PannerNode(world, { distanceModel: "linear", refDistance: 0, maxDistance: att, rolloffFactor: 1,
        panningModel: settings.hrtf ? "HRTF" : "equalpower", positionX: ev.x, positionY: ev.y, positionZ: ev.z });
      g.connect(p); p.connect(cats[ev.cat]);
    }
    voices++; src.onended = () => { voices--; }; src.start();
  }
  return { play, unlock: () => { world.resume(); ui.resume(); }, pause: () => world.suspend(), resume: () => world.resume() };

## 12. Что решить главному агенту

1. **Удар = шаг на 0.5** (как MC, без лишних файлов) или свои наборы «hit», если шаги на половинной скорости звучат плохо.
2. **Кактус — группа WOOL**: нужны наборы «ткань» (Kenney carpet + RPG cloth, CC0) — или осознанно отступить (кактус → GRASS).
3. **Стекло**: CC0 (rubberduck, стекло ×5) или CC BY 3.0 с настоящим «звоном осколков» (исходники Minetest).
4. **CC BY-SA** (наборы Mito551 из Minetest/VoxeLibre) — правило пока запрещает; текстуры у нас и так CC BY-SA. Нужны ли они?
5. **Звук урона**: глухой удар (Kenney punch) или голос (CC0 «ух»).
6. **Порядок частиц и воды**: «до воды» (пузыри видны сквозь воду) или как в ванили «после воды».
7. **Отдельный ГСЧ эффектов** — да/нет (рекомендую да: эталоны дропа не зависят от звуков).
8. **Пауза**: два `AudioContext` или перезапуск голосов с `offset`.
9. **Пул**: 128 голосов (MC 247) и отбрасывание новых при переполнении.
10. **Формат**: Ogg Vorbis моно; Safari — на этапе телефона (возможен второй формат).
11. Настройки: громкость категорий (общая, блоки, игроки, окружение, существа), «Направленный звук (HRTF)», позже
    «Частицы: все/меньше/минимум».
12. Свет частиц до ASP-14 — «небо + солнце в центре частицы», как у руки и предметов.
