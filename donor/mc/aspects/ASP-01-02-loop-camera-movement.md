## 0. Коротко: главное для реализации

1. **Кадр:** накопитель времени → от 0 до 10 целых тиков по 50 мс (лишние тики **отбрасываются**, игра «замедляется») →
   поворот камеры мышью (каждый кадр, после тиков) → отрисовка с долей `tickDelta` ∈ [0, 1). [src]
2. **Интерполируются:** позиция тела, высота глаз, множитель FOV, фаза и амплитуда покачивания, крен от удара.
   **Не интерполируются:** yaw/pitch своего игрока (мышь меняет их сразу, `ClientPlayerEntity` переопределяет
   `getYaw/getPitch(tickDelta)`). [src]
3. **Тик игрока** — строго в таком порядке: ввод → решение о беге → обнуление малых скоростей (< 0.003) → прыжок по
   `onGround` **прошлого** тика → ввод ×0.98 → ускорение (земля/воздух по `onGround` прошлого тика) → `move` (защита
   края → коллизия Y, затем бо́льшая из X/Z, затем другая, со ступенькой) → `onGround` = упор снизу при движении вниз →
   трение и гравитация `(vy − 0.08)·0.98` → поза в конце тика. [src]
4. **Коллизия — своя AABB, как в Java** (урок cubi-core: два решателя на одно тело дают бесконечную серию дефектов). [cubi]
5. Эталоны совпали с cubi-core: ходьба **4.31718** б/с, бег **5.61234**, апекс прыжка **1.252203**. [расчёт][cubi]
6. Поправки к каталогу (подробно в §7): диагональ **быстрее** прямой на 2 % (присед по диагонали — на 41 %); присед и
   еда **не срывают** бег в 1.21.1; прыжки подряд — раз в **0.6 с** (12 тиков), а не 0.5; окно двойного W — второе
   нажатие не позже **6 тиков** (300 мс); fallDistance не включает спуск тика приземления; сервер обнуляет
   fallDistance при любом движении вверх; ступенька 1.21.1 поднимает ровно на верх препятствия.
7. Браузер: Ctrl+W закрыть страница не может запретить → основной бег — **двойное W**, Ctrl — с защитой
   (`beforeunload`, `navigator.keyboard.lock()` в полноэкранном режиме Chromium). Решение — за пользователем (§9).

# Часть ASP-01. Цикл, ввод, камера

## 2.1 Порядок кадра (`MinecraftClient.render`) [src]

1. Выполнить отложенные задачи рендер-потока.
2. `n = renderTickCounter.beginRenderTick(now)`: `tickDelta += (now − prev) / 50 мс`; `n = floor(tickDelta)`;
   `tickDelta −= n`.
3. Выполнить `min(10, n)` клиентских тиков (§2.2). Тики сверх 10 **не переносятся**: дробная часть уже вычтена,
   поэтому после зависания игра не «догоняет», а просто пропускает время.
4. Звук: позиция слушателя по камере прошлого кадра.
5. `mouse.tick()` — поворот взгляда накопленной дельтой курсора (§2.5). То есть **мышь применяется после тиков и
   прямо перед отрисовкой**: тики этого кадра движутся по yaw, который был до этого поворота.
6. `gameRenderer.render(tickDelta)`: проверка потери фокуса (§2.11) → `renderWorld` (луч прицела с `tickDelta`, камера,
   FOV, покачивание, мир, рука) → HUD.
7. Обмен буферов. Внутри `RenderSystem.flipFrame` — `glfwPollEvents` до и после swap: события клавиш и мыши
   обрабатываются **в конце кадра**; их увидят тики следующего кадра.
8. `paused` = одиночная игра и открыт экран, который ставит паузу (меню Esc). На паузе `RenderTickCounter` запоминает
   `tickDelta` и отдаёт его неизменным (картинка не дёргается), тики мира не идут.

`tickDelta` из `RenderTickCounter` — `float`; скорость тика 20 TPS (`new Dynamic(20.0F, …)`; команда `/tick` может
замедлить, нам не нужно).

## 2.2 Порядок клиентского тика (`MinecraftClient.tick`) [src]

1. `itemUseCooldown−−` (ПКМ, ASP-05).
2. HUD, луч прицела `updateCrosshairTarget(1.0)`.
3. `interactionManager.tick()` — прогресс ломания (ASP-04).
4. Если экран не открыт: `handleInputEvents()` (§2.9), затем `attackCooldown−−`. Если открыт — `attackCooldown = 10000`.
5. `gameRenderer.tick()`: **сначала** `updateFovMultiplier` и `camera.updateEyeHeight` — по состоянию игрока **на конец
   прошлого тика** (бег, поза). Отсюда задержка FOV и камеры приседа на 1 тик относительно физики.
6. `worldRenderer.tick()`.
7. `world.tickEntities()` → для игрока `ClientWorld.tickEntity`: `resetPosition()` (prev = cur для позиции, yaw, pitch),
   `age++`, `tick()` — вся физика (§3.2).
8. Частицы, звук и т. п.

## 2.3 Что интерполируется в отрисовке [src]

| Величина | Как рисуется | Где |
|---|---|---|
| Позиция камеры X, Z | `lerp(tickDelta, prevX, x)` | `Camera.update` |
| Позиция камеры Y | `lerp(prevY, y) + lerp(lastCameraY, cameraY)` | `Camera.update` |
| Yaw, pitch своего игрока | **текущие**, без интерполяции | `ClientPlayerEntity.getYaw/getPitch(float)` |
| Множитель FOV | `lerp(tickDelta, lastFovMultiplier, fovMultiplier)` | `GameRenderer.getFov` |
| Покачивание | фаза `horizontalSpeed + (horizontalSpeed − prev)·tickDelta`, амплитуда `lerp(prevStride, stride)` | `GameRenderer.bobView` |
| Крен от удара | `hurtTime − tickDelta` (ASP-12) | `tiltViewWhenHurt` |
| Луч прицела | из `getCameraPosVec(tickDelta)`: интерполированная позиция + **несглаженная** высота глаз | `renderWorld → updateCrosshairTarget(f)` |
| Другие сущности | `lerp(prev, cur)` | рендереры сущностей (ASP-07) |

Мышь меняет `yaw` и `prevYaw` на одну и ту же величину (`Entity.changeLookDirection`), поэтому даже для чужих
сущностей поворот мышью не «размазывается» по тикам. [src]

## 2.4 Мышь (`Mouse`, `Entity.changeLookDirection`) [src]

- Колбэк курсора копит `cursorDeltaX/Y` (только при фокусе окна). Раз в кадр `Mouse.tick` → `updateMouse` → обнуление.
- Коэффициент: `d = sens·0.6 + 0.2; f = d³·8`; поворот: `yaw += dx·f·0.15°`, `pitch += dy·f·0.15°·(инверсия ? −1 : 1)`,
  `pitch` зажат в [−90°, 90°]. **Yaw не заворачивается** в ±180 (растёт неограниченно, float).
- Ускорения и сглаживания нет. Сырой ввод (`rawMouseInput`, по умолчанию вкл.) — без ускорения ОС.
- «Плавная камера» (кинематографичная): `Smoother` для X и Y, параметр `timeDelta·f`. Клавиша `key.smoothCamera`
  в 1.21.1 **не назначена** по умолчанию (в каталоге — F8). P2.
- Подзорная труба: `f` → `d³` без ×8 (не нужно).
- Ось: yaw 0 — взгляд на +Z (юг), yaw 90 — на −X; вектор взгляда `(−sin yaw·cos pitch, −sin pitch, cos yaw·cos pitch)`;
  pitch > 0 — вниз. Мышь вправо → yaw растёт.

| Чувствительность (меню) | `sens` | °/отсчёт | отсчётов на 360° |
|---|---|---|---|
| 0 % | 0.0 | 0.0096 | 37 500 |
| 50 % | 0.25 | 0.0514 | 6 997 |
| **100 % (по умолчанию)** | **0.5** | **0.1500** | **2 400** |
| 150 % | 0.75 | 0.3295 | 1 092 |
| 200 % | 1.0 | 0.6144 | 586 |

Захват курсора `lockCursor` [src]: только при фокусе; перечитывает физически зажатые клавиши (`updatePressedStates`,
кроме macOS); ставит `attackCooldown = 10000` — **клик, которым вернули мышь в игру, не бьёт и не ломает**, пока ЛКМ
не отпущена (`handleBlockBreaking(false)` обнуляет cooldown). Освобождение `unlockCursor` — при открытии любого экрана.

Колесо [src]: дробные прокрутки копятся, шаг слота — каждая целая единица; смена направления сбрасывает накопленное
(ASP-08).

## 2.5 FOV (`AbstractClientPlayerEntity.getFovMultiplier`, `GameRenderer`) [src]

- Цель каждого тика: `t = (speedAttr / walkSpeed + 1) / 2`, где `walkSpeed = 0.1`; полёт ×1.1; затем
  `t = lerp(fovEffectScale, 1, t)` (опция «Эффекты FOV», по умолчанию 1.0). Бег: атрибут 0.13 → `t = 1.15`.
  Цель зависит от **флага бега (атрибута)**, а не от фактической скорости: бег в упор с мягким касанием стены держит FOV.
- Сглаживание в `GameRenderer.tick`: `fov += (t − fov)·0.5`, зажим [0.1, 1.5]; рисуется `lerp(tickDelta, last, cur)`.
- Угол: `FOV_опция (30…110, по умолчанию 70) · lerp(...)`; под водой/в лаве ещё `· lerp(fovEffectScale, 1, 0.85714287)`
  (ASP-03); при смерти — делитель (ASP-12).
- Проекция: `perspective(fov, aspect, near = 0.05, far = viewDistance·4)`; **FOV вертикальный**.
- Рука рисуется с базовым **70°** без множителя бега и без опции FOV (`getFov(…, false)`) — для ASP-11.

FOV при FOV-опции 70, по тикам от начала бега [расчёт]: 70.00 → 75.25 → 77.88 → 79.19 → 79.84 → 80.17 → 80.34 → 80.42 → …
→ 80.5. 90 % перехода — за ~3.3 тика (0.17 с). Учитывая задержку 1 тик (§2.2), картинка начинает расширяться
через 50 мс после старта бега.

## 2.6 Покачивание камеры (`GameRenderer.bobView`) [src]

- Фаза `g = −(horizontalSpeed + (horizontalSpeed − prevHorizontalSpeed)·tickDelta)`; амплитуда
  `h = lerp(tickDelta, prevStrideDistance, strideDistance)`.
- Матрица в **пространстве камеры** (домножается на проекцию: `P · Bob · View`):
  сдвиг `(sin(gπ)·h·0.5, −|cos(gπ)·h|, 0)`, затем поворот вокруг Z на `sin(gπ)·h·3°`, затем вокруг X на
  `|cos(gπ − 0.2)·h|·5°` (0.2 — радианы). Та же матрица применяется к руке.
- `horizontalSpeed += |Δ_гор|·0.6` в `Entity.move` — по фактическому смещению после коллизии, **и в воздухе тоже**;
  но **не растёт**, если `getMoveEffect() == NONE`: полёт или (`onGround` и Shift зажат) — при ходьбе на корточках фаза
  замирает (камера чуть смещена и не качается).
- `strideDistance` в `PlayerEntity.tickMovement`: цель `min(0.1, |v_гор|)` на земле (скорость **после** трения), иначе 0;
  `stride += (цель − stride)·0.4`. Ходьба и бег дают одинаковую амплитуду 0.1 (скорость > 0.1 б/т в обоих), бег отличается
  только частотой. В прыжке амплитуда гаснет ×0.6/тик (к приземлению ~0.0004), после приземления растёт за ~5 тиков.
- Опция «Покачивание» (`bobView`), по умолчанию вкл.

[расчёт] Ходьба: `Δфазы = 0.12952`/тик → «шаг» (полупериод вертикали) 7.72 тика = **0.386 с**, полный цикл вбок
15.44 тика = 0.772 с. Бег: 0.16837/тик → шаг 5.94 тика = **0.297 с**. Размах: вбок ±0.05 блока, вниз до 0.1, крен ±0.3°,
кивок до 0.5°. Звук шага (`distanceTraveled`, тот же прирост ×0.6, порог +1) совпадает с крайней точкой
`|cos(gπ)| = 1` (ASP-13).

## 2.7 Высота глаз и её сглаживание (`Camera.updateEyeHeight`, `PlayerEntity.POSE_DIMENSIONS`) [src]

- Глаза: стоя **1.62**, присед **1.27**, плавание/полёт на элитрах **0.4**, смерть 1.62 (коробка 0.2×0.2).
- Каждый тик (в `GameRenderer.tick`, **до** тика игрока): `cameraY += (eyeHeight − cameraY)·0.5`; рисуется
  `lerp(tickDelta, lastCameraY, cameraY)`.
- Поза меняется в **конце** тика игрока (`PlayerEntity.updatePose`), камера начнёт движение в следующем тике.
- Луч прицела и всё «от глаз» берут **несглаженную** высоту (`getStandingEyeHeight`): при приседе луч опускается
  сразу, камера — за ~4 тика. Для ASP-04: несколько кадров рамка может «не совпадать» с центром на 0.35 блока по высоте.

Последовательность при Shift [расчёт]: 1.6200 → 1.4450 → 1.3575 → 1.3138 → 1.2919 → 1.2809 → 1.2755 → 1.2727. 90 %
перехода — 3.3 тика (~0.17 с), плюс 1 тик задержки. Вставание — зеркально.

## 2.8 Клавиши: `isPressed`, `wasPressed`, повтор, переключение [src]

- `KeyBinding` хранит `pressed` (удержание) и `timesPressed` (счётчик нажатий). Событие «нажато» и **автоповтор ОС**
  (`action != 0` в `Keyboard.onKey`) увеличивают счётчик; «отпущено» снимает `pressed`.
- `isPressed()` — удержание в момент опроса. Движение (`KeyboardInput.tick`) опрашивает раз в тик: нажатие
  и отпускание между двумя тиками (< 50 мс) **не увидит**.
- `wasPressed()` съедает одно нажатие. `handleInputEvents` берёт `while (wasPressed)` для F5, инвентаря, Q, F, чата,
  ЛКМ/ПКМ/СКМ — несколько кликов внутри одного тика дают несколько действий в этом тике; горячие клавиши 1–9 — `if`:
  одно нажатие за тик, остальные ждут. Зажатая Q из-за автоповтора выбрасывает предметы с частотой повтора ОС.
- Порядок `handleInputEvents`: F5 → плавная камера → 1–9 → P → E → L → F → Q → T, `/` → (если используется предмет:
  отпускание ПКМ, клики съедаются впустую) иначе ЛКМ (`doAttack`), ПКМ (`doItemUse`), СКМ → удержание ПКМ раз в 4 тика →
  `handleBlockBreaking(экрана нет && не было атаки && ЛКМ зажата && курсор захвачен)`.
- Одна клавиша — одно действие (`KEY_TO_BINDINGS` — отображение клавиша → привязка).
- `StickyKeyBinding` (Shift и Ctrl): в режиме «переключение» каждое нажатие инвертирует `pressed`, отпускание
  игнорируется. Опции `sneakToggled`, `sprintToggled` — по умолчанию **удержание**. `unpressAll()` переключённое
  состояние не сбрасывает (вызов «отпустить» игнорируется); сбрасывает `untoggleStickyKeys()` при возрождении.

Раскладка по умолчанию [src `GameOptions`]: W/A/S/D, Space прыжок, **LShift** присед, **LCtrl** бег, E инвентарь, Q выброс,
F вторая рука, 1–9 слоты, ЛКМ атака, ПКМ использование, СКМ выбор блока, T чат, `/` команда, Tab список, L достижения,
P соцвзаимодействия, F1 скрыть HUD, F2 снимок, F3 отладка, F5 вид, F11 полный экран, Esc меню. Клавиши — по

## 2.9 Бег: ввод (двойное W и Ctrl) [src `ClientPlayerEntity.tickMovement`]

Обозначения: `walking(т)` = вперёд ≥ 0.8 после множителей приседа/предмета; `prev*` — значения прошлого тика.

1. Счётчик окна `dtap` уменьшается в начале тика.
2. Если в прошлом тике был Shift — `dtap = 0`.
3. `canStart = !бег && walking(сейчас) && canSprint && !используется_предмет && !слепота && !элитры`.
   `canSprint` = еда > 6 **или** разрешён полёт; у нас голода нет → всегда истина.
4. **Двойное W:** если (`onGround` или под водой) и `!prevShift` и `!prevWalking` (фронт нажатия) и `canStart`:
   если `dtap ≤ 0` и Ctrl не зажат → открыть окно `dtap = 7`; иначе → бег.
5. **Ctrl:** если (не в воде или под водой) и `canStart` и Ctrl `isPressed` → бег. **Земля не нужна**: Ctrl включает бег
   и в воздухе.
6. **Срыв** (только эти условия, проверяются до движения, по столкновению прошлого тика): вперёд ≤ 1e-5, или
   `!canSprint`, или `horizontalCollision && !collidedSoftly`, или касание воды не под водой. Отпускание Ctrl бег
   **не** снимает.

Окно [расчёт]: первое нажатие замечено на тике 0 → `dtap = 7`; на тике k счётчик `7 − k`; бег, если `7 − k > 0` →
второе нажатие должно попасть в тик **k ≤ 6** (между замеченными нажатиями ≤ 300 мс, отпускание должно продержаться
хотя бы один опрос тика). Оба нажатия — на земле.

## 3.3 `LivingEntity.travel`: суша и воздух [src]

Все «на земле» здесь — `onGround` **прошлого** `move`.

1. Гравитация `g = 0.08` (атрибут `generic.gravity`).
2. Скользкость `p` блока в `getVelocityAffectingPos()` (§3.10), по умолчанию 0.6.
3. Трение `k = onGround ? p·0.91F : 0.91F` (float; для 0.6 → 0.546) — **посчитано до `move`**.
4. Ускорение: `onGround ? speed·(0.21600002F / p³) : (бег ? 0.025999999F : 0.02F)`; `speed` — атрибут скорости
   (0.1, бег 0.13 — `+0.3` ADD_MULTIPLIED_TOTAL). Для p = 0.6 множитель ровно 1.0.
5. `updateVelocity`: вектор ввода `(вбок, 0, вперёд)`; если длина² < 1e-7 → ничего; если > 1 → нормализовать; ×ускорение;
   поворот по yaw: `x = s·cos − f·sin`, `z = f·cos + s·sin` (sin/cos — таблица `MathHelper`, 65536 значений).
   Нормализуется **только** длина > 1: после ×0.98 прямо = 0.98, по диагонали = 1.386 → 1.0. Присед по диагонали
   (0.294, 0.294) длиной 0.416 не нормализуется.
6. `move(SELF, velocity)` (§3.4).
7. `vy = vy_после_move − g` (если кусок под ногами не загружен: −0.1, у дна мира 0).
8. `velocity = (vx·k, vy·0.98F, vz·k)`.

Следствия [src]: тик отрыва (прыжок) — ещё наземное ускорение и трение; тик приземления — воздушные. Стоя на земле
`vy = −0.0784` каждый тик (пол срезает её, `onEntityLand` обнуляет, гравитация возвращает) — **это и даёт `onGround`
каждый тик** [cubi].

## 3.4 `Entity.move` по шагам [src]

1. (Паутина/ягоды: `movementMultiplier` — не нужно.)
2. `m = adjustMovementForSneaking(m)` (§3.9).
3. `v = adjustMovementForCollisions(m)` (§3.5–3.6).
4. Если `|v|² > 1e-7`: (если `fallDistance ≠ 0` и `|v|² ≥ 1` — луч `FALLDAMAGE_RESETTING` + вода от старой позиции к новой;
   попал → `fallDistance = 0`); `pos += v`. Иначе позиция не меняется вовсе.
5. Флаги: `horizontalCollision = |m.x − v.x| ≥ 1e-5 || |m.z − v.z| ≥ 1e-5`; `verticalCollision = m.y ≠ v.y` (точно);
   `groundCollision = verticalCollision && m.y < 0`; `collidedSoftly = horizontalCollision && hasCollidedSoftly(v)`.
6. `onGround = groundCollision`; обновить опорный блок (§3.10).
7. `fall(v.y, onGround, блок под 0.2, …)` (§3.11).
8. По заблокированной горизонтальной оси (по тому же допуску 1e-5) — эта компонента **скорости** = 0.
9. Если `m.y ≠ v.y` (пол **или потолок**): `block.onEntityLand` → `vy = 0` (слизь и кровать — иначе).
10. На земле — `onSteppedOn` (магма и т. п., не нужно).
11. Если `getMoveEffect() ≠ NONE` (не полёт и не «на земле с Shift»): `horizontalSpeed += |v_гор|·0.6`,
    `distanceTraveled += |v|·0.6` (Y — только на лестнице) → звук шага при пересечении целого (ASP-13).
12. `checkBlockCollision` (касание кактуса, огня — ASP-12), множитель скорости блока (песок душ/мёд 0.4 — не нужно).

## 3.5 Коллизия AABB [src `Entity.adjustMovementForCollisions`, `VoxelShape.calculateMaxDistance`]

**Какие формы берутся:** все блоки, чья форма коллизии пересекает (строго, с ненулевым объёмом) коробку, растянутую на
перемещение (`box.stretch(m)`); плюс сущности с коллизией (лодки — не нужно) и граница мира. Перебор клеток —
`floor(min − 1e-7) − 1 … floor(max + 1e-7) + 1`; клетки на внешней рамке берутся, только если форма выше куба (забор 1.5).
Незагруженный кусок — форм нет.

**Порядок осей:** сначала Y; затем бо́льшая по модулю из X/Z; затем другая (при равенстве — сначала X). После каждой оси
коробка сдвигается на найденное расстояние, следующая ось проверяется уже из нового положения.

**Одна ось против одной формы:**
- Форма учитывается, если перекрывает коробку по двум другим осям с допуском: `box.max − 1e-7 ≥ shape.min` и
  `box.min + 1e-7 < shape.max`.
- Движение +: если `box.max − 1e-7 < shape.min`, ход ограничивается `shape.min − box.max` (может быть слегка
  отрицательным, до −1e-7). Если коробка **уже вошла** в форму глубже 1e-7 — форма игнорируется (можно выйти).
- Движение −: зеркально.
- Перед каждой формой: `|d| < 1e-7` → 0.

Следствия, которые чувствует игрок:
- Скольжение вдоль стены — само собой (заблокированная ось обнуляется, другая работает).
- Шов между блоками пола не даёт «ложной стены»: Y решён первым, коробка уже над полом, боковые грани соседей не
  перекрывают её по Y (верх пола = низ коробки, `box.min + 1e-7 < shape.max` ложно). Урок FEEL-017 cubi-core. [cubi]
- «Лишний тик опоры»: в тике, где игрок сходит с края, Y проверяется **на старом** месте → `onGround` истинно, а XZ
  уже унесли коробку за край. В следующем тике ещё можно прыгнуть, уже сойдя с края на 0.2–0.28 блока [расчёт].
- Внутри блока (поставили на голову, песок упал) коллизия не держит: выход в любую сторону свободен, пока не вылез
  (плюс выталкивание §3.12).

## 3.6 Ступенька 0.6 (алгоритм 1.21.1) [src `adjustMovementForCollisions`, `collectStepHeights`]

Условия: `stepHeight (0.6) > 0` и (приземляется в этом тике — упор снизу при движении вниз — **или** `onGround`) и
заблокирована X или Z.

1. `box2` = коробка, опущенная на найденный Y, если приземляемся; иначе исходная.
2. Область поиска: `box2`, растянутая на `(m.x, 0.6, m.z)`; если не приземляемся — ещё на 1e-5 вниз. Формы в ней.
3. Кандидаты высоты: все границы форм по Y (`getPointPositions`), отсчитанные от низа `box2`, в [0, 0.6], кроме
   значения, равного найденному Y (float-сравнение); по возрастанию.
4. Для каждого кандидата `h`: коллизия с перемещением `(m.x, h, m.z)` от `box2`. **Первый** кандидат, у которого
   горизонтальный путь длиннее исходного, — ответ (плюс сдвиг приземления).

Итог: подъём ровно на верх препятствия за один тик (плита 0.5 → ровно 0.5), без «подъёма на 0.6 и опускания», как
в старых версиях [не проверено, с какой версии]. Полный блок (1.0) и забор (1.5) — стена. В нашем мире пока только кубы → подъём не проявляется (кандидаты 0 и 1.0);
код нужен сразу для будущих плит, слоёв снега (коллизия на слой ниже вида: 1 слой — без коллизии), грядок (15/16),
кровати и т. п. Плавность подъёма — интерполяцией позиции между тиками, без трюков камеры [cubi].

## 3.7 onGround, упор в стену, срыв бега [src]

- `onGround` — только результат последнего `move`: был ли срез Y при движении вниз. Никаких лучей «есть ли пол».
- `horizontalCollision` — с допуском 1e-5 (микросрезы не считаются).
- «Мягкое» касание (`ClientPlayerEntity.hasCollidedSoftly`): угол между направлением ввода (по yaw) и фактическим
  горизонтальным смещением < **0.13962634 рад = 8°**. Если ввод или смещение почти нулевые (< 1e-5) — касание жёсткое.
- Бег срывается в **следующем** тике после жёсткого касания. [расчёт]: вдоль стены под углом ≤ 7.5° — бег держится,
  ≥ 8.5° — срывается; в лоб: тик касания (дотянулся до стены) считается мягким, срыв тиком позже.

## 3.8 Прыжок [src `LivingEntity.jump`, `tickMovement`]

- `vy = 0.42F` (атрибут `jump_strength`) × множитель блока (мёд 0.5) + эффект прыгучести (не нужно); если ≤ 1e-5 — нет прыжка.
- При беге: `+0.2` по горизонтали **по направлению взгляда (yaw)**, не по направлению движения.
- Прыжок — в тике, где Space зажат, `onGround` (прошлого `move`) и `cooldown == 0`; потом `cooldown = 10`; отпускание
  Space обнуляет `cooldown`. На ровном полёт длится 12 тиков > 10, поэтому cooldown ощутим только под низким потолком.
- Тик прыжка двигается на `vy = 0.42` сразу; приземление обнуляет `vy`; при зажатом Space следующий прыжок — в первом
  же тике после приземления (без паузы на земле).

## 3.9 Присед: скорость и защита края [src]

- Скорость: ввод ×0.3 (атрибут `player.sneaking_speed`) — с задержкой в 1 тик от нажатия Shift (§3.2 шаг 3).
- **Защита края** (`PlayerEntity.adjustMovementForSneaking`) работает, если: не полёт; `m.y ≤ 0` (не на взлёте прыжка);
  движение своё (SELF/PLAYER); Shift зажат **в этом** тике; и (`onGround` или `fallDistance < 0.6` и в пределах
  `0.6 − fallDistance` под коробкой есть опора).
- «Пусто под коробкой со сдвигом (dx, dz)» = коробка `[min.x+dx, min.y − 0.6 − 1e-5, min.z+dz] … [max.x+dx, min.y, max.z+dz]`
  не пересекает ни одной формы. Ищется глубина 0.6, поэтому можно сойти на плиту/ступень, но не с полного блока.
- Поиск: X урезается шагами 0.05 к нулю, пока под сдвигом пусто (≤ 0.05 → 0); затем Z так же; затем, если оба ненулевые
  и по диагонали пусто, — оба вместе (внешний угол). Тот же след коробки, что у коллизии (урок FEEL-016). [cubi]

  обеим осям; вдоль края до угла и за угол не падает.
- Бег присед **не срывает** (§2.9): с флагом бега на корточках 1.68 б/с вместо 1.30. Частицы бега на корточках нет.

## 3.10 Скользкость и опорный блок [src `Entity.updateSupportingBlockPos`, `getPosWithYOffset`, `Blocks`]

- Опорный блок (`supportingBlockPos`): на земле — из блоков, пересекающих тонкий слой 1e-6 под коробкой, тот, чей
  **центр ближе** к позиции ступней (при равенстве — по порядку BlockPos). Если не нашёлся — поиск со следом,
  сдвинутым назад на горизонтальное перемещение.
- Блок «влияющий на скорость» = (X, Z опорного блока, `floor(y − 0.500001)`); без опоры — `floor` позиции. Значит, у края
  льда, где под центром воздух, игрок всё равно скользит; на плите учитывается блок **под** плитой.
- `slipperiness`: по умолчанию 0.6; лёд, плотный лёд, тающий лёд 0.98; синий лёд 0.989; слизь 0.8. У нас этих блоков
  нет (P2), но формула трения — сразу общая.

## 3.11 Падение и fallDistance — только учёт (урон — ASP-12) [src]

- `Entity.fall` в каждом `move`: если `onGround` → если `fallDistance > 0`, `onLandedUpon` → `handleFallDamage(fallDistance)`;
  затем `fallDistance = 0`. Иначе, если смещение Y < 0 → `fallDistance −= Δy` (float, фактическое Δy после коллизии).
- **Спуск тика приземления в fallDistance не входит** (сначала проверка `onGround`, прибавления нет).
- Подъём на клиенте fallDistance не уменьшает; **сервер** (`ServerPlayNetworkHandler.onPlayerMove`) обнуляет его при
  любом движении вверх за пакет (= тик). У нас один авторитет — берём правило сервера: `Δy > 0 → fallDistance = 0`.
- Обнуляют также: касание воды (`checkWaterState`), лестница/лианы (`applyClimbingSpeed`), луч `FALLDAMAGE_RESETTING`
  при смещении ≥ 1 блока за тик, медленное падение.
- Урон (для ASP-12): `ceil((fallDistance − safe_fall_distance 3.0) · множитель)`; частицы и звук — там же.

## 3.12 Выталкивание из блоков (`ClientPlayerEntity.pushOutOfBlocks`) [src]

- В начале каждого тика (до бега и физики), если не noclip, — 4 точки: `x ± 0.35·ширины`, `z ± 0.35·ширины` (±0.21).
- Для точки: клетка `(floor x, floor y_ступней, floor z)`; «занята», если коробка столбца
  `[клетка.x, box.minY, клетка.z] … [+1, box.maxY, +1]`, сжатая на 1e-7, пересекает форму **удушающего** блока
  (полный непрозрачный: камень, земля; не стекло, не листва).
- Если занята: из соседей W/E/N/S, которые не заняты, выбрать ближайший к точке край клетки → скорость по этой оси = ±0.1.
- Это мягкий толчок, не телепорт; работает вместе с правилом «внутри формы коллизия не держит» (§3.5).

## 3.13 Автопрыжок (MOV-16) [src `ClientPlayerEntity.autoJump`]

По умолчанию **выключен**. Срабатывает после `move` на земле с вводом, без Shift: смотрит на ~`max(7·speed, длина
перемещения)` вперёд в полосе ширины коробки; если препятствие выше 0.5 и не выше 1.2, а над ним 2 свободных клетки —
`ticksToNextAutojump = 1` (прыжок в следующем тике). Взгляд должен быть не против движения (cos > −0.15). Для телефона, P2.

## 3.14 Край мира и незагруженные куски [src]

- Тик игрока не идёт, если его кусок не загружен; в незагруженном куске нет форм; если не загружен блок под ногами,
  вертикальная скорость после тика ставится −0.1 (медленное равномерное падение), у дна мира — 0.
- Нам это не нужно: генератор детерминирован, `World::get_block` догенерирует кусок на промахе (~0.3 мс) — коллизия
  есть всегда. Предложение: Y < 0 — твёрдо (как «под бедроком» в cubi-core), Y ≥ 128 — воздух.

## 3.15 Точность [src][cubi]

- Позиции и скорости — double; ввод, ускорения, трение, fallDistance, horizontalSpeed, stride, FOV, высота камеры — float.
- В Rust — `f64` для позиции/скорости (допуск 1e-7 требует double: в cubi-core float32 на x ≈ 766 давал 6e-5). Для
  точной сверки с эталонами — `f32` в тех же местах, что Java.
- Yaw в Java не заворачивается; у нас — заворачивать в [0, 360) или хранить `f64` (поведение то же, без потери точности).

## 6. Граничные случаи и мелочи, которые чувствует игрок

1. Мышь поворачивает сразу каждый кадр; движение берёт yaw на начало тика → при резком повороте траектория меняется
   с задержкой до 50 мс (как в Minecraft, не «исправлять»).
2. Короткое нажатие клавиши движения/прыжка (< 50 мс между опросами) может пропасть — так и в Java.
3. «Лишний тик опоры» у края: прыжок прощает опоздание на один тик (§3.5).
4. Прыжок с бега даёт рывок по взгляду, даже если бежишь по диагонали W+A.
5. В прыжке покачивание гаснет, после приземления возвращается за ~0.25 с; на корточках — замирает.
6. Присед начинает замедлять тиком позже, чем включается защита края — у края безопасно сразу.
7. Под низким потолком (1.5…1.8) встать нельзя — игрок медленный без Shift, камера низко.
8. Бег включённый Ctrl в воздухе — работает; двойное W в воздухе — нет.
9. Бег на корточках сохраняется (1.21.1); FOV остаётся широким.
10. Упор в стену в лоб: бег срывается тиком позже касания; FOV сужается за ~4 тика.
11. Пол из отдельных блоков, шов, край, угол — без дрожи и остановок (1e-7, Y первым). Стоя на месте — `onGround` каждый тик,
    без дрожи камеры. [cubi]
12. Клик, вернувший мышь в игру, не ломает блок.
13. Esc/потеря фокуса — персонаж сразу останавливается, очередь кликов сброшена.
14. Тик пропущен (вкладка в фоне) — по возвращении не больше 10 тиков догонки, остальное время теряется; у нас лучше
    пауза (§9).
15. Луч прицела при приседе опускается раньше камеры (§2.7).

## 8. Чего нет в исходнике / не ясно

1. Как браузер отдаёт `movementX`: масштаб `devicePixelRatio`, ускорение ОС без `unadjustedMovement` [браузер, не проверено] —
   нужен замер (тест «2400 отсчётов = 360°» по сырому счёту мыши недоступен в браузере напрямую).
2. Бег-прыжки: расхождение 7.10 (модель) и 7.00–7.02 (стенд cubi-core) не разобрано; вики — по памяти.
3. Таблица синусов Java (65536 значений) против точного `sin`: на эталонах при yaw = 0 разницы нет; при других yaw —
   ≤ 1e-4 рад. Решить: брать таблицу (256 КБ, бит-в-бит) или точный `sin` (рекомендация — точный, эталоны при yaw 0/90).
4. Первые тики после появления в мире (спуск на землю при входе, `ClientPlayerEntity.init` ищет свободное место вверх) —
   за пределами аспекта; правило появления — в срезе 1 (cubi FEEL-005: проверять всё тело, не центр).
5. Взаимодействие с водой (касание сбрасывает бег, fallDistance) — ASP-03.
6. Как выглядит переход позы в третьем лице, анимация ног (`LimbAnimator`) — не нужно для первого лица.
7. `Block.onEntityLand` у слизи/кровати (отскок) — P2, не читалось подробно.

## 9. Браузер: Pointer Lock, клавиши, раскладка бега

Поведение браузеров — [браузер, не проверено в нашем коде]; проверить на Chrome, Edge, Firefox.

**Pointer Lock** — аналог `lockCursor`:
- Захват только по жесту пользователя (клик). `canvas.requestPointerLock({ unadjustedMovement: true })` — сырые отсчёты
  без ускорения ОС (Chromium); если отклонено (Firefox) — обычный `requestPointerLock()`.
- Клик, вызвавший захват, — как `attackCooldown = 10000`: не атакует, ЛКМ «не нажата» до отпускания.
- Esc в захвате браузер забирает себе: страница получает `pointerlockchange`, а не `keydown Escape`. Значит, потеря захвата
  в игре = Esc = открыть меню паузы + `unpressAll`.
- Повторный захват — только по новому клику; Chrome после выхода по Esc может отказывать ~1 с.
- Закрыть инвентарь клавишей E и сразу захватить мышь можно (keydown E — жест); по Esc — нельзя (Esc не считается
  жестом) → после Esc в инвентаре нужен клик «вернуться в игру».
- Отпускания клавиш при потере фокуса браузер может не прислать → на `blur` и `visibilitychange` самим вызвать
  `unpressAll` и открыть паузу (у Minecraft — 500 мс; у нас сразу, т. к. захват мыши всё равно потерян).
- Фоновая вкладка: `requestAnimationFrame` стоит, по возвращении большой dt → не больше 10 тиков (как Java), а лучше
  пауза уже открыта.
- Физически зажатые клавиши браузер перечитать не умеет (в Java `updatePressedStates`) — после паузы движение начнётся
  со следующего нажатия.

**Клавиши:** `KeyboardEvent.code` (физическая клавиша, «KeyW» и на русской раскладке) — как GLFW. Автоповтор `e.repeat`
считать нажатием для очередей (Q, 1–9), для удержаний не важен. В игре — `preventDefault` на всех `keydown` (Space,
Tab, F1, F3, F5, Ctrl+S/D/F/E/…, Alt), `contextmenu` отключить.

**Что браузер не отдаёт:** Ctrl+W (закрыть вкладку), Ctrl+T, Ctrl+N, Ctrl+Tab, Ctrl+Shift+W, F11/F12 у части браузеров;
Ctrl+1…9 (переключение вкладок) — проверить. На Linux Ctrl+Q закрывает браузер (у нас Ctrl+Q — «выбросить стопку», ASP-07).
При зажатом Ctrl **повторное нажатие W закрывает вкладку** — типичное действие бегущего игрока (отпустил и снова нажал W).

**Предложение раскладки бега:**
1. **Двойное W** — основной способ, точно по Java (§2.9), без модификаторов.
2. **Ctrl (удержание)** — как в Java, но с защитой:
   - `beforeunload` с `preventDefault`, пока идёт игра: Ctrl+W покажет «Покинуть сайт?» вместо молчаливого закрытия
     (захват мыши и игра встанут на паузу — терпимо);
   - кнопка «Полный экран» → `requestFullscreen` + `navigator.keyboard.lock()` (Chromium): тогда Ctrl+W, Esc и прочие
     уходят игре (Esc в Keyboard Lock надо держать для выхода);
   - подсказка при первом входе: «Ctrl+W в браузере закрывает вкладку — бегите двойным W или в полном экране».
3. **Настройка:** клавиша бега (Ctrl / R / другая — R в Java свободна) и режим «удержание / переключение» (`sprintToggled`).
   В режиме «переключение» Ctrl нажимается и отпускается — опасных сочетаний почти нет.

Решение пользователя: оставить Ctrl по умолчанию (с защитой) или по умолчанию R / переключение (§14).

**Камера в нашем рендере:** FOV вертикальный; `near = 0.05`, как в Minecraft. От глаз до потолка 0.18 блока (1.8 − 1.62),
до стены 0.3, покачивание сдвигает камеру ещё до 0.1 вверх и 0.05 вбок. Угол ближней плоскости отстоит от глаза на
`near·√(1 + t² + (t·aspect)²)`, `t = tan(FOV/2)`: при 16:9 это ≈ 1.74·near при FOV 70 и ≈ 2.0·near при беге (80.5°).
Сейчас в `web/main.js` `near = 0.25` → у стены и под потолком будет видно сквозь блоки. Цена — точность глубины на
дальних LOD; решать в рендере (reversed-Z с float-глубиной, раздельные проходы ближнего/дальнего).

## 10. Сценарии проверки человеком

Перед проверкой: ровная трава, день, FOV 70, чувствительность 100 %, ограничитель кадров 60 и 144 (или 30) — сравнить.
Можно включить отладочный HUD со скоростью, `onGround`, fallDistance, тиками.

**ASP-01**
1. *Мышь.* Медленно и быстро веду мышь на одно и то же расстояние по коврику. Ожидаю: поворот одинаковый (нет ускорения),
   без запаздывания и сглаживания; вверх-вниз упирается в вертикаль.
2. *Частота кадров.* Иду по прямой 10 блоков при 60 и при 144 Гц (или 30). Ожидаю: время одинаковое (~2.4 с с места),
   камера плавная, без рывков 20 Гц; прыжок одинаковой высоты.
3. *FOV бега.* Двойное W. Ожидаю: картинка плавно расширяется за ~0.2 с (+15 %). Отпускаю W — сужается так же.
   Бегу в стену в лоб — бег срывается, FOV сужается.
4. *Покачивание.* Иду 3 с. Ожидаю: подъём-опускание на каждый шаг (~0.4 с), лёгкий крен в стороны (цикл ~0.8 с).
   Бегу — шаги чаще (~0.3 с), размах тот же. Прыгаю — покачивание гаснет в воздухе, после приземления возвращается
   за ~0.25 с. Иду с Shift — не качается.
5. *Присед.* Нажимаю Shift. Ожидаю: взгляд опускается на ~1/3 блока плавно за ~0.2 с, отпускаю — поднимается.
6. *Esc.* Иду с W, жму Esc. Ожидаю: меню, персонаж стоит. Кликаю «Вернуться» — мышь захвачена, этот клик не ломает блок.
7. *Потеря фокуса.* Иду с W и переключаюсь на другое окно, возвращаюсь. Ожидаю: персонаж не идёт сам, игра на паузе.
8. *Окно двойного W.* Быстро дважды W (< 0.3 с) — бег; медленно (> 0.35 с) — шаг.
9. *Ctrl.* Держу W, нажимаю и отпускаю Ctrl. Ожидаю: бег продолжается, пока держу W (не нужно держать Ctrl).
10. *Прицел.* Крестик в центре, инвертирует цвет фона (на небе тёмный, на тёмном камне светлый); F1 — пропал.

**ASP-02**
1. *Скорости.* С места 10 блоков: шагом ~2.4 с, бегом ~1.85 с. Разгон короткий (~0.2 с), торможение — проезжаю ~¼ блока.
2. *Прыжок.* С места запрыгиваю на блок вплотную — получается; на два блока и на забор/1.5 — нет. Держу Space на ровном —
   прыжки ровно каждые ~0.6 с, без «залипания» после приземления.
3. *Бег-прыжки.* Space+бег — заметно быстрее бега (~7.1 против 5.6 б/с).
4. *Яма.* Шагом перепрыгиваю яму в 2 блока, в 3 — нет; бегом — 3 всегда, 4 — только прыгнув с самого края.
5. *Край с Shift.* Иду к обрыву с Shift — не падаю, нависаю почти на пол-тела; иду вдоль края до угла и вокруг угла —
   не падаю. Со ступеньки в 1 блок с Shift не сойти. Отпускаю Shift — схожу.
6. *Прощение края.* Бегу к обрыву и жму Space чуть поздно — прыжок всё равно происходит.
7. *Стена.* Иду по диагонали в стену — скольжу вдоль без остановок. Бегу почти параллельно стене, задевая её, — бег
   держится; под заметным углом — срывается.
8. *Низкий проход.* В тоннеле высотой 2 прыгаю — стукаюсь головой, прыжки чаще (~0.5 с). В проём высотой 1.5 прохожу
   только присев; внутри, отпустив Shift, остаюсь присевшим.
9. *Пол из блоков.* Стою на месте 10 с — никакой дрожи. Хожу по полу из разных блоков, по швам и углам — без подёргиваний.
10. *Падение (учёт).* Схожу с уступа 3 блока — fallDistance у земли ~2.7 (урона нет, когда появится ASP-12); с 4 — ~3.35.
11. *Внутри блока.* Ставлю (отладкой) блок в клетку ног — меня мягко выталкивает в ближайшую свободную сторону.

## 11. Что нужно от движка

- **E2 (главное для ASP-02).** Физика игрока целиком в Rust (`Game` уже владеет `World`): запрос «кубоиды коллизии в
  области AABB» без перехода JS↔WASM. Нужна таблица форм по ID блока: пусто (воздух, вода, растения), куб, особые
  (кактус; будущие плиты, снег, грядка). Плюс `slipperiness(id)` и `suffocates(id)`. Объём: ~60 клеток на `move`
  плюс ~10 малых проверок (край, поза, выталкивание) — ~200 `get_block` за тик; при микросекундах — пренебрежимо.
  Промах кэша (~0.3 мс) у границы куска — допустимо. Y < 0 — твёрдо, Y ≥ 128 — воздух.
- **E3 (главное для ASP-01).** Цикл в JS по образцу `MinecraftClient.render`: `acc += dt/50`; `n = floor(acc)`;
  `acc −= n`; выполнить `min(n, 10)` раз `game.tick(input)`; затем `game.turn(dx, dy)` (накопленная мышь); затем
  `game.view(acc)` → позиция камеры, yaw/pitch, FOV, покачивание → отрисовка. На паузе тики не идут, `acc` заморожен.
- **Ввод в тик:** снимок удержаний (W, A, S, D, Space, Shift, клавиша бега) на момент тика + счётчики нажатий с прошлого
  тика (ЛКМ, ПКМ, СКМ, Q, E, 1–9, F5) — первый тик кадра съедает очереди (`while`), 1–9 — по одному.
- **E4.** Игрок — первая сущность: prev/cur позиции, флаги, поза; интерполяция в `view(alpha)`.
- **E7.** Прицел (инверсное смешивание), меню паузы (Esc / потеря захвата), подсказка про Ctrl+W.
- **E1.** Правка блока в клетке тела → выталкивание работает само (§3.12); луч и коллизия видят правку сразу.
- **Рендер.** `near = 0.05` (§9); координаты камеры — f64 в JS, в шейдер — относительно камеры (f32 на дальних координатах).
  Матрица покачивания — между проекцией и видом. Рука — отдельная проекция с FOV 70 (ASP-11).
- Режим полёта оставить отладочной клавишей (без физики Java).

## 12. Rust-набросок модуля физики игрока (своими словами)

// player.rs — физика игрока по Java 1.21.1. Блоки, тики; f64 — позиция/скорость, f32 — где Java во float.

#[derive(Clone, Copy)]
pub struct Aabb { pub lo: [f64; 3], pub hi: [f64; 3] }
impl Aabb {
    fn moved(&self, d: [f64; 3]) -> Aabb { /* lo+d, hi+d */ }
    fn swept(&self, d: [f64; 3]) -> Aabb { /* растянуть в сторону знака каждой компоненты */ }
    fn overlaps(&self, o: &Aabb) -> bool { /* строго: lo < o.hi && hi > o.lo по трём осям */ }
}

/// То, что физике нужно от мира (E2). Реализует World из world.rs.
pub trait Solids {
    fn shapes_in(&self, area: &Aabb, out: &mut Vec<Aabb>); // кубоиды коллизии, пересекающие area
    fn slip(&self, x: i32, y: i32, z: i32) -> f32;         // 0.6 по умолчанию
    fn chokes(&self, x: i32, y: i32, z: i32) -> bool;      // удушающий блок (выталкивание)
}

const EPS: f64 = 1e-7;

/// Сколько можно пройти по оси a, не входя в формы (VoxelShapes.calculateMaxOffset).
fn clip(a: usize, b: &Aabb, shapes: &[Aabb], mut d: f64) -> f64 {
    for s in shapes {
        if d.abs() < EPS { return 0.0; }
        let others_overlap = (0..3).filter(|&o| o != a)
            .all(|o| b.hi[o] - EPS >= s.lo[o] && b.lo[o] + EPS < s.hi[o]);
        if !others_overlap { continue; }
        if d > 0.0 && b.hi[a] - EPS < s.lo[a] { d = d.min(s.lo[a] - b.hi[a]); }
        if d < 0.0 && b.lo[a] + EPS >= s.hi[a] { d = d.max(s.hi[a] - b.lo[a]); }
    }
    d
}

/// Y, потом бо́льшая из X/Z, потом другая.
fn sweep(m: [f64; 3], mut b: Aabb, shapes: &[Aabb]) -> [f64; 3] { /* §3.5 */ }

pub struct Keys { pub fwd: bool, pub back: bool, pub left: bool, pub right: bool,
                  pub jump: bool, pub sneak: bool, pub sprint: bool, pub using_item: bool }

pub struct Player {
    pub pos: [f64; 3], pub prev_pos: [f64; 3], pub vel: [f64; 3],
    pub yaw: f32, pub pitch: f32,                 // мышь меняет каждый кадр (turn)
    pub on_ground: bool, h_hit: bool, soft_hit: bool,
    pub fall: f32, pub sprinting: bool, jump_cd: u8, dtap: u8,
    prev_walk: bool, prev_sneak: bool, pub crouched: bool,   // поза (коробка 1.5, глаза 1.27)
    in_side: f32, in_fwd: f32,                    // ввод после ×0.98 — для «мягкого» касания
    pub hspeed: f32, prev_hspeed: f32, pub stride: f32, prev_stride: f32,
    pub cam_y: f32, last_cam_y: f32, pub fov: f32, last_fov: f32,
    support: Option<[i32; 3]>,
}

impl Player {
    pub fn turn(&mut self, dx: f64, dy: f64, sens: f64) {
        let d = sens * 0.6 + 0.2;
        let k = d * d * d * 8.0 * 0.15;
        self.yaw = (self.yaw + (dx * k) as f32).rem_euclid(360.0);
        self.pitch = (self.pitch + (dy * k) as f32).clamp(-90.0, 90.0);
    }

    /// Один тик 20 Гц. Порядок — §2.2 шаг 5 и §3.2.
    pub fn tick(&mut self, w: &impl Solids, k: Keys) {
        // камера по состоянию прошлого тика (GameRenderer.tick)
        self.last_fov = self.fov;
        let target = if self.sprinting { 1.15 } else { 1.0 };
        self.fov = (self.fov + (target - self.fov) * 0.5).clamp(0.1, 1.5);
        self.last_cam_y = self.cam_y;
        let eye = if self.crouched { 1.27 } else { 1.62 };
        self.cam_y += (eye - self.cam_y) * 0.5;

        self.prev_pos = self.pos;
        self.prev_hspeed = self.hspeed;
        self.dtap = self.dtap.saturating_sub(1);

        // ввод; замедление приседа — по Shift прошлого тика
        let slow = self.prev_sneak || !self.fits(w, 1.8);
        let mut f = axis(k.fwd, k.back);
        let mut s = axis(k.left, k.right);
        if slow { f *= 0.3; s *= 0.3; }
        if k.using_item { f *= 0.2; s *= 0.2; self.dtap = 0; }
        self.push_out(w);
        if self.prev_sneak { self.dtap = 0; }

        // бег (§2.9)
        let walking = f >= 0.8;
        let can_start = !self.sprinting && walking && !k.using_item;
        if self.on_ground && !self.prev_sneak && !self.prev_walk && can_start {
            if self.dtap == 0 && !k.sprint { self.dtap = 7 } else { self.sprinting = true }
        }
        if can_start && k.sprint { self.sprinting = true; }
        if self.sprinting && (f <= 1e-5 || (self.h_hit && !self.soft_hit)) { self.sprinting = false; }
        self.prev_walk = walking;
        self.prev_sneak = k.sneak;

        // LivingEntity.tickMovement
        self.prev_stride = self.stride;
        self.jump_cd = self.jump_cd.saturating_sub(1);
        for c in &mut self.vel { if c.abs() < 0.003 { *c = 0.0; } }
        if k.jump {
            if self.on_ground && self.jump_cd == 0 { self.jump(); self.jump_cd = 10; }
        } else { self.jump_cd = 0; }
        self.in_side = s * 0.98;
        self.in_fwd = f * 0.98;
        self.travel(w, k.sneak);

        // покачивание, поза
        let tgt = if self.on_ground { (hlen(self.vel) as f32).min(0.1) } else { 0.0 };
        self.stride += (tgt - self.stride) * 0.4;
        self.crouched = (k.sneak && self.fits(w, 1.5)) || !self.fits(w, 1.8);
    }

    fn travel(&mut self, w: &impl Solids, shift: bool) {
        let p = self.slip_here(w);                       // опорный блок, y − 0.500001
        let fr = if self.on_ground { p * 0.91 } else { 0.91 };
        let speed: f32 = if self.sprinting { 0.13 } else { 0.1 };
        let acc = if self.on_ground { speed * (0.21600002 / (p * p * p)) }
                  else if self.sprinting { 0.026 } else { 0.02 };
        self.accelerate(acc);                             // нормализация только при длине > 1, поворот по yaw
        let m = self.vel;
        self.mv(w, m, shift);
        self.vel[1] = (self.vel[1] - 0.08) * 0.98;
        self.vel[0] *= fr as f64;
        self.vel[2] *= fr as f64;
    }

    fn mv(&mut self, w: &impl Solids, m: [f64; 3], shift: bool) {
        let m = if shift { self.edge_guard(w, m) } else { m };   // §3.9
        let v = self.collide(w, m);                               // §3.5–3.6 со ступенькой
        if v.iter().map(|c| c * c).sum::<f64>() > 1e-7 { for i in 0..3 { self.pos[i] += v[i]; } }
        let bx = (m[0] - v[0]).abs() >= 1e-5;
        let bz = (m[2] - v[2]).abs() >= 1e-5;
        self.h_hit = bx || bz;
        self.soft_hit = self.h_hit && self.softly(v);             // угол < 8°
        let vert = m[1] != v[1];
        self.on_ground = vert && m[1] < 0.0;
        self.update_support(w, v);
        // учёт падения (§3.11): приземление — без Δy этого тика; подъём обнуляет (правило сервера)
        if self.on_ground { /* отдать self.fall в ASP-12 */ self.fall = 0.0; }
        else if v[1] < 0.0 { self.fall -= v[1] as f32; }
        else if v[1] > 0.0 { self.fall = 0.0; }
        if bx { self.vel[0] = 0.0; }
        if bz { self.vel[2] = 0.0; }
        if vert { self.vel[1] = 0.0; }
        if !(self.on_ground && shift) { self.hspeed += (hlen(v) as f32) * 0.6; }
    }

## 13. Уроки cubi-core и как они ложатся сюда [cubi]

| Урок cubi-core | Здесь |
|---|---|
| Два решателя (Humanoid + Java) на одно тело → серия дефектов ступеней | Одна своя коллизия по §3.5–3.6, других контактов нет |
| Дробление тика по кадрам ломало прыжки и коллизии | Только целые тики 20 Гц + интерполяция (§2.1, §11 E3) |
| Ступенька как телепорт | Плавность — интерполяция позиции между тиками, без сглаживания камеры |
| На земле нужна −0.0784, иначе нет `onGround` | §3.3 следствие |
| Тик отрыва — наземное трение | §3.3 |
| Защита края и пол с разными следами → падение на углу (FEEL-016) | Один `getBoundingBox` для всех проверок |
| Ложная стенка на шве пола (FEEL-017) | Y первым + эпсилон 1e-7 (§3.5) |
| float32 на дальних координатах | f64 в Rust и JS, шейдер относительно камеры |
| Урон за всю лестницу при беге вниз | Приземление = `onGround` из `move` каждый тик, fallDistance обнуляется на каждой ступени |
| Не лечить контакт подгонкой Java-констант | Константы §4 не трогать; новый дефект — сначала запись и падающая регрессия |
| Численные тесты не доказывают ощущение | Сценарии §10 — отдельная приёмка человеком |

## 14. Что решить главному агенту или пользователю

1. **Клавиша бега по умолчанию** (§9): Ctrl с защитой (`beforeunload`, полноэкранный Keyboard Lock) или R /
   режим «переключение». Двойное W работает в любом случае. — пользователь.
2. **Бег на корточках** (1.21.1 сохраняет флаг бега при Shift): оставить как в Java или срывать (как в более новых
   версиях [не проверено]). Рекомендация: как в 1.21.1. — пользователь (ощущение).
3. **Пауза при потере фокуса:** сразу (браузер теряет захват мыши) или через 500 мс как в Java. Рекомендация: сразу. — главный агент.
4. **fallDistance:** правило сервера (обнулять при подъёме) — рекомендую; влияет на ASP-12. — главный агент.
5. **Синусы:** таблица Java или точный `sin` (§8 п. 3). Рекомендация: точный. — главный агент.
6. **near-плоскость 0.05** и точность глубины дальних LOD — задача рендера, нужна до среза 1, иначе у стен видно
   сквозь блоки. — главный агент.
7. **Где живёт yaw/pitch:** в Rust (`turn` раз в кадр, один источник для луча и движения) — рекомендую; JS только
   передаёт дельту мыши. — главный агент.
8. Кактус: сейчас полный куб; в Java коллизия 14/16×15/16 и урон при касании — нужно состояние формы (E2/E5) и ASP-12.

Модель для эталонов (независимая, своими словами, не код Mojang) лежит у исследователя во временной папке; при
желании её можно перенести в `tools/` как генератор тестовых векторов.
