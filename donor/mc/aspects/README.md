# Этап 2: разбор исходников по аспектам

Каждый аспект из `../checklist.md` разбирает отдельный агент и пишет один файл `ASP-NN-<имя>.md` в этой папке.
Статусы в `checklist.md` обновляет только главный агент после приёмки.

Требования к файлу аспекта (из `../plan.md`):
1. Порядок операций по шагам (тик за тиком, кадр за кадром), как в исходнике Java 1.21.1.
2. Все числа с источником: [src] класс.метод, [data] путь в данных, [вики], [не проверено].
3. Граничные случаи и мелочи, которые чувствует игрок.
4. «Чего нет в исходнике / не ясно».
5. Сценарий проверки человеком: точные действия и ожидаемые наблюдения.
6. Что нужно от движка (коды E1–E11 из `../checklist.md`) и предложение, как это ляжет в нашу архитектуру.
7. Численные эталоны для тестов (как 4.317 / 5.612 / 1.2522 в cubi-core).
8. Псевдокод или Rust-набросок своими словами — не копия Java.

Архитектура (решение главного агента): игровая логика и мир — в Rust (WASM, f64 там, где важно, `cargo test`);
JS — ввод, рендер, UI. Мир 16×128×16 кусков, уровень моря 48, высота 0–127.
