# ASP-06 Блоки, инструменты и таблицы добычи (данные)

Версия — Java Edition 1.21.1. Механики: BLK-01, BLK-02, BLK-04, BLK-06, TOOL-01, TOOL-02, TOOL-03, TOOL-05 (опц.), BRK-07,
BRK-08; данные для INV-03 (стеки) и INV-11 (броня). Объём расширен по `../decisions.md`: сундук, лестница, ведро,
броня кожаная и железная. Опыт не берём — сферы опыта из руд и печи здесь не описаны.

Пометки:
- **[src]** — зеркало Yarn `Soumeh/1.21.1-Deobfuscated@414d1696`, путь класса от `minecraft/src/net/minecraft/`;
- **[data]** — `misode/mcmeta`, ветка `1.21.1-data`, путь от `data/minecraft/`;
- **[расчёт]** — посчитано мной по формулам [src] с точной арифметикой float32 (скрипт в рабочей папке агента, не в репозитории);
- **[вики]** / **[не проверено]** — как в `../sources.md`.

## 0. Главное коротко

1. **Скорость добычи:** `delta = speed / hardness / (canHarvest ? 30 : 100)` в float32. Прогресс тоже копится во float32.
   Из-за этого многие времена **на 1 тик длиннее**, чем `ceil(1/delta)`: бревно рукой ломается за 61 тик, а не за 60,
   камень рукой — за 151, верстак рукой — за 76 (§3). Если мы хотим совпадать тик в тик, считать нужно в `f32`.
2. **Инструмент 1.21 = компонент `tool` с двумя правилами** (`item/ToolMaterial.createComponent`):
   (1) блоки из тега `incorrect_for_<тир>_tool` — «не дропает», скорость это правило не задаёт;
   (2) блоки из `mineable/<тип>` — скорость тира и «дропает». Поэтому скорость тира работает и на слишком твёрдой руде:
   деревянная кирка бьёт железную руду со скоростью 2.0, но с делителем 100 и без дропа.
3. **Износ** (проверено): кирка, топор, лопата и мотыга теряют 1 прочность за **любой** блок с твёрдостью ≠ 0, даже за
   блок не своего типа, и 2 — за удар по мобу. У меча наоборот: 2 за блок и 1 за удар. Мгновенные блоки (твёрдость 0) прочность
   не тратят.
4. **Дроп решается до износа:** блок, на котором инструмент сломался, всё равно дропается.
5. **Содержимое сундука и печи высыпается всегда**, даже если сам блок ничего не дал (печь рукой).

## 1. Порядок операций

### 1.1 Тик ломания (клиент; полностью — в ASP-04)
`client/network/ClientPlayerInteractionManager` **[src]**:
1. Тик клика: `attackBlock`. Если `delta ≥ 1` — блок ломается сразу. Иначе прогресс = 0.
2. В том же тике и в каждом следующем, пока зажата ЛКМ: `updateBlockBreakingProgress` → `progress += delta` (f32).
   Первая прибавка — уже в тике клика.
3. Стадия трещин — `(int)(progress·10)`. Звук удара — каждый 4-й тик (ASP-13).
4. Когда `progress ≥ 1.0`, блок ломается; затем 5 тиков паузы (`blockBreakingCooldown = 5`).
5. Прогресс сбрасывается, если сменилась цель **или стек в руке** (`isCurrentlyBreaking` сравнивает предмет и все компоненты,
   включая `damage`).

`delta` пересчитывается каждый тик (`calcBlockBreakingDelta`). Поэтому прыжок или погружение посреди ломания меняют скорость
сразу, с текущего тика.

### 1.2 Завершение ломания (`server/network/ServerPlayerInteractionManager.tryBreakBlock`) [src]
1. `item.canMine(...)` — у всех предметов `true`; у меча `false` только в креативе.
2. `block.onBreak` → мировое событие 2001 (частицы и звук разрушения, ASP-13).
3. `world.removeBlock`. Блок с инвентарём (`ChestBlock`, `AbstractFurnaceBlock`) в `onStateReplaced` высыпает содержимое
   (`util/ItemScatterer.spawn`). Это происходит **до** дропа самого блока и **не зависит** от инструмента.
4. `canHarvest = !requiresTool || mainHand.isSuitableFor(state)` (`entity/player/PlayerEntity.canHarvest`). Флаг считается
   **до** износа.
5. `mainHand.postMine` → `item/Item.postMine`: если у предмета есть компонент `tool`, `hardness ≠ 0` и `damagePerBlock > 0`,
   то `stack.damage(damagePerBlock)` (§1.3).
6. Если блок удалён и `canHarvest`, вызывается `block/Block.afterBreak` → `dropStacks(..., tool = копия стека до износа)` →
   таблица добычи → `Block.dropStack`. Каждый стек появляется в центре клетки со смещением ±0.25 по каждой оси (по Y ещё
   −0.125, полвысоты предмета). Физика и задержка подбора — в ASP-07.

### 1.3 Износ и поломка инструмента [src]
- `component/type/ToolComponent.damagePerBlock`: 1 у кирки, топора, лопаты и мотыги (`ToolMaterial.createComponent`),
  2 у меча (`item/SwordItem.createToolComponent`).
- `Item.postMine` тратит прочность только на сервере и только при `hardness ≠ 0`. Подходит ли инструмент к блоку, не важно:
  кирка теряет 1 и на земле, меч — 2 на листве.
- Удар по сущности (`PlayerEntity.attack`): только если урон прошёл (`target.damage` вернул `true`) и `postHit` вернул
  `true`. Тогда `postDamageEntity`: `MiningToolItem` −2, `SwordItem` −1.
- ПКМ-действия: дорожка лопатой, грядка мотыгой, снятие коры топором — по −1 (`ShovelItem`/`HoeItem`/`AxeItem.useOnBlock`;
  P2, TOOL-05).
- `item/ItemStack.damage`: в креативе ничего; иначе `damage += amount` (Unbreaking у нас нет). Если `damage ≥ maxDamage`,
  стек уменьшается на 1 (инструмент исчезает) и вызывается `LivingEntity.sendEquipmentBreakStatus` (статус 47 — главная рука).
- Эффект поломки (`entity/LivingEntity.playEquipmentBreakEffects`): звук `entity.item.break`, громкость 0.8,
  pitch `0.8 + rand·0.4`, и 5 частиц `ITEM` с текстурой сломанного предмета (`spawnItemParticles(stack, 5)`). Частицы
  появляются примерно в 0.6 блока перед глазами и на 0.3–0.9 ниже. Скорость: `((r−0.5)·0.1, 0.1…0.2 + 0.05, 0)`, повёрнута по
  pitch/yaw игрока.
- Полоска прочности (`Item.isItemBarVisible / getItemBarStep / getItemBarColor`). Видна при `damage > 0`.
  Длина `clamp(round(13 − damage·13/max), 0, 13)` пикселей из 13. Цвет — HSV(hue = f/3, s = 1, v = 1), где
  `f = (max − damage)/max`: от зелёного через жёлтый к красному.

### 1.4 Листва: дистанция и опад (`block/LeavesBlock`) [src]
- Состояния: `DISTANCE` 1–7 (по умолчанию 7), `PERSISTENT` (поставленная игроком — `true`), `WATERLOGGED`.
- Сосед изменился → `getStateForNeighborUpdate` планирует тик через **1 тик** → `DISTANCE = min(дистанция соседей + 1)` по
  6 сторонам. У брёвен (тег `#logs`) дистанция 0, у листвы — её `DISTANCE`, у остального — 7. Так волна дистанции
  расходится по кроне 1 блок за тик.
- `DISTANCE == 7 && !PERSISTENT` → у блока включаются случайные тики. На случайном тике он выдаёт дроп (`dropStacks` без
  инструмента, таблица из §2.2) и удаляется.
- Случайные тики: `world/GameRules.RANDOM_TICK_SPEED = 3`. `server/world/ServerWorld.tickChunk` берёт 3 случайные клетки на
  каждую секцию 16³ за тик. Шанс на блок — 3/4096 за тик, в среднем 1365.3 тика (**68.3 с**), медиана ≈ 946 тиков (47 с)
  **[расчёт]**. Так же тикают трава, снежный слой, кактус и саженцы.

### 1.5 Прочие случайные тики блоков пути [src]
- Трава (`block/SpreadableBlock.randomTick`): если сверху непрозрачный для света блок (или полный блок воды), трава
  становится землёй. Слой снега в 1 слой траву не убивает. Если свет над травой ≥ 9 — 4 попытки перекинуть траву на землю
  в кубе 3×5×3 (по Y от −3 до +1).
- Снежный слой (`block/SnowBlock.randomTick`): при блочном свете > 11 тает. Дропа нет: таблице нужен игрок (§2.2).
- Кактус (`block/CactusBlock`): растёт до 3 блоков (возраст 0–15). Если сбоку твёрдый блок или снизу не песок/кактус —
  через 1 тик ломается с дропом. При касании наносит 1 урона (ASP-12).

### 2.5 Типы инструментов: правила, износ, урон, скорость атаки [src `item/Items`, `item/MiningToolItem`, `item/SwordItem`]

Урон = 1 (атрибут игрока `generic.attack_damage`, `PlayerEntity.createPlayerAttributes`) + база типа + бонус материала.
Скорость атаки = 4.0 (`generic.attack_speed`) + модификатор. Перезарядка = 20 / скорость, в тиках.

| Тип | Правила `tool` | Износ: блок / удар | Урон: дер / кам / жел / зол / алм | Скорость атаки: дер / кам / жел / зол / алм |
|---|---|---|---|---|
| Кирка (база 1, −2.8) | incorrect_for_тир; `mineable/pickaxe` → скорость тира | 1 / 2 | 2 / 3 / 4 / 2 / 5 | 1.2 у всех (16.7 т) |
| Топор (база 6/7/6/6/5) | `mineable/axe` | 1 / 2 | 7 / 9 / 9 / 7 / 9 | 0.8 / 0.8 / 0.9 / 1.0 / 1.0 |
| Лопата (база 1.5, −3.0) | `mineable/shovel` | 1 / 2 | 2.5 / 3.5 / 4.5 / 2.5 / 5.5 | 1.0 у всех (20 т) |
| Мотыга (база 0/−1/−2/0/−3) | `mineable/hoe` | 1 / 2 | 1 у всех | 1.0 / 2.0 / 3.0 / 1.0 / 4.0 |
| Меч (база 3, −2.4) | паутина 15 (дропает); `sword_efficient` 1.5 (о дропе не говорит); по умолчанию 1.0 | **2 / 1** | 4 / 5 / 6 / 4 / 7 | 1.6 у всех (12.5 т) |
| Рука | — (скорость 1.0, ничего не «правильно») | — | 1 | 4.0 (5 т) |

Сколько блоков или ударов выдерживает инструмент **[расчёт]**:
- кирка, топор, лопата, мотыга: блоков = прочности (59 / 131 / 250 / 32 / 1561), ударов по мобу = ⌈прочность/2⌉
  (30 / 66 / 125 / 16 / 781);
- меч: блоков ⌈прочность/2⌉, ударов = прочности.

Меч «правилен» только для паутины. Для листвы и растений это неважно: им инструмент не обязателен.

- Кожа — дроп коров (MOB-01), которых сейчас нет. Пока мобов нет, кожаная броня недоступна (§5).

## 3. Формула скорости добычи и примеры

```
speed   = скорость инструмента по блоку      // ToolComponent.getSpeed: первое правило со скоростью, чей тег содержит блок;
                                              // иначе 1.0 (рука, «не тот» инструмент)
correct = правильность для дропа             // ToolComponent.isCorrectForDrops: первое правило с флагом; иначе false
if speed > 1: speed += mining_efficiency      // Efficiency (ур² + 1); у нас 0
speed *= haste / mining_fatigue               // эффектов нет
speed *= player.block_break_speed             // 1.0
if глаза в воде: speed *= 0.2                 // player.submerged_mining_speed (Aqua Affinity — нет)
if !onGround:    speed /= 5
harvest = !requiresTool || correct
delta   = speed / hardness / (harvest ? 30 : 100)    // f32; hardness −1 → 0 (неломаемый); hardness 0 → +∞
тики    = минимальное N: f32-сумма N раз по delta ≥ 1.0   (первая прибавка — в тике клика; delta ≥ 1 → мгновенно)
```
Источники: `entity/player/PlayerEntity.getBlockBreakingSpeed`, `canHarvest`; `block/AbstractBlock.calcBlockBreakingDelta`;
`component/type/ToolComponent`; `item/Item.getMiningSpeed`; `entity/player/PlayerInventory.getBlockBreakingSpeed`
(предмет в выбранном слоте хотбара) **[src]**.

Примеры **[расчёт]**:

| Случай | delta (f32) | Тики | Секунды | Дроп |
|---|---|---|---|---|
| Бревно рукой: 1 / 2 / 30 | 0.016666668 | **61** (сумма за 60 = 0.9999997) | 3.05 | бревно |
| Камень деревянной киркой: 2 / 1.5 / 30 | 0.044444446 | 23 | 1.15 | булыжник |
| Камень рукой: 1 / 1.5 / 100 | 0.006666667 | **151** | 7.55 | ничего |
| Железная руда деревянной киркой: 2 / 3 / 100 | 0.006666667 | 151 | 7.55 | ничего |
| Железная руда каменной киркой: 4 / 3 / 30 | 0.044444446 | 23 | 1.15 | сырое железо |
| Земля рукой: 1 / 0.5 / 30 | 0.06666667 | 15 | 0.75 | земля |
| Земля рукой в прыжке: 0.2 / 0.5 / 30 | 0.013333334 | 76 | 3.8 | земля |
| Земля рукой стоя на дне, голова под водой: 0.2 / 0.5 / 30 | 0.013333334 | 76 | 3.8 | |
| Земля рукой под водой и не на земле: 0.04 / 0.5 / 30 | 0.0026666666 | 376 | 18.8 | |
| Камень деревянной киркой в прыжке: 0.4 / 1.5 / 30 | 0.008888889 | 113 | 5.65 | булыжник |
| Листва мечом: 1.5 / 0.2 / 30 | 0.25 | 4 | 0.2 | по таблице |
| Листва деревянной мотыгой: 2 / 0.2 / 30 | 0.33333334 | 3 | 0.15 | по таблице |
| Снежный блок рукой: 1 / 0.2 / 100 | 0.05 | 20 | 1.0 | ничего |
| Снежный блок деревянной лопатой: 2 / 0.2 / 30 | 0.33333334 | 3 | 0.15 | 4 снежка |
| Снежный слой каменной лопатой: 4 / 0.1 / 30 | 1.3333334 | 0 (мгновенно) | — | 1 снежок |

Сумма во float32 часто чуть меньше точной (1/60 в float32 = 0.016666668, но 60 прибавок дают 0.9999997). Поэтому счёт
в точной арифметике (как в `catalog.md` и на вики) занижает ответ на 1 тик в таблице §2.3:
- рукой: бревно и доски 61 (точно 60), верстак и сундук 76 (75), лестница и кактус 13 (12), камень 151 (150),
  булыжник 201 (200), песчаник 81 (80), угольная и железная руда 301 (300), блок сырого железа 501 (500);
- деревянной киркой: песчаник 13 (12), железная руда 151 (150), сланцевая железная руда 226 (225).

Порядок операций важен: в Java это `speed / hardness / divisor` — два деления подряд, каждое округляется до f32. Формула
`speed / (hardness·divisor)` в f32 даст другие тики.

## 4. Граничные случаи, которые чувствует игрок

1. **Инструмент «не того» типа всё равно изнашивается**: кирка по земле −1, меч по листве −2. Сломать киркой 59 блоков
   земли — кирка сломается.
2. **Мгновенные блоки не тратят прочность**: факел, трава-растение, цветы, саженцы. Мгновенные за счёт инструмента тратят:
   листва железной мотыгой, снежный слой каменной лопатой — по −1.
3. **Последний блок перед поломкой дропается**: `canHarvest` и копия стека взяты до износа (§1.2).
4. После поломки в руке пусто. Следующий блок ломается рукой с начала: стек сменился, и прогресс сбросился.
5. **Деревянная или золотая кирка по железной руде** ломает (7.55 с или 1.25 с), но ничего не даёт. Игрок думает «руда
   пустая» — это ванильное поведение.
6. **Печь рукой** ломается за 17.5 с, печь не выпадает, но её содержимое высыпается. Сундук рукой — 3.8 с, сундук выпадает
   (инструмент не обязателен).
7. **Снег на наших вершинах** (SNOW 6 = snow_block) требует лопату: рукой 1 с и ничего. Это верно для ванилы, но легко
   принять за баг.
8. **Глина рукой даёт 4 комка**, а не блок. Блок собирается обратно крафтом 2×2.
9. **Гравий иногда даёт кремень вместо гравия** (не «в дополнение»). Столб гравия при этом обваливается (BLK-07).
10. **Листва дуба** — яблоко 1 раз на ~200 блоков, у берёзы и ели яблок нет. Саженцы — 1 на 20, палки — 1 раз на 50 (1–2 шт.).
11. **Трава-растение и папоротник** — семя в 1 случае из 8. Мёртвый куст — 0–2 палки.
12. **Прыжок при копании** замедляет в 5 раз. В воде с головой — тоже в 5 раз, вместе — в 25 раз. Скорость меняется с того
    тика, когда игрок оторвался от земли.
13. **Лестница и факел отваливаются**, если убрать опору, и выпадают предметом (ASP-05). Кактус ломается, если рядом
    поставить блок.
14. **Трава под поставленным блоком** через ~1 мин (случайный тик) становится землёй (§1.5). С игрока при этом ничего не
    берётся.
15. Полоска прочности появляется после **первого** использования. Она полной длины (13 px) и зелёная: у деревянной кирки при
    1 износе `round(12.78) = 13`.

## 5. Чего нет в исходнике / не ясно / нужно решить

1. **Точность времени.** В Java прогресс — float32 (§3). Предлагаю считать в Rust так же (`f32` для delta и прогресса) и
   держать тест «бревно рукой = 61 тик». Если главный агент выберет `f64`, все времена из §2.3 со сдвигом станут на 1 тик
   короче. Разницу в 50 мс игрок вряд ли заметит, но эталоны тестов сменятся.
2. **Эффект поломки на клиенте** берёт стек, который *сейчас* в руке (`getEquippedStack(MAINHAND)` по статусу 47). Если
   клиент уже получил пустой слот, эффекта не будет. В одиночной игре он есть. У нас один цикл: проигрывать по копии
   сломанного стека.
3. **Ножниц нет на пути**, поэтому листва, трава-растение и куст как блоки недоступны. Ножницы — 2 слитка, дёшево. Решение
   пользователя: добавлять ли.
4. **Кожаная броня зависит от мобов** (коровы → кожа). Пока мобов нет, она недоступна. Решить: ждать MOB-01 или временный
   источник кожи.
5. **Наш SNOW 6 — полный блок** = snow_block: только лопатой, 4 снежка. В ваниле поверх снежной травы лежит снежный *слой*
   в 1 слой. Нужен ли нам слой в генераторе — вопрос к генератору и рендеру (он неполный: E5, E8).
6. **Варианты травы** (DRY_GRASS, DARK_GRASS, GRASS_FULL, GRASS_EDGE 28–33, SNOWY_GRASS) — это наш рендер. В MC это один
   `grass_block` (у снежной — состояние `snowy`). Поведение у всех — как у grass_block. Но если трава «умирает» или растёт
   (§1.5), нужно правило, какой вариант ставить. Это решение по рендеру, не по данным.
7. **Двойной сундук** (`ChestBlock` `TYPE`, слияние соседних) — нужен ли сразу. Также сундук не открывается, если сверху
   твёрдый блок (`ChestBlock.isChestBlocked`) — это детали аспекта сундука или ASP-10.
8. **Опад листвы по-ванильному** требует хранить `DISTANCE` и `PERSISTENT` у каждой листвы (E5), запланированные тики
   (1 тик) и случайные тики. Упрощение: при удалении бревна обойти BFS листву в радиусе 6. Ту, что не связана с бревном
   цепочкой ≤ 6, пометить «опадает» и удалять каждую в случайный момент — экспоненциально, среднее 68 с. Поставленная игроком
   листва не опадает.
9. **Удача и шёлковое касание** не нужны без зачарований. Таблицы в §2.2 уже записаны «без зачарований».
10. Не сверял по коду (не нужно для данных): точную форму жилы `OreFeature`, физику `ItemEntity` при дропе (ASP-07),
    `SaplingBlock` (рост, P2).

## 6. Сценарий проверки человеком

Предполагает срезы 2–3 (предметы в мире, инвентарь, крафт, печь). Время — от нажатия ЛКМ до исчезновения блока, игрок
стоит на земле.

1. Пустая рука, дубовое бревно. Держу ЛКМ: ~3 с, выпало 1 бревно.
2. Рукой камень: ~7.5 с, блок исчез, **ничего не выпало**. Рукой землю: ~0.75 с, выпала земля.
3. Деревянной киркой камень: ~1.15 с, выпал булыжник. Под иконкой кирки появилась **зелёная полоска полной длины**.
4. Той же киркой 5 блоков земли: каждый за ~0.75 с (как рукой). Полоска заметно укоротилась (износ идёт и на «чужом» блоке).
5. Деревянной киркой угольную руду: ~2.25 с, 1 уголь. Железную руду: **~7.5 с и ничего**. Каменной киркой железную руду:
   ~1.15 с, 1 сырое железо.
6. Деревянной лопатой землю: ~0.4 с (вдвое быстрее руки). Песок так же.
7. Прыгаю и бью камень деревянной киркой в прыжке: ломается заметно дольше (~5–6 с при непрерывных прыжках).
8. Ломаю 100 блоков дубовой листвы рукой: каждый ~0.3 с. Выпало около 5 саженцев (норма 2–9), 1–4 раза палки, яблоко —
   редко, чаще ни одного. Берёзовая листва — саженцы и палки, яблок нет.
9. Ломаю 20 гравия: обычно 1–3 раза вместо гравия выпадает кремень (бывает и ни разу, ~12%). 40 травинок: около 5 семян.
10. На снежной вершине рукой снег: ~1 с, ничего. Деревянной лопатой: мгновенно на глаз (0.15 с), 4 снежка.

## 7. Что нужно от движка (E1–E11) и как это ляжет

- **Реестр блоков и предметов (новое, Rust)** — §8. Таблицы §2 — единственный источник чисел для ломания, дропа, износа,
  стеков и звуков. JS получает из Rust только то, что нужно рендеру и UI: имя, иконку, полоску прочности.
- **E1** изменяемый мир: удаление блока → дроп. Высыпание содержимого блок-сущности при удалении. Цепочки обновлений
  соседей: факел, лестница, кактус, снежный слой, листва.
- **E4** сущности: `ItemEntity` для каждого стека дропа (ASP-07). Частицы поломки инструмента (E10).
- **E5** состояния блоков пути:
  - ось бревна — 3;
  - печь: `FACING` 4 × `LIT` 2;
  - настенный факел: `FACING` 4;
  - листва: `DISTANCE` 1–7 + `PERSISTENT`, это 4 бита;
  - снежный слой: `LAYERS` 1–8;
  - лестница: `FACING` 4;
  - сундук: `FACING` 4 (+ `TYPE` 3 для двойного);
  - саженец: `STAGE` 2 (P2), кактус: `AGE` 16 (P2).

  Всё влезает в **один байт состояния**. Предложение: ячейка `u16 = id | state << 8`, где младший байт — нынешний `u8` без
  изменений. Решают E5 и ASP-05.
- **E6** блок-сущности: сундук (27 слотов) и печь (3 слота) — содержимое выпадает при разрушении.
- **E7** UI: иконки всех предметов §2.6, полоска прочности (§1.3, 13 px, HSV), подсказка с уроном, скоростью атаки и
  защитой (INV-12).
- **E8** ресурсы:
  - блоки: доски ×3, верстак (верх, перед, бок, низ = доски), печь (перед выкл/вкл, бок, верх), факел (спрайт и тонкая
    модель 2×10 px), угольная и железная руда, саженцы ×3, лестница (спрайт на плашке 3 px), сундук (модель или
    упрощённый куб), снежный слой (текстура снега), трещины `destroy_stage_0..9`; опц. — блок сырого железа, железный
    блок, угольный блок;
  - предметы: палка, уголь, древесный уголь, сырое железо, слиток, самородок, кремень, яблоко, семена, снежок, комок
    глины, кожа, ведро пустое / вода / лава, инструменты 5 типов × 3 тира (+ золото и алмаз опц.), броня 4 × 2
    (кожа — серая основа под окраску + оверлей);
  - звуки по группам GRASS, GRAVEL, STONE, WOOD, SAND, SNOW, WOOL, LADDER (+ METAL) × break/step/place/hit/fall, плюс
    `item.break`, надевание кожи и железа, ведро набрать/вылить (свои CC0/CC-BY, `decisions.md`).
- **E10** звук и частицы: эффект поломки (громкость 0.8, pitch 0.8–1.2, 5 частиц предмета).
- **E11** свет: факел 14, горящая печь 13; листва гасит свет на 1 (ASP-14).
- **Тики блоков (новое)**: запланированные (листва через 1 тик, кактус через 1 тик) и случайные — 3 на секцию 16×16×16 за
  тик. Наш мир 16×128×16 = 8 секций на кусок. Нужны для опада листвы, травы, таяния снега и кактуса.
- **Детерминированный ГСЧ в Rust** для дропа: тест — фиксированный сид и N попыток, частоты в допуске.
- **Генератор (`gen.rs`)**: руды — отдельный аспект. Доски, верстак и прочее не генерируются.

## 8. Rust-набросок: реестр блоков и предметов

Правила ID:
- `BlockId = u8` — как сейчас в мире. **0…33 уже заняты** (`GRASS_EDGE` + 6 вариантов = 28…33) и не переставляются.
  Новые блоки — только в конец, append-only.
- `ItemId = u16`, 0 = пусто. Предлагаю: 1…255 — предмет блока с тем же номером, что `BlockId` (определён только для
  добываемых блоков), 256+ — чистые предметы, тоже append-only. Тогда «блок → свой предмет» не требует таблицы.
- Варианты рендера травы получают `base = GRASS`: вся логика §1–§3 смотрит на `base`.
- Если `GRASS_EDGES` когда-нибудь вырастет, его диапазон наедет на новые ID. Нужно либо заморозить `GRASS_EDGES = 6`, либо
  начать новые блоки с запасом (например, с 40). Решает главный агент.

Предложение новых ID (окончательно решает главный агент, файл общий):

| BlockId | Блок | | BlockId | Блок |
|---|---|---|---|---|
| 34 | oak_planks | | 42 | iron_ore |
| 35 | spruce_planks | | 43 | snow (слой) |
| 36 | birch_planks | | 44–46 | oak / spruce / birch_sapling |
| 37 | crafting_table | | 47 | chest |
| 38 | furnace (`LIT`, `FACING` — состояние) | | 48 | ladder |
| 39 | torch | | 49 | raw_iron_block (опц.) |
| 40 | wall_torch | | 50 | iron_block (опц.) |
| 41 | coal_ore | | 51 | coal_block (опц.) |

Чистые предметы с 256 (в порядке пути): stick, coal, charcoal, raw_iron, iron_ingot, iron_nugget, flint, apple,
wheat_seeds, snowball, clay_ball, leather, bucket, water_bucket, lava_bucket; wooden / stone / iron (+ golden / diamond)
× pickaxe / axe / shovel / hoe / sword; leather / iron × helmet / chestplate / leggings / boots.

```rust
// registry.rs — данные блоков и предметов (подключать include!, как blocks.rs). Числа — из ASP-06 §2.

pub type BlockId = u8;
pub type ItemId = u16;

#[derive(Clone, Copy, PartialEq, Eq)]
pub enum Snd { None, Stone, Wood, Gravel, Grass, Sand, Snow, Wool, Ladder, Metal }

// Маска тегов mineable/*.
pub const PICKAXE: u8 = 1;
pub const AXE: u8 = 2;
pub const SHOVEL: u8 = 4;
pub const HOE: u8 = 8;

/// Строка таблицы добычи. alt = 0 — независимый пул; одинаковый alt > 0 — «альтернативы»:
/// берётся первая сработавшая строка группы, последняя (chance 1.0) — запасная (гравий: кремень 10%, иначе гравий).
#[derive(Clone, Copy)]
pub struct Drop { pub item: ItemId, pub min: u8, pub max: u8, pub chance: f32, pub alt: u8 }

#[derive(Clone, Copy)]
pub enum Loot {
    None,
    Table(&'static [Drop]),
    SnowLayers(ItemId), // число предметов = LAYERS из состояния; без игрока — ничего
}

#[derive(Clone, Copy)]
pub struct BlockDef {
    pub mc: &'static str,     // имя в Minecraft — для сверки с данными и тестов
    pub base: BlockId,        // чьё поведение (варианты травы → GRASS)
    pub hardness: f32,        // −1 неломаемый, 0 мгновенный
    pub resistance: f32,
    pub requires_tool: bool,
    pub mineable: u8,         // PICKAXE | AXE | ...
    pub needs: u8,            // 0 любой, 1 камень, 2 железо, 3 алмаз
    pub sword_fast: bool,     // тег sword_efficient
    pub sound: Snd,
    pub light: u8,            // факел 14; печь 13 только при LIT — через состояние
    pub loot: Loot,
}

#[derive(Clone, Copy)]
pub struct Tier { pub level: u8, pub speed: f32, pub durability: u16, pub attack: f32 }
pub const T_WOOD: Tier = Tier { level: 0, speed: 2.0, durability: 59, attack: 0.0 };
pub const T_STONE: Tier = Tier { level: 1, speed: 4.0, durability: 131, attack: 1.0 };
pub const T_IRON: Tier = Tier { level: 2, speed: 6.0, durability: 250, attack: 2.0 };
pub const T_GOLD: Tier = Tier { level: 0, speed: 12.0, durability: 32, attack: 0.0 };
pub const T_DIAMOND: Tier = Tier { level: 3, speed: 8.0, durability: 1561, attack: 3.0 };

#[derive(Clone, Copy)]
pub enum Kind {
    Plain,
    Block(BlockId),
    /// Кирка/топор/лопата/мотыга: base — база урона типа, speed_mod — модификатор скорости атаки (§2.5).
    Tool { mask: u8, tier: Tier, base: f32, speed_mod: f32 },
    Sword { tier: Tier },
    Armor { slot: u8, points: u8, toughness: f32 },
    Bucket { fluid: u8 },
    Food { nutrition: u8 },
}

#[derive(Clone, Copy)]
pub struct ItemDef { pub mc: &'static str, pub max_stack: u8, pub max_damage: u16, pub kind: Kind }

/// Скорость и «правильность для дропа» — как ToolComponent.getSpeed / isCorrectForDrops.
pub fn tool_speed(item: Option<&ItemDef>, b: &BlockDef) -> (f32, bool) {
    match item.map(|i| i.kind) {
        // Скорость тира — даже если ярус мал; дроп — только если ярус достаточен.
        Some(Kind::Tool { mask, tier, .. }) if b.mineable & mask != 0 => (tier.speed, b.needs <= tier.level),
        Some(Kind::Sword { .. }) if b.sword_fast => (1.5, false),
        _ => (1.0, false),
    }
}

/// Прибавка прогресса за тик (f32 — как в Java; см. §3 и §5.1).
pub fn break_delta(item: Option<&ItemDef>, b: &BlockDef, on_ground: bool, eyes_in_water: bool) -> f32 {
    if b.hardness < 0.0 {
        return 0.0;
    }
    let (mut speed, correct) = tool_speed(item, b);
    if eyes_in_water {
        speed *= 0.2;
    }
    if !on_ground {
        speed /= 5.0;
    }
    let harvest = !b.requires_tool || correct;
    speed / b.hardness / if harvest { 30.0 } else { 100.0 } // hardness 0 → +inf → мгновенно
}

pub struct Stack { pub item: ItemId, pub count: u8, pub damage: u16 }

/// После ломания блока (порядок §1.2): harvest считается ДО износа, дроп — по копии.
/// Возвращает (дропать ли, сломался ли инструмент — для звука и частиц).
pub fn on_block_mined(hand: &mut Stack, def: Option<&ItemDef>, b: &BlockDef) -> (bool, bool) {
    let harvest = !b.requires_tool || tool_speed(def, b).1;
    let per_block = match def.map(|d| d.kind) {
        Some(Kind::Tool { .. }) => 1,
        Some(Kind::Sword { .. }) => 2,
        _ => 0,
    };
    let mut broke = false;
    if per_block > 0 && b.hardness != 0.0 {
        hand.damage += per_block;
        if hand.damage >= def.unwrap().max_damage {
            hand.count -= 1; // стек 1 → пусто
            broke = true;
        }
    }
    (harvest, broke)
}
```
