# Карточка пользователя: что важно Олегу

Читать каждому агенту перед задачей. Это прямые решения пользователя (2026-10-22); главнее любых планов.

## Приоритеты
- **Ровные 60 к/с без задержки ввода — главное.** Картинка уступает. Цель меряется на его машине: ноутбук RTX 3050,
  экран 3440×1440, 120 Гц, Chrome + ANGLE D3D11. Маленькое окно и программный рендер — не мерило.
- **Дальность и детальность дали (LOD) — последние рычаги** авто-качества и первые к возврату. Цель — сделать даль
  почти бесплатной, а не урезать её. Дорогое вдали — плотность сетки (lodq > 4), а не сама дальность.
- **Без мыла.** Размытие, TAA по умолчанию, нецелочисленный апскейл без нужды — нельзя. Резкие тексели.
- **Без дёрганий.** Ровный темп важнее среднего FPS; рывки и «качели» темпа заметны и бесят.
- **Красиво и «вкусно»:** дымка и воздушная перспектива, листва с просветами, вода, без «молочности» и артефактов
  (полосы, сетки, искорки, ореолы). Стиль — Minecraft, но «лучше Minecraft».

## Игра
- Механики — как Minecraft Java 1.21.1 (числа и ощущения из исходников, mcsrc.dev). Мобы: зомби, съедобные, птицы.
- **Только сеть:** одиночной игры нет, мир — на сервере. Вход на Перекрёсток (первый раз и после смерти), дальше —
  где вышел. Новый генератор = новый мир.
- Mekanism — после мультиплеера: объём M «Сталь, ветер и удвоение» + джетпак + логистика (mekanism/decisions.md).
- Еда лечит + медленная регенерация; звуки — CC0/CC-BY, скачивание — только с его разрешения.

## Как с ним работать
- Отвечать по-русски, кратко и конкретно; статус — наглядно (схемы, таблицы), когда просит.
- Не задавать вопросов про легко меняемые числа: выбрать, записать, дать переключатель.
- Проверки ему — одна ссылка-сцена и что ожидать; баги — F8; скорость — телеметрия. Не просить копировать отчёты.
- Вкус — вариантами рядом (A/B/C), а не догадкой.
- Быстрый сигнал важнее осторожности: лучше ошибка, замеченная за 3 минуты, чем 30 минут перечиток.
- Он часто играет в своём Chrome — видеокарта может быть занята; стенд это учитывает.
- Ограничений на проверки нет (контроль температуры остаётся). Диск ноутбука почти полон — сборка в общей папке
  `voxel-wt/_target`, временное — убирать.

## Сервер и границы
- Свой VPS — Oracle (ssh `OracleUbuntu`): сайт, телеметрия, баг-репорты, предпросмотр. **VPS NiSea не трогать никогда.**
- Правки VPS: копия файла → правка → проверка → перезагрузка; фаервол — только с его согласия.
- Репозиторий — приватный GitHub Astraneer/voxel-rust-demo; master пушит только главный агент.

## Решения 2026-10-23 (вечер) и 24 — главнее раздела ниже
- Заморозка графики снята для: свечения, неба, пака AVPBR и **оптимизации WebGL**. «Пока без WebGPU. Этот оптимизируем
  насколько можем» (порт на WebGPU есть в Astraneer/gpt_rust_webgpu_port — не трогать).
- **MSAA и тени не выключать автоматически никогда.** «Сглаживание отключать не надо», «чтобы не терялся антиалиасинг
  главное и тени». 60 к/с как константа, без рывков и качелей; одиночные пики — убирать.
- Вид принимает только пользователь; агенты доказывают числом (маршрут `perf/bench/route.mjs`: мерцание, попиксельная
  разница, кадр) — `docs/HANDOFF-optimization.md`.
- Пак AVPBR (JoaquiX) — по умолчанию всем (сайт — демо, ссылка только у тестеров); файлы пака не в git.
- Звуки Mojang не раздаём: импорт из своего `.minecraft` только в браузер игрока.

## Решение 2026-10-23: только геймплей (утро; частично отменено разделом выше)
- Сейчас занимаемся **только геймплеем**. Графику, вид, тени, оптимизацию картинки **не трогаем** — ни исправлений, ни вариантов на выбор, ни полировки.
- Агенты не принимают графику сами: статичные снимки не показывают дёргание и рябь. Вид оценивает только пользователь.
- Снимки — только когда без них не понять, работает ли механика; без итераций «покрасивее».
