# Памятка telem — телеметрия, бортовой самописец, причины рывков

Цель: про любой рывок сказать, **откуда** он — какая подсистема кадра, видеокарта, задача вне кадра, сборка мусора или
чужая нагрузка на машине. Карточка — `tasks/Q15-flight-recorder.md`. Пользователь не доверяет замерам: каждое число здесь
— с источником и уверенностью, без догадок.

## Что где

| файл | что |
|---|---|
| `web/engine/flight.js` | бортовой самописец: кольцо кадров (типизированные массивы, без выделений в кадре), отметки подсистем, обёртки GL/игры, разбор рывков, `dump()` |
| `web/engine/frame.js` | только отметки `fl.at(STAGE)` между вызовами подсистем |
| `web/engine/telemetry.js` | поле `fr` в снимке `snap` (рывки по причинам, подсистемы, счётчики) |
| `web/engine/report.js` | `report.flight` — дамп самописца в отчёте профайлера и F8 |
| `web/ui/debug_overlay.js` | F3: столбики рывков — цветом причины, строка «последний рывок» |
| `tools/loadlog.ps1` | журнал нагрузки ноутбука раз в секунду (процессор по группам, 3D по процессам, nvidia-smi) |
| `tools/telemetry.py` | сводка: рывки по причинам и подсистемам, стык с журналом нагрузки и прогонами проверок, `--compare A B`, `--html` |
| `web/engine/stalltest.js`, `tools/telem/stalltest.mjs` | `?stalltest=1` — искусственные рывки в настоящем браузере и проверка меток |
| `tools/telem/flight_test.mjs` | модель кадров без браузера: метки всех причин, ни одного ложного рывка, цена |

## Формат 1: дамп самописца (`report.flight`, `window.__flight.dump()`)

Объект `v: 1`, столбцами (массив на поле — удобно читать стенду):

```
{ v: 1, t0, hz, P, stages: [имена], n,
  f: { t, iv, exp, late, js, bt, d, sk, skg, gw, gpu, gp, gpm, upkb, upms, upn, glkb, comp, first, fst, alloc,
       net, netn, netkb, uo, uokb, gc, lt, ev, calls, tris, mobs, models, players, sil, cause },
  st: { <стадия>: [мс по кадрам] }, sc: { <стадия>: [вызовов] }, stri: { <стадия>: [треугольников] },
  stalls: [ рывок, … ], byCause, stallsTotal,
  cost: { avgUs, maxUs, frames, nowUs, wrapUs, settleN, settleAvgUs, settleMaxUs, gc: { minor, major } } }
```

Время — `performance.now()` страницы, мс (как `at` у профайлера). Числа округлены до 0,01. Chrome без cross-origin
isolation огрубляет `performance.now()` до 0,1 мс с дрожанием — малые стадии верны в среднем по кадрам, не по кадру.

Поля кадра (`f`, по одному числу на нарисованный кадр, старые первыми):

| поле | смысл |
|---|---|
| `t` | метка rAF кадра (начало развёртки) |
| `iv` | интервал от прошлого нарисованного кадра, мс (0 — первый кадр или после скрытой вкладки) |
| `exp` | ожидаемый интервал при темпе: d × период экрана |
| `late` | опоздание: начало колбэка rAF − `t` (главный поток был занят в момент развёртки) |
| `js` | весь JS кадра, мс (= сумма стадий `st`) |
| `bt` | время между концом прошлого кадра и началом этого (ожидание развёртки + всё, что шло вне кадра) |
| `d` | делитель темпа (кадр каждую d-ю развёртку) |
| `sk`, `skg` | пропущено rAF перед кадром; из них — из-за забора (видеокарта не доделала кадр N−2) |
| `gw` | мс ожидания забора (от первого пропуска из-за забора до кадра) |
| `gpu`, `gp`, `gpm` | GPU кадра по таймеру (приходит через 1–3 кадра; −1 — нет), самый дорогой проход (индекс в `passes`) и его мс |
| `upkb`, `upms`, `upn` | загрузка мешей плиток в видеопамять в кадре: КБ, мс, штук |
| `glkb` | все байты в видеокарту в кадре (bufferData/SubData, texImage/SubImage) |
| `comp`, `first` | программ собрано (link) в кадре; программ, впервые использованных в кадре |
| `alloc` | выделено целей/текстур в кадре, Мпикс |
| `net`, `netn`, `netkb` | разбор сообщений сервера (`game.recv`) в интервале перед кадром: мс, штук, КБ |
| `uo`, `uokb` | загрузка плиток вне кадра (из сообщения воркера, в пропущенном rAF): мс, КБ |
| `gc` | биты: 1 — малая сборка мусора, 2 — большая (канарейки FinalizationRegistry) в интервале |
| `lt` | мс долгих задач вне кадра (Long Animation Frames / longtask), пересекающих интервал |
| `ev` | биты событий: 1 смена темпа, 2 шаг авто-качества, 4 кадр ограничен (меню), 8 после скрытой вкладки, 16 «план», 32 «арена» |
| `calls`, `tris` | вызовов рисования и треугольников всего (обёртка GL) |
| `mobs`, `models`, `players` | мобов, моделей (сундуки, машины, лестницы…), других игроков в кадре |
| `sil` | мс молчания потока в интервале: развёртки без колбэка rAF сверх своего JS (+ опоздание колбэка — при разборе) |
| `fst` | стадия, где было первое рисование новой программой (255 — не было) |
| `cause` | причина, если кадр — рывок (после разбора, через 0,25 с), иначе "" |

Стадии (`stages`, порядок кадра; сумма = `js`): `pre` (размер целей, окна), `tick`, `plan`, `retire`, `edit`, `input`
(мышь, камера, звук), `cull`, `shadow`, `sky`, `blocks`, `items`, `models`, `boards`, `players`, `mobs`, `outline`,
`resolve`, `water`, `taa`, `hand`, `post`, `hud`, `debug` (F3, профайлер, телеметрия, F8), `tune` (авто и темп).

### Рывок (`stalls[]`, и кратко — в телеметрии)

Рывок — кадр, чей интервал больше ожидаемого темпом хотя бы на полразвёртки: `iv > exp + max(P/2, 2)`.

```
{ at, ms, exp, over, cause, conf, sub, why, sev, i0, i1 }
```

`at` — метка кадра, `ms` — интервал, `over = ms − exp`, `sev` — `minor` | `major` (≥ 50 мс или ≥ 2 × exp), `i0..i1` —
кадры снимка (0,5 с до, 0,2 с после) в дампе. `conf` — 0…1: доля лишнего времени, объяснённая измеренным источником,
умноженная на надёжность источника. `why` — строка для человека.

Причины `cause` (строки стабильны, стенд и сводка читают их):

| cause | когда | `sub` | надёжность |
|---|---|---|---|
| `js` | JS прошлого кадра съел время | стадия (`blocks`, `tick`, …) | 1,0 |
| `shader` | в тяжёлой стадии — первая программа или сборка | стадия | 0,9 |
| `upload` | в тяжёлой стадии — загрузка в видеокарту ≥ 1 МБ | стадия | 0,9 |
| `alloc` | выделение целей кадра в тяжёлом кадре | — | 0,9 |
| `gpu` | кадр ждал забор: видеокарта не доделала кадр N−2 | проход (`opaque`…) или `чужая?` | 1,0 / 0,6 |
| `task` | главный поток занят вне кадра задачей с атрибуцией | `net`, `upload`, `worker`, `timer`, … | 0,9 |
| `gc` | поток молчал, в интервале — сборка мусора | `major` / `minor` | 0,6 |
| `gap` | поток молчал (нет ни rAF, ни задач) — браузер/ОС не дали процессор | — | 0,5 |
| `pace` | темп сменил делитель (60 → 40/30 к/с) — это решение темпа, а не сбой | — | 1,0 |
| `quality` | шаг авто-качества в интервале | рычаг | 0,7 |
| `unknown` | лишнее время не объяснено ничем выше | — | 0 |

## Формат 2: телеметрия — поле `fr` в `snap` (приёмник не менялся)

```
fr: { n, major, by: { cause: [штук, мс] }, sub: { "cause:sub": [штук, мс] },
      list: [[at_с, ms, cause, conf, sub], …до 12 худших],
      st: { стадия: [сред, p95, макс] }, cnt: { mobs, models, players, calls, tris: [сред, макс] },
      net: [мс/с, сообщ/с, КБ/с], gc: [малых, больших], cost: [мкс сред, мкс макс] }
```

`at_с` — секунды страницы (как `up`): настенное время = время сообщения − `up` + `at_с`.

## Формат 3: журнал нагрузки ноутбука (`tools/loadlog.ps1`)

Строка JSON в секунду, файлы `voxel-wt/_loadlog/ГГГГ-ММ-ДД.jsonl` (UTC), хранится 7 дней:

```
{ "ts": "2026-10-23T15:09:38Z", "cpu": 85.2, "perf": 97,          // процессор всего %, частота % от базовой
  "g": { "cargo": 34.1, "stand": 40.2, "chrome": 12.0, "node": 1.1, "other": 6.3, "self": 0.4 },  // % всего процессора
  "top": [["rustc", 22.0], …3],                                    // самые тяжёлые процессы
  "gpu3d": { "chrome": 30.1, "stand": 20.0, "other": 2.0 },        // 3D-движок видеокарты по группам, %
  "nv": { "util": 55, "temp": 71, "clk": 1650, "w": 40.1 } }       // nvidia-smi, если есть
```

Группы: `cargo` — cargo, rustc, link, lld, wasm-bindgen, wasm-opt; `stand` — Chrome проверок и стендов (headless,
`--remote-debugging-port`, профиль в `.check`/`_rig`/TEMP); `chrome` — Chrome пользователя (игра и вкладки); `node`;
`self` — сам журнал.

## Цена

- Точно: `node tools/telem/flight_test.mjs` (Node) — 5 мкс на кадр; тот же замер в Chrome на ноутбуке — 11 мкс
  (24 стадии, 42 вызова рисования). Цель ≤ 100 мкс.
- `cost.avgUs` в дампе — самозамер по `performance.now()`, огрублённому Chrome до 0,1 мс: верхняя оценка (40–70 мкс).
- В кадре выделений нет (кроме объекта `arguments` в обёртках bufferData/texImage до оптимизации). Разбор рывка — в
  простое между кадрами (`requestIdleCallback`), обычно 0,2 мс; дамп и снимок — по запросу и раз в 10 с.

## Как разбирается рывок (почему так)

- Интервал кадра k меряется от метки прошлого кадра: его удлиняет **прошлый** кадр (его JS) и то, что было между
  ними. Профайлер до самописца относил интервал к JS текущего кадра — отсюда «mix» у кадра после JS 1097 мс.
- Колбэк rAF в Chrome несёт метку развёртки, даже если поток был занят: опоздание колбэка (`late`) — занятость потока
  до нашего кадра (задача, сборка, браузер), а не наш JS.
- Пропуски rAF темпом и забором различаются так же, как в pacing.js: пропуск при `round((t − прошлый)/P) ≥ d` — забор
  (видеокарта не доделала кадр N−2).
- Малые сборки мусора идут ~30 раз в секунду (кадр мусорит) — причиной считается только большая.
- `performance.memory` в Chrome без флага огрублён и каждый раз — новый объект: для «падения кучи» не годится;
  сборки видны канарейками `FinalizationRegistry` (реестр нужно держать ссылкой — иначе он собирается сам).
- Порог «рывок» — относительно темпа: при 30 к/с кадр 33 мс — норма, при 60 — рывок.

## Как пользоваться

- Самописец включён всегда (цена — `cost` в дампе, цель ≤ 0,1 мс на кадр); `?flight=0` — выключить (сравнение цены).
- F3 — график: рывок — столбик цвета причины; строка «последний рывок: причина · мс · уверенность».
- `python -I tools/telemetry.py --session ID` — вердикт и «рывки по причинам»; с журналом нагрузки — «в эту секунду
  cargo 85 %». `--compare A B` — две сессии или две сборки (`rev`). `--html F` — страница итога с графиками.
- Журнал нагрузки: `powershell -NoProfile -File tools/loadlog.ps1` (фоном; `-Once` — одна строка для проверки).
