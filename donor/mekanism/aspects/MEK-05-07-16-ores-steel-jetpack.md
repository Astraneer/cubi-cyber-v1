## 0. Главное коротко

1. **Руды Mekanism генерируются тем же `OreFeature`, что ванильные** (`ResizableOreFeature` — копия ванильного с размером из
   настроек), тем же конвейером «попытки → случайная точка в куске → высота → биом» [src][data]. Значит, в `gen.rs` осмий,
   олово, медь, золото и редстоун — **это новые строки в таблице `ORES`** и три новых размера жилы (10, 8, 7). Правило переноса
   высот на 0–127 — то же, что уже принято для угля и железа (§2.3).
2. **Осмий** — три слоя, как у железа: «верхний» 65 попыток, жила 7, Y 72…343 с плато 8 (горы); «средний» 6, жила 9, −32…56;
   «малый» 8, жила 4, равномерно −64…64 [src `OreType`]. У нас: 59…133 (17.75 попытки), 12…45 (2.25), 0…49 (3.06) [расчёт].
   На глубине Y 20–40 осмия **примерно в 1.7 раза меньше, чем железа** (≈15 против ≈25 блоков на кусок) [расчёт].
3. **Олово** — два слоя: 14 попыток жилой 4 (−20…94) и 12 жилой 9 (−32…72) [src]; у нас 17…71 и 12…59. Олова в камне
   **больше, чем железа** (~49 блоков на кусок против ~34 на равнине) [расчёт], а в нашем объёме оно нужно **только джетпаку: 3
   слитка** (§4.13). Решить, сколько его генерировать.
4. **Медь, золото, редстоун** — ванильные фичи: медь 16 попыток жилой 10 (−16…112); золото 4 жилой 9 (−64…32), **половина
   блоков у воздуха отбрасывается** (`ore_gold_buried`) + редкая нижняя 0–1 попытка; редстоун 4 жилой 8 (−64…15) + 8 попыток с
   треугольником, наполовину ушедшим под дно мира [data]. Медная «большая» (жила 20) — только в пещерах-капельниках, «лишнее»
   золото — только в бесплодных землях: **не берём**.
5. **Руды Mekanism — твёрдость 3, кирка не ниже каменной, звук камня, 1 сырьё** [src `BlockOre`, data `needs_stone_tool`,
   loot]. Медь — каменная кирка, 2–5 сырой меди; золото и редстоун — **железная**, 1 сырое золото / 4–5 пыли [data].
6. **Редстоуновая руда «загорается»** (свет 9, красные частицы) от начала удара, от шага (кроме приседа; каждый тик, пока
   стоишь на ней) и от ПКМ; **гаснет только на случайном тике — в среднем через ~68 с** (медиана ~47 с), а не «через
   несколько секунд», как в чеклисте [src `RedstoneOreBlock`].
7. **Сталь = ярус алмаза** (`incorrect_for_steel_tool` = `incorrect_for_diamond_tool`), скорость 8 (= алмаз), прочность 500
   (×2 железа, ~⅓ алмаза), бонус урона 3 [src `SteelMaterialDefaults`, data]. Стальной камень — 6 тиков (0.3 с), железной — 8;
   руда — 12 против 15 [расчёт f32]. **Стальной топор бьёт на 11** — сильнее алмазного (9) [src].
8. **Стальная броня 3/8/6/3 = 20, стойкость 2 на каждую часть (комплект 8)**, прочность 220/320/300/260 [src]. По защите —
   ровно алмазная; урон зомби 3 → 0.69 (в железе 1.38) [расчёт]. **От падения броня не защищает** (тип `fall` в
   `bypasses_armor`) — сценарий MEK-07 «падение с 10 блоков в стали отнимает меньше» неверен [data].
9. **Джетпак — нагрудник с баком водорода 24 000 мБ, без брони** (0 очков); заправка не быстрее **16 мБ/т** (из бака — 75 с,
   от сепаратора — 2 мБ/т, 10 мин); расход **1 мБ за каждый тик работы** (20 мин полёта) [src `GearConfig`, `ItemJetpack`].
   Скорость 256 мБ/т в MEK-04/06/10/11 — это модуль Мека-костюма, не джетпак (§11).
10. **Тяга — прибавка к скорости в начале тика игрока, до ванильной физики**, по вводу **прошлого** тика [src
    `ClientTickHandler.onTick(Pre)`]. «Обычный»: `vy += 0.15·min(1, e^(−vy))`, `vx, vz *= 1.08`; установившийся подъём
    **0.597 б/т ≈ 12 б/с**, 40 блоков за 3.5 с. «Парение»: без клавиш висишь неподвижно, Space/Shift — ровно ±0.3 б/т (6 б/с).
    Каждый тик работы **обнуляет fallDistance** [src `IJetpackItem.handleJetpackMotion`].
11. **Горизонтальный разгон «обычного» режима копится:** ×1.08 к горизонтальной скорости каждый тик тяги → до ~23 б/с
    шагом и ~30 б/с бегом (постоянная ~3 с) [расчёт]. Это сильное ощущение «ракеты» — проверить руками и решить, оставлять ли.
12. **Кончился водород — тяги нет, падаешь с обычным уроном** от точки последнего тика тяги; Space, зажатый до самой земли,
    снимает урон падения целиком, с любой скорости [вывод из src].
13. **Газовый генератор** даёт ровно столько, сколько стоит электролиз (200 Дж/мБ; 400 Дж/т → 2 мБ → 400 Дж) — прибыли нет;
    в объём не входит (справочно, §4.12).

# Часть MEK-05. Руды и ресурсы мира

## 1. Порядок генерации руд (как в Minecraft и Mekanism)

На шаге `UNDERGROUND_ORES` для каждого куска, по фичам в порядке списка биома [src `GenHandler`, data `placed_feature/*`,
`biome_modifier/*`]:
1. **Число попыток** (`minecraft:count`): постоянное (у Mekanism — из настроек, по умолчанию `perChunk`), у `ore_gold_lower` —
   равномерное 0…1.
2. На каждую попытку — **точка в куске** (`in_square`: x, z случайно 0…15 от угла куска) и **высота** из поставщика высоты:
   - равномерно `[min, max]` включительно;
   - трапеция: `span = max − min`; если `plateau ≥ span` — равномерно; иначе `l = (span − plateau)/2` (целое),
     `m = span − l`, `y = min + U(0, m) + U(0, l)` (обе — равномерные целые включительно) [src
     `ConfigurableHeightProvider.sampleTrapezoid` — совпадает с ванильным `TrapezoidHeightProvider`]. Плато 0 — треугольник.
3. **Биом** (`minecraft:biome`): фича должна быть у биома. Осмий и олово — все биомы верхнего мира (`#is_overworld`);
   ванильные — по спискам биомов (медь-большая — пещеры-капельники, золото-лишнее — бесплодные земли) [data].
4. **`OreFeature`**: если коробка жилы целиком выше рельефа (`OCEAN_FLOOR_WG`) — ничего; иначе отрезок длиной `size/4` под
   случайным углом, `size` шаров вдоль него; каждая клетка шара: в пределах высоты мира, цель — камень (`stone_ore_replaceables`)
   → обычная руда, сланец/туф → сланцевая; при `discard > 0` клетка у воздуха пропускается с этой вероятностью [src
   `ResizableOreFeature.place/doPlace/canPlaceOre`]. Жила заменяет **только камень**: где уже стоит руда раньше прошедшей
   фичи, позже прошедшая её не перекрывает [вывод].
5. Порядок фич в ванили (`plains.json`, шаг 6): … `coal_upper, coal_lower, iron_upper, iron_middle, iron_small, gold,
   gold_lower, redstone, redstone_lower, diamond…, lapis…, copper` [data]. Фичи Mekanism добавляются модификатором биома в тот
   же шаг — после ванильных [не проверено: порядок модификаторов NeoForge; при пересечении жил решает только, чья руда
   останется].

Наш `gen.rs` (`place_ores`) уже повторяет п. 2–4 для угля и железа: хеш вместо ГСЧ Java, формы жил заранее (512 на размер),
обход своего куска и восьми соседей, отсев жил над рельефом, `discard` — по хешу клетки.

## 2. Числа фич: Java и наш мир

### 2.1 Правило переноса на 0–127 и море 48 (то же, что в `gen.rs`; принято для угля и железа)

`y' = (y + 64)·48/127` при `y ≤ 63`; `y' = 48 + (y − 63)·20/17` при `63 < y ≤ 80`; `y' = 68 + (y − 80)·59/240` при `y > 80`;
границы округляются. **Попытки умножаются на (наш диапазон)/(диапазон Java)** — объёмная плотность руды на каждой высоте как в
ванили. Плато трапеции в горном отрезке × 59/240. [src `gen.rs`, расчёт]

## 7. Порядок операций в тике

### 7.1 Как это устроено в моде (клиент двигает, сервер считает топливо)

1. **Клиент, начало тика** (`ClientTickEvent.Pre`, до тика мира и до `ClientPlayerEntity.tick`) [src `ClientTickHandler.onTick`]:
   1. активный джетпак = стек в слоте груди, если в нём есть водород (и игрок не в транспорте) [src `getActiveJetpack`];
   2. «в работе» (`isJetpackInUse`) — по вводу **прошлого** тика (`input.jumping`, `input.sneaking` выставляются в
      `tickMovement` прошлого тика):
      - «обычный»: зажат Space и окно не открыто;
      - «парение»: (Space и не Shift и окно не открыто) **или** не на земле — то есть в воздухе парение работает всегда, даже с
        открытым инвентарём;
   3. состояние «в работе» → звук и частицы (§9);
   4. если в работе — **прибавка к скорости** (§7.2) и `fallDistance = 0`.
2. **Ванильный тик игрока** (ASP-02 §3.2): `prev = pos` → … → «малые скорости < 0.003 → 0» → прыжок (если на земле —
   `vy = 0.42`, **перезаписывает** тягу) → ввод ×0.98 → `travel`: ускорение, `move`, `vy = (vy − 0.08)·0.98`, трение.
3. **Сервер, конец тика игрока** (`PlayerTickEvent.Post`) [src `CommonPlayerTickHandler.tickEnd`]: тот же выбор режима по
   присланной клавише «вверх» (Space) и Shift → если режим не «выкл.»: та же прибавка (на сервере ничего не двигает — позицию
   шлёт клиент), `fallDistance = 0`, **−1 мБ водорода**; раз в 10 тиков — игровое событие «джетпак горит» (для скалка — нам не
   нужно).

Сервер решает режим так (`getPlayerJetpackMode`): «обычный» — если зажат Space; «парение» — если (Space и не Shift) или не на
земле (`onGround`, сон или полёт креатива считаются «на земле»); иначе «выкл.» — ни тяги, ни расхода.

### 7.2 Тяга (`handleJetpackMotion`), `T = 0.15`

**«Обычный»** (к текущей скорости, до физики тика):
`vx += 0.08·vx; vz += 0.08·vz; vy += T·min(1, e^(−vy))`.
Чем быстрее летишь вверх, тем слабее тяга; при падении (`vy < 0`) множитель 1 [src `getVerticalCoefficient`].
Горизонталь получает +8 % своей же скорости — тягу направления не даёт, но разгоняет то, что набрал W.

**«Парение»** (Space = вверх, Shift = вниз, ввод прошлого тика):
- оба или ни одного: если `vy > 0` → `vy = max(vy − T, 0)`; если `vy < 0` и не на земле → `vy = min(vy + T, 0)`;
- только Space: `vy = min(vy + T, 2T)` = не больше **0.3**;
- только Shift, не на земле: `vy = max(vy − T, −2T)` = не меньше **−0.3**.

Горизонталь «парение» не трогает. В обоих режимах после тяги `fallDistance = 0`.

### 7.3 Для нас — один шаг [наше, по `../../mp/design.md` путь А]

В `Player::tick` **первым делом после `prev = pos`**, до обнуления малых скоростей и прыжка: если в груди джетпак с водородом
и режим по вводу прошлого тика активен — прибавка §7.2, `fall = 0`, −1 мБ в стеке. В мультиплеере это тот же код у клиента
(предсказание) и в теневом тике сервера; водород — состояние инвентаря, авторитет сервера (как у Mekanism).

37, 40 — 70 (3.5 с), 60 — 104 (5.2 с), 80 — 137**. От моря (48) до вершины 110 — ~5.3 с и ~105 мБ. Под потолком тяга
упирается (`vy = 0` каждый тик), водород тратится.

### 8.2 «Обычный» + W (горизонталь в воздухе)

Каждый тик тяги: `v_гор ← (1.08·v_гор + a)·0.91`, `a` = 0.02·0.98 (шаг) или 0.026·0.98 (бег). `0.91·1.08 = 0.9828 < 1` — скорость
сходится, но медленно (постоянная ~58 тиков).

| Время тяги с W | Шаг, б/т | Бег, б/т |
|---|---|---|
| 1 с | 0.38 | 0.57 |
| 2 с | 0.60 | 0.84 |
| 3 с | 0.76 | 1.03 |
| 5 с | 0.95 | 1.25 |
| предел | **1.14 (22.8 б/с)** | **1.48 (29.6 б/с)** |
| для сравнения: в воздухе без джетпака | 0.218 (4.4 б/с) | 0.283 (5.7 б/с) |

Держа Space, всё это время поднимаешься на 12 б/с, поэтому «ракетный» разгон по горизонтали — короткими импульсами Space.

## 9. Звук, частицы, HUD

### 9.1 Звук [src `JetpackSound`, `PlayerSound.tick`; data `sounds.json` `item.jetpack`]
- Одна петля на игрока, категория «игроки», позиция — игрок; звучит, пока состояние «в работе».
- Громкость начинается с 0.1 и **растёт на 0.1 за тик** до 1.0 (~0.5 с); выключение — **−0.1 за тик** до 0 (0.5 с), без обрыва.
- Субтитр повторяется раз в 3 с. Затухание — по умолчанию (линейно до 16 блоков) [не проверено: `attenuationDistance` не
  переопределён]. Файл `.ogg` Mekanism не берём — свой CC0/CC-BY «шипение/пламя» (`../sources.md`).

### 9.2 Частицы [src `RenderTickHandler.tickEnd/doJetpackRender`, `JetpackFlameParticle`, `JetpackSmokeParticle`]
- Каждый клиентский тик для каждого игрока в работе — **3 точки × (пламя + дым) = 6 частиц**.
- Точки в осях тела (x — вбок, y — вниз от глаз, z — назад), повёрнуты по повороту тела: левое сопло `(−0.43, −0.55, −0.54)`,
  правое `(0.43, −0.55, −0.54)`, центр `(±0.2 случайно, −0.86, −0.30)`; к точке прибавлена скорость игрока. Присед: наклон
  20° и +0.125 вверх.
- Скорость частицы = `0.2·смещение + скорость игрока` (у боковых ещё `смещение·r`, `r` до ±0.05) — струя вниз-назад и
  наружу.
- Пламя — ванильный `FLAME`, дым — ванильный `SMOKE` (размеры, сроки 12…44 и 8…40 тиков, ×0.96 — ASP-13), но **яркость своя**:
  ~12 из 15 при любом освещении; на нулевом тике частица не рисуется (не вспыхивает в лице).

### 9.3 HUD
Mekanism выводит два текстовых строки внизу слева [src `MekanismHUD`]. Предложение [наше]: те же строки «Джетпак: обычный» и
«Водород: 23 950 / 24 000 мБ (99 %)» внизу слева; полоска на иконке в слоте груди; сообщение над хотбаром при смене режима.

### 10.2 Заправка джетпака
- Слот «наполнить предмет» (у бака — верхний, у сепаратора — левый газовый слот водорода): каждый тик переливает из бака
  машины в предмет, сколько предмет примет, — у джетпака не больше 16 мБ/т [src `ChemicalInventorySlot.drainChemicalTank`].
- Сепаратор (MEK-11): 2 мБ воды → 2 мБ водорода (левый бак 2 400) + 1 мБ кислорода, 400 Дж/т [data, src].
- Практика: сепаратор → (выталкивание/трубка) → бак 64 000 → джетпак в слот «+». Без трубок — джетпак прямо в левый слот
  сепаратора.
- **Крафт джетпака переносит газ бака** (рецепт `mekanism:mek_data`): водород из бака-ингредиента уходит в джетпак. Если в баке
  другой газ или водорода больше 24 000 мБ — **рецепт не даёт результата** [src `MekanismShapedRecipe.assemble`,
  `ChemicalRecipeData.applyToStack`].

### 10.3 Рецепты джетпака
- **Джетпак:** `SCS / ITI / ·I·` — S сталь ×2, C базовая схема ×1, I **олово ×3**, T базовый химический бак [data `jetpack`].
- Всего по сырью [расчёт]: 2 стали (2 железа + 4 угля через инфузор), схема (осмий + 2 пыли редстоуна), 3 олова, бак (4 осмия +
  4 пыли редстоуна) → **5 осмия, 3 олова, 2 железа, 6 пыли редстоуна, ~4 угля**.

### 10.4 Газовый генератор (справочно; предлагаю — вне объёма) [src `TileEntityGasGenerator`, `GeneratorsConfig`, `GeneratorsBlockTypes`; data]
- Водород **200 Дж/мБ**, сгорает за 1 тик (`chemical_attribute_fuel`: `energy 200, burn_time 1`); этилен 705 / 40 (вне).
- Бак топлива **18 000 мБ**, буфер **200 кДж** (1 000 × 200), отдача соседям — до 2× выработки.
- Сжигает за тик до `⌈256 · запас/ёмкость⌉` мБ (и не больше, чем влезет в буфер): полный бак — 256 мБ/т = **51 200 Дж/т**,
  наполовину пустой — вдвое меньше.
- Рецепт: `OAO / XCX / OAO` — осмий ×4, пропитанный сплав ×2, стальной корпус ×2, электролитическое ядро [data].
- **Энергии он не добавляет:** электролиз 400 Дж/т даёт 2 мБ водорода = 400 Дж в генераторе (MEK-11). Это «аккумулятор на
  газе», а не источник. В объём M + джетпак не нужен.

### 10.5 Олово
- Генерация — §2.2 (два слоя); руда — §3.1; плавка сырья — 200 т; пыль — обогащением 3 → 4.
- **Где нужно в нашем объёме:** только джетпак — **3 слитка** [data]. В Mekanism ещё: бронза (3 меди + 10 мБ инфузии олова →
  4 бронзы; бронзовые инструменты, бронированный джетпак), фляга, огнемёт, жидкостный заполнитель, резистивный нагреватель,
  сейсмический вибратор, база модулей, улучшение-фильтр (пыль олова) — всё вне объёма [src datagen `MekanismRecipeProvider`,
  `UpgradeRecipeProvider`].
- Вывод: олово генерируется щедро (§2.3), а нужно на один предмет — §13 п. 1.

## 11. Граничные случаи и мелочи

Руды:
1. **Медь сыплется горстями**: 2–5 с блока, жилы по ~8 клеток, ~50 блоков на кусок — после первой шахты меди с избытком.
2. **Золото у пещер «облезлое»**: половина клеток жилы, касающихся воздуха, не ставится (`discard 0.5`).
3. **Каменная кирка по редстоуну и золоту** — 3.8 с и ничего; деревянная по осмию, олову, меди — 7.5 с и ничего (ASP-06).
4. **Редстоун зажигается мобами и упавшими предметами** (у них нет приседа); пыль, лежащая на руде, не даёт ей погаснуть.
5. **Пустые малые жилы:** у четверти жил размера 4 (малый осмий, малое олово, малое железо) нет ни одной клетки [расчёт] —
   так и в ванили.
6. Осмий «верхнего» слоя и железо в горах выходят на склоны (у воздуха не отбрасываются); олово, медь, золото у нас на
   склоны почти не выходят (верх 59–76).
7. **На равнине у моря осмия мало** — он в основном на 12…45 и в горах. Первая шахта «вниз до 20–30» — правильный совет.

Сталь:
8. **Стальной топор бьёт сильнее алмазного** (11 против 9) — топор становится лучшим оружием по разовому урону, меч — по
   урону в секунду (7 × 1.6 = 11.2 против 11 × 1.0).
9. Стальная мотыга атакует со скоростью 4.0 (как алмазная), урон 1 — как у всех мотыг.
10. Стальной инструмент изнашивается **в 3 раза быстрее алмазного** (500 против 1 561); починка двумя в сетке — как у любых
    инструментов (ASP-09).
11. Броня не спасает от падения — ни железная, ни стальная.

Джетпак:
12. **Надеть джетпак = снять нагрудник:** с остальной стальной бронёй 12 очков (урон 6 → 3.53 вместо 1.56).
13. **Тяга по вводу прошлого тика:** Space на земле — сначала обычный прыжок, тяга со следующего тика; отпустил — ещё один
    тик тяги.
14. **Отпустил Space на подъёме** — летишь ещё ~1.7 блока вверх (апекс) и падаешь; урон считается от апекса (подъём обнуляет
    fallDistance, правило сервера в ASP-02 §3.11). С 10 блоков — 7 ед. (3.5 сердца), с 20 — 16, с 23 — 19, с 30 — смерть
    [расчёт, ASP-12].
15. **Space в последний момент гасит урон**: каждый тик тяги обнуляет fallDistance, урон зависит только от неё, а не от
    скорости удара. Тяга работает по вводу прошлого тика, поэтому Space должен быть зажат хотя бы за тик до касания: держишь
    до земли — урона нет; коротко нажал за 2 тика до земли при падении 3.75 б/т — 1 ед. [вывод]. А **затормозить** после
    долгого падения тяга не успевает: с предельной скорости 3.9 б/т «обычный» гасит её за ~38 тиков и ~67 блоков [расчёт].
16. **Кончился водород в полёте** — тяга и звук гаснут (звук — за 0.5 с), падение обычное от точки последнего тика тяги.
17. **«Парение» с открытым инвентарём** держит в воздухе (в воздухе оно работает без клавиш).
18. «Парение» тратит водород, даже когда висишь неподвижно; на земле — нет.
19. **Shift в «парении»** — вниз 6 б/с и присед (коробка 1.5 — пролезаешь в щель 1.5); в «обычном» Shift ни на что не влияет,
    кроме приседа.
20. Space на земле под потолком в «обычном» — тяга и расход есть, взлёта нет; горизонталь чуть быстрее (+11 % при ходьбе)
    [расчёт].
21. **В воде тяга тоже работает** (проверок воды нет) — выныриваешь быстро [вывод из src].
22. Мир выше 127 не ограничен для полёта — нужно, чтобы физика считала клетки над миром воздухом.
23. В мультиплеере: водород тратит сервер; если клиент считает, что топливо ещё есть, расхождение — до одного RTT, правит
    теневой тик.

Бак:
24. Сломанный бак уносит газ в предмете; поставленный — с тем же газом.
25. В слот «+» бака можно положить только предмет, который примет газ бака; пустой бак принимает любой газ из предмета.

## 12. Чего нет в исходнике / не ясно

1. Порядок фич Mekanism относительно ванильных внутри шага руд — модификатор биома добавляет их в конец шага
   [не проверено: порядок применения модификаторов NeoForge]. Влияет только на то, чья руда остаётся на пересечении жил.
2. Точные тексты строк HUD и подсказок (файлы языка не читал) — свои русские.
3. Знаки поворота `Pos3D.xRot/yRot` для точек сопел — по смыслу «назад и вниз от спины»; при рисовании подобрать на глаз.
   В коде сказано, что у чужих игроков в «парении» позиция частиц неверна (TODO мода).
4. Происхождение `jetpack.ogg` неизвестно — не берём.
5. Модель джетпака на игроке (`ModelJetpack`) не разбиралась: у нас пока нет модели игрока от третьего лица.
6. Что «режим» в ванильном HUD брони: Mekanism ничего не рисует в ряду брони — 0 очков, ряд пуст.

## 13. Что решить (главному агенту / пользователю)

1. **Сколько олова.** Как в моде — два слоя (~49 блоков на кусок, больше железа) ради 3 слитков; или только «большой» слой
   (~37), или только «малый» (~13). Рекомендация: как в моде (данные одни, бронза может понадобиться позже).
2. **Разгон «обычного» режима** ×1.08/тик (до 23–30 б/с) — оставить как в моде или ограничить [наше]. Рекомендация: как в
   моде, решить после пробы руками.
3. **Джетпак вместо нагрудника** — как в моде (броня 0). Бронированный джетпак требует алмазов и бронзы — вне.
4. **Режимы** — «обычный», «парение», «выкл.» (решение пользователя); клавиша G / Shift+G, круг без «вектора».
5. **Вода для водорода:** полный джетпак = 24 ведра воды через сепаратор. Без насоса (вне M) — ведрами; трубы из MEK-14 от
   бесконечного источника — если в объёме есть насос или «вода из источника рядом». Решить вместе с MEK-11/14.
6. **Ввод джетпака — прошлого тика** (как в моде, 50 мс) или текущего [наше]. Рекомендация: как в моде — первый тик совпадает
   с обычным прыжком, разницы почти нет.
7. **Плато осмия «верхнего»** (2 блока у нас) — реализовать трапецию с плато (3 строки) или считать треугольником (разница < 1
   блока). Рекомендация: трапеция — общий код с Mekanism.
8. **Блоки металлов** (осмий, олово, сталь, медь, золото, редстоун, сырьё) — P2; медный блок без окисления [наше] или не брать.
   Самородки: стальной — да (плавка снаряжения), осмия и олова — P2.
9. **Газовый генератор** — вне (§10.4).
10. Округление границ высот: в `gen.rs` `iron_small` верх 58 (58.59 обрезано), а `coal_upper` 81.77 → 82 (округлено). Для новых
    фич предлагаю округлять, `iron_small` оставить как есть (эталоны уже зелёные).

## 14. Сценарий проверки человеком

Один проход, мир новый, выживание; нужны готовые срезы M1 (инфузор, тепловой генератор), MEK-11 (сепаратор) и бак.

1. **Шахта.** У точки появления копаю лестницу вниз до Y ≈ 30 и ветку 60 блоков в сторону.
   *Ожидаю:* голубовато-серая осмиевая руда — несколько жил по 3–8 блоков, примерно вдвое реже железа; оловянной (светло-серой)
   — больше, чем железной; медь — часто, и с одного блока 2–5 кусков; уголь заметно реже, чем у поверхности.
2. **Ярусы.** Деревянной киркой по осмию: ~7.5 с, ничего. Каменной: ~1.15 с, 1 сырой осмий. Каменной по редстоуну (ниже Y 30,
   у дна чаще) — ~3.8 с, ничего; железной — ~0.75 с, 4–5 пыли.
3. **Редстоун светится.** Бью по редстоуновой руде и отпускаю — красные искры из открытых граней, в тёмной шахте руда светится
   (если блочный свет уже есть). Встаю на неё — светится, пока стою; присел и подошёл — не зажигается. Ухожу — гаснет не сразу:
   обычно через полминуты–полторы, иногда через несколько секунд, иногда через 3 мин.
4. **Горы.** На склоне горы выше Y 80 вижу осмий прямо на поверхности камня.
5. **Сталь.** Плавлю сырой осмий в печи (10 с на штуку). Инфузором делаю 3 стальных слитка; кирка: 3 стали сверху, 2 железа
   по центру столбиком. *Ожидаю в подсказке:* «Урон 5, скорость атаки 1.2», прочность 500.
6. **Скорость.** Ломаю подряд 20 камня стальной и 20 железной киркой. *Ожидаю:* камень ~0.3 с против ~0.4 с; руда ~0.6 с
   против ~0.75 с.
7. **Броня.** Надеваю стальной комплект — ряд брони полный (10 значков). Даю зомби ударить 10 раз: в железной теряю ~7 сердец,

/// Высота попытки из 32 бит хеша: равномерно или трапеция (как TrapezoidHeightProvider / sampleTrapezoid).
pub(crate) fn ore_height(f: &OreFeature, h: u32) -> i32 {
    let u = |bits: u32, n: i32| ((bits as i64 * (n as i64 + 1)) >> 16) as i32; // 0..=n
    let span = f.hi - f.lo;
    match f.shape {
        Shape::Uniform => f.lo + u(h & 0xFFFF, span),
        Shape::Trapezoid { plateau } if plateau >= span => f.lo + u(h & 0xFFFF, span),
        Shape::Trapezoid { plateau } => {
            let l = (span - plateau) / 2;
            f.lo + u(h & 0xFFFF, span - l) + u(h >> 16, l)
        }
    }
}

#[derive(Clone, Copy, PartialEq, Eq)]
pub(crate) enum JetMode { Normal = 0, Hover = 1, Off = 3 } // 2 — «вектор» мода, вне объёма

impl ItemStack {
    pub(crate) fn gas(&self) -> u32 { self.aux as u32 }
    pub(crate) fn set_gas(&mut self, mb: u32) { self.aux = (self.aux & !0xFFFF_FFFFu64) | mb as u64; }
    pub(crate) fn jet_mode(&self) -> JetMode {

    }

// ---------------- полёт (MEK-16): в начале Player::tick, до «малые → 0» и прыжка; ввод — прошлого тика.
impl Player {
    /// true — джетпак «в работе» в этом тике (звук, частицы).
    pub(crate) fn jetpack_step(&mut self, chest: &mut ItemStack) -> bool {
        if chest.item != I_JETPACK || chest.gas() == 0 {
            return false;
        }
        let (up, down, ground) = (self.jump_in, self.sneak_in, self.on_ground); // прошлый тик
        let t = JET_THRUST;
        match chest.jet_mode() {
            JetMode::Normal if up => {
                let k = (-self.vel[1]).exp().min(1.0);
                self.vel[0] += 0.08 * self.vel[0];
                self.vel[2] += 0.08 * self.vel[2];
                self.vel[1] += t * k;
            }
            JetMode::Hover if (up && !down) || !ground => {
                let vy = &mut self.vel[1];
                if up == down {
                    if *vy > 0.0 { *vy = (*vy - t).max(0.0) } else if *vy < 0.0 && !ground { *vy = (*vy + t).min(0.0) }
                } else if up {
                    *vy = (*vy + t).min(2.0 * t);
                } else if !ground {
                    *vy = (*vy - t).max(-2.0 * t);
                }
            }
            _ => return false,
        }
        self.fall = 0.0;
        chest.set_gas(chest.gas() - 1);
        true
    }
}

    }
