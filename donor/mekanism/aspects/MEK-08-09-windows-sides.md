## 0. Главное

1. **Все окна машин — 176×166**, рюкзак с y = 84, хотбар — 142, как у печи; размер окна ни одна машина объёма не меняет
   [src] `GuiMekanism` (наследует размеры ванильного экрана), `MekanismContainer.BASE_Y_OFFSET`. Окно собирается из
   **элементов**: слоты (рамка цвета режима), вертикальная полоса энергии 4×52, полосы и шкалы баков, полоса прогресса,
   кнопки, информационный «экран», **вкладки** по краям и **подокна** (стороны, транспортёры, улучшения).
2. **Полосы в окне не сглаживаются.** Полоса энергии и полосы баков рисуют `floor(доля · высота)` от последних пришедших
   чисел — меняются ровно раз в тик. Формула `(9·старое + новое)/10` (`MekanismUtils.getScale`) в окнах **не используется**,
   она нужна только ядру куба энергии в мире [src] `GuiVerticalPowerBar`, `GuiTankBar`, `TileEntityEnergyCube.prevScale`.
   У шкал (gauge) иначе: `max(1, round(доля · высота))`, любое ненулевое количество видно хотя бы одним пикселем.
3. **Цвет рамки слота — постоянный «родной» режим слота**, а не то, что сейчас стоит на гранях: вход — тёмно-красный,
   выход — тёмно-синий, энергия — зелёный, **доп. (слот вещества инфузора и газа очистителя) — жёлтый**, второй выход
   сепаратора — бирюзовый [src] `GuiMekanism.addSlots`, `ISideConfiguration.getActiveDataType`, `SlotType.get`.
4. **Синхронизация — раз в серверный тик, только изменившиеся значения**: слоты, энергия, прогресс, флаги ошибок, баки,
   особые числа машины. Режимы сторон идут пакетом обновления блока при каждой правке; флаги выталкивания, цвета
   транспортёров и улучшения — **только пока открыто соответствующее подокно** [src] `MekanismContainer.broadcastChanges`,
   `startTracking`, `TileComponentConfig.getSpecificSyncableData`.
5. **Shift-клик Mekanism отличается от ванильного:** из слота машины — сначала доложить в такие же стопки **хотбара слева
   направо**, потом рюкзака; потом пустые ячейки в том же порядке (у печи выход идёт справа налево). В машину — сначала в
   **непустые** слоты машины по порядку описания, если ничего не ушло — в пустые; только если машина ничего не взяла —
   рюкзак ↔ хотбар (и броня, если у окна есть боковая панель брони) [src] `MekanismContainer.quickMoveStack`.
6. **Выход машины можно взять частично**: курсор с 60 пыли, в выходе 10 — заберётся 4 и останется 6. У ванильной печи в
   этом случае не происходит ничего [src] `InventoryContainerSlot.tryRemove` (`allowPartialRemoval`).
7. **Стороны — по типу ресурса** (энергия, жидкость, вещество, предметы; тепло — вне объёма), у каждого типа 6 граней
   **относительно лица** машины (`RelativeSide`: лицо, лево, право, зад, верх, низ). Повернул машину — настройка
   повернулась вместе с ней. Режимы: ничего, вход (1, 2), выход (1, 2), вход-выход, энергия, доп. [src] `DataType`.
8. **Умолчания камер:** предметы — все грани «вход», **правая — выход**, **задняя — энергия** (у инфузора и очистителя ещё
   **нижняя — доп.**); энергия — все 6 граней «вход»; выталкивание **выключено**. «Правая» — справа от игрока, который
   смотрит машине в лицо [src] `AttachedSideConfig.LightConfigInfo.MACHINE` / `EXTRA_MACHINE`, `RelativeSide.getDirection`.
9. **Окно сторон:** ЛКМ по грани — следующий режим, ПКМ — предыдущий, **Shift+ЛКМ — «ничего»**. Кнопка внизу справа: если
   все грани одинаковы — сдвинуть все на следующий режим (ПКМ — на предыдущий), если разные — сбросить все в «ничего»;
   с Shift — сбросить все грани **всех типов**. Кнопка вверху справа — вкл./выкл. выталкивания текущего типа [src]
   `GuiSideConfiguration`, `PacketSideData`, `PacketBatchConfiguration`, `PacketEjectConfiguration`.
10. **Выталкивание предметов — раз в 11 тиков, а не в 10:** после выталкивания счётчик ставится в 10 и уменьшается на 1 за
    тик, выталкивание — на тике, когда он уже 0 [src] `TileComponentEjector.tickServer`, `outputItems`. За один раз
    уходит **вся стопка выхода** (сколько влезет) одним видом предмета на грань. Вещества, жидкости и энергия
    выталкиваются **каждый тик** (вещества и жидкости до 1024 мБ/т, энергия куба — до 4 000 Дж/т).
11. **Порядок граней при выталкивании — мировой, а не относительный:** низ, верх, север, юг, запад, восток; первая грань,
    куда что-то влезло, получает всё, что влезло [src] `getSidesForData` (`EnumSet<Direction>`), `outputItems`.
12. **Цель выталкивания — любой блок с инвентарём на этой грани** (сундук, ванильная печь, другая машина), со своими
    правилами граней: в печь сверху — во вход, сбоку — только топливо; в машину — только через её грань «вход» (или «доп.»,
    «энергия» для своих предметов) и только то, что проходит проверку слота [src] `TransitRequest.addToInventoryUnchecked`,
    `ConfigHolder`, ванильный `AbstractFurnaceBlockEntity.getAvailableSlots`.
13. **Конфигуратор (8 режимов) энергию не хранит** (в 10.7 это простой предмет), рецепт — железо ×2, осмий, сталь [src]
    `ItemConfigurator`, [data] `recipe/configurator.json`. **По машине с окном простой ПКМ открывает окно** почти во всех
    режимах — действие идёт по **Shift+ПКМ**: «настройка» — режим грани **вперёд** (назад в мире нельзя), «опустошить» —
    вывалить все слоты, «ключ» — снять машину целиком в инвентарь. В режиме «поворот» ПКМ поворачивает машину на 90° по
    часовой, Shift+ПКМ ставит лицо **от** нажатой грани [src] `ItemConfigurator.useOn`, `TileEntityMekanism.tryWrench`,
    `openGui`; [вывод] порядок «блок → предмет» ванильного `interactBlock`.
14. **Mekanism сам рисует цвет грани в мире:** с конфигуратором в режиме «настройка» грань под прицелом закрашивается
    цветом её режима (прозрачность 0.6, полная яркость) [src] `RenderTickHandler` (участок «configurable machine»). Это
    поправка к `loop.md` §4 п. 11: наше «сверх» — только показ всех граней сразу.
15. **Снятая ключом или сломанная киркой машина хранит в предмете** слоты, энергию, баки, улучшения, стороны, настройку
    выталкивания — но **не прогресс** [data] `loot_table/blocks/*.json` (`copy_components`). Ключ лишь кладёт предмет сразу
    в инвентарь и не тратит время на ломание [src] `WorldUtils.dismantleBlock`.

## 1. Окно машины: как устроено

### 1.1 Каркас [src] `GuiMekanism`, `GuiMekanismTile`, `GuiConfigurableTile`, `MekanismTileContainer`

- Экран — ванильный экран-контейнер, но **все** части, кроме самих предметов в ячейках, — элементы (`GuiElement`):
  фон каждого слота, полосы, кнопки, вкладки. Порядок добавления: (боковая панель брони, если есть) → слоты → общие
  вкладки (улучшения, редстоун, защита) → вкладки сторон и транспортёров (у настраиваемых машин) → элементы машины →
  вкладка предупреждений (если отслеживается хоть одно).
- Размер 176×166; заголовок — имя блока по центру, y = 6; «Инвентарь» — (8, 72); рюкзак (8 + 18j, 84 + 18i), хотбар
  (8 + 18i, 142) [src] `MekanismContainer.addInventorySlots`, `GuiMekanism.renderInventoryText`.
- **Боковая панель брони** (4 слота брони + вторая рука) — у теплового генератора и ветряка слева в (−20, 11), у куба
  энергии справа в (180, 41) [src] `GeneratorsContainerTypes`, `MekanismContainerTypes` (`armorSideBar`). Нужна, чтобы
  быстро класть броню (джетпак!) в слот зарядки и обратно. У камер её нет.
- Дальность: окно машины **не закрывается по расстоянию** — только если блок сломан или кусок выгружен [src]
  `MekanismTileContainer.stillValid`. У ванильных печи и сундука — 8.5 блока (ASP-10 §2.5). Решение для нас — §16.
- Наведение на слот или элемент: подсказка элемента; под подокном слоты «не видны» мыши [src] `GuiMekanism.isHovering`.

### 1.3 Вкладки и подокна [src] `element/tab/*`, `element/window/*`

| Вкладка | Где (x, y относительно окна) | Что |
|---|---|---|
| Стороны | слева (−26, 6) | открывает подокно сторон (§5.5) |
| Транспортёры | слева (−26, 34) | подокно цветов для транспортёров: «строгий вход», цвет выхода, цвет входа по граням (L, MEK-14) |
| Предупреждения | слева (−26, 109), 26×26; у теплового генератора — справа | видна, только если есть предупреждение; подсказка — «Проблемы:» и строки |
| Энергия | слева (−26, 137), 26×26 | только подсказка: «Использует: 50.0 J/t», «Нужно: 11.6 kJ», «Единица: Джоули»; клик меняет единицу (Дж/FE — у нас нет) |
| Тепло (тепловой генератор) | слева | подсказка: температура, передано, рассеяно |
| Улучшения | справа (176, 6) | подокно улучшений (MEK-10) |
| Редстоун, защита | справа (176, 137) и др. | вне объёма (UPG-06) |

- «Использует» — расход за тик **только пока вид «активна»** (а вид гаснет с задержкой, MEK-01 §5), иначе 0; «Нужно» —
  ёмкость минус запас [src] `GuiEnergyTab(…, isActive)`, `MachineEnergyContainer.getNeeded`. У сепаратора «использует» —
  фактически потраченное за тик; у куба — «Скорость входа» и «Макс. выход»; у генераторов — «Вырабатывает» и «Макс. выход».
- **Подокно** (`GuiWindow`): своё окно поверх основного; перетаскивается за полосу высотой **18 px** сверху; кнопка
  «закрыть» (6, 6) и «закрепить» (16, 6). **Esc закрывает верхнее незакреплённое подокно, а не экран**; E закрывает
  весь экран. Закреплённое подокно само открывается при следующем открытии экрана; положение запоминается по виду
  подокна. Открыть второе такое же нельзя: вкладка гаснет, пока её подокно открыто [src] `GuiWindow.keyPressed`, `close`,
  `GuiWindowCreatorTab`, `SelectedWindowData.WindowType.canPin`.
- Подокно сторон 156×135, открывается в ((176 − 156)/2, 15) = (10, 15); транспортёров — 156×119 там же; улучшений —
  198 × (76 + max(18, 12·рядов)) в (−11, 15) [src] `GuiSideConfigurationTab.createWindow` и соседи.
- **Взаимодействие с основным окном при открытом подокне:** у подокон сторон, транспортёров и улучшений режим «всё»
  — основное окно остаётся полностью живым (можно класть предметы, жать кнопки). У прочих подокон по умолчанию — только
  нижние 90 px (инвентарь игрока) [src] `GuiWindow.InteractionStrategy`, `mouseClicked`.
- Порядок кликов: сначала подокна (верхнее первым; клик по нижнему поднимает его наверх), потом элементы основного окна в
  обратном порядке добавления, потом слоты [src] `GuiMekanism.mouseClicked`.

### 1.4 Предупреждения [src] `WarningTracker`, `TileEntityRecipeMachine.getWarningCheck`

- Каждый элемент подписывается на флаг ошибки рецепта (MEK-01 §4). Список во вкладке — **в порядке видов**: «вход не даёт
  выхода» → «нет рецепта или мало входа» → «нет места в выходе» → «не хватает энергии» → «энергии мало для полной
  скорости»; если есть «не хватает энергии», строка «мало для полной скорости» не добавляется.
- Где загорается: «не хватает энергии» — полоса энергии; «вход не даёт выхода» — полоса прогресса; «нет рецепта / мало
  входа» — слот входа (и полоса бака доп. вещества); «нет места» — слот выхода (шкалы газов у сепаратора).
- Пустой вход предупреждения **не** даёт: ошибки очищаются, когда рецепта нет (MEK-01 §2.2).
- Пока окно открыто хоть у кого-то, машина раз в **100 тиков** (сдвиг случайный) перепроверяет **все** ошибки, иначе —
  до первой [src] `RECIPE_CHECK_FREQUENCY`, `shouldRecheckAllErrors`. Поэтому вторая проблема может появиться в списке с
  опозданием до 5 с.

## 3. Что синхронизируется и как часто [src] `TileEntityMekanism.addContainerTrackers` и наследники, `MekanismContainer`

Сервер каждый тик сравнивает отслеживаемые значения с прошлыми и шлёт **одним пакетом только изменившиеся**; при открытии
окна — всё сразу [src] `broadcastChanges`, `sendAllDataToRemote`. Клиент рисует каждый кадр из последних значений.

| Значение | Тип | Когда | Для чего |
|---|---|---|---|
| предметы в слотах машины и игрока | стек | каждый тик, если изменились (ванильная часть) | иконки |
| энергия | целое (Дж) | каждый тик | полоса, подсказки |
| ёмкость и расход за тик | целые | только у машин с улучшениями (а это все камеры, инфузор, сепаратор) | подсказки |
| получено энергии за прошлый тик | целое | каждый тик | (генераторы, сети) |
| прогресс, нужно тиков | int ×2 | каждый тик | прогресс |
| флаги ошибок рецепта | bool ×4…5 | каждый тик | предупреждения |
| баки веществ, жидкостей | вид + количество | каждый тик | полосы, шкалы |
| тепло и теплоёмкость | double | (тепловой) | вкладка тепла |
| особое машины | сепаратор: 2 режима газа, «потрачено энергии»; тепловой: выработка, потери; ветряк: множитель, «нет ветра» | каждый тик | кнопки, экраны |
| режим редстоуна и сигнал | — | — | вне объёма |
| **флаги выталкивания** по типам ресурса | bool на тип | **только пока открыто подокно сторон** (при открытии — сразу) | кнопка выталкивания |
| строгий вход, цвет выхода, 6 цветов входа | — | только пока открыто подокно транспортёров | L |
| улучшения | — | только пока открыто подокно улучшений | MEK-10 |
| **режимы граней** (6 на тип) | — | пакетом обновления блока при каждой правке (`sideChanged` → `sendUpdatePacket`) | подокно сторон, наложение конфигуратора |
| «активна» | состояние блока | при смене вида | «Использует» во вкладке энергии, вид |

Мелочи: открытое у кого-то окно включает «полную перепроверку ошибок» раз в 100 тиков (§1.4). Число смотрящих
(`playersUsing`) другого влияния не имеет.

## 4. Мышь и Shift-клик

### 4.1 Слоты машины против ванильных [src] `InventoryContainerSlot`, `BasicInventorySlot`, `Input/OutputInventorySlot`

| | Вход | Выход | Энергия / вещество / жидкость |
|---|---|---|---|
| Положить рукой | только предмет с рецептом этой машины (у инфузора и очистителя — с учётом вещества в баке) | **нельзя** | что можно залить или превратить (редстоун — в энергию, уголь — в углерод, ведро воды — в бак) |
| Взять рукой | да | да, **частично тоже** | да |
| Взять трубой / выталкивателем | **нет** | да | только «отработанное» (пустую батарею) |
| Предел | `min(99, предел стека)` → 64 | 64 | 64 |

- Обмен «курсор ↔ слот» разрешён, если курсорный предмет проходит проверку слота **без учёта текущего содержимого** и
  текущее можно вынуть [src] `InventoryContainerSlot.mayPlace`.
- Частичное взятие из выхода: курсор с тем же предметом, места меньше, чем лежит, — заберётся сколько влезет [src]
  `tryRemove` (`allowPartialRemoval = true`), ванильный `ScreenHandler` PICKUP-ветка «тот же предмет, класть нельзя».
- Двойной клик (PICKUP_ALL) собирает и из слотов машины, включая вход и выход [src] `canTakeItemForPickAll`.

### 4.2 Маршрут Shift-клика [src] `MekanismContainer.quickMoveStack`, `insertItem`

Ванильный цикл «повторять, пока в слоте тот же предмет и что-то сдвинулось» остаётся (ASP-08 §2.2).

**Из слота машины** (переносится не больше `предел стека` за проход):
1. доложить в непустые: броня панели (если есть) → хотбар 0 → 8 → рюкзак 9 → 35;
2. в пустые: броня панели → хотбар 0 → 8 → рюкзак 9 → 35.

**Из инвентаря игрока:**
1. в **непустые** слоты машины по порядку описания (§2), с проверкой слота;
2. если ничего не ушло — в **пустые** слоты машины по тому же порядку;
3. если машина ничего не взяла: из рюкзака — в пустую броню панели, потом хотбар (доложить, потом пустые); из хотбара —
   пустая броня, потом рюкзак; из брони панели — хотбар и рюкзак.

Виртуальный слот улучшений «существует» для Shift-клика **только пока подокно улучшений открыто и выбрано**; без него
улучшение в машину Shift-ом не уйдёт [src] `VirtualInventoryContainerSlot.exists`.

## 5. Стороны

### 5.1 Модель [src] `TileComponentConfig`, `ConfigInfo`, `DataType`, `TransmissionType`, `RelativeSide`, `IIncrementalEnum`

- На машину — набор **типов ресурса** в порядке объявления блока: камеры — предметы, энергия; инфузор и очиститель —
  предметы, вещества, энергия; сепаратор — жидкость, вещества, предметы, энергия; куб — энергия, предметы [src]
  `AttributeSideConfig`, `MekanismBlockTypes.*.withSideConfig`. Этот порядок — порядок вкладок подокна, первая открывается
  сразу.
- На тип — `ConfigInfo`: 6 режимов (по относительным граням), «можно выталкивать», «выталкивает», выключенные грани (у
  машин M нет), и **таблица «режим → что за ним»**: какие слоты / баки / энергия, можно ли туда класть и брать [src]
  `addSlotInfo`, `InventorySlotInfo(вход, выход, слоты)`.
- **Поддерживаемые режимы** = «ничего» + режимы с записью в таблице. Перебор по кругу в порядке перечисления
  (ничего → вход → вход 1 → вход 2 → выход → выход 1 → выход 2 → вход-выход → энергия → доп.), пропуская
  неподдерживаемые [src] `IIncrementalEnum.getNext/getPrevious`.
- «Выход» по смыслу выталкивателя — выход, выход 1, выход 2 и **вход-выход** [src] `DataType.canOutput`.

### 5.2 Относительная грань ↔ мир [src] `RelativeSide.getDirection`, `fromDirections`

Лево/право — **с точки зрения игрока, смотрящего машине в лицо** (машина «смотрит» на север → её левая грань — восток).

| Лицо смотрит | лицо | лево | право | зад | верх | низ |
|---|---|---|---|---|---|---|
| север (−Z) | N | E | W | S | U | D |
| юг (+Z) | S | W | E | N | U | D |
| запад (−X) | W | N | S | E | U | D |
| восток (+X) | E | S | N | W | U | D |
| вверх | U | E | W | D | S | N |
| вниз | D | E | W | U | N | S |

Куб энергии может смотреть вверх и вниз (`FACING`), камеры — только по горизонтали [src] `createEnergyCube`
(`AttributeStateFacing(FACING)`).

### 5.3 Типы и режимы по машинам [src] конструкторы `TileEntity*`, `setupItemIOConfig`, `setupItemIOExtraConfig`, `setupIOConfig`, `setupInputConfig`

| Машина | Предметы: режимы → слоты | Энергия | Вещества | Жидкость | Выталкивать можно |
|---|---|---|---|---|---|
| Камеры, плавильня, дробилка | вход → вход; выход → выход; вход-выход → оба; энергия → слот энергии | вход | — | — | предметы |
| Инфузор | + доп. → слот вещества | вход | вход / выход / вход-выход → бак инфузии | — | предметы (вещества — нет) |
| Очиститель | как инфузор | вход | вход → бак кислорода | — | предметы |
| Сепаратор | вход → слот жидкости; выход 1 → левый газ-слот; выход 2 → правый; вход-выход → все три; энергия | вход | выход 1 → водород, выход 2 → кислород | вход → вода | предметы, вещества |
| Куб | вход → заряд, выход → разряд, вход-выход → оба | вход / выход / вход-выход | — | — | энергия |

Режимы по кругу [расчёт по §5.1]: камеры, предметы: ничего → вход → выход → вход-выход → энергия → ничего; инфузор,
предметы: … → энергия → доп. → ничего; энергия машин: ничего ↔ вход; инфузор, вещества: ничего → вход → выход →
вход-выход; сепаратор, предметы: ничего → вход → выход 1 → выход 2 → вход-выход → энергия; сепаратор, вещества:
ничего → выход 1 → выход 2; куб, энергия: ничего → вход → выход → вход-выход.

### 5.4 Умолчания [src] `AttachedSideConfig`, `ItemBlockEnergyCube.SIDE_CONFIG`, `MekanismBlocks` (компоненты предмета)

Умолчания приходят **из предмета-блока** (компонент «настройка сторон»); поставленная машина берёт их при ставлении.

| Машина | Предметы | Энергия | Вещества | Жидкость | Выталкивание по умолчанию |
|---|---|---|---|---|---|
| Камеры, плавильня, дробилка | все — вход; **право — выход; зад — энергия** | все 6 — вход | — | — | выкл. |
| Инфузор | все — вход; право — выход; **низ — доп.**; зад — энергия | все — вход | все — вход; **право — выход** | — | выкл. |
| Очиститель | как инфузор | все — вход | все — вход | — | выкл. |
| Сепаратор | **лицо — вход; лево — выход 1; право — выход 2; зад — энергия**; верх, низ — ничего | все — вход | **лево — выход 1 (водород), право — выход 2 (кислород)** | все — вход | предметы выкл.; **вещества вкл.** |
| Куб | все — вход; лицо — выход | все — вход; **лицо — выход** | — | — | **энергия вкл.** |

### 5.5 Что значит грань для соседа [src] `ConfigHolder.getSlotInfo`, `canInsert`, `canExtract`, `TileComponentConfig.sideChanged`

- Сосед (кабель, труба, выталкиватель другой машины) спрашивает «что у тебя на этой грани для такого-то ресурса»:
  грань «ничего» — **ничего нет**, кабель к ней **не подключается**; «вход» — можно класть (в слоты этого режима, через
  их проверки); «выход» — можно брать; «вход-выход» — и то и другое; «энергия» / «доп.» — класть в слот энергии / доп.
- Правка режима грани сразу сбрасывает кэши возможностей на этой мировой грани, будит соседей и шлёт обновление блока.
  Для нас: **маска соединений кабеля зависит от настройки сторон машины** — после правки нужно пересчитать маску
  кабеля-соседа (E14/E16).
- Поворот машины меняет мировые грани всех режимов сразу (настройка хранится относительно лица).

## 6. Выталкивание [src] `TileComponentEjector`, `InventoryUtils.getEjectItemMap`, `TransitRequest`, `CableUtils.emit`, `EmitUtils`

### 6.1 Место в тике

Тик машины (MEK-01 §2.1): улучшения → задержка вида → **выталкиватель** → слот энергии → доп. слот → рецепт. Выход,
сделанный в тике t, уйдёт не раньше следующего срабатывания (≥ t + 1) [src] `TileEntityConfigurableMachine.onUpdateServer`.
Выталкиватель тикает **не зависимо от редстоуна** (у куба энергия — только если машина «может работать»).

### 6.2 Предметы — по шагам

1. Тип «предметы» есть, выталкивание включено (и разрешено). Иначе счётчик **стоит**.
2. Счётчик > 0 → уменьшить на 1, выход. Счётчик = 0 → шаги 3–6, потом **счётчик = 10**. Итого период **11 тиков**
   (0.55 с). У новой и загруженной машины счётчик 0 (не сохраняется) → первое выталкивание — в первом же тике [src].
3. Для каждого «выходного» режима в порядке выход → выход 1 → выход 2 → вход-выход, если в его слотах что-то есть:
4. Мировые грани с этим режимом в порядке **низ, верх, север, юг, запад, восток**; грань без инвентаря соседа —
   пропустить.
5. «Заявка» строится один раз на режим: слоты режима **в случайном порядке**, из каждого — сколько можно взять внешне
   (вход не берётся, выход — весь). Одинаковые предметы складываются.
6. На грань: по видам предметов из заявки — попробовать положить **всё количество** вида в слоты соседа по порядку
   0, 1, 2, … (каждый слот берёт сколько может, с проверками своей грани); первый вид, от которого хоть что-то ушло,
   заканчивает грань; ушедшее вынимается из слотов. Заявка пуста → к следующему режиму.

Итого за срабатывание: на каждую грань — **один вид предмета, сколько влезет** (до целой стопки 64). Ванильная воронка —
1 предмет в 8 тиков; здесь — стопка в 11 тиков.

### 6.3 Вещества, жидкости, энергия

- Каждый тик (без счётчика), если включено: для «выходных» режимов — непустые баки / буферы, грани с этим режимом;
  на бак — `emit`: до **1 024 мБ/т** веществ или жидкости, поровну между приёмниками на этих гранях (с переносом остатка)
  [src] `GeneralConfig.chemicalAutoEjectRate`, `fluidAutoEjectRate`, `ChemicalUtil.emit`, `EmitUtils.sendToAcceptors`.
- Сепаратор: бак в режиме «сброс» не выталкивается [src] `setCanTankEject`. Сброс — 8 мБ/т × множитель скорости;
  «сброс лишнего» — держать 85 % (2 040 из 2 400 мБ), сбрасывая излишек до 1 024 мБ/т [src] `handleTank`,
  `dumpExcessKeepRatio`.
- Куб: энергия — до **4 000 Дж/т** (выход яруса) поровну приёмникам на «выходных» гранях; приёмник — кабель (сеть, MEK-02)
  или машина с гранью «вход» энергии [src] `TileEntityEnergyCube` (выталкиватель с `tier.getOutput()`), `CableUtils.emit`.

### 6.4 Цели [вывод: `TransitRequest` + ванильный `SidedInventory` + `ConfigHolder`]

| Сосед | Через какую его грань | Что примет |
|---|---|---|
| Сундук | любую | любой предмет по слотам 0, 1, 2, …: каждый пустой или с тем же предметом берёт сколько может; неполная стопка **после** пустого слота не доливается первой |
| Печь (ванильная) | верх | вход (что угодно) |
| | бок | топливо (только топливо и пустое ведро) |
| | низ | топливо (выход принимать нельзя) |
| Машина Mekanism | грань «вход» | слот входа (только с рецептом), «доп.» — вещество, «энергия» — предмет-энергия |
| | грань «выход» / «ничего» | ничего |
| Транспортёр (L) | своей трубой | стопку с цветом выхода машины (MEK-14) |

Строгий вход и цвета входа (подокно транспортёров) работают только для предметов, приходящих **по транспортёру**: со
«строгим входом» машина берёт с грани только стопки её цвета входа [src] `TransporterUtils.canInsert`. Это L / MEK-14.

## 7. Конфигуратор [src] `ItemConfigurator`, `TileEntityMekanism.tryWrench`, `openGui`, `BlockTile.useItemOn`

### 7.1 Режимы

Хранятся в предмете, по умолчанию «предметы». По кругу: настройка предметов → жидкостей → веществ → энергии → тепла →
опустошить → поворот → ключ. Смена: **N** — следующий, **Shift+N** — предыдущий, **Shift+колесо** (с подсветкой
режима над хотбаром), круговое меню [src] `MekanismKeyHandler.handModeSwitchKey`, `PacketModeChange`,
`ClientTickHandler.onMouseEvent`. Сообщение «Режим: …» в строке над хотбаром. Предмет не складывается (1 в стопке).

### 7.2 Что делает клик [src] + [вывод: ванильный `interactBlock` — сначала блок, потом предмет; Shift пропускает блок, если предмет не просит иначе]

| Опустошить | открывает окно | **все слоты** высыпаются из нажатой грани; баки и энергия не трогаются | — |
| Поворот | **поворот на 90° по часовой** (вид сверху); куб — по кругу вверх → север → восток → вниз → юг → запад → вверх | лицо = грань, **противоположная нажатой** (машина отворачивается) | — |

- Не машина и без окна (настраиваемый блок): ПКМ в режиме настройки пишет «Сейчас <тип>: <режим> (<цвет>)» [src].

Сохраняются (и при ломании киркой): имя, выталкиватель, владелец и защита, редстоун, **стороны**, улучшения, **энергия**,

## 8. Граничные случаи и мелочи (что чувствует игрок)

1. Стрелка камеры никогда не доходит до конца: на тике завершения прогресс уже 0, видимый максимум — 22 из 23 px
   [расчёт]; целиком (и красной) она бывает только при «вход не даёт выхода».
2. В пустой машине 1–384 Дж энергии полоса не показывает (0 px из 52 при ёмкости 20 000); 10 мБ углерода в баке
   инфузора тоже не видно (0 из 52), 20 мБ — 1 px [расчёт]. Шкалы (куб, сепаратор, лава) показывают ≥ 1 px.
3. «Использует 50 J/t» во вкладке энергии держится, пока горит вид «активна», и пропадает вместе с ним.
4. Shift-клик редстоуна в инфузор с пустым баком тратит редстоун на **инфузию**, а не на энергию — частая ошибка новичка.
5. В обогатительную камеру Shift-клик редстоуна уходит во **вход** (обогащённый редстоун), а не в энергию.
6. Из выхода в хотбар вещи идут **слева направо**, а не как из печи.
7. Выход можно добрать в неполный курсор частично; в печи — нельзя.
8. Окно машины не закрывается, если отойти, пока кусок загружен.
9. Esc сначала закрывает подокно сторон, второй Esc — окно.
10. Подокно сторон не мешает класть предметы в слоты под ним.
11. Включил выталкивание при полном выходе — первая порция уходит в **том же тике** (счётчик был 0), дальше раз в 0.55 с.
    Выключил на середине — счётчик замер; включил — продолжит с того же значения.
12. Две «выходные» грани с соседями: всё уходит в ту, что раньше по мировому порядку (низ, верх, С, Ю, З, В), вторая
    получает только остаток.
13. Выталкивание в сундук кладёт в первый подходящий слот, а не в неполную стопку дальше — пыль может оказаться в двух
    стопках.
14. Камера выталкивает в печь **сбоку** — пыль не уходит (бок печи — топливо). Сверху — уходит во вход.
15. Машина-сосед с гранью «выход» к тебе ничего не принимает — «петли» выход-в-выход нет; линия «вход ← выход» работает.
16. С умолчаниями линия собирается без конфигуратора: ставлю камеры в ряд **слева направо, лицом к себе** — правая грань
    (выход) каждой касается левой (вход) следующей; нужно только включить выталкивание [вывод по §5.2, §5.4].
17. Сепаратор сразу (по умолчанию) толкает водород влево и кислород вправо в соседей с гранью «вход» вещества: очиститель
    справа получает кислород **без труб** — до 1 024 мБ/т.
18. Куб по умолчанию отдаёт энергию только с лица; поставил лицом к стене — ничего не отдаёт.
19. Поворот машины поворачивает и стороны; кабель, подключённый к «энергетической» задней грани, после поворота может
    оказаться у грани «ничего» и отключиться.
20. Конфигуратором ПКМ по машине — открылось окно (не сообщение): для действия нужен Shift.
21. «Поворот» с Shift ставит машину **задом** к игроку (лицо — от нажатой грани).
22. Ключ в творческом и выживании одинаков: предмет в инвентарь; сломанная киркой машина тоже хранит содержимое — разница
    только во времени и в том, куда падает предмет.
23. Режимы граней видны в мире только на одной грани под прицелом; цвет не зависит от того, есть ли там сосед.

## 10. Сценарии проверки человеком

### A. Окно инфузора (MEK-08)
Подготовка: инфузор на земле, рядом ничего; в инвентаре 16 угля, 8 железных слитков, 4 пыли редстоуна, 1 стальная пыль.

   красный вход, стрелка, синий выход, зелёный слот энергии и справа вертикальная полоса энергии; слева вкладки «стороны»
   (и «транспортёры» — когда будет логистика), снизу слева «энергия»; справа «улучшения».
2. Shift-клик 4 редстоуна. **Ожидаю:** они уходят в **жёлтый** слот (бак пуст), за 4 тика по одной пыли превращаются в
   вещество, жёлтый слот пустеет; подсказка шкалы «Редстоун: 40 мБ». ЛКМ по кнопке «сброс» под шкалой — шкала пустеет сразу.
3. Shift-клик 4 угля. **Ожидаю:** в жёлтый слот; шкала углерода растёт по 10 мБ за уголь, «Углерод: 40 мБ».
4. Shift-клик железа. **Ожидаю:** во вход. Стрелка не двигается (нет энергии), полоса энергии в красную полоску, вкладка
   «проблемы» слева с текстом «не хватает энергии».
5. Shift-клик 4 редстоуна ещё раз. **Ожидаю:** теперь в **зелёный** слот (в баке углерод); за 2 тика машина берёт 2 пыли,
   полоса энергии — доверху, подсказка «20 кДж / 20 кДж» (наш формат — §11.3), в слоте остаётся 2; стрелка ползёт ~10 с,
   полоса энергии тает.
6. Shift-клик стальной пыли из хотбара. **Ожидаю:** уходит в рюкзак, в машину — нет.
7. Когда в выходе лежат 5 обогащённого железа: держу в курсоре 62 таких же (заготовка отладочной выдачей) и щёлкаю ЛКМ
   по выходу. **Ожидаю:** в курсоре 64, в выходе остаётся 3 (у печи в такой же ситуации не взялось бы ничего).
8. Наведение на вкладку «энергия» во время работы. **Ожидаю:** «Использует: 50 Дж/т», «Нужно: …».

### B. Стороны и выталкивание (MEK-09)
Подготовка: обогатительная камера и плавильня с энергией (ветряк или куб), 16 сырого железа, сундук.
1. Ставлю камеру, справа от неё — плавильню, справа от плавильни — сундук; обе машины смотрят лицом на меня.
2. Открываю камеру → вкладка «стороны». **Ожидаю:** подокно поверх окна; лицо (центр развёртки), верх, низ и левая —
   красные (вход), правая — синяя, задняя (левый нижний квадрат) — зелёная; на правой кнопке нарисована плавильня, в её
   подсказке — «Право», «Выход», имя плавильни. Экран — «Выталкивание: выкл.».
3. Включаю выталкивание, кладу 16 сырого железа во вход. **Ожидаю:** каждые ~10 с в выходе камеры появляются 4 пыли и
   примерно через полсекунды **всей пачкой** перескакивают во вход плавильни (в плавильне видно, как растёт вход); выход
   камеры почти всегда пуст.
4. В плавильне включаю выталкивание. **Ожидаю:** слитки уходят в сундук, в первый слот.
5. ЛКМ по правой грани камеры в подокне: синий → фиолетовый (вход-выход) — пыль продолжает уходить; ещё ЛКМ → зелёный —
   пыль перестаёт уходить и копится в выходе; Shift+ЛКМ → серый. Кнопка «сброс» (грани разные) — все серые; ещё раз —
   все красные.
6. Беру конфигуратор (режим «настройка предметов»), смотрю на правую грань камеры. **Ожидаю:** грань подсвечена цветом
   режима. Shift+ПКМ — цвет меняется на следующий, сообщение над хотбаром. Простой ПКМ — открывается окно.
7. N до режима «ключ», Shift+ПКМ по камере с железом внутри. **Ожидаю:** камера исчезает, в инвентаре предмет камеры;
   ставлю обратно — железо, энергия, стороны и включённое выталкивание на месте, прогресс начат заново.
8. Режим «поворот», ПКМ по плавильне. **Ожидаю:** поворот на 90° по часовой, вместе с цветами граней; линия рвётся.

## 11. Что нужно от движка и предложение

Коды: E15 (машина v2: компонент сторон и выталкивателя), E17 / P0-7 (окна из виджетов), E14 (кабели: подключение по
граням, отдача куба), E16 (наложение граней), P0-4 / §4.1 (возможности по сторонам у всех блоков с инвентарём: печь,
сундук, машины), P1-10 (`aux`: режим конфигуратора; содержимое снятой машины), E7 (окна, ASP-08), E3 (тик), P0-3
(сохранение сторон).

### 11.1 Окно машины из виджетов (P0-7) [наше]

- **Описание окна — данные в `MachineDef`**: слоты (роль, координаты, рамка) и виджеты `[вид, x, y, w, h, источник]`.
  Один код JS рисует все окна; Rust не знает о пикселях текстур, но **считает пиксели заполнения** по формулам §1.2
  (как сейчас `furnace_view`: `flame_px`, `arrow_px`) — формулы тестируются в `cargo test`, JS их не повторяет.
- **Значения — снимок раз в тик**: `screen_values()` отдаёт плоский буфер `[px, флаги]` на виджет (флаги: предупреждение,
  видим, активен, цвет вещества), обновляемый в фазе после блок-сущностей; JS читает каждый кадр. Это же — будущий
  пакет мультиплеера («только изменившееся», §3) без переделки.
- **Подсказки — строки из Rust по запросу** (`screen_tip(виджет)`), с нашим форматом чисел (§11.3). Для телефона:
  касание виджета закрепляет подсказку (наведения нет; `loop.md` §3).
- **Действия — в Rust**: `screen_button(id, клик)` (клик: 0 ЛКМ, 1 ПКМ, 2 Shift+ЛКМ, 3 Shift+ПКМ) для «сброс бака»,
  режимов газа, граней, «сброс / сдвиг», выталкивания. Проверки (`can_eject`, поддерживаемые режимы) — в Rust.
- **Подокна — состояние JS**, но Rust знает, какое подокно сверху (`screen_window(вид)`), потому что от этого зависит
  Shift-клик в слот улучшений (§4.2). Перетаскивание, закрепление, запоминание места — JS (настройки UI).
- **Слоты машины** — новый вид слота `SlotKind::Machine(i)` с ролью из описания; `can_insert`, `limit`,
  `take_partial = true` для выхода; Shift-клик — общий `quick_move_machine` по §4.2 (а не ванильный «с конца»).
- **Вкладки** — виджеты с краю окна; вкладка «проблемы» видна, если маска ошибок не пуста; «энергия» — только подсказка.

### 11.2 Стороны в блок-сущности v2 (E15, P0-4) [наше]

- Компонент `Sides`: на тип ресурса — 6 режимов по относительным граням (4 бита), флаг «выталкивает», счётчик
  выталкивания предметов (не сохраняется, как в Mekanism). Описание типа (`SideDef`) — в `MachineDef`: поддерживаемые
  режимы, «можно выталкивать», умолчания, таблица «режим → слоты/бак, класть, брать».
- Единый вопрос мира «что у блока на мировой грани `d` для ресурса `r`» (`access(pos, d, r)`) — им пользуются кабели
  (маска соединений), выталкиватель, будущие трубы и транспортёры, воронок у нас нет. Для печи и сундука — фиксированные
  правила (§6.4).
- Правка режима — через одну дорогу записи мира (`Game::set_world`-подобный хук): пересчитать маску кабелей-соседей,
  поставить кусок на перестройку (если цвет граней когда-нибудь будет в меше), записать «грязно» для сохранения.
- Сохранение: 4 типа × 6 граней × 4 бита = 12 байт + 1 байт флагов; умолчания — из `MachineDef` при ставлении.
- Выталкивание — **внутри тика машины, до слота энергии** (как в Mekanism), с прямой записью в соседнюю блок-сущность.
  Предлагаю вынимать текущую машину из карты на время её тика (ARCHITECTURE-REVIEW §4.1, путь 1), тогда сосед
  изменяется сразу и порядок «кто раньше тикнул» совпадает с модом. Энергия куба — в фазе блок-сущностей приёмнику-
  машине, кабелю — в буфер сети (MEK-02).
- Порядок заявки — **фиксированный** (по описанию), без случайности (§9 п. 4) — детерминизм тестов.

### 11.3 Формат чисел [наше]

Русские единицы, запятая, обрезание до 2 знаков как в моде, **без хвостового «,0»**: 8 400 → «8,4 кДж», 20 000 → «20 кДж»,
50 → «50 Дж», 0 → «0 Дж», 1 234 567 → «1,23 МДж»; расход «50 Дж/т»; баки «Углерод: 40 мБ» и, по решению, «из 1 000»
(§16). Эталоны Mekanism-формата — §14 (чтобы видеть отличие).

### 11.4 Конфигуратор [наше]

- Режим — в `ItemStack.aux` (3 бита); режимы, которых нет в мире (тепло; жидкости до L), пропускаются при переборе.
- Ввод: N / Shift+N; Shift+колесо при конфигураторе в руке перехватывает прокрутку хотбара (как мод; сверить с
  ASP-08 §5, где колесо листает хотбар); на телефоне — кнопка режима рядом с хотбаром.
- ПКМ / Shift+ПКМ — в `interact_block` (ASP-05 §11.2) по таблице §7.2, с тем же порядком «блок → предмет».
- Наложение граней (E16): Rust отдаёт `config_overlay() -> [x, y, z, грань, rgb]` для грани под прицелом (как мод) или
  для всех 6 граней (наше «сверх», решение §16); JS рисует прозрачный квад полной яркости поверх грани в проходе рамки.
- Ключ: дроп блока с содержимым — тот же путь, что ломание киркой (GEN-02), но сразу в инвентарь. Нужна большая
  «полезная нагрузка» стека (P1-10, решение §16).

// sides.rs — компонент сторон и выталкиватель машины v2 (E15). Направления — номера Minecraft: 0 D, 1 U, 2 N, 3 S, 4 W, 5 E.

#[derive(Clone, Copy, PartialEq, Eq, Debug)] #[repr(u8)]
pub enum Res { Energy = 0, Fluid = 1, Chem = 2, Item = 3 }

#[derive(Clone, Copy, PartialEq, Eq, Debug, Default)] #[repr(u8)]
pub enum Mode { #[default] None = 0, In, In1, In2, Out, Out1, Out2, InOut, Energy, Extra }
const MODES: [Mode; 10] = [Mode::None, Mode::In, Mode::In1, Mode::In2, Mode::Out, Mode::Out1, Mode::Out2,
                           Mode::InOut, Mode::Energy, Mode::Extra];
impl Mode {
    pub fn can_output(self) -> bool { matches!(self, Mode::Out | Mode::Out1 | Mode::Out2 | Mode::InOut) }
}

#[derive(Clone, Copy, PartialEq, Eq, Debug)] #[repr(u8)]
pub enum Rel { Front = 0, Left, Right, Back, Top, Bottom }

fn cw(d: u8) -> u8 { match d { 2 => 5, 5 => 3, 3 => 4, 4 => 2, x => x } }   // по часовой (вид сверху)
fn ccw(d: u8) -> u8 { match d { 2 => 4, 4 => 3, 3 => 5, 5 => 2, x => x } }
fn opp(d: u8) -> u8 { d ^ 1 }

/// Мировое направление относительной грани при лице `f` (таблица §5.2).
pub fn dir_of(f: u8, r: Rel) -> u8 {
    let vertical = f <= 1;
    match r {
        Rel::Front => f,
        Rel::Back => opp(f),
        Rel::Left => if vertical { 5 } else { cw(f) },
        Rel::Right => if vertical { 4 } else { ccw(f) },
        Rel::Top => match f { 0 => 2, 1 => 3, _ => 1 },
        Rel::Bottom => match f { 0 => 3, 1 => 2, _ => 0 },
    }
}
pub fn rel_of(f: u8, d: u8) -> Rel {
    [Rel::Front, Rel::Left, Rel::Right, Rel::Back, Rel::Top, Rel::Bottom]
        .into_iter().find(|&r| dir_of(f, r) == d).unwrap()
}

/// Что стоит за режимом (строка таблицы ConfigInfo): слоты/бак машины и разрешения для соседей.
pub struct ModeDef { pub mode: Mode, pub slots: &'static [u8], pub tank: Option<u8>, pub put: bool, pub take: bool }

/// Описание типа ресурса у машины (часть MachineDef).
pub struct SideDef {
    pub res: Res,
    pub modes: &'static [ModeDef],     // поддерживаемые (кроме None)
    pub can_eject: bool,
    pub defaults: [Mode; 6],           // по Rel
    pub eject_default: bool,
}
impl SideDef {
    fn supports(&self, m: Mode) -> bool { m == Mode::None || self.modes.iter().any(|d| d.mode == m) }
    fn row(&self, m: Mode) -> Option<&ModeDef> { self.modes.iter().find(|d| d.mode == m) }
    /// Следующий/предыдущий поддерживаемый по кругу (IIncrementalEnum).
    fn step(&self, m: Mode, dir: i32) -> Mode {
        let mut i = m as i32;
        loop {
            i = (i + dir).rem_euclid(10);
            if MODES[i as usize] == m || self.supports(MODES[i as usize]) { return MODES[i as usize]; }
        }
    }
}

#[derive(Clone, Default)]
pub struct Sides {
    pub mode: [[Mode; 6]; 4],          // [Res][Rel]
    pub eject: u8,                     // бит на Res
    pub item_delay: u8,                // не сохраняется
}

pub enum SideClick { Next, Prev, Clear }

impl Sides {
    pub fn new(defs: &[SideDef]) -> Self {
        let mut s = Sides::default();
        for d in defs { s.mode[d.res as usize] = d.defaults; if d.eject_default { s.eject |= 1 << d.res as u8; } }
        s
    }
    /// Клик по грани в подокне (PacketSideData). true — изменилось (пересчитать соседей, сохранить).
    pub fn click(&mut self, d: &SideDef, r: Rel, c: SideClick) -> bool {
        let cur = self.mode[d.res as usize][r as usize];
        let new = match c { SideClick::Next => d.step(cur, 1), SideClick::Prev => d.step(cur, -1), SideClick::Clear => Mode::None };
        self.mode[d.res as usize][r as usize] = new;
        new != cur
    }
    /// Кнопка «сброс / сдвиг» (PacketBatchConfiguration). shift — все типы в None.
    pub fn batch(&mut self, defs: &[SideDef], res: Res, dir: i32, shift: bool) -> bool {
        let mut changed = false;
        for d in defs.iter().filter(|d| shift || d.res == res) {
            let row = &mut self.mode[d.res as usize];
            let target = if shift { Mode::None }
                         else if row.iter().all(|&m| m == row[0]) { d.step(row[0], dir) } else { Mode::None };
            for m in row.iter_mut() { if *m != target { *m = target; changed = true; } }
        }
        changed
    }
    pub fn toggle_eject(&mut self, d: &SideDef) -> bool {
        if !d.can_eject { return false; }            // мод этого не проверяет на сервере
        self.eject ^= 1 << d.res as u8; true
    }
    /// Доступ соседа с мировой грани `dir` (ConfigHolder): None — ничего (кабель не подключается).
    pub fn access<'a>(&self, defs: &'a [SideDef], facing: u8, res: Res, dir: u8) -> Option<&'a ModeDef> {
        let d = defs.iter().find(|d| d.res == res)?;
        d.row(self.mode[res as usize][rel_of(facing, dir) as usize])
    }
}

/// Что выталкивателю нужно от мира: вставить стек в соседа через его грань (печь, сундук, машина — §6.4).
pub trait Neighbors {
    /// Сколько штук стека `s` влезет и будет положено в блок `pos` через его грань `face` (слоты по порядку 0..).
    fn insert_items(&mut self, pos: [i32; 3], face: u8, s: ItemStack) -> i32;
    fn has_items(&self, pos: [i32; 3], face: u8) -> bool;
}

const EJECT_ORDER: [u8; 6] = [0, 1, 2, 3, 4, 5];   // D, U, N, S, W, E — мировой порядок, как EnumSet<Direction>

/// Предметы: вызывается в начале тика машины (до слота энергии и рецепта).
pub fn eject_items(m: &mut Machine, def: &MachineDef, pos: [i32; 3], w: &mut dyn Neighbors) {
    let Some(sd) = def.sides.iter().find(|d| d.res == Res::Item) else { return };
    if m.sides.eject & (1 << Res::Item as u8) == 0 || !sd.can_eject { return; }      // счётчик стоит
    if m.sides.item_delay > 0 { m.sides.item_delay -= 1; return; }
    for row in sd.modes.iter().filter(|r| r.mode.can_output()) {
        // заявка: только слоты, из которых можно брать снаружи (вход — нет), порядок фиксированный [наше]
        let slots: Vec<u8> = row.slots.iter().copied().filter(|&i| def.slot_role(i).external_take()).collect();
        if slots.iter().all(|&i| m.slots[i as usize].is_empty()) { continue; }
        for &dir in &EJECT_ORDER {
            if m.sides.mode[Res::Item as usize][rel_of(m.facing, dir) as usize] != row.mode { continue; }
            let to = step(pos, dir);
            if !w.has_items(to, opp(dir)) { continue; }
            // один вид предмета на грань: первый, от которого что-то ушло
            for &i in &slots {
                let s = m.slots[i as usize];
                if s.is_empty() { continue; }
                let total = slots.iter().map(|&j| m.slots[j as usize]).filter(|t| t.same_kind(&s)).map(|t| t.n()).sum();
                let moved = w.insert_items(to, opp(dir), s.with_count(total));
                if moved > 0 { take_from(m, &slots, s, moved); break; }
            }
            if slots.iter().all(|&i| m.slots[i as usize].is_empty()) { break; }
        }
    }
    m.sides.item_delay = 10;   // период 11 тиков
}

    fn quick_move_machine(&mut self, u: &mut Ui, id: usize, n_machine: usize) -> ItemStack {

        if orig.is_empty() { return ItemStack::EMPTY; }
        let mut s = orig.with_count(orig.n().min(orig.max()));
        let (hot, main, armor) = self.player_ranges();             // хотбар 0→8, рюкзак 9→35, броня панели (или пусто)

            let before = s.n();
            self.insert_pass(u, &mut s, machine.clone(), true);
            if s.n() == before { self.insert_pass(u, &mut s, machine, false); }
            if s.n() == before {
                if hot.contains(&id) { self.insert_pass(u, &mut s, armor, false); self.insert_both(u, &mut s, main); }
                else if main.contains(&id) { self.insert_pass(u, &mut s, armor, false); self.insert_both(u, &mut s, hot); }
                else { for r in [hot.clone(), main.clone()] { self.insert_both(u, &mut s, r); } }
            }
        }
        self.finish_quick_move(u, id, orig, s)
    }
}

// web/game/machine_screen.js — универсальное окно машины поверх screen.js (слоты и мышь — как сейчас).

// vals = game.screen_values(): на виджет [px, флаги, цвет]; меняется раз в тик, читаем каждый кадр.
const W = { POWER: 1, TANK: 2, GAUGE: 3, PROGRESS: 4, BUTTON: 5, SCREEN: 6, TAB: 7, STATE: 8, DECOR: 9, ARMOR: 10 };
const WARN = 1, VISIBLE = 2, ACTIVE = 4;

export function drawWidgets(ctx, theme, layout, vals) {
  for (let i = 0; i < layout.widgets.length; i++) {
    const w = layout.widgets[i], px = vals[i * 3], fl = vals[i * 3 + 1], col = vals[i * 3 + 2];
    if (!(fl & VISIBLE)) continue;
    switch (w.kind) {
      case W.POWER: case W.TANK: case W.GAUGE:              // заполнение снизу вверх ровно px пикселей (из Rust)
        theme.frame(ctx, w); if (fl & WARN) theme.warnStripes(ctx, w);
        theme.fillUp(ctx, w, px, w.kind === W.POWER ? theme.energy : theme.chem(col)); break;
      case W.PROGRESS: theme.arrow(ctx, w, px, fl & WARN); break;
      case W.BUTTON: theme.button(ctx, w, fl & ACTIVE); break;
      case W.SCREEN: theme.lines(ctx, w, game.screen_lines(w.id)); break;   // строки из Rust
      case W.TAB: theme.tab(ctx, w, fl & ACTIVE); break;
      default: theme.decor(ctx, w);
    }
  }
}

// Клики по виджетам — до слотов (как GuiMekanism: подокна → элементы → слоты).
export function clickWidget(ev, layout, x, y) {
  const w = hit(layout.widgets, x, y); if (!w) return false;
  const click = (ev.button === 2 ? 1 : 0) | (ev.shiftKey ? 2 : 0);    // 0 ЛКМ, 1 ПКМ, 2 Shift+ЛКМ, 3 Shift+ПКМ
  if (w.kind === W.TAB && w.arg) openSubwindow(w.arg);                 // стороны / улучшения: состояние JS
  else game.screen_button(w.id, click);                                // всё остальное решает Rust
  return true;
}

// Подокно сторон: game.side_view(res) → [можно_выталк., выталкивает, 6 × (режим, блок_соседа)].
// Развёртка: верх (67,46), лево (44,69), лицо (67,69), право (90,69), зад (44,92), низ (67,92) — порядок Rel.
function drawSides(ctx, theme, res) {
  const v = game.side_view(res);
  for (let r = 0; r < 6; r++) {
    const mode = v[2 + r * 2], neighbor = v[3 + r * 2];
    theme.sideButton(ctx, NET[r], MODE_COLOR[mode]);       // цвет режима (§1.5) — палитра в теме
    if (neighbor) theme.icon(ctx, neighbor, NET[r].x + 3, NET[r].y + 3);
  }
}
// Esc при открытом незакреплённом подокне закрывает его, а не окно; E — всё окно (как Mekanism).
