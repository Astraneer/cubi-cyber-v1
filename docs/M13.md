# M13 — маршрут, запись и переносимые сборки

Общий маршрут `client::benchmark` повторяет 1800 кадров ввода с шагом 1/60 с:
ходьба, бег, прыжки, повороты, движение боком, полёт вверх/вниз и остановка.
Он использует настоящие `ClientView`, физику, пул задач и GPU-рендер леса.
Это диагностическая сцена генератора; сетевой игровой сценарий принимается отдельно.

## Запуск и отчёт

Из корня репозитория:

```bash
source tools/env.sh
cargo run --locked --release -p client-native -- --benchmark .local/artifacts/bench/run.json
# Проверка без окна:
bash tools/bench run --out .local/artifacts/bench/offscreen.json
bash tools/bench report .local/artifacts/bench/run.json --out .local/artifacts/bench/report.html
bash tools/bench compare .local/artifacts/bench/a.json .local/artifacts/bench/b.json --out .local/artifacts/bench/compare.html
```

Оконный запуск включает настоящие `surface.present` и завершения GPU; физическое сканирование дисплея не измеряется. F8 сохраняет последние 10 секунд в локальный JSON. `tools/bench run` собирает offscreen release. У этого отдельного offscreen-производителя размер по умолчанию 1280×720; его `--width`/`--height`
меняют размер явно, `--frames 18` запускает короткий дымовой прогон. Оконный
`client-native` принимает `--benchmark ПУТЬ` и, для короткой диагностики,
`--benchmark-frames 18`; аргументы `--frames`/`--width`/`--height` ему не передаются.
`--software` выбирает программный адаптер; для замера RTX его не добавляют.
Полный маршрут — 1800 кадров; неполный отмечается
в метаданных. Для сравнения должны совпадать адаптер/backend, seed, исходный хеш,
размер, маршрут, число кадров и режим измерения.

В записи находятся фактические CPU-интервалы, GPU timestamp queries по проходам,
счётчики работы, аллокации основного Rust-потока, ввод и сопутствующие события.
Неизвестное время остаётся `null`. Проход `terrain` пока объединяет небо и геометрию;
неподключённые тени/вода/GI не получают выдуманного времени. Аллокации рабочих
потоков и возраст очереди в этом производителе не измерены, что указано в JSON.

Текущий производитель выводит в offscreen-текстуру и ожидает GPU между кадрами:
`presentationIncluded=false`, `blockingReadback=true`. Он проверяет запуск маршрута
и корректность отчёта; это не измерение задержки окна или доказательство бюджета RTX.
Оконный маршрут и F3/F8 используют тот же ввод и самописец. Детерминированный повтор движения уже проверен на самодостаточном файле настоящего маршрута; подключение этого payload к ручному F8 проверяется отдельно. Это повтор движения и внешних контрольных состояний, а не GPU, интерфейса или приватной симуляции сервера.

Заказчику для анализа нужны JSON, HTML, модель GPU, версия драйвера, режим питания
и сведения об изменениях настроек. Локальные записи не отправляются автоматически.

## Из распакованного Windows ZIP

Откройте PowerShell в каталоге полностью распакованного архива. Rust и checkout
не нужны; для HTML используется Python 3 и включённый в ZIP `bench_report.py`.
Оконный маршрут запускается отдельно от сервера и сам завершает 1800 кадров:

```powershell
.\client-native.exe --benchmark measurements/route-a.json
python bench_report.py report measurements/route-a.json --out measurements/route-a.html
```

Не добавляйте `--connect` или `--smoke-frames`: CLI отвергает такое совмещение.
Не меняйте размер окна во время маршрута. Для второго прогона сохраните те же
backend/GPU, разрешение и сравнимые настройки; запишите намеренное изменение:

```powershell
.\client-native.exe --benchmark measurements/route-b.json
python bench_report.py report measurements/route-b.json --out measurements/route-b.html
python bench_report.py compare measurements/route-a.json measurements/route-b.json --out measurements/compare.html
```

Сравнение проверяет маршрут, seed/исходный хеш, размер, число кадров, адаптер и
область GPU-измерения. Отказ несовместимого сравнения не обходят переименованием
метаданных. `benchmark.exe --out ...` — отдельный offscreen-производитель с
ожиданием GPU; он не заменяет оконный прогон и не сравнивается с ним.

Для игрового случая запустите сервер и клиент по включённой в ZIP `ЗАПУСК.txt`,
дождитесь загрузки и накопления не менее 10 секунд записи, затем нажмите F8.
Выберите `.local/artifacts/flight/native-*.json` и скопируйте его как `F8.json`:

```powershell
python bench_report.py report F8.json --out measurements/f8.html
.\movement-replay.exe F8.json
```

Прислать нужно `route-a.json`/`.html`, при A/B — `route-b.json`/`.html` и
`compare.html`, при игровом рывке — `F8.json` и `f8.html`, а также `BUILD.json`
из соответствующего архива. Укажите backend из JSON, модель GPU, версию драйвера,
режим питания, разрешение окна, рендер-масштаб, MSAA, дальность, эффекты и момент
сбоя. Если используются две сборки, приложите оба `BUILD.json` с понятными именами.
Не нужны `saves/`, identity, `.local/client/`, `.minecraft`, сами ресурс-паки и
пути к личным ресурсам. Ничего из этого не отправляется автоматически.

Команды и описание включаются в каждый native ZIP. Свежий архив, его распаковка
и запуск — отдельная проверка поставки; наличие этой инструкции не означает,
что текущая сборка или аппаратный бюджет уже приняты. Создание ZIP не требует PR
или изменения VPS/DNS; HTTP 403 при публикации PR упаковку не блокирует.

## Фактическая проверка в облаке

Полный debug-прогон llvmpipe/Vulkan 320×224 завершил 1800 кадров ввода и
1602 GPU-отрисовки, сохранил все кадры/ввод без потерь. Сканировано 664848 клеток,
создано 44941 квадов, загружено 1055824 байта; в кадрах нет компиляции пайплайнов
и синхронной генерации. Внешняя длительность — 49,74 с; аппаратный бюджет этим
не подтверждается. Артефакты: `.local/artifacts/bench/route-1800.json` и `.html`.

Оконный прогон также завершил 1800 настоящих показов, 1800 записей ввода и
1800 GPU-замеров: максимум 1 кадр в работе, потерь нет. Работа: 664848 клеток,
44941 квадов, 1080800 байт загрузок, без компиляций/синхронной генерации в кадре.
Программный Vulkan занял 120,3 с; файл `.local/artifacts/native-benchmark-1800.json`.
Реальная клавиша F8 выгрузила полное 10-секундное окно на 602 кадра: неподвижная
ветка — 0 аллокаций/realloc и 0 загрузок; положительный контроль обнаружил 1240
аллокаций. Это проверка статичной ветки, а не обещание нулевой стоимости движения.

GPU-сборщик использует два постоянных readback-буфера по 1040 байт. Рабочий цикл
не ждёт map: результат дополняет исходный кадр после callback. Реальный GPU-тест
проверяет объединение до 64 запросов из разных проходов, backpressure, отмену, поколение билета, поздний результат вытесненного
кадра и сохранение неизвестных проходов. Самописец F8 хранит последние 10 секунд;
режим маршрута сохраняет весь ограниченный прогон, включая длительность >10 с.

## Упаковка

```bash
source tools/env.sh
cargo build --locked --release -p client-native -p server
cargo build --locked --release -p client --example benchmark
cargo build --locked --release -p sim --example replay
bash tools/package native --directory target/release --platform linux --out .local/artifacts/dist/cubi-linux.zip
bash tools/build_web.sh --release
bash tools/package web --directory .local/web-dist --out .local/artifacts/dist/cubi-web.zip
```

Для Windows упаковщик принимает `--platform windows` и каталог фактической
Windows-сборки. Он проверяет сигнатуры ELF/PE/WASM, выбирает только перечисленные
программы/страницы/worker-файлы и добавляет уведомления ассетов/зависимостей.
Если registry-пакет не содержит отдельного LICENSE, сохраняется весь исходный
архив этого закреплённого пакета вместе с метаданными. Ничьи права не заменяются.
В `BUILD.json` находятся Git SHA, признак незакоммиченного дерева и SHA256 файлов;
рядом с ZIP — его контрольная сумма. Сохранения, identity, кеши и выбранные
пользователем ресурсы не включаются. Развёртывание на VPS не выполняется.

Единая команда сборки всех файлов поставки: `bash tools/build_release.sh linux --web`
(Windows: `bash tools/build_release.sh windows`). CI сохраняет ZIP и SHA256 как артефакты
после обязательных проверок. В native ZIP входит самостоятельный `movement-replay`.
Он повторяет только публичное движение и явно записанные внешние контрольные состояния.

## Самодостаточный повтор движения

```bash
source tools/env.sh
cargo run --locked -p sim --example replay -- .local/artifacts/bench/replay-route-180.json
```

CUBR1 записывает фактически прочитанные публичные клетки и потоки жидкости,
клавиши и точные состояния до/после каждого тика. Изменения камеры, прав или
авторитетного состояния отмечаются явно. Повтор использует текущую физику;
первое расхождение состояния/исхода или незаписанное чтение завершает его с ошибкой.
Данные рендерера, identity, ключи и локально выбранные ресурсы сюда не входят.

Проверены 10 000 записей без аллокаций, усечения/повреждения, пропущенные клетки,
переполнение и истечение по реальным 10 секундам. Native и настоящий WASM создали
одинаковый архив 64 тиков; WASM независимо воспроизвёл native-архив с итогом
`3a438526021a44ec`. Реальный GPU-маршрут 180 кадров дал 60 шагов / 37 699 байт
архива; независимый запуск получил `72ab1ce91e608376` без потерь. Его длительность
меньше 10 секунд, поэтому `completeWindow=false` указан явно.

Новые native/web/offscreen производители ставят внешнюю пару timestamp вокруг
всех команд сцены и UI в encoder. Если `gpuTotalComplete=true`, `gpuNs` — этот
полный интервал: он включает предварительное отсечение моделей, восстановление
теней и промежутки между проходами. Дочерние таймеры остаются диагностикой и
повторно не суммируются. Записи в очередь до начала encoder, чтение самописца
после конца интервала и физическое сканирование дисплея не включены.

При отсутствии внешней пары `gpuTotalComplete=false`: `gpuNs` сохраняет старую
сумму измеренных областей. Неизвестное время остаётся `null`. HTML разделяет оба
вида измерений, а `compare` отклоняет сравнение разных или смешанных областей.
Короткий offscreen-маршрут320×224 дал18 показов в текстуру и18 полных
GPU-интервалов, создал JSON+HTML без компиляций/синхронной генерации в кадре;
полный1800-кадровый повтор готовится отдельно. Полный интервал также проверен
реальным GPU-тестом с дополнительными вычислениями вне именованных проходов; отменённый encoder и пропущенное начало не создают ложного
полного измерения. Это измерение команд приложения, а не всей занятости устройства.

Кольцо движения увеличено до 2048 шагов: оно хранит не только 200 прямых тиков
за 10 секунд, но и настоящие повторные вызовы физики при сетевой коррекции.
Регрессия с шестью пересчётами на каждый 20 Гц тик сохранила последние
1206 шагов полного окна без потерь, аллокаций и расхождений при независимом
повторе. Исчерпание любого конечного лимита по-прежнему отмечается явно.

Фоновые native CPU-продолжения накапливают время, работу и аллокации в следующий
настоящий показ. Они не увеличивают число кадров и не сбрасывают интервал между
показами:50 опросов CPU во время одного1-секундного GPU-кадра остаются одним
кадром1000ms. Регрессия сохраняет52msCPU,400клеток и все50 аллокаций; неизвестные
значения остаются неизвестными. Браузер использует аналогичное накопление и
`last_present_ms`.
