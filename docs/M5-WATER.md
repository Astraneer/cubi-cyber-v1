# M5 — публичная вода точной дальней колонки

Серверный путь связан с настоящими World, WAL, PublicGeometry и HeightColumn. Холодная каноническая проекция теперь описана в [M5-COLD.md](M5-COLD.md); она передаёт ту же классификацию без создания дальних игровых страниц. Отдельный поток передаёт форму воды, которой нет в палитре прежней PublicGeometry. Полную приёмку M5 это пока не закрывает: клиентский worker, атомарная замена непрозрачной геометрии вместе с водой и полёт через переходы проверяются отдельно.

`net::water::WaterHalo` содержит 5832 классифицированные клетки halo18³ и 256 публичных RGB565 tint. Допустимы только Unknown, Air, Solid и Water с amount1..8/falling; кодов ID блоков, руд, компонентов, инвентаря, LIGHT и приватных источников в DTO нет. FWT1 занимает 6396 Б. Заголовок связывает снимок с реально опубликованными source/view центральной PublicGeometry и source точной колонки; независимый water_view меняется при изменении соседнего halo даже при прежних центральной геометрии и колонке. Запрос/снимок проходят внутренний и внешний bounded codec.

Исторический standalone capture helper захватывает 27 immutable Arc<Page> и sampled input для плоскостей, рёбер и углов. Отдельно запоминается доступность: Unknown не может стать Air при совпадении номера версии. Захват читает версии/ссылки, но не клетки и не генерирует мир; классификация 5832 клеток и 256 публичных tint выполняется в NativePool. Перед публикацией owner повторно проверяет все sampled SHAPE/OPACITY/FLUID версии, доступность и текущие публичные привязки. Только LIGHT и несэмплируемая внутренняя правка соседней страницы не требуют нового снимка. У FLUID соседа пока консервативная полностраничная версия; это может дать лишнюю работу, но не пропущенную правку.

Публикация разрешена после durable frontier; событие dirty поступает из подтверждённого пакета WAL. Индекс source-page→подписанные halo будит только зависимые потоки. Один неподтверждённый снимок на поток ограничивает кредит; дальнейшие правки объединяются в один dirty-флаг. ACK означает приём в ограниченный клиентский кэш, включая Unknown-снимки, а не готовность GPU. Известная старая геометрия/вода должна сохраняться клиентом до готовности новой пары. Явный full-repair пересобирает текущий снимок в worker; историю полных 6,4 КБ изображений сервер не хранит. Повтор снимка с тем же сертификатом сохраняет water_view, а переподписка после Forget получает новый epoch. Старый completion не может занять новый поток с тем же ключом.

Исторические лимиты standalone capture owner: два worker, восемь удерживаемых jobs, максимум две отправки работы и две публикации за 20 Гц тик, четыре пробы очереди и 54 попытки коалесцируемого запроса канонической генерации. Peer обслуживаются по кругу. Подписок на peer не больше текущего MAX_PUBLIC_GEOMETRY_PAGES, peer не больше 64. ForgetWater, ForgetGeometry, ForgetHeight и disconnect очищают индекс; удалённый/забаненный peer также снимается без прохода всех потоков. После этого worker завершается/отменяется в ограниченной очереди.

Для generation=true канонических space0/Y0..7 отдельный cold worker использует настоящий приватный ServerGenerator, сохранённые правки и текущие resident snapshots. Одна ограниченная работа даёт восемь публичных geometry и восемь classified halos с сертификатом источников. Эти данные не создают World pages и не запускают LIGHT или gameplay ticks. Generation=false теперь использует тот же сертифицированный owner с allow_cold=false для существующих страниц; старый ore-only Geometry fallback удалён, другие spaces/Y получают GeometryUnavailable; main tick нигде не генерирует 27 страниц синхронно. Неизвестные недоступные источники за пределами профиля сохраняются. Клиент признаёт поверхность полной только по известности нужных samples, включая сертификат пустой воды.


Проверки:

- Три теста capture: все состояния уровня/падения, углы 27-page halo и tint, нулевые аллокации захвата, LIGHT/внутренняя правка/угол/Unknown→Known, отсутствие центральной страницы и отмена. Полный halo читает 5832 клетки, частичный центральный —4096.
- Три теста owner: настоящие native completions со stale/ABA rejection, кредит и 1000 объединённых правок, равномерность четырёх peer, квоты и строгие лимиты тика. 10 тыс. припаркованных подписок удерживают 31103694 Б метаданных и 270 тыс. watcher-связей;10 тыс. пустых фаз не выделяют/не освобождают память и не читают клетки. Это измерение parked metadata, не память полностью обслуженных front-сертификатов и не весь World/RSS.
- Три теста настоящего Server: legacy eight-page Column с фактически отправленными PublicGeometry stamps→WaterHalo; запрет RawPage и canary/private entropy в каждом encoded сообщении; forged binding; LIGHT создаёт 0 water jobs; до ACK нет второго изображения; правка западного halo меняет water_view при прежних centre geometry и column_source; Forget очищает 27 watcher-связей. Mixed resident/cold тест сохраняет 8 World pages. Полностью холодная колонка получает все 8 Geometry и 8 WaterHalo, совпадающие с независимым exterior union-find эталоном канонического мира; World pages/version и canonical generation/LIGHT work остаются нулевыми. Прежний прототип требовал 16 generator jobs/72 World pages; это историческое измерение, не текущая архитектура.


Команды: `cargo test --locked -p server --lib far_water`, `cargo test --locked -p server --test far_water`, `cargo test --locked -p server --test far_water_stream`; также net water codec и all-target Clippy с `-D warnings`. Серверные девять тестов прошли; программные/аппаратные GPU-кадры этим отчётом не заявляются.

Холодная проекция предотвращает новые far-only World births; её тела ограничены LRU 128 колонок/32 МиБ, метаданные — явными lease-квотами. Она не выселяет ранее принятые игровые World pages. Бюджет дальнего отбора, полная память клиента, атомарная GPU-пара и действительный полёт всё ещё учитываются в общей приёмке M5.


Клиентский worker и staging owner также проверены отдельно от общей сцены. `FarWaterTask::new` читает только заголовок и удерживает Arc без аллокации; расшифровка 5832 классификаций, RGB565 и существующий `mesh_water` выполняются в worker. Дополнительная проверка Unknown у центральных клеток и 3³ зависимостей воды не позволяет выдать пустой сертификат для неизвестного центра или пропустить неизвестную нижнюю грань. FWJ1 —6404 Б; FWR1 — максимум 393344 Б, без исходного halo. Независимые golden уровней 8/9 и 1/9 дают упакованные 227/28; checkerboard даёт 12288 квадов/196736 Б. Пять worker-тестов проверяют codec bounds, work counters/descriptors, отмену, настоящий NativePool completion и source binding.

`FarWaterSource` сохраняет внешний Context с уникальным checked epoch каждого dispatch; lease не переиспользуется после Forget и даже пересоздания owner. До запуска каждой из четырёх работ резервируется худшая удерживаемая память результата внутри 2 МиБ квоты. Неизвестный результат паркуется до нового water_view; ready-очередь коалесцируется по странице. По умолчанию 512 желаемых страниц и 65536 квадов будущего front; эта квота не увеличивается от расширения общего WaterGpu для нескольких владельцев. Три CPU-теста включают stale/ABA, worst-result reservations,1000 смен water_view с одной ready-записью,10 тыс. неизменных фаз без аллокаций и ограниченные ошибки.

Два настоящих Vulkan/lavapipe GPU-теста завершают кадры с readback. Новая геометрия загружается в неактивный объект: до публикации старое изображение побитно неизменно, включая промежуточный бюджет 80 Б только на object. Повтор после нехватки диапазона/байтов удерживает тот же handle; счётчик object uploads не растёт. Batch двух флагов требует 8 Б: при 4 Б нет записей и старое изображение сохраняется; при 8 Б новая вода появляется целиком. Бюджет 159 Б для rebase двух 80 Б объектов даёт 0 записей;160 Б переносит front и staging вместе, возврат воспроизводит исходный кадр. Все модели и поколения проверяются до первой записи, None удерживает весь batch. Независимый near guard скрывает старую дальнюю воду даже при Unknown в замене; при 0 бюджете guard_ready=false требует клиентского fallback. Rebase скрытого front его не включает. Teardown освобождает object/range, кадр совпадает с пустым baseline.

1000 статических GPU-owner publication/guard фаз дают 0 аллокаций,0 освобождений и 0upload bytes. Проверка отдельной логической квоты 256 блокирует вторую 256-квадовую страницу до каких-либо записей, даже при доступном общем GPU. Проверки запускаются с `VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p client --test far_water_source_gpu -- --test-threads=1`, CPU — `--test far_water_worker --test far_water_source`. Targeted Clippy с `-D warnings` и `cargo check --locked -p client --target wasm32-unknown-unknown` проходят. Это доказательства worker/staging/flags, а не готовности целого Horizon/Height/opaque/water маршрута: общий атомарный cover и реальный native/browser продукт остаются отдельной интеграционной проверкой.
