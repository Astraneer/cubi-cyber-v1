# Перекрёсток: серверная витрина

Витрина использует обычные World-компоненты, машину тика и общий WAL.
Канонический центр — `[site.x, site.y0, site.z]`: Y обозначает блок пола,
а не ступни игрока. Секретная генерация, инвентари и seed руд в объявление
ориентира не входят. Отдельный сетевой courier публикует ориентир после
durable Welcome; клиент не ищет место генератором.

Включение: обычная генерация включена, `spawn_override` отсутствует,
радиус защиты ≥32. Явный диагностический/custom spawn не переносит площадь,
поэтому там витрина выключена; уменьшенная/выключенная защита также не
создаёт бесконечный источник вещей. Настройки и caps не увеличены.

| Павильон относительно центра | Действительная линия |
|---|---|
| `(-19,+6)`, лицо E | Куб → сепаратор → очиститель → дробилка → обогатитель → плавильня → сундук; сырьё поступает из отдельного сундука через пять транспортёров |
| `(-19,-6)`, лицо E | Угольный генератор → два инфузора → плавильня → сундук |
| `(-19,-16)`, лицо E | Ветряк → обогатитель → плавильня → сундук |

Локальные координаты павильона: `(u,v)` → `(x+v,z-u)`; машины находятся
на `site.y0+1`, кабели позади ряда. Геометрия павильонов уже принадлежит
генератору. Сервер ставит только фиксированный набор клеток и типизированных
компонентов. Зависимости запрашиваются через существующий bounded worker;
чтение клетки не генерирует мир. Только фиксированные страницы витрины
остаются активными без наблюдателей. Полного обхода World на тике нет.

После установки источник транспортёра получает PULL отдельной durable
топологической границей, завершённой до следующего глобального тика.
Дальше обычный machine owner исполняет энергию, рецепты, газы и видимые грузы
20 раз в секунду. Каждые20тиков пополняются разрешённые входы/вода/куб;
выходные сундуки очищаются после48предметов. Это собственные демонстрационные
ресурсы, а не выдача игроку. Прогресс, слоты, компоненты и транспорт сохраняются
обычным WAL. Повторное открытие сохраняет существующие ID и точные байты
компонентов; проверка готовности не сбрасывает работающую линию.
Холодный ветряк ждёт настоящий SKY15. Изменение SKY в его верхней секции
после fsync будит только соответствующий существующий компонент через
индекс регистрации. RGB и чужие клетки не будят машины. При восстановлении
проверяется эта производная зависимость в уже существующем однократном
обходе метаданных компонентов; периодического обхода спящих ветряков нет.
Проверка выявила прежний сон перед самим опросом неба: счётчик уже был20,
а опрос20 ещё не исполнялся. Теперь первый опрос0 не пропускается при
позднем добавлении компонента; заблокированный ветряк спит после опроса,
с нулевой работой до изменения его входа.

Окна витрины доступны для просмотра при обычных проверках луча/дальности.
Любые Click/RecipeFill/TakeCraft/MachineSide при привязке к витрине сервер
отклоняет как Protected, включая Owner/Admin. Открытие другого окна,
закрытие и автоматическое обновление показаний разрешены. Общие правила
остальных защищённых блоков не изменены. Серверная защита не зависит от
наличия кнопок или флага в клиентском интерфейсе.
В owner-only WUI1 подтверждается `read_only`: бит1 существующего байта
флагов. При false прежние байты совпадают точно; неизвестные биты и
read-only закрытое/непривязанное окно отвергаются. Это признак отображения;
авторитетный отказ переноса всё равно проверяет сервер.

Доски: по две на задней стене каждого павильона, размер5×3 блока, центр
`[site.x−20.5, site.y0+3.5, site.z+dz+0.5]±[0.54,0,0]`.
Лицевая сторона E показывает цепочку, сторона W — четыре настоящих рецепта.
Иконки/рецепты берутся из общего реестра, renderer не получает содержимое
закрытых инвентарей. Графический владелец проверяет эти доски отдельно.

Проверки настоящего Server/WAL выполняются в
`cargo test --locked -p server --lib spawn_showcase::tests -- --test-threads=1`:
три линии без наблюдателей/транспорт, сохранение и повторное открытие,
Owner-окно с отказом переноса, порядок Welcome→Landmark и отключённые
диагностические профили. Это не аппаратная приёмка или доказательство
полного игрового сценария M9/M11.
