# Сертификаты экранной ошибки M5

Этот документ описывает границу ошибки и выбор представления. Сам по себе он не подтверждает завершение игровой приёмки M5: для неё нужны действующий сетевой запрос точного листа, полное GPU-покрытие, проверка обычного клиента и измерение ограничения вместимости.

## Что ограничивается

Исходная поверхность — верхние грани фактических целочисленных колонок публичного terrain baseline. Внутри единичной клетки высота постоянна; вертикальные ступени не переименовываются в непрерывную поверхность. Height tile содержит две треугольные плоскости на каждый из 16×16 coarse-квадов.

`gen::Generator::public_height_error` возвращает верхнюю границу вертикального отклонения в блоках и диапазон высот. Сервер округляет границу вверх до 1/1024 блока. `HTI2` передаёт эту метаинформацию вместе с той же `source`, высотами и доказательством замены. Отсутствие сертификата означает неизвестную ошибку. Его нельзя заменять нулём или оценкой только по 289 вершинам.

Сертификат baseline не заменяет защиту правок и конструкций. Изменённые колонки и защищённые области продолжают требовать дочерних тайлов либо полного публичного геометрического представления.

## Ограниченная работа серверного воркера

| Уровень | Точные колонки | Единичные footprints | Интервальные coarse-области |
|---|---:|---:|---:|
| 0 | 289 | 256 | 0 |
| 1 | 1089 | 1024 | 0 |
| 2 | 4225 | 4096 | 0 |
| 3–10 | 289 | 0 | 256 |

Малые уровни используют фиксированный массив до 65² высот без аллокаций. Для каждой единичной клетки проверяются значения coarse-плоскости в четырёх углах. Coarse-диагонали идут под 45° по целочисленной сетке, поэтому их пересечения с единичной клеткой также лежат в её углах. Замкнутые целочисленные границы проверяются отдельно. Это ограничивает и ступень, и плоскость между целочисленными выборками.

Для больших областей применяется интервальное вычисление исходных публичных формул. Все возможные ветви объединяются, включая раннюю ветвь озера, речной clamp, mountain gate, террасы и округление высоты. Холодная область большого уровня целиком не сканируется. Числа `intervals`, `unit_cells`, `sampled_columns` и `noise_evaluations` отражают фактический выбранный путь. Запрос мира и клиентский tick этот генератор не вызывают.

Perlin использует глобальную границу амплитуды и производной; для footprint не шире одной noise-клетки она пересекается с явным интервальным вычислением максимум четырёх gradient-клеток. Это не поиск максимума по нескольким случайным пробам.

## Численные сужения

Операции исходного `f32` kernel сохранены. Интервальные арифметические границы расширяются наружу. Дополнительные сужения пересекаются с исходным общим интервалом.

Smoothstep монотонен на [0,1]. Для его `f64` endpoint-вычисления используется запас 2⁻²⁰: он превышает абсолютную ошибку scalar `f32` cubic, ограниченную `9u(1+u)³+8η`, и ошибку endpoint-вычисления; `u=2⁻²⁴`, `η=2⁻¹⁴⁹`.

Для террасы `T(v,s)=sG(v/s)`, при `s>0` и представленном scalar sharp `a∈(0,1]`, функция непрерывна на целочисленных переходах. Выполняются `0≤G'≤1.5/a` и `|∂T/∂s|≤1+K(1+1.5/a)`, где `K=max|v/s|` по всему входному прямоугольнику. Интервал endpoint-значений при среднем положительном `s` расширяется этой производной, радиусом `s` и двумя глобальными границами scalar roundoff. В коде отдельно учтены округление деления через floor-переход, дробная часть, clamp, cubic, сумма и произведение. Произвольный фиксированный epsilon вместо этих членов не используется.

## Проекция и гистерезис

План выполняется только в воркере. Он получает публичные сертификаты, прежние ветви выбора, размеры viewport и консервативный camera box. Текущий View группирует положения в 16-блочные ячейки, FOV — в интервалы 10°, направление — в 45° по yaw и 30° по pitch. Конус видимости расширен на диагональ viewport и весь угловой запас. Интерполяция и bob внутри этих границ не вызывают новую задачу каждый кадр.

Пусть `f` — focal length в пикселях, `k=sqrt(1+tan(diagonal)²)`, `d` — минимальное расстояние между camera box и сертифицированным AABB, `e` — ошибка baseline плюс максимальный сдвиг вершины при seam. Используется:

`pixels = f·e·k / (d/k−e)`.

Неположительный знаменатель даёт бесконечную оценку; нулевая ошибка даёт ноль. Это учитывает смещение знаменателя perspective projection и точки вне центральной оси. Потенциально невидимые тайлы не расходуют SSE-refinement, однако крупное покрытие сохраняется и вне текущего направления камеры.

Текущая запрошенная настройка — максимум 32 px с полосой гистерезиса 8 px. Существующая coarse-ветвь уточняется после 32 px; уже уточнённая ветвь сохраняется до 24 px. Гистерезис не расширяет запрошенную верхнюю границу ошибки. Near cutout, защищённые конструкции и баланс 2:1 обязательны независимо от SSE. Дополнительное уточнение выполняется по приоритету ошибки, с ограниченной очередью и проверяемой вместимостью.

### Измеренная вместимость профиля 32 px

`cargo run --locked -p client --example horizon_capacity -- 512 1024 2048 4096`
использует публичные сертификаты фактических voxel stairs, одинаковые camera/FOV bounds, баланс 2:1 и точные Column replacements. Это CPU-эксперимент выбора, а не GPU/FPS-бенчмарк. Проверены seeds 1 и 1337, горизонт 1024 страницы, камера 780×437.

| Предел тайлов | Seed 1: тайлы / max px | Seed 1337: тайлы / max px |
|---|---:|---:|
| 512 | 510 / 160.915 | 510 / 219.599 |
| 1024 | 1023 / 78.736 | 1023 / 94.675 |
| 2048 | 2046 / 48.647 | 2046 / 54.570 |
| 4096 | 3369 / 31.881 | 3813 / 31.972 |

Строка 4096 повторена с минимальным покрытием 5×5 корневых тайлов: оно сохраняет радиус 1024 страницы в обоих концах camera-bin, в том числе при отрицательных координатах. Предыдущие меньшие вместимости измерены на центральном 4×4 fixture. Последняя строка сходится без `capacity_limited` и без неизвестных сертификатов. Требуется 42/39 точных колонн (336/312 geometry pages), поэтому предел geometry 512 включает также исходные 32 страницы spawn-защиты. Кеш выученных сертификатов достиг 4419/5011 элементов; явный предел metadata — 8192. Ни превышение вместимости, ни Unknown не превращаются в нулевую ошибку.

Фиксированный HeightGpu резерв на front+staging для 4096 тайлов — 8192×(3276 B payload+64 B header+8 B для двух visible lists)+128 B camera/indirect+4160 B near mask = **27 431 104 B**. Фактический двойной payload выбранных 3369/3813 тайлов — 22 073 688 / 24 982 776 B. Верхняя граница примитивов до GPU culling — 1 724 928 / 1 952 256 треугольников; это не измерение реально видимых примитивов или частоты кадров. Полные сетевые Height payloads — 9 457 806 / 10 701 987 B без outer framing и отдельно передаваемых защищённых geometry/water images.

Соседи worker-планировщика определяются через общий `height_neighbors::ancestor_neighbour` и dyadic ancestor lookup. Независимая all-pairs проверка 16 нерегулярных положительных/отрицательных деревьев подтверждает отсутствие перекрытий, баланс и все seam-флаги. При удвоении дальности 256→512→1024 добавляется ограниченное кольцо; тест ограничивает рост тайлов и lookup work, а не скрывает дополнительный холодный scan. Сумма lookup work до сходимости последней строки — 837 423 / 1 211 040; прежний O(N²) поиск упирался в 4M budget уже при 2048.

Worker protocol CHJ4/CHR4 ограничен 450 000 B: до 8192 сертификатов, 4096 previous/refine keys и 4096 выходных тайлов. Source/geometry/Column freshness и атомарная GPU-публикация покрытия остаются отдельными обязательными условиями. Во время первого прогрева допускается 64 Height uploads и 16 proxy uploads за GPU-фазу внутри того же общего 2 MiB UploadBudget; затем пределы возвращаются к 4/2. Эти измерения ещё не заменяют проверку полного покрытия в настоящем native/browser клиенте и сохранения воды в exact proxy.

PXP2 сохраняет непрозрачный DDA без alpha-to-coverage и добавляет обычные 16-байтовые Cutout descriptors, подготовленные только воркером. Cutout проходит отдельный A2C pipeline. Максимум страницы — 24 576 descriptors и 432 808 B PXP2 payload; полный CHR4 envelope занимает 432 858 B и укладывается в прежние 450 000 B. Максимальный CPU roundtrip проверен на 4096 различных публичных Cutout voxels. Scheduling credit 524 288 cell-work units / 2 MiB — консервативная граница, а не измеренное время или число прочитанных клеток. Startup Proxy count равен 4, frame pipeline compilation остаётся 0; дополнительный Cutout visible buffer резервирует 8 MiB при прежней payload arena 16 MiB.

Запрошенная ошибка не означает автоматически достигнутую. Отдельно сообщаются неизвестные сертификаты, ограничение вместимости, остаток на листовом уровне, максимальная сертифицированная оценка и ожидание точных колонок. При отказе ресурса сохраняется прежнее целое покрытие.

## Точный лист и свежесть покрытия

Если единичный leaf всё ещё превышает запрошенную ошибку, его нельзя уточнить дальше. Выбор запрашивает точное публичное представление колонки. Используются существующие `Replacement::Column` и source/view-manifest всех вертикальных страниц. На клиент не передаются авторитетные клетки, содержимое компонентов, руды или приватный seed.

Контракт кеша для перехода при той же публичной `source` строго монотонен: `Replacement::None` и пустая protection mask могут перейти в полную protection mask и валидный непустой Column manifest. Высоты, Known, atlas, tint и исходная граница ошибки остаются равны. Обратная смена при той же source отклоняется. Ошибка выбранного точного представления считается нулевой только как ошибка геометрического представления; исходный сертификат не переписывается.

Сервер ведёт отдельную публичную Height-версию для полного тела и Column manifest. Приватная HID-версия проверяет свежесть задачи, но не отправляется как публичная идентичность. Поэтому открытие соседней страницы, меняющее Geometry manifest при прежней центральной HID-версии, получает новую Height source; Water.column_source ссылается именно на неё. Равное публичное тело сохраняет source после hidden-only правки, включая вытеснение тела из LRU: active lease хранит отдельный 32-байтовый BLAKE3 witness публичных полей без приватного HID и wire source. При сохранённом теле дополнительно сравниваются все поля. Actual encoded Server regression проверяет автоматическую цепочку Geometry→Height→Water после соседнего portal edit и равенство закрытой приватной AIR/lava-компоненты публично заполненной компоненте.

GPU не скрывает старые height-треугольники до готовности всего точного покрытия. Частично загруженные страницы, устаревший view либо отказ upload-бюджета оставляют предыдущий кадр. Повторно выбранный кешированный родитель ждёт свежего ответа текущего периода интереса, даже при неизменной source. Старые метаданные разрешено использовать для планирования запросов, но не для публикации нового покрытия.

Кеш планирования защищает выбранные листья и полезных предков. Другие изученные сертификаты сохраняются до фактической нехватки места, затем удаляются по ограниченному LRU. Немедленное удаление всех невыбранных детей могло бы вызвать повторные запросы и колебания выбора. Вместимость остаётся фиксированной и проверяемой.


## Объёмное ближнее покрытие

CPU halo не является GPU-геометрией. Новая выбранная сцена хранит все Height поверхности под ближним регионом и вырезает только фактический 3D объём intended raw draw pages; бюджетно задержанные старые GPU pages добавляются отдельной маской. Exact proxy и physical water отключаются по полному PageId, включая Y. Поэтому полёт над землёй не удаляет поверхность в другой вертикальной странице той же колонки. Внутри intended near Unknown не заполняется дальней публичной геометрией.

Маска Height занимает 4160 B; неизменная маска не загружается. Два GPU cull buckets оставляют обычную pixel-frequency отрисовку вдали и выбирают sample-frequency world interpolation только для тайлов, чьи AABB пересекают ближний объём. Второй render pipeline готовится при загрузке: фактический startup Height count равен4, per-frame pipeline count остаётся0. При отказе маски/флагов новый стык не считается готовым; новый HDR-кадр должен дождаться joined guard, используя прежний HDR для UI-only presentation.

Изолированная наклонная GPU-проверка сопоставляет неизменную полную Height-плоскость с RawNear+3D Height mask и читает все четыре конечных MSAA depth samples. В ближнем bucket sample index остаётся динамически используемым через заранее заданное число сэмплов, вместе с sample-qualified interpolation. Проверка прошла на Ubuntu Mesa25.2.8; она не заменяет полный независимый JOIN с exact Proxy.

Повтор CPU capacity-эксперимента `horizon_capacity --near-3d 4096` с intended3×3×3 около Y64..111, теми же camera/FOV и горизонтом1024:

## Ограниченный выбор Near

`client::near_profile` трактует настройку как минимальный горизонтальный радиус в блоках вокруг страницы Scene/player, а не смещённой камеры третьего лица. Значения 4/8/12/16 используют фактический радиус 16; 24/32 используют 32. Вертикальный draw radius остаётся одной страницей. Профиль 32 требует 75 visible pages, 245 raw halo pages (7×5×7) и 145 GPU objects с резервом 64 edit patches и 6 legacy self parts. Анизотропный Connection AOI сохраняет жёсткий предел 256; полный куб 7³=343 отклоняется. Actual Connection test проверяет 245 первых запросов и 35 новых после перехода на одну страницу.

При текущем raw/GPU профиле 48/64 возвращают явную ошибку вместимости, без ложного effective receipt. Увеличение одной GPU arena не снимает сетевой предел. Loading/reprepare и пользовательский receipt должны использовать тот же проверенный профиль; CPU-планировщик сам по себе не означает продуктовую GPU-приёмку. Уменьшение настройки внутри одной page-группы не сокращает работу и не является полезным шагом AutoQuality.

Во время GPU loading подтверждённая raw queue может хранить весь проверенный профиль из 245 страниц; старый жёсткий early guard 128 удалён. Число страниц по-прежнему ограничено 256, один GUI drain — 128, outbox — 256. Same-page updates coalesce. Actual Connection test принимает все 245 страниц при остановленном GUI, независимо дренируя сетевые ACK, и затем получает последнюю версию каждой страницы.

Новый additive Client `ForgetPage(PageId)`, outer tag 21, сокращает только public near lease: raw history/requests, LIGHT, props, packet stream и raw projection reference. Канонический World и generation не удаляются. Это требуется для движения профиля 245 под неизменным server cap 256: старый удержанный слой не должен блокировать новый. На клиенте отменяются также старые queued raw/LIGHT и ACK/requests; отсутствие credit откладывает переход. Старый server binary, не понимающий tag 21, несовместим с новым движущимся клиентом: приёмка требует свежую согласованную server/native/WASM пару. Runtime moving-245 proof и продуктовый receipt являются отдельными условиями.

`client/tests/near_interest_owner.rs` проверил фактический Server+Connection через оба кодека: остановленный GUI, перемещение по X и Y и возврат, 139 ForgetPage, максимум 256 server leases и GUI queue. Все 245 желаемых страниц получили текущие Raw/LIGHT/Props; настоящий packet stream исчез и восстановился, а поздние пакеты не воскресили retired pages. Канонические 504 fixture pages сохранены, gameplay generation равна нулю. Проверка заняла 106.82 s; это проверка bounded liveness без сокета/GPU, а не длительность загрузки продукта. Три NearProfile/queue теста повторены с новым `Raw.applied_action` (server tags 28/29), без изменения пределов. Для полного продуктового прогона нужен server с тем же новым форматом.

Native и browser loading используют один NearProfile до замены текущего View. Запрос 48/64 остаётся в пользовательских настройках с явной ошибкой; текущая сессия и профиль сохраняются. Receipt Near выставляется только при совпадающих Scene bounds и фактически ready View. Новый read-only `has_committed_far_front()` отличает ещё пустой Far от сохранённого опубликованного покрытия во время следующей подготовки; initial Far=0 не считается применённым качеством.
