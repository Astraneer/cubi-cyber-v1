# SMAA 1×

Альтернатива MSAA4 из SPEC §6.8 использует один отсчёт сцены и собственный
ограниченный алгоритм семейства SMAA: классификацию контрастных границ,
поиск геометрического рисунка, таблицу площадей и смешивание соседей.
SDK-код, готовые area/search текстуры и чужие реализации не использованы.
Побитное соответствие SMAA SDK не заявляется. TAA с векторами движения —
отдельный необязательный режим, выключенный по умолчанию.

Post сначала выполняет экспозицию/bloom и тонмаппинг в линейный RGBA16F
размером с физическую поверхность. Затем три подготовленных прохода строят
RG8 границы, RGBA16F веса и конечное изображение. Смешивание происходит
в линейном свете; выходная передаточная функция применяется ровно один раз.
Scale уменьшает HDR/depth, а SMAA и UI сохраняют физическое разрешение.
MSAA4 оставляет прежний Post без дополнительных текстур, pipeline и запросов.

## Геометрическая модель

Контраст проверяется по perceptual luma с порогом 0,1 и локальным подавлением
слабой границы при контрасте соседей более 2×. R хранит западную, G — северную
границу. Поиск каждого прямого участка ограничен 16 пикселями в обе стороны;
проверка диагонального рисунка — 8 шагами. На концах участка пересечения
задают высоты −0,5 / 0 / +0,5. Через концы проводится аффинный контур.

Для горизонтального участка концы имеют координаты x₀=−d₀−0,5,
x₁=d₁+0,5 и высоты h₀/h₁. В текущем единичном пикселе веса равны
интегралам положительной и отрицательной частей этого контура. Таблица
51×51 содержит все пары расстояний 0…16 и трёх высот каждого конца;
2601 пара f32 генерируется из f64 при загрузке. Вертикальный случай
транспонирует и направление, и обращения к crossing edges.

Участки U, неоднозначные двойные crossing, незавершённый поиск и край экрана
консервативно сохраняются без сглаживания. Изолированная Z-диагональ
принимается только при подтверждении соседнего такого же рисунка; проверены
обе ориентации и инверсии. Проверка соседства использует два явных направления:
первоначальный walk принимал ≥2 совпадения, начиная с одного, и прекращал
направление при первом несовпадении; более дальние шаги не влияли на ответ.
Это позволяет точно убрать вложенные циклы. Первоначальный Weights shader
вызвал внутренний abort FXC в настоящем Windows CI; причинность исправления
остаётся неподтверждённой до нового Windows запуска. Backend и компилятор
не заменяются. При смешивании выбирается ось с большим суммарным
весом, равенство решается детерминированно; сумма весов ограничена единицей.
Выравненные границы, тонкие линии, прямоугольные углы и checkerboard не
размываются. У алгоритма нет истории кадров.

## Ограничения ресурсов и учёт

Дополнительная память SMAA равна 18 байт на физический пиксель плюс 20 824
байта таблицы и параметров; 64² требует 94 552 байта. Подготовка создаёт
три pipeline. Resize меняет только targets/bindings, сохраняя pipeline/LUT.
Работа ограничена 3P выходными пикселями, не более 304P поисковыми чтениями
и 2P area lookup. Последние два числа — верхние границы, а не измеренные
счётчики исполненных чтений. Максимальный размер — 16 777 216 пикселей.

Весь Post проверяет общую пиксельную квоту до первой команды. Максимальные
Automatic Exposure + шестиступенчатый bloom + tone + SMAA занимают 13
проходов в заранее подготовленном таймере на 16 проходов. Cached present
делает tone и SMAA, сохраняя историю экспозиции/bloom. Неизменившаяся сцена
не запускает граф. F3 объединяет эти интервалы в Tone/AA; полный GPU-таймер
обрамляет фактически отправленный encoder вместе с UI.

## Проверено

`render/tests/reference/smaa_area.rs` создан независимо от реализации:
клиппинг прямоугольника и формула площади многоугольника служат эталоном
аналитическому интегралу. Все 2601 значения таблицы совпадают с ним с
ошибкой меньше 2×10⁻¹⁴. Native GPU проверяет повороты/инверсии лестниц,
прямые границы, углы, тонкие линии, checkerboard, статическую повторяемость
и движущийся контур. За 33 фазы сумма квадратов ошибок относительно точного покрытия снизилась
с 284,692 до 134,779; максимальный скачок — с 1 до 0,74902. Целочисленный
перенос совпадает побитно.

`tools/smaa_gpu_smoke.mjs` загрузил точные production WGSL и таблицу Rust в
настоящий Dawn: 30 случаев, 185 856 проверенных пикселей, максимальная
ошибка 0 байт, ошибок shader validation нет. Его независимый polygon oracle
проверил также 17 временных фаз: сумма квадратов ошибок 67,904 против 144,399
у исходного изображения, статическая повторяемость побитная.

Post GPU проверяет оба output transfer, HDR scale, атомарный отказ квоты,
ресурсный resize, cached present и максимальный граф 13 проходов. Полный
ClientView подтвердил действующий receipt SMAA1, реальные четыре Post
прохода и 1000 CPU/upload фаз без аллокаций и работы. Сохранённый выбор
сам по себе receipt не создаёт. Новая продуктовая проверка native/WASM
с согласованным серверным протоколом остаётся отдельной приёмкой;
аппаратная производительность и Windows/DX12 этим не подтверждены.
