# Отзыв GPU-семейства моделей при восстановлении cursor

Одна CPU-сверка Props недостаточна: старый64-Б GPU record может оставаться видимым при нулевом бюджете upload. Кандидат добавляет отдельный признак допустимости содержимого BlockModelsGpu. Его отзыв — O(1), без прохода по записям и без новой записи в GPU-буферы. Обычный draw, shadow draw и маски основного/стеклянного temporal draw возвращают0. Необработанные диагностические instance_records остаются прежними: их наличие не является свидетельством допустимого содержимого.

Ресурсы теней остаются available. При отзыве и восстановлении меняются source epoch и shadow revision; неизвестный damage принуждает полный restore предыдущих динамических теней, включая sparse-footprint путь. После настоящего commit damage снова считается известным. Terrain, другие модели, тени и их настройки сохраняют обычную работу; новые таймеры, callback, квоты или pipeline не добавляются.

ViewProps закрывает семейство при cursor_recoveries в работе нормальной CPU-фазы. Source выполняет ограниченную сверку и обычные immutable-worker задачи. Открытие возможно только при source.settled и пустых pending/contexts/retry, после реальных hidden GPU uploads. Если fallible-операция CPU или upload возвращает ошибку до финальной записи работы, внешний метод сначала закрывает семейство O(1), затем передаёт исходную ошибку. Даже вызывающий код, отложивший обработку ошибки, не получает старый HDR за текущий.

Монотонный epoch меняется и при повторном отзыве уже закрытого семейства. У всех переходов проверяется переполнение до изменения полей.

ClientView сохраняет epoch реально закодированного HDR. has_cached_present, encode_cached_present и планирование кадра отвергают другой epoch; принудительная инвалидизация renderer заставляет Environment построить текущий HDR без отозванных моделей. Новый настоящий кадр без семейства может стать кэшем своего epoch, хотя начальный вход всё ещё ждёт готовности Source. Старое кодирование с0 terrain passes не получает новый сертификат epoch.

Optional TAA включает props epoch в SourceKey и SOURCE_REVOKED. Scene/Post candidates сохраняют свой epoch; поздний commit старого submitted token выполняет discard и не делает старый HDR допустимым. Физически отправленную ранее GPU-команду отменить нельзя; этот механизм не позволяет её позднему завершению возродить старый cache/history. Общий начальный World/HUD PresentationGate дополнительно квалифицируется тем же epoch отдельным согласованным патчем.

Подготовлено по literal R7 совместно с CPU recovery850ae41c. Rustfmt разобрал4 production-файла. Cargo/GPU пока не запускались; обязательные проверки реальных пикселей/глубины при нулевом upload, динамических теней, позднего TAA/cache commit и начального World/HUD gate готовятся отдельно. До этих проверок кандидат не принимается.

## Дополнение R2: незавершённый encoder обычного AA

Обычный AA сохраняет CPU-stamp HDR уже при encode; Caller обязан выполнить submit/present перед его использованием. Если encoder отброшен после кодирования нового epoch, GPU-текстура ещё содержит старый HDR. Поэтому explicit discard при отсутствии TAA закрывает cached availability, инвалидирует Environment/renderer и заставляет заново восстановить тени после незавершённого shadow-encode. encode_cached_present дополнительно проверяет available, а не только совпадение epoch. Это фиксированные инвалидизации без прохода по N моделям; настройки качества не меняются. Отдельный отрицательный GPU-контроль отброшенного MSAA4 encoder ещё требуется; исходники R2 только разобраны Rustfmt.
