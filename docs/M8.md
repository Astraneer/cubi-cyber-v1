## Контракт подключения

`server::survival::SurvivalRuntime` хранит ограниченную очередь по `(срок, порядок)` и независимый индекс возраста. В каждом тике рассматриваются только события в бюджете. `plan_tick` читает известные страницы, применяет последовательные результаты к локальному наложению и возвращает транзакции по пространствам, счётчики и `RuntimeDelta`. План не меняет `World` или сам планировщик.

Владелец проверяет и сохраняет транзакции и дельту в одной WAL-партии. Только после `fsync` вызывает `acknowledge`, затем публикует состояние. Дельта пропорциональна событиям этого тика; полная очередь сериализуется только при контрольной точке. `plan_register`/`plan_wake` нужны в той же партии, что и принятие действий игрока. `register` предназначен для начального восстановления и тестовых сцен.

| Значение | Формат |
|---|---|
| Инвентарь | `INV1`, 260 байт |
| Здоровье | `HPS1`, 64 байта |
| Печь / сундук | `FUR1`, 30 / `CHS1`, 174 байта |
| Чистая очередь жидкости | `FLQ1`, 16 + 29N байт |
| Контрольная точка планировщика | `SVR1`, 32 + 48N байт, включая ключ RNG мира |
| Дельта планировщика | `SVD1`, 36 + 16R + 48A байт |
| Группа выпавших предметов | `DRP1`, 8 + 56N байт, N≤64 |

Все декодеры ограничивают размеры, проверяют слоты, состояния и идентификаторы. Дроп использует один компонент на клетку, сохраняя независимые ID предметов из игрока, номера действия и индекса. Переполнение отклоняется до изменения мира. Предметы из сундука и его удаление можно включить в одну транзакцию. M7 должен переносить подтверждённые группы в физические сущности, сохраняя ID.
