# Подтверждённый звук изменения блоков

`Mine` и оба пути `Place` добавляют событие в ту же World-транзакцию, что и
фактическое изменение клетки. Передача начинается только после успешного
завершения SaveWorker. Отказ, повтор ActionId, прогноз клиента и восстановление
WAL сами по себе звук не создают. Материал определяется из actual old/new
транзакции, а не из присланного клиентом предположения.

| Граница | Контракт |
|---|---|
| Старый звук | ACU1, kinds0…11 и все64 байта сохранены |
| Изменение блока | Вложенный ACU2, kinds12/13,80 байт; прежний внешний AudioCue27 |
| Идентичность | Полный публичный UUID128 + ActionId64 + вид; u64 emitter не заменяет UUID при dedup |
| Материал | Только10 звуковых семейств; ID/состояние руды, содержимое, private source и World counter отсутствуют |
| Наблюдатель | Действующая Raw lease, точный подтверждённый public preimage, свежий known-only LOS до изменения |
| После записи | Тот же UUID/session/Raw view и lease, Space/радиус32, новый known-only LOS; Unknown закрывает звук |
| Владелец | Используется уже проверенный action witness, без гонки с асинхронным Raw ACK |
| Локальный дубль | Mine/Place идут по общему causal-пути; старый reply-путь остаётся только для разрушенного ведром растения |

Аудитория хранится только в приватном WAL: не более32 записей
`UUID/session/Rawview`, максимум1105 байт вместе с cue. Сам редактирующий actor
входит в эту аудиторию. Перед публикацией нельзя требовать совпадения старого
private Raw source с текущим: изменение клетки само его продвигает. Вместо
этого сохранённый public preimage разрешает старое звуковое семейство, а свежий
LOS проверяет текущую видимость места. Directed guard-тест сохраняет Raw view,
но переносит observer за существующую стену: cue отменяется. Это отдельный
тест защиты, не заявление о конкурентном движении: обычный Server сериализует
очередь движения за pending WAL.

Общие ограничения прежние:64 аудиособытия/batch,8 доставок всех AudioCue на peer.
При `MAX_CONNECTIONS=64` это не более512 сообщений по103 байта net-frame
(52736 байт без WS/UDP overhead); при32 участниках —256 сообщений.
Сверх квоты временный звук пропускается со счётчиком; игровое действие не
отклоняется. Перебор кандидатов ограничен64 peers на событие; LOS ограничен
радиусом и не вызывает загрузку/генерацию World. Фактические запросы учитываются
отдельно: `block_audio_rays/segments/cell_reads`. Этот bound не является замером
стоимости максимальной активной сцены.

Проверки покрывают настоящие Server/Store: owner+observer, точный WAL вместе
с клеткой, дубль/restart, скрытое/Unknown/неподтверждённое состояние и
Forget/reentry. Отдельная Unix-проверка достигает настоящего отказа SaveWorker
по лимиту WAL через sparse-файл; звук и Accepted не публикуются, восстановление
возвращает прежнюю клетку. Ошибка системного `sync_all` этим не инжектируется.
Клиентские encoded-тесты проверяют reply-before-observe, отсутствие собственного
дубля, исходный decoded PCM, Space/age и idle1000 без выделений.
Физическая слышимость и полный UI-прогон нового public block audio не заявлены.

Команды: `cargo test --locked -p net --test audio_cue`;
`cargo test --locked -p server --lib block_audio::tests`;
`cargo test --locked -p client --test block_causal_audio --test causal_audio --test confirmed_block_sounds`.
Требуется согласованная пара клиента и сервера; версия envelope/owner/save не меняется.
