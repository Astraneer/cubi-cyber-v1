# M4: свет и стабильные тени

Native и browser подключают authoritative LIGHT, GPU-объёмы и кэш теней в общий View. Компонентные GPU-проверки, длинный лесной H5 и независимый непрерывный Sun-H5 пройдены на программном GPU. Продуктовые дневной/ночной и enclosed-room эталоны остаются отдельной приёмкой. Энергия и ответственность — [LIGHTING.md](LIGHTING.md).

## Выполненные проверки

`cargo test --locked -p world --test lighting` проверяет CPU RGB/skylight независимой BFS: удаление источника, крыша/стены, граница страниц и пространств, Unknown и ограниченные очереди. Эти 13 тестов существовали до GPU-интеграции.

`VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test shadows -- --nocapture --test-threads=1` запускает настоящий программный Vulkan: компонентные проверки и длинный H5-маршрут.

- Аналитический AABB-эталон: 336 точных отсчётов глубины коробки и отсутствие лишнего покрытия. Двенадцать статичных кадров: 0 shadow draw вместо 180 у полного обновления трёх каскадов. После локального переноса очищено 944 из 49 152 текселей; результат совпадает с полным перерисовыванием побитно. Статика и 20 субтексельных шагов дают нулевое мерцание.
- На 32 шагах ходьбы сетка пересекла 31 границу привязки; маска теней на неподвижных мировых получателях дала 0 ‰ дрожи при пороге H5 0,02 ‰. Независимые лучи против AABB подтвердили 547 затенённых и 15 375 освещённых пикселей. Реальный шаг солнца меняет тень, затем изображение стабилизируется. Чёрная/белая константа не проходит эталон видимости.
- Настоящее GPU-чтение светового буфера: изменение трёх отсчётов занимает 12 байт и сохраняет все остальные значения. Старое поколение, неверный порядок индексов и недостаточный бюджет отклоняются до записи.

Дополнительно проверены 4-байтовая живая ссылка overlay на базовый том и равномерный свет модели (8 байт при создании, затем 4). Fixed OwnerPatch-оболочка правки отбрасывает побитно ту же глубину тени, что финальный greedy-меш.

Шесть CPU-тестов проверяют стабильные матрицы, атомарную публикацию, локальные dirty-области, справедливость обслуживания и границы конфигурации. Два теста упаковки света проверяют все уровни и координаты рамки. Учёт аллокаций с положительным контролем подтверждает нулевую работу статичного CPU-кэша.

## Выбранный продуктовый профиль и измерения

Runtime выбрал 2048²×3 для статического и отдельного combined depth:
96 MiB полезных depth-данных. Tier A 1024² — 24 MiB; доступный API 4096²
с combined — 384 MiB. Это размеры созданных Depth32Float descriptor,
а не измерение фактически занятой VRAM драйвера.

H5 повторён на разрешении 2048² с combined, но с тестовыми полуширинами
16/32/64 и depth_half_extent32 вместо продуктовых 32/128/512 и1024.
Проверка использует одну коробку и неподвижные приёмники в области24×24;
она не покрывает переход между каскадами, листву и живую модель.
32 шага камеры дали 32
ограниченных cascade updates, мерцание фиксированных приёмников 0‰,
независимо подтверждены 547 shadow и 15 375 sky samples. Изменение солнца
меняет результат; после сходимости — 0 draw/query/copy. Warm + walking +
sun всего 38 обновлений: 159 383 552 обработанных depth texel и
637 534 208 байт GPU static→combined copy (16 MiB на обновлённый слой).
Длительность на RTX этим software-Vulkan тестом не измерена.

`ShadowGpu` сохраняет детальные фиксированные queries: kind1 static
frustum, kind2 static clear/depth, kind3 combined restore/model depth.
Отдельная пара query охватывает весь shadow graph: начало до первого
static/caster compute, конец после restore, draw и возможных copy-команд.
`timing_source()` передаёт FrameGpuCapture только этот TOTAL (kind4), без
двойного суммирования вложенных проходов. Тест проверяет, что TOTAL не
меньше суммы шести внутренних проходов. Статический кэш не запускает
query/dispatch/draw. Queue.write staging вне command buffer учитывается
байтами отдельно и не объявляется измеренным временем GPU-прохода.

Обновление RGB8/confirmed LIGHT описано в `LIGHTING.md`: том 23 332 байта,
независимый header, alias 4 байта, uniform 8 байт при создании / 4 при
изменении. Пять client GPU-проверок включают нулевой LIGHT snapshot без
WorldChange, [231,17,255] без потери и отзыв при смене public cell_view.

Для authoritative mode добавлен отдельный `ingest_scene_cpu`: ограниченное
чтение журнала работает независимо от ожидания GPU и не имеет доступа к
Queue. Крупная LIGHT-транзакция (>1024 samples) инвалидирует полные тома
через метаданные изменённых страниц и halo, не обходит поштучно snapshot.
GPU затем читает актуальное World LIGHT с прежней проверкой сертификатов;
малые дельты сохраняют patch-путь. Отбросить dirty metadata без resident
можно в пределах 27 probes на квоту страницы, без расходования квоты
реальных загрузок. Диагностика ready отдельно показывает source, journal,
полные тома, aliases, instances и shadow cache; критерии готовности не
ослаблены. Тест проверяет 4096 changes → 1 metadata entry, CPU sample reads0
и uploads0, прежнее GPU-слово до публикации, затем точный HDR RGB8.


## Локальное обновление combined depth

Прежний путь копировал все три слоя static→combined при любой смене позы:
48 MiB за кадр при2048². Это исторический отрицательный результат, а не
текущая стоимость динамической модели. Теперь EntityGpu и BlockModelGpu
сохраняют первые показанные старые границы и последние новые границы
каждого изменённого экземпляра. Промежуточные ещё не показанные позы не
раздувают damage. При пропуске истории выполняется явный полный fallback.

Для каждого каскада объединяются old/new footprint и static dirty rect.
Scissor-проход восстанавливает только эту область fragment-depth чтением
чистого static слоя, затем отдельная compute-компактация и draw заново
добавляют попадающие модели. Частичный Depth32Float copy не используется.
Динамический обычный путь выполняет0 copy bytes. Полная матрица рендера
сохранена; только cull-камера ограничивается dirty rect. RGB, hurt-flash и
неизменная геометрия не инвалидируют тень. Удаление последней модели также
меняет shadow revision через ненулевой restore, даже когда model draw=0.

Actual GPU128²×3: перенос моба восстанавливает1158 пикселей вместо49152;
изображение побитно равно forced-full восстановлению, старый след исчезает.
Совместная тень моба и сундука после открытия/удаления также побитно равна
full; static depth не меняется. Неподвижный следующий кадр —0 работы.
Открытая крышка ограничена настоящей высотой1,6 блока, а не старой1,3.
Прежний профиль без GPU bounds сохраняет пять shadow pipelines (reset/cull/depth/clear/restore);
кадр и resize не компилируют их.

## Длинный H5-маршрут: границы доказательства

Новый тест использует реальные продуктовые2048²×3, combined, полуширины
32/128/512 и depth_half_extent1024: voxel-лес с cutout-листвой, настоящий
HDR/MSAA4 alpha-to-coverage проход и анимированная GPU-модель человека.
Фиксированные мировые получатели читаются float-пробой каждый завершённый
кадр. Поле получателей находится вне движущегося следа человека: эта
проверка изолирует CSM jitter от настоящего движения тени. Геометрия/анимация
кастера участвуют в полной стоимости; корректность самого движущегося
силуэта отдельно проверена local/full bitwise model-тестами128². CPU f64 эталон независимо вычисляет плавный LOD по footprint и
начальным отдельным слоям; шум каждого слоя измеряется отдельно.
Методика и сохранённые отрицательные raw-результаты — DECISIONS.md.

64-кадровая диагностика прошла: layer jitter0,002937‰, expected absolute
error0,003033‰, expected temporal residual0,002937‰, cached/full absolute
и temporal residual0,002932‰. GPU negative controls дают968,933‰ для
чередования и29,203‰ для одного резкого L0→L1 jump, то есть уверенно
проваливают неизменный порог0,02‰. Независимые лучи подтверждают347 deep
shadow и1024 clear samples. Чистый far-PCF до исправления slope bias
ложно затемнял открытый пол; receiver-plane bias теперь учитывает размер
линейного comparison footprint, сохраняя разрешение и committed matrix.

## Ограничение дальних casters

Текущий static ShadowGpu получает TerrainGeometry; отдельный dynamic
backend содержит Entity/BlockModels. HeightGpu и LodProxyGpu пока только
получают освещение, но не рисуют свои активные front-объекты в directional
shadow depth. Поэтому приведённые H5 результаты относятся к явно заданным
Terrain/model casters и не доказывают тень дальней горы/постройки на near.
Это реальная оставшаяся интеграция §6.4: нужны active-front caster hooks,
Unknown/protected/cutout clipping и независимый hill/building→near oracle.
Её нельзя подменять SSAO или объявлять выполненной по ночному zero-light
тесту. До соответствующего proof ограничение сохраняется.
