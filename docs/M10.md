# M10: графические подсистемы в разработке

`render::atmosphere` вычисляет LUT пропускания и sky-view из Rayleigh, Mie и озонового поглощения вокруг сферической планеты. Это собственные Rust/WGSL; код рендера и шейдеры донора не использованы. Расстояния — километры, высоты экспоненциальных профилей — 8 и 1,2 км.

По умолчанию пропускание имеет размер 256×64 и 64 шага интегрирования; sky-view — 192×108 и 48 шагов. Формат — `RGBA16Float`, два compute-конвейера готовятся при загрузке. Изменение солнца/высоты пересчитывает только sky-view, статичный кадр — ничего. Записи параметров и шаги интегрирования имеют явные бюджеты; отказ сохраняет ожидающую работу. После отмены уже закодированного, но не отправленного обновления владелец вызывает `invalidate`.

`TerrainGpu::attach_atmosphere` подключает LUT при загрузке к общему MSAA 4× / HDR / final transfer. Направление берётся из обратной матрицы камеры; её изменение добавляет 64 байта загрузки. Изменение только LUT не загружает камеру или геометрию. Владелец выполняет `encode_update` до terrain и инвалидирует сохранённый план кадра при изменении сияния. Эталон M2 сохраняет исходный режим неба.

Тот же расчёт пишет 80-байтный `AtmosphereLighting`: RGB SH L1
`E_sky / PI` и прямую солнечную освещённость `20 × T_sun` в согласованных
относительных единицах HDR. SH строится 16 ограниченными направлениями
верхней полусферы; солнечное пропускание интегрируется на настоящей
высоте наблюдателя, без грубой интерполяции первого texel LUT.
Lambert-приёмники используют `albedo × E / PI`; labPBR — `BRDF × E`.
Локальный RGB block light добавляется один раз, scalar block light не
создаёт энергию. Ночная сцена больше не получает постоянный белый ambient.
Облака и вода получают ту же солнечную шкалу. Старый режим без атмосферы
сохраняет пиксели эталона M2.

| Настоящий software Vulkan | Результат |
|---|---|
| Пропускание против независимого f64 / 4096 шагов | 242 RGB-отсчёта, максимальная абсолютная ошибка 0,00058784 |
| Уменьшенная тестовая конфигурация | 205 632 шага при старте; 74 560 при смене солнца; 0 в статике |
| Солнце за планетой | Просочившегося прямого рассеянного света 0 |
| Общий terrain HDR, 12 513 пикселей | Яркость при взгляде вверх 5 059 696, вниз 285 218 |
| Изменение только LUT | 0 байт камеры и геометрии; ночное изображение без солнечного света |
| Общая энергия Terrain + labPBR, 1148 приёмников | Ошибка солнечной освещённости против f64 ≤0,011374 при шкале 20; ночных утечек 0; прежний белый ambient ошибочно освещает 1148 пикселей |
| Необязательные loading-конструкторы Entity / BlockModels / Height | Настоящие ночные и дневные изображения, 0 компиляций при смене солнца |


Это ограниченное однократное рассеяние, а не завершённая модель Hillaire или весь M10. Многократное рассеяние описано ниже; остаётся соединение всех выбранных проходов с живым клиентом. Физическая вода, облака, светила, PostGpu и GI описаны ниже; локальный labPBR — в `docs/M10-materials.md`. Прохождение отдельных тестов не завершает M10. Alpha sky-view хранит диагностическое среднее пропускание и не заменяет RGB-пропускание при композиции поверхностей.

## Многократное рассеяние Hillaire

Собственная реализация опубликованных уравнений 5–11 из статьи
S. Hillaire, *A Scalable and Production Ready Sky and Atmosphere Rendering
Technique* (2020), §5.5: <https://sebh.github.io/publications/egsr2020.pdf>.
Читалась статья, чужой код реализации не использован.

Для порядка ≥2 приняты изотропная фаза и одинаковая освещённость соседних
точек. LUT хранит нормированную передачу `Psi = L2 / (1 - f_ms)` при
`EI=1`; аналитическое интегрирование сегмента удерживает `f_ms` в границах.
Прямое отражение от усреднённой поверхности планеты учитывается с albedo
0,3. Умножение на настоящее солнечное E происходит в общем sky/aerial
источнике, поэтому смена солнца или высоты не пересчитывает эту LUT.
Для порядка ≥2 воксельная видимость игнорируется по приближению статьи;
M4 shadow подавляет только прямое однократное рассеяние.

| Реальный software Vulkan | Результат |
|---|---|
| Однородная сфера против независимой f64 геометрической суммы 100 порядков | максимальная ошибка half-float 0,00014231; feedback≤0,5 |
| Земная конфигурация, 64 контрольных texel | `Psi` конечна, feedback<1, полностью ночной столбец 0 |
| Отражение грунта | дневная разница `Psi` 0,048996 против чёрного грунта |
| Настоящий sky shader с выбранной LUT | 416 texel стали ярче; ночное небо без утечек |
| Смена солнца/наблюдателя | 0 новых проходов MS; сохранённая LUT побитно прежняя |

По умолчанию 32×32, 64 фиксированных направления и 24 шага:
1 572 864 ограниченных шага при старте, 16 KiB двух LUT и 1056 байт
начальной загрузки. Sky/SH и aerial читают один результат. Ресурсы
подключаются до первого кадра через `prepare_multiple_scattering`;
`ViewEnvironment` включает их по умолчанию, `multiple_scattering: None`
сохраняет прежний режим. Эталонный M2 без Environment не менялся;
FLIP-пороги и golden-изображения не обновлялись.

## Экспозиция и bloom

`PostGpu` читает линейный HDR после композиции сцены. Автоэкспозиция строит
256-корзинную гистограмму логарифма яркости, затем плавно меняет выдержку;
ручной режим не создаёт гистограмму. Bloom включает отдельную пирамиду
`RGBA16Float` только при выбранном режиме. Изменение размера сохраняет
конвейеры. Финальный проход применяет ACES fitted и единственный выходной
sRGB transfer. Размытия движения, зерна и DOF нет.

Измерение яркости и bloom сохранённой сцены повторно не вычисляются;
адаптация экспозиции может продолжаться отдельно. Версия источника,
бюджет обработанных пикселей, загрузка параметров и GPU timestamps
передаются явно. Отказ бюджета оставляет работу ожидающей.
`request_present` выводит сохранённый HDR в новый surface после изменения
интерфейса: один tone-проход, 0 загрузок, без повторных histogram/bloom;
вывод побитно совпал с прежним. Без явного запроса неподвижный граф
по-прежнему не требует кадра.

| Software Vulkan, 3 теста PASS | Результат |
|---|---|
| Ручная экспозиция, независимый f64 | 3072 пикселя, максимальная RGB8-ошибка 0 |
| Изменение размера | 0 новых компиляций конвейеров |
| Автоэкспозиция | 768 отсчётов; 41 кадр без повторного измерения; цель 0,1829481, итог 0,18294816 |
| Bloom | 1001 пиксель ореола, 1020 texel пирамиды; в статике 0 пересчитанных texel и побитно одинаковый вывод |

## Кэш проб GI и H6

`GiGpu` трассирует ограниченные DDA-лучи по известным GPU-кирпичам 16³.
Неизвестный воксель останавливает луч без света. Вход хранит только уже
отражённую радиансность поверхности: отдельный прямой свет и ушедшее в
небо излучение не прибавляются второй раз. RGB SH L1 и шесть осевых
границ видимости занимают 128 байт на пробу. Трилинейный приёмник
отсекает пробу за стеной и применяет Lambert `albedo / PI`.

Планировщик сначала обновляет изменённые видимые пробы; ограничение
возраста сохраняет очередь справедливой. Версии источника отвергают
устаревшие уже поставленные GPU-задания. Число лучей, шагов DDA, загрузок
и проходов ограничено; статичный кэш не трассирует лучи. Имеются реальные
счётчики и timestamps двух compute-проходов.

| Software Vulkan, 4 теста PASS | Результат |
|---|---|
| H6: 64 пробы, 24 видимых, бюджет 152 луча/tick | Разрушение стены и выключение лампы обновляют ≥90% к tick 6; контроль FIFO к tick 6 — 0% |
| Независимый ray/AABB → SH | Максимальная ошибка 0,00000051; 2034 шага DDA при границе 9728 |
| Lambert в однородной комнате, законный RGB8 HDR | 2048 HDR-пикселей, максимальная ошибка энергии 0,00000954 |
| Неизвестные данные и устаревшее задание | Просачиваний 0, ошибочных публикаций 0 |
| Статичная сцена | 0 лучей, 0 байт загрузки, 0 мерцания |

`recenter` переносит AOI кирпичей и сетку проб тороидально. Перекрывающиеся
128-байтные пробы остаются побитно прежними, входящие пробы получают новое
поколение, входящие кирпичи очищаются в Unknown. Бюджет проверяется до
всех записей. GPU-контроль сдвига сохранил 12 проб, заменил 4 и очистил
одну страницу: 16 992 байта; SH/visibility после обновления побитно совпали
с независимым заново построенным кэшем. Телепорт не оставил старого света.

Четырёхбайтный `GiVoxel` хранит RGB10 в диапазоне 0–32. Это покрывает
законный RGB8 HDR `255 / 15 = 17` и максимальный разрешённый sky ambient 8
без отказа/обрезания. Ошибка упаковки одного канала ≤0,01565; после
декодирования GPU Lambert сохраняет эту энергию до 0,00000954.
Прежняя граница 8 не подходила всем законным данным мира.

`attach_lighting_with_gi` уже включает приёмник в настоящий terrain shader:
3256 тёмных пикселей получили красное отражение, затем синее после замены
источника. Геометрия и конвейеры не обновлялись; scalar block level 15
не создаёт излучение. Клиентский владелец уже передаёт известные источники
в выбранном GI-профиле; подготовленная конфигурация `product()` включает
GI с ограниченной worker-подготовкой. Продуктовый визуальный проход
проверяется отдельно от этих численных контролей.
H9 проверен независимым ограниченным прототипом ниже; рабочий профиль
сохраняет кэш проб.

`EntityGpu` и `BlockModelsGpu` используют те же пробы и Lambert-единицы
через необязательные loading-конструкторы `new_with_lighting`. Отражение
не умножается на sky visibility и не добавляет прямой солнечный свет.
Одна проверка известного source-вокселя отсекает свет из сохранённых проб
в области, снова ставшей Unknown. Прежний `NoGi` сохраняет положительные
и тёмные изображения побитно; всего три storage-буфера на shader stage
укладываются в минимальный WebGPU-предел 8.

| Dawn: те же production WGSL, цветной albedo и block tint | 432 / 576 пикселей; ошибка 0 / 0,000000477; Unknown тёмный, восстановление и `NoGi` побитны |

### H9: сравнение с пространственно-угловыми каскадами

Удалённый после проверки собственный эксперимент использовал тот же настоящий AOI
известных кирпичей, source revision, тороидальный адрес и остановку на
Unknown. Три уровня: 4³×16, 2³×64, 1³×256 лучей; раздельные интервалы
`L/T` 0–4, 4–12, 12–24 блока. Слияние — трилинейное по позиции и
усреднение четырёх дочерних угловых ячеек. Это конкретный 3D-прототип,
а не заявление об оптимальности всех вариантов Radiance Cascades.

Оба метода получили одинаковый предел 152 луча и 9728 шагов DDA за tick,
одинаковую стену, её пролом и выключение отражающего источника. Каждая
фаза длится 16 tick; новая недействительная проба не засчитывается как
обновлённый чёрный результат. Качество проверяет независимый f64-интеграл
по конечной плоской поверхности, без выборки направлений одного метода.

| Software Vulkan, H9 PASS | Пробы | Каскадный прототип |
|---|---:|---:|
| Освещённые приёмники за закрытой стеной, из 64 | 0 | 48 |
| ≥90% видимых изменённых проб после пролома, допуск 10% | tick 6 | не достигнуто за 16 tick |
| ≥90% после выключения источника | tick 6 | tick 12 |
| RMS освещённости после полного обновления против f64 | 0,31140 | 0,56388 |
| Лучи двух фаз | 4864 | 3584 |
| Реальные шаги DDA двух фаз | 57 012 | 17 798 |
| Результаты без общего source/очереди заданий | 8192 байта | 28 672 L/T + 7168 stamps + 8192 SH |

Сумма настоящих GPU query в одном запуске lavapipe: 16,09 / 37,76 мс
за обе фазы; это справочная цена software GPU, не оценка RTX или FPS.
Каскады тратят меньше шагов DDA, но их пространственное смешивание
пропускает свет через стену, угловое слияние дороже и задержка хуже H6.
По измеренным качеству и задержке оставлены пробы. Прототип удалён из production и CI по §11; воспроизводимый исходник,
тест и лог сохранены локально в ignored `.local/artifacts/h9-repro.zip`.
Независимый f64 finite-wall oracle сохранён в рабочем GI regression.

```sh
CARGO_INCREMENTAL=0 VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test gi -- --nocapture
```

## Соединённый HDR-граф

`prepare_scene_sampling` включает чтение MSAA-цвета только выбранного
режима. `encode_scene_with_extra` сохраняет четыре sample и общий resolve
без преждевременной презентации; физическая вода может исключить обычные
водные buckets 2/5. Следующие проходы читают эти вложения и пишут отдельные
цели: обратной связи read/write attachment нет. `hdr_revision` меняется
при новом HDR-кадре, включая движение камеры. Размер цели меняется без
перекомпиляции, потребители заново связывают изменённые view.

GPU-проверка terrain → CloudGpu → PostGpu: 6144 пикселя / 24 576 sample;
при нулевой плотности облаков результат побитно равен прямому HDR → Post,
единственный итоговый transfer. Удаление обычной воды меняет 3124 байта
контрольного изображения; девять scene draw-вызовов сокращаются до семи.
Реальная GPU-длительность post-прохода положительна. Отдельная проверка
подтверждает описанный выше GI-приёмник. Это соединённые GPU-сцены;
профиль подключён к общему `View`. Продуктовые визуальные сценарии
проверяются отдельно от этих численных контролей.

`EnvironmentGpu` уже связывает весь подготовленный граф и имеет общий
предварительный бюджет до записей. Соединённый GPU-тест с настоящим
водным квадом получил 25 проходов и 25 положительных независимых
GPU-длительности. Статика — 0 проходов / 0 байт; resize сохраняет все
конвейеры и водные дескрипторы. Отдельный тест автоэкспозиции продолжает
только exposure + tone: 2 прохода, 0 повторного terrain/LUT/гистограммы,
0 загрузок. Источники таймеров предыдущего terrain-кадра исключаются.
`extra_timing_sources` возвращает фиксированный массив ContactAO/Multiple/Aerial/Water/Cloud/Post/GI/
Atmo; общая длительность — сумма измеренных проходов, не время барьеров.

### Необязательное контактное затенение

`EnvironmentConfig.contact_ao` выбирает при загрузке отдельный signed
ambient MRT и один проход `ContactAoGpu` после полного Terrain/моделей,
перед Water/Aerial/Cloud. `None` и quality0 сохраняют прежние shaders,
targets и layout, без дополнительной памяти. Качества1/2 ограничены
16/32 направлениями и явным `contact_depth_reads` до любых записей.
Общий таймер учитывает этот проход в категории terrain.

MRT хранит удаляемую разность цвета, а не полный HDR: RGB/sky/GI без
прямого солнца и emission. Для `max(light,glow)` учитывается разность
обоих полных выражений, в том числе отрицательная у тёмного port overlay.
Излучающие проводники labPBR сохраняют emission при нулевой diffuse delta.
Все выбранные color pipelines, включая Sky/Celestial/Height/Proxy,
готовят совместимый двухцелевой вариант; новые storage-буферы не нужны.

Software Vulkan подтвердил побитно прежний первый вывод Terrain/PBR
в четырёх режимах: 1543–1567 окрашенных пикселей; conductor emission
не попал в ambient MRT. Native и Dawn также сохранили первый вывод
Entity/BlockModels побитно; в Dawn 432/576 приёмников получили точную
GI delta с ошибкой0. Независимые численные проверки компонента и память
16/72 байта на пиксель при MSAA1/4 описаны в `docs/CONTACT_AO.md`.
Совместный graph с Terrain/PBR/Height/Proxy/Human/Chest/Sky/Celestial
прошёл четыре сочетания MSAA1/4 и AO1/2: 44/53/190/244 контактных
приёмника, прямой floor сохранён на 2571/10310 RGB-отсчётах, sky exact.
Quality0 совпал с `None` побитно, статика дала 0 работы, resize —
0 новых конвейеров. Настоящий `ClientView` с GI и SSAO1 также сохранил
69 GI-пикселей существа и 1000 idle-фаз без аллокаций/работы.
Продуктовое переключение через настройки ещё проверяется отдельно.

Высокие loading-профили учитывают 4K: AO2 допускает 1,3 млрд depth reads
при максимуме 1 227 571 200 для 3840×2160/MSAA4; CloudB — 96 млн density
samples при максимуме 82 944 000. Эти пределы ограничивают логическую
работу и не означают прохождение временного бюджета RTX.

`client::gi_source` связывает известные данные мира с отражёнными
источниками: линейное среднее albedo и отдельная grass tint mask, RGB и
ambient skylight из `World::Page::light`, сертификаты семи входных страниц.
Скалярный игровой block light и прямое излучение emitter исключены.
Простой GPU-контроль: 6 граней, 4102 чтения клеток, 16 480 байт;
красный → синий отражённый свет, статический повтор — 0 чтений / 0 загрузок.
Повторный вход в перераспределённый GPU brick требует настоящего заполнения,
даже когда CPU-сертификат страницы остался в кэше. Прежний компактный
режим хранит изотропное среднее граней и сохраняет результаты H6/H9.
Белая замена физического skylight в клиентском владельце отключена.

### Подготовка источников в workers

Живой `SourceOwner` создаёт полную страницу только через `GiBakeTask`:
семь неизменяемых снимков, точные сертификаты shape/opacity/emission/light,
версия локального albedo и эпоха владельца. Захват native выполняет семь
`Arc`-клонирований без чтения клеток. Основной поток применяет только
подтверждённую дельту не более 64 клеток; отсутствие сертификата направляет
работу в очередь, без скрытого полного прохода.

Ограничения: 2 потока, очередь исполнителя 2, максимум 4 задания с резервом
по 4 МиБ до публикации результата, один слот для правки, срок 40 тиков.
Готовый результат сохраняет резерв и переживает отказ общего бюджета
загрузки. До публикации проверяются все семь входов и локальная эпоха;
Sun/shadow привязываются последним 96-байтным GPU-сертификатом, поэтому
движение солнца не пересобирает CPU-источники. Неизвестные клетки не
генерируются. Отсутствующий biome tint задерживает только окрашиваемый
материал, без белой подмены.

`CGJ1/CGR1` передаёт только уже известные локальные клетки, свет и средние
albedo. Native не сериализует клетки; браузер честно считает до 57 344
foreground-копирований cell/light на семь известных страниц. Полная
классификация и построение 4096 источников выполняются в worker.

| Проверка настоящего владельца и GPU, RGB и directional | Результат |
|---|---|
| Две начальные страницы, native и бинарный транспорт | 8198 worker-чтений, 0 foreground-чтений классификации |
| Публикация при бюджете 0 с последующим повтором | 0 частичных записей; результат сохранён |

Нативный владелец и браузерный pool подключены к `View`. Проверка
`client/tests/view_gi.rs`: настоящие авторитетные RAW/LIGHT, 27 известных
страниц, две страницы в текущем GI-AOI, 9728 worker-чтений, положительный

только публикация и перенос AOI требуют общего бюджета загрузки.
`gi_started` подтверждает хотя бы одну опубликованную известную страницу
и закодированный проход проб этого владельца. Он сохраняется при
обычном обновлении Sun/shadow и очищается при полном переносе в Unknown
или новой сессии/материалах. Настройка режима отделена от свежести:
`source_ready` и `pending_probes` остаются отдельными счётчиками, поэтому
непрерывный ход солнца не выдаётся за неприменённую настройку и не
объявляет все неизвестные пробы готовыми.

Свежий WASM и настоящий Chrome проверили оба транспорта `transfer`/SAB:
37 919 байт запроса → 213 118 байт направленного результата, 4102
worker-чтения, одна непрозрачная клетка, шесть точных граней с красным
RGB. Неверный magic, недостаточный предел результата и отмена SAB
отвергнуты. Команда — `node tools/m10_graphics_smoke.mjs` после
`bash tools/build_web.sh`; проверены также предыдущие GI, Snell MSAA1/4
и водные worker-контроли. Полный продуктовый визуальный проход остаётся
отдельной проверкой.

### Направленный источник GI

Необязательный `prepare_directional_gi` готовится при загрузке. Он добавляет
48 байт на воксель: шесть пар из линейного RGB8 albedo, sky4, признака
открытой грани и полного RGB8 соседнего света. Только при попадании DDA
выбирается настоящая грань; её исходящий Lambert-свет вычисляется по
общему `AtmosphereLighting` и текущим M4 PCF-теням. Учтены sky SH,
`sunE × NdotL × visibility / PI` и видимый RGB block light. Scalar block,
прямое излучение emitter и ушедший в небо луч не добавляют энергию.
Закрытая или Unknown-грань не получает источник.

Солнце и shadow revision инвалидируют ограниченную очередь проб, без
повторного CPU-чтения мира, загрузки страниц и GPU→CPU readback.
96-байтная GPU-версия источника не позволяет ранее закодированному
заданию публиковаться под другим небом/тенями; отказ на 95 байтах
атомарен. Старое SH сохраняется до ограниченного актуального пересчёта.
Клиент сохраняет остаток 152 лучей на весь tick: две партии по 76
исчерпывают его, третье изменение теней переносится на следующий tick.
Ожидание не вызывает лишний terrain/cull или кадр.
Проверка живого владельца охватывает оба режима: 8198 чтений двух страниц,
полный бюджет до публикации, запрет частичного журнала, настоящий синий
GPU SH, статический кэш, перезаполнение Unknown и освобождение cursor.
Изменение одного света требует 13 чтений и 460 байт для семи владельцев
в направленном режиме; прежний режим остаётся 13 чтений / 124 байта.

| Настоящий software Vulkan, независимый f64 finite-floor oracle | Результат |
|---|---|
| Крыша в настоящей M4 depth map | максимальная ошибка SH 0,000000200 |
| Крыша удалена, отражение настоящего солнечного E | ошибка SH 0,000002210, отражение выросло более чем вдвое |
| Нулевая солнечная энергия, RGB-источник 0 | все коэффициенты отражения 0 |
| Смена солнца и shadow revision | CPU-страницы прежние, 96 байт GPU-сертификата; устаревших публикаций 0; статика — 0 проходов |
| Атомарные загрузки | полная страница 213 088 байт, один владелец 148; 147 байт отклонены без изменения версии |

Дополнительная GPU-память равна 196 608 байт на страницу: 9 MiB для
обычного AOI 4×3×4, только при выборе этого режима. Настоящий Chrome/Dawn также завершил GPU-пробу: 14 попаданий,
максимальная ошибка SH 0,000000511, утечек синего 0, ошибок WGSL 0.
RGB8 albedo имеет
абсолютную ошибку упаковки ≤1/510; текстуры усредняются при локальной
загрузке в линейном свете. На пробу добавляется не более восьми PCF
отсчётов на отражающий луч; шесть осевых лучей видимости их не выполняют.
Это первое диффузное отражение, без многократного обмена между
поверхностями и проводниковой BRDF источников. Режимы загрузки
`with_quality(clouds,gi)` используют 0/1/2: GI выключен / 32+6 лучей на
пробу при 152 лучах на tick / 64+6 при 280. Облака — выключены / Layer A
½ разрешения / Volume B ¼ разрешения; для 3440×1440 последний режим
ограничен 49 536 000 отсчётами плотности. Изменение ресурсов применяется
через асинхронную подготовку; сохранённые настройки не подменяются.

## Воздушная перспектива

`AerialGpu` интегрирует RGB T и однократное рассеяние в логарифмических
froxels. Он читает те же оптические параметры и LUT пропускания, что
небо; прежний HDR не тонируется повторно. Композиция отдельно читает
каждый из четырёх исходных depth/color sample; depth=0 остаётся небом,
Unknown не получает вымышленную поверхность. К дымке относятся и LOD,
и существа, уже нарисованные в общем HDR. Порядок графа:
Terrain → Water → Aerial → Cloud → Post; цели чтения/записи различны.

По умолчанию 32×18×32, 24 шага, дальность 16 384 блока: 442 368
ограниченных шагов, 294 912 байт двух объёмов и 40 байт/pixel MSAA+resolve.
Предел целей 512 MiB проверяется до создания/resize; число composition
sample и шагов имеет независимые бюджеты. При изменении только цвета
источника volume сохраняется: 1 composition, 0 шагов, 0 загрузок.
Камера, атмосфера или версия карты тени требуют нового volume/112 байт.

M4 передаёт настоящий comparison atlas. До восьми PCF-отсчётов за шаг
подавляют солнечное рассеяние в доступных каскадах; изменение версии
карты инвалидирует volume. Без M4 выбирается отдельный вариант без
shadow bindings. Обновления мира/солнца должны предшествовать этому проходу.

| Реальный software Vulkan | Результат |
|---|---|
| Независимые f64 Beer + scattering, 512 пикселей | максимальная ошибка HDR 0,00096971 |
| Каждый пиксель: 2 opaque + 2 sky sample | alpha ровно 0,5, исходное небо сохранено |
| Контрольный закрытый shadow atlas | 512 из 512 приёмников подавили солнечную дымку |

отключает её ресурсы. Карты вне M4-каскадов не дают воксельной окклюзии.
Остаются временная реконструкция объёма, отдельная проверка тонких
передних планов при малой сетке и согласование воздушного участка
внутри облака; это не подтверждение всех приближений полной path-traced атмосферы.

## Солнце, луна и звёзды

`CelestialGpu` хранит неизменяемый каталог направлений звёзд; один MSAA4
instanced draw рисует его и два диска в общий HDR только при reverse-Z
`depth == 0`. Alpha не превращает фон в непрозрачную геометрию. Солнце
использует тот же `E_sun / solid_angle`, луна и звёзды — атмосферное T;
пик HDR ограничен 60 000, без переполнения half-float. Луна имеет 8 фаз,
собственные моря/кратеры; вращение и мерцание звёзд не строят CPU-вершины.

Варианты солнца 0/1/2, луны 0/1 и звёзд 0/1/2 взяты из разрешённых
описаний `sky-sun.json` / `sky-moon.json`. Рисунки и формулы собственные;
точное пиксельное совпадение с закрытым рендером донора не заявляется.

`set_celestial_calendar` задаёт фазу и смещение вращения. Подсистема

UI/post-only повтор не перерисовывает HDR. Ресурсы не создаются в
обычном `EnvironmentGpu` без явного подключения. Лунное освещение
поверхностей и визуальное сравнение живого профиля ещё не проверены.

## Облака: независимый физический GPU-проход

`CloudGpu` создаёт конвейеры и цели при загрузке. Layer A интегрирует слой
аналитическим одним отрезком; Volume B выполняет до 96 шагов по лучу и до
8 отсчётов света на шаг. Плотность — собственный непрерывный шум,
переносимый ветром. Рассеяние использует те же transmittance/sky LUT,
Henyey–Greenstein и Beer–Lambert. Имеются предельный бюджет отсчётов,
176-байтные параметры и настоящие GPU-счётчики; конфигурация с возможным
переполнением счётчиков отвергается. Отказ бюджета не кодирует проходы.

Compute хранит полное рассеяние и T, рассеяние до непрозрачного depth и
расстояние для восстановления. Композиция читает **каждый исходный MSAA
sample** цвета/depth и пишет отдельный MSAA4 HDR target с resolve, сохраняя
покрытие переднего плана. Одинаковая поза/время/версия сцены — 0 проходов;
движущийся ветер закономерно требует обновления. Входные attachment должны
иметь TEXTURE_BINDING; читать и писать одну цель одновременно не требуется.

Native `render/tests/clouds.rs`: **2 теста PASS**, all-targets Clippy PASS.
Однородная контрольная среда обоих качеств согласуется с независимым f64
Beer–Lambert: максимальная ошибка HDR 0,0002421 после half-float. Красный
передний план на двух из четырёх sample остаётся ровно 0,5, два sample неба
ослабляются физическим T. Layer A: 1024 шага; B: 32768. Настоящие LUT
атмосферы и процедурный объём: 256 пикселей, 8192 шага обзора, 18596
отсчётов плотности/света при границе 40960. Ветер изменяет HDR, coverage=0
оставляет небо побитно прежним, облака за известной непрозрачной плоскостью
не меняют её цвет.

Настоящий Chrome/Dawn-прогон `tools/cloud_gpu_smoke.mjs` проверил рабочие
шейдеры Layer A/B: по 1024 пикселя, без ошибок шейдеров и валидации.
Максимальная ошибка против независимого f64 Beer — 0,000109205; передние
2 из 4 MSAA-отсчётов сохранены точно, непрозрачная плоскость побитно прежняя.
Однородный слой A/B побитно совпал при 1024 / 32 768 шагах. Отрицательный
контроль с неверным источником неба дал ошибку 0,317749 и не прошёл эталон.
Результат: `.local/cloud-dawn-proof.json`; продуктовая сцена проверяется отдельно.

Живой граф уже располагает облака после воды и перед PostGpu. Остаются
измерения RTX, временное восстановление, проверка краёв на уменьшенном разрешении
в сложной глубине и отражение текущего облачного слоя водой. Объём
низкого разрешения использует ближайшую непрозрачную глубину группы;
произвольные несколько слоёв непрозрачной геометрии внутри облака пока
не имеют отдельной полной интеграции для каждого sample. Это ограничение
качества реконструкции, не повод объявлять весь M10 завершённым.

## Физическая вода и источник настоящих M8-изменений

### Ограниченные отражения без множителя поверхностей

SSR перенесён из фрагментов каждой водной поверхности в один отдельный
полноэкранный проход на sample. Опциональная цель `normal_foam` хранит
окончательную мировую нормаль и пену; исходный HDR и reverse-Z depth
читаются отдельно. При попадании заменяется только прежняя средовая
составляющая с тем же Fresnel, пеной и подводным пропусканием. Промах и
Unknown возвращают исходный sample побитно. Цвет и глубина не читаются
из одновременно записываемой цели.

Верхняя граница — `width × height × samples × steps`, независимо от
квадов и их перекрытия. `with_reflections(0/1/2)` подготавливает выключено /
32 шага до 16 блоков / 64 шага до 32 блоков. Общий бюджет вычисляется
по настоящему размеру и sample count, обновляется при resize. Конвейеры
создаются при загрузке; resize сохраняет их, дескрипторы и содержимое.

| Настоящий Dawn, 32² | Лучи стены по независимому f64 | Шаги / граница |
|---|---|---|
| MSAA1, качество 1 | 84 / 84 | 8556 / 32768 |
| MSAA1, качество 2 | 112 / 112 | 10196 / 65536 |
| MSAA4, качество 1 | 76 / 76 | 33880 / 131072 |
| MSAA4, качество 2 | 104 / 104 | 40691 / 262144 |

Максимальная ошибка HDR Fresnel — 0,0000731. Неверная нормаль проваливает
контроль; Unknown побитно сохраняет фон. При 257 перекрывающихся
поверхностях изображение и фактические GPU-счётчики остаются побитно
прежними. Software Vulkan отдельно проверил настоящий `WaterGpu`:
84/84 и 112/112 лучей, resize побитно точен, 0 повторной компиляции и
загрузки квадов. Четвёртый проход воды входит в общий timestamp capture.

Ресурсы SSR создаются только при включённом режиме: дополнительные
16 байт/пиксель при MSAA1 или 64 при MSAA4. В MSAA4 прежняя неиспользуемая
resolve-цель переиспользуется; при 3440×1440 это 79 257 600 или
317 030 400 байт. Во время подготовки до привязки общей resolve-цели
есть временная дополнительная цель 8 байт/пиксель. При выключенном SSR
сохраняются прежние пять конвейеров и ноль дополнительных целей;
при включённом — шесть конвейеров. Это учтённая цена режима, не
измерение RTX-производительности.

Проверки: `cargo test -p render --test water --test water_reflection`,
`node tools/water_reflection_gpu_smoke.mjs`. Общая продуктовая проверка
настроек выполняется отдельно от этих численных контролей.

`WaterGpu` хранит стабильные 16-байтные квады с четырьмя высотами углов,
потоком, tint и foam. Изменение страницы пишет только её диапазон; общая
геометрия не пересобирается. Отдельные MSAA4 HDR/depth цели сохраняют
исходное покрытие. Opaque snapshot снимается до воды; SSR читает этот
снимок, а не одновременно записываемое вложение. Fresnel, в том числе
порог полного внутреннего отражения, Beer–Lambert, мутность, преломление,
ограниченный SSR, отражение неба, солнечный GGX и M4 shadow выполняются
в линейном HDR. Неизвестное дно не подменяется светлым полом. Под водой
известная непрозрачная сцена ослабляется по настоящей глубине, Unknown
переходит к консервативному рассеянию. Независимый f64 Snell/Fresnel-эталон проверяет сам порог полного
внутреннего отражения: 48,606626°, 543 пропускающих и 481 полностью
отражающий пиксель, выше порога передача строго 0. Максимальная ошибка
четырёх исходных sample — 0,00076246; их расположение измеряется на GPU.
Прежняя интерполированная мировая позиция крупных отсечённых квадов
давала ошибку 0,2637 около порога. Теперь позиция восстанавливается из
настоящих MSAA XY/depth и уже имеющейся обратной камеры; лишний varying
удалён. Контроль с неверной средой не проходит.

Для согласованной смены дальнего покрытия `upload_object_inactive`
подготавливает скрытый объект; изменение его transform и отказ
`upload_page_quads` по Capacity/бюджету сохраняют невидимость.
`enabled_batch_upload_bytes` позволяет сначала проверить суммарный
бюджет воды и height/opaque, затем `set_enabled_batch` меняет только
4-байтные флаги. Все поколения и дубликаты проверяются до первой записи.
Настоящий GPU-тест: отказ при 7 байтах не меняет ни одного пикселя;
8 байт согласованно меняют два объекта без загрузки квадов. Устаревшая
ссылка не скрывает действующее покрытие, переиспользованный slot не
возвращает старые диапазоны. Согласование дальнего cover в клиенте
проверяется его владельцем отдельно от этих GPU-API.

Девять native GPU-тестов `render/tests/water.rs` прошли: независимый
Fresnel/Beer — максимальная ошибка HDR 0,0005403; 112 из 112 независимо
проверенных экранных SSR-свидетелей нашли красную стену (39635 шагов,
граница соблюдена); известная/неизвестная подводная сцена — ошибки
0,0003072 / 0,0000488. Water → Cloud → Post согласуется с независимой
энергией до 0,001101 HDR и одного итогового RGB8-отсчёта. После resize
нет новых конвейеров или водных загрузок. Одно изменение страницы
пишет 16 байт без изменения соседнего диапазона; retire/ABA проверены.
Три настоящих GPU timestamp-прохода: snapshot, cull, copy/surface.

`client::water` захватывает 27 неизменяемых ссылок и сертификаты точного
одноклеточного ореола. Worker классифицирует 18³ отсчётов и строит
поверхности из настоящих fluid levels. Общие углы соседних страниц
совпадают; Unknown удерживает зависимую поверхность, без генерации.
`WaterSource` читает ограниченный журнал, отбирает страницы по готовой
fluid mask, объединяет грязные задания и хранит ограниченные running /
ready очереди. Старый результат не публикуется, даже если его пакет
переписали новым сертификатом. Native задания несут Arc-снимки;
CWJ1 браузера — 7104 байта классифицированных публичных данных и tint,
без raw BlockId или seed. Упаковка браузерного задания требует 5832
ограниченных чтений/классификаций на отправляемое задание; этот расход
должен учитываться интегратором, он не является нулевой работой кадра.

Четыре pure mesh-теста и шесть owner/transport-тестов прошли. Настоящие
два `M8::fluid::plan_tick` сделали 10 и 11 чтений, изменили колонку с 6 до
14 GPU-квадов. Устаревшее задание отклонено; публикация одной страницы —
232 байта. Сто неподвижных циклов owner: 0 чтений клеток, загрузок и
аллокаций. Перенос начала координат требует только 80 байт матрицы,
при недостаточном бюджете вся старая группа матриц остаётся прежней.
Смена tint с прежними значениями не загружает квады. Полный teardown
сначала проверяет бюджет и удаляет диапазоны/handles; повторные удаления
страниц со старым worker-результатом не оставляют метаданных.

Живые View/worker hooks подключены в native и браузере. До полного начального
покрытия EnvironmentGpu сохраняет обычные водные buckets. Это ещё не
проверка минимальной задержки жидких правок H1: соседние worker-страницы
могут завершаться в разных кадрах, немедленная owner-patch вода и
атомарная публикация общих углов требуют отдельного испытания. Также
остаются waterlogged-формы, нормаль уклона четырёх углов, волновая модель
в локальной гравитации движущегося пространства и отражение облаков.


`view::water::ViewWater` соединяет источник с ограниченным Scheduler и
двумя native работниками. Для браузера имеются CWJ1/CWR1 и отдельная
DOM-free worker-точка; её 7104-байтная посылка классифицирует 5832
foreground-отсчёта, native-путь делает это в worker. Транспортный ID
содержит эпоху владельца и остаётся точным JS integer; старый результат
другой сессии не потребляет текущее задание. Tint берётся только из
существующего кэша Scene, без генерации и белой подстановки.

Два теста владельца проверили native-публикацию шести квадов,
устаревшие входы, повтор очереди, ABA сессий, бюджет 0, атомарное
освобождение и 1000 статичных проходов с нулевой работой источника.
Флаг полного актуального покрытия переключает обычную и физическую
воду перед кадром. Неполная физическая арена не рисует поверхность;
GPU-эталон сохранил фон MSAA побитно и не получил двойную воду.
Отдельный настоящий Chrome Worker-прогон подтвердил transfer и SAB:
7104 → 393 байта, 4096 worker-клеток, шесть квадов, 0 frame vertices;
предел ответа отвергнут, предстоящая SAB-работа отменена.
Два настоящих GPU-теста общего `View` подтвердили замену обычной воды
физической, 0 квадов halo и старого положения, перенос 160 → 6 квадов,
а также 1000 статичных циклов без работы и аллокаций. Численная проверка
владельца не заменяет продуктовый сценарий жидкой правки H1.

## Масштаб сцены 85–100%

Общий ClientView теперь применяет выбранный процент к HDR/depth/SSAO/water/cloud
буферам при resize/асинхронной подготовке; размер поверхности и UI остаётся
физическим. Оси округляются вверх, чтобы фактический масштаб не был ниже85%.
Последний существующий Post-проход расширяет линейный HDR билинейно до поверхности,
без добавочных текстур, sampler-ов и конвейеров. При100% остаётся прежнее чтение
текселя; MSAA и разрешение теней этот параметр не меняет. Proxy DDA получает
настоящий внутренний viewport, а SSE-планирование сохраняет физические пиксели.
Квитанция Scale выдаётся после применения размера, AllowResolution управляет только
правом автоматического контроллера менять процент.

Проверены пять native Post GPU-тестов, включая независимое f64-расширение55×38→64×44
с ошибкой не более одного8-bit значения. Лимит на2816 конечных пикселей проверен
отдельно от размера входа; отказ бюджета не изменяет состояние. Общий View прошёл
100→85→100: при85% HDR55², поверхность64², MSAA4 сохранён; четыре cached-показа
побитно стабильны и учитывают4096 конечных пикселей без terrain/uploads. Возврат к100%
побитно равен исходному кадру. Post resize не создаёт конвейеров; render/all-targets
Clippy прошёл. Логи: `.local/artifacts/render-scale-post-gpu.log`,
`render-scale-view-gpu.log`, `render-scale-render-clippy.log`. Оконный и браузерный
контроль нового процента выполняются отдельно; аппаратная экономия не заявляется.

Во время незавершённой атомарной смены near/far-покрытия `encode_cached_present`
может показать последний законченный HDR на новой поверхности одним Post-проходом.
Он сохраняет histogram, bloom, экспозицию, историю адаптации и сертификат исходного
кадра; Scene, атмосфера, GI и вода не пересчитываются. Без готового HDR владелец
возвращает `None`, чтобы runtime сохранил экран загрузки. Настоящий GPU-тест:
20 повторных показов побитно одинаковы, 1 проход, 0 histogram/bloom и 0 загрузок;
отказ пиксельного бюджета атомарен, обычное обновление затем продолжает адаптацию.
