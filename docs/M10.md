# M10: графические подсистемы в разработке

`render::atmosphere` вычисляет LUT пропускания и sky-view из Rayleigh, Mie и озонового поглощения вокруг сферической планеты. Это собственные Rust/WGSL; код рендера и шейдеры донора не использованы. Расстояния — километры, высоты экспоненциальных профилей — 8 и 1,2 км.

По умолчанию пропускание имеет размер 256×64 и 64 шага интегрирования; sky-view — 192×108 и 48 шагов. Формат — `RGBA16Float`, два compute-конвейера готовятся при загрузке. Изменение солнца/высоты пересчитывает только sky-view, статичный кадр — ничего. Записи параметров и шаги интегрирования имеют явные бюджеты; отказ сохраняет ожидающую работу. После отмены уже закодированного, но не отправленного обновления владелец вызывает `invalidate`.

`TerrainGpu::attach_atmosphere` подключает LUT при загрузке к общему MSAA 4× / HDR / final transfer. Направление берётся из обратной матрицы камеры; её изменение добавляет 64 байта загрузки. Изменение только LUT не загружает камеру или геометрию. Владелец выполняет `encode_update` до terrain и инвалидирует сохранённый план кадра при изменении сияния. Эталон M2 сохраняет исходный режим неба.

Тот же расчёт пишет 80-байтный `AtmosphereLighting`: RGB SH L1
`E_sky / PI` и прямую солнечную освещённость `20 × T_sun` в согласованных
относительных единицах HDR. SH строится 16 ограниченными направлениями
верхней полусферы; солнечное пропускание интегрируется на настоящей
высоте наблюдателя, без грубой интерполяции первого texel LUT.
Lambert-приёмники используют `albedo × E / PI`; labPBR — `BRDF × E`.
Локальный RGB block light добавляется один раз, scalar block light не
создаёт энергию. Ночная сцена больше не получает постоянный белый ambient.
Облака и вода получают ту же солнечную шкалу. Старый режим без атмосферы
сохраняет пиксели эталона M2.

| Настоящий software Vulkan | Результат |
|---|---|
| Пропускание против независимого f64 / 4096 шагов | 242 RGB-отсчёта, максимальная абсолютная ошибка 0,00058784 |
| Уменьшенная тестовая конфигурация | 205 632 шага при старте; 74 560 при смене солнца; 0 в статике |
| Солнце за планетой | Просочившегося прямого рассеянного света 0 |
| Общий terrain HDR, 12 513 пикселей | Яркость при взгляде вверх 5 059 696, вниз 285 218 |
| Изменение только LUT | 0 байт камеры и геометрии; ночное изображение без солнечного света |
| Общая энергия Terrain + labPBR, 1148 приёмников | Ошибка солнечной освещённости против f64 ≤0,011374 при шкале 20; ночных утечек 0; прежний белый ambient ошибочно освещает 1148 пикселей |
| Необязательные loading-конструкторы Entity / BlockModels / Height | Настоящие ночные и дневные изображения, 0 компиляций при смене солнца |

```sh
source tools/env.sh
VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test atmosphere -- --nocapture
VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test terrain_gpu -- --nocapture
```

Это ограниченное однократное рассеяние, а не завершённая модель Hillaire или весь M10. Остаются многократное рассеяние и соединение всех выбранных проходов с живым клиентом. Физическая вода, облака, светила, PostGpu и GI описаны ниже; локальный labPBR — в `docs/M10-materials.md`. Прохождение отдельных тестов не завершает M10. Alpha sky-view хранит диагностическое среднее пропускание и не заменяет RGB-пропускание при композиции поверхностей.

## Экспозиция и bloom

`PostGpu` читает линейный HDR после композиции сцены. Автоэкспозиция строит
256-корзинную гистограмму логарифма яркости, затем плавно меняет выдержку;
ручной режим не создаёт гистограмму. Bloom включает отдельную пирамиду
`RGBA16Float` только при выбранном режиме. Изменение размера сохраняет
конвейеры. Финальный проход применяет ACES fitted и единственный выходной
sRGB transfer. Размытия движения, зерна и DOF нет.

Измерение яркости и bloom сохранённой сцены повторно не вычисляются;
адаптация экспозиции может продолжаться отдельно. Версия источника,
бюджет обработанных пикселей, загрузка параметров и GPU timestamps
передаются явно. Отказ бюджета оставляет работу ожидающей.
`request_present` выводит сохранённый HDR в новый surface после изменения
интерфейса: один tone-проход, 0 загрузок, без повторных histogram/bloom;
вывод побитно совпал с прежним. Без явного запроса неподвижный граф
по-прежнему не требует кадра.

| Software Vulkan, 3 теста PASS | Результат |
|---|---|
| Ручная экспозиция, независимый f64 | 3072 пикселя, максимальная RGB8-ошибка 0 |
| Изменение размера | 0 новых компиляций конвейеров |
| Автоэкспозиция | 768 отсчётов; 41 кадр без повторного измерения; цель 0,1829481, итог 0,18294816 |
| Bloom | 1001 пиксель ореола, 1020 texel пирамиды; в статике 0 пересчитанных texel и побитно одинаковый вывод |

## Кэш проб GI и H6

`GiGpu` трассирует ограниченные DDA-лучи по известным GPU-кирпичам 16³.
Неизвестный воксель останавливает луч без света. Вход хранит только уже
отражённую радиансность поверхности: отдельный прямой свет и ушедшее в
небо излучение не прибавляются второй раз. RGB SH L1 и шесть осевых
границ видимости занимают 128 байт на пробу. Трилинейный приёмник
отсекает пробу за стеной и применяет Lambert `albedo / PI`.

Планировщик сначала обновляет изменённые видимые пробы; ограничение
возраста сохраняет очередь справедливой. Версии источника отвергают
устаревшие уже поставленные GPU-задания. Число лучей, шагов DDA, загрузок
и проходов ограничено; статичный кэш не трассирует лучи. Имеются реальные
счётчики и timestamps двух compute-проходов.

| Software Vulkan, 4 теста PASS | Результат |
|---|---|
| H6: 64 пробы, 24 видимых, бюджет 152 луча/tick | Разрушение стены и выключение лампы обновляют ≥90% к tick 6; контроль FIFO к tick 6 — 0% |
| Независимый ray/AABB → SH | Максимальная ошибка 0,00000051; 2034 шага DDA при границе 9728 |
| Lambert в однородной комнате, законный RGB8 HDR | 2048 HDR-пикселей, максимальная ошибка энергии 0,00000954 |
| Неизвестные данные и устаревшее задание | Просачиваний 0, ошибочных публикаций 0 |
| Статичная сцена | 0 лучей, 0 байт загрузки, 0 мерцания |

`recenter` переносит AOI кирпичей и сетку проб тороидально. Перекрывающиеся
128-байтные пробы остаются побитно прежними, входящие пробы получают новое
поколение, входящие кирпичи очищаются в Unknown. Бюджет проверяется до
всех записей. GPU-контроль сдвига сохранил 12 проб, заменил 4 и очистил
одну страницу: 16 992 байта; SH/visibility после обновления побитно совпали
с независимым заново построенным кэшем. Телепорт не оставил старого света.

Четырёхбайтный `GiVoxel` хранит RGB10 в диапазоне 0–32. Это покрывает
законный RGB8 HDR `255 / 15 = 17` и максимальный разрешённый sky ambient 8
без отказа/обрезания. Ошибка упаковки одного канала ≤0,01565; после
декодирования GPU Lambert сохраняет эту энергию до 0,00000954.
Прежняя граница 8 не подходила всем законным данным мира.

`attach_lighting_with_gi` уже включает приёмник в настоящий terrain shader:
3256 тёмных пикселей получили красное отражение, затем синее после замены
источника. Геометрия и конвейеры не обновлялись; scalar block level 15
не создаёт излучение. Живой клиент пока не передаёт отражённые источники.
H9 проверен независимым ограниченным прототипом ниже; рабочий профиль
сохраняет кэш проб.

```sh
source tools/env.sh
VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test post --test gi -- --nocapture
```

### H9: сравнение с пространственно-угловыми каскадами

Удалённый после проверки собственный эксперимент использовал тот же настоящий AOI
известных кирпичей, source revision, тороидальный адрес и остановку на
Unknown. Три уровня: 4³×16, 2³×64, 1³×256 лучей; раздельные интервалы
`L/T` 0–4, 4–12, 12–24 блока. Слияние — трилинейное по позиции и
усреднение четырёх дочерних угловых ячеек. Это конкретный 3D-прототип,
а не заявление об оптимальности всех вариантов Radiance Cascades.

Оба метода получили одинаковый предел 152 луча и 9728 шагов DDA за tick,
одинаковую стену, её пролом и выключение отражающего источника. Каждая
фаза длится 16 tick; новая недействительная проба не засчитывается как
обновлённый чёрный результат. Качество проверяет независимый f64-интеграл
по конечной плоской поверхности, без выборки направлений одного метода.

| Software Vulkan, H9 PASS | Пробы | Каскадный прототип |
|---|---:|---:|
| Освещённые приёмники за закрытой стеной, из 64 | 0 | 48 |
| ≥90% видимых изменённых проб после пролома, допуск 10% | tick 6 | не достигнуто за 16 tick |
| ≥90% после выключения источника | tick 6 | tick 12 |
| RMS освещённости после полного обновления против f64 | 0,31140 | 0,56388 |
| Лучи двух фаз | 4864 | 3584 |
| Реальные шаги DDA двух фаз | 57 012 | 17 798 |
| Результаты без общего source/очереди заданий | 8192 байта | 28 672 L/T + 7168 stamps + 8192 SH |

Сумма настоящих GPU query в одном запуске lavapipe: 16,09 / 37,76 мс
за обе фазы; это справочная цена software GPU, не оценка RTX или FPS.
Каскады тратят меньше шагов DDA, но их пространственное смешивание
пропускает свет через стену, угловое слияние дороже и задержка хуже H6.
По измеренным качеству и задержке оставлены пробы. Прототип удалён из production и CI по §11; воспроизводимый исходник,
тест и лог сохранены локально в ignored `.local/artifacts/h9-repro.zip`.
Независимый f64 finite-wall oracle сохранён в рабочем GI regression.

```sh
CARGO_INCREMENTAL=0 VK_ICD_FILENAMES="$PWD/.local/mesa/lvp-local.json" cargo test --locked -p render --test gi -- --nocapture
```

## Соединённый HDR-граф

`prepare_scene_sampling` включает чтение MSAA-цвета только выбранного
режима. `encode_scene_with_extra` сохраняет четыре sample и общий resolve
без преждевременной презентации; физическая вода может исключить обычные
водные buckets 2/5. Следующие проходы читают эти вложения и пишут отдельные
цели: обратной связи read/write attachment нет. `hdr_revision` меняется
при новом HDR-кадре, включая движение камеры. Размер цели меняется без
перекомпиляции, потребители заново связывают изменённые view.

GPU-проверка terrain → CloudGpu → PostGpu: 6144 пикселя / 24 576 sample;
при нулевой плотности облаков результат побитно равен прямому HDR → Post,
единственный итоговый transfer. Удаление обычной воды меняет 3124 байта
контрольного изображения; девять scene draw-вызовов сокращаются до семи.
Реальная GPU-длительность post-прохода положительна. Отдельная проверка
подтверждает описанный выше GI-приёмник. Это соединённые GPU-сцены;
профиль живого клиента ещё подключается.

`EnvironmentGpu` уже связывает весь подготовленный граф и имеет общий
предварительный бюджет до записей. Соединённый GPU-тест с настоящим
водным квадом получил 24 прохода и 24 положительные независимые
GPU-длительности. Статика — 0 проходов / 0 байт; resize сохраняет все
конвейеры и водные дескрипторы. Отдельный тест автоэкспозиции продолжает
только exposure + tone: 2 прохода, 0 повторного terrain/LUT/гистограммы,
0 загрузок. Источники таймеров предыдущего terrain-кадра исключаются.
`extra_timing_sources` возвращает фиксированный массив Aerial/Water/Cloud/Post/GI/
Atmo; общая длительность — сумма измеренных проходов, не время барьеров.

`client::gi_source` связывает известные данные мира с отражёнными
источниками: линейное среднее albedo и отдельная grass tint mask, RGB и
ambient skylight из `World::Page::light`, сертификаты семи входных страниц.
Скалярный игровой block light и прямое излучение emitter исключены.
Простой GPU-контроль: 6 граней, 4102 чтения клеток, 16 480 байт;
красный → синий отражённый свет, статический повтор — 0 чтений / 0 загрузок.
Повторный вход в перераспределённый GPU brick требует настоящего заполнения,
даже когда CPU-сертификат страницы остался в кэше. Это компактное
изотропное среднее граней; направленное отражение солнца и per-face BRDF
этим мостом пока не моделируются.
Живой владелец пока использует для этого среднего только видимый RGB
block light: белая замена физического skylight отключена, чтобы не
появлялось искусственного ночного GI. Полное направленное отражение
обновлённой атмосферы остаётся отдельной работой.

## Воздушная перспектива

`AerialGpu` интегрирует RGB T и однократное рассеяние в логарифмических
froxels. Он читает те же оптические параметры и LUT пропускания, что
небо; прежний HDR не тонируется повторно. Композиция отдельно читает
каждый из четырёх исходных depth/color sample; depth=0 остаётся небом,
Unknown не получает вымышленную поверхность. К дымке относятся и LOD,
и существа, уже нарисованные в общем HDR. Порядок графа:
Terrain → Water → Aerial → Cloud → Post; цели чтения/записи различны.

По умолчанию 32×18×32, 24 шага, дальность 16 384 блока: 442 368
ограниченных шагов, 294 912 байт двух объёмов и 40 байт/pixel MSAA+resolve.
Предел целей 512 MiB проверяется до создания/resize; число composition
sample и шагов имеет независимые бюджеты. При изменении только цвета
источника volume сохраняется: 1 composition, 0 шагов, 0 загрузок.
Камера, атмосфера или версия карты тени требуют нового volume/112 байт.

M4 передаёт настоящий comparison atlas. До четырёх PCF-отсчётов за шаг
подавляют солнечное рассеяние в доступных каскадах; изменение версии
карты инвалидирует volume. Без M4 выбирается отдельный вариант без
shadow bindings. Обновления мира/солнца должны предшествовать этому проходу.

| Реальный software Vulkan | Результат |
|---|---|
| Независимые f64 Beer + scattering, 512 пикселей | максимальная ошибка HDR 0,00096971 |
| Каждый пиксель: 2 opaque + 2 sky sample | alpha ровно 0,5, исходное небо сохранено |
| Контрольный закрытый shadow atlas | 512 из 512 приёмников подавили солнечную дымку |
| Открытый atlas после смены версии | результат точно совпал с вариантом без тени |
| Статика / source-only / resize | 0 работы / 1 composition без volume / 0 компиляций |
| Соединённый граф | 24 реальных прохода, 24 положительных GPU query |

`ViewEnvironment` включает подсистему при loading, `aerial: None`
отключает её ресурсы. Карты вне M4-каскадов не дают воксельной окклюзии.
Остаются временная реконструкция объёма, отдельная проверка тонких
передних планов при малой сетке и согласование воздушного участка
внутри облака; это не полная многократная модель Hillaire.

## Солнце, луна и звёзды

`CelestialGpu` хранит неизменяемый каталог направлений звёзд; один MSAA4
instanced draw рисует его и два диска в общий HDR только при reverse-Z
`depth == 0`. Alpha не превращает фон в непрозрачную геометрию. Солнце
использует тот же `E_sun / solid_angle`, луна и звёзды — атмосферное T;
пик HDR ограничен 60 000, без переполнения half-float. Луна имеет 8 фаз,
собственные моря/кратеры; вращение и мерцание звёзд не строят CPU-вершины.

Варианты солнца 0/1/2, луны 0/1 и звёзд 0/1/2 взяты из разрешённых
описаний `sky-sun.json` / `sky-moon.json`. Рисунки и формулы собственные;
точное пиксельное совпадение с закрытым рендером донора не заявляется.

| Реальный Vulkan, 2 теста + соединённый граф PASS | Результат |
|---|---|
| Полная / четверть / новая луна, сумма RGB8 | 117 782 / 50 444 / 4791 |
| Солнечный цвет трёх вариантов против f64 T | ошибка ≤3 RGB8 |
| 4096 звёзд | 131 072 байта каталога при загрузке; 16 392 GPU-вершины, один draw; 144 байта изменённых параметров |
| Мерцание трёх вариантов, 0,4 с | изменение общей яркости ≤0,194%; неподвижный повтор побитно одинаков |
| Вращение на 0,3 рад | 191–433 изменённых пикселя |
| Известная непрозрачная геометрия перед луной | 0 изменённых пикселей |

`EnvironmentGpu::prepare_celestials` разрешён только до первого кадра;
`set_celestial_calendar` задаёт фазу и смещение вращения. Подсистема
включена в loading-профиль `ViewEnvironment`, отключается через
`celestials: None`. Днём неиспользуемое время звёзд канонизируется:
UI/post-only повтор не перерисовывает HDR. Ресурсы не создаются в
обычном `EnvironmentGpu` без явного подключения. Лунное освещение
поверхностей и визуальное сравнение живого профиля ещё не проверены.

## Облака: независимый физический GPU-проход

`CloudGpu` создаёт конвейеры и цели при загрузке. Layer A интегрирует слой
аналитическим одним отрезком; Volume B выполняет до 96 шагов по лучу и до
8 отсчётов света на шаг. Плотность — собственный непрерывный шум,
переносимый ветром. Рассеяние использует те же transmittance/sky LUT,
Henyey–Greenstein и Beer–Lambert. Имеются предельный бюджет отсчётов,
176-байтные параметры и настоящие GPU-счётчики; конфигурация с возможным
переполнением счётчиков отвергается. Отказ бюджета не кодирует проходы.

Compute хранит полное рассеяние и T, рассеяние до непрозрачного depth и
расстояние для восстановления. Композиция читает **каждый исходный MSAA
sample** цвета/depth и пишет отдельный MSAA4 HDR target с resolve, сохраняя
покрытие переднего плана. Одинаковая поза/время/версия сцены — 0 проходов;
движущийся ветер закономерно требует обновления. Входные attachment должны
иметь TEXTURE_BINDING; читать и писать одну цель одновременно не требуется.

Native `render/tests/clouds.rs`: **2 теста PASS**, all-targets Clippy PASS.
Однородная контрольная среда обоих качеств согласуется с независимым f64
Beer–Lambert: максимальная ошибка HDR 0,0002421 после half-float. Красный
передний план на двух из четырёх sample остаётся ровно 0,5, два sample неба
ослабляются физическим T. Layer A: 1024 шага; B: 32768. Настоящие LUT
атмосферы и процедурный объём: 256 пикселей, 8192 шага обзора, 18596
отсчётов плотности/света при границе 40960. Ветер изменяет HDR, coverage=0
оставляет небо побитно прежним, облака за известной непрозрачной плоскостью
не меняют её цвет.

Остаются подключение в живой граф после воды и перед PostGpu, измерения
RTX, временное восстановление, проверка краёв на уменьшенном разрешении
в сложной глубине и отражение текущего облачного слоя водой. Объём
низкого разрешения использует ближайшую непрозрачную глубину группы;
произвольные несколько слоёв непрозрачной геометрии внутри облака пока
не имеют отдельной полной интеграции для каждого sample. Это ограничение
качества реконструкции, не повод объявлять весь M10 завершённым.

## Физическая вода и источник настоящих M8-изменений

`WaterGpu` хранит стабильные 16-байтные квады с четырьмя высотами углов,
потоком, tint и foam. Изменение страницы пишет только её диапазон; общая
геометрия не пересобирается. Отдельные MSAA4 HDR/depth цели сохраняют
исходное покрытие. Opaque snapshot снимается до воды; SSR читает этот
снимок, а не одновременно записываемое вложение. Fresnel, в том числе
порог полного внутреннего отражения, Beer–Lambert, мутность, преломление,
ограниченный SSR, отражение неба, солнечный GGX и M4 shadow выполняются
в линейном HDR. Неизвестное дно не подменяется светлым полом. Под водой
известная непрозрачная сцена ослабляется по настоящей глубине, Unknown
переходит к консервативному рассеянию. Отдельный GPU-эталон самого порога
полного внутреннего отражения пока отсутствует.

Шесть native GPU-тестов `render/tests/water.rs` прошли: независимый
Fresnel/Beer — максимальная ошибка HDR 0,0007322; 112 из 112 независимо
проверенных экранных SSR-свидетелей нашли красную стену (40350 шагов,
граница соблюдена); известная/неизвестная подводная сцена — ошибки
0,0003072 / 0,0000488. Water → Cloud → Post согласуется с независимой
энергией до 0,001276 HDR и одного итогового RGB8-отсчёта. После resize
нет новых конвейеров или водных загрузок. Одно изменение страницы
пишет 16 байт без изменения соседнего диапазона; retire/ABA проверены.
Три настоящих GPU timestamp-прохода: snapshot, cull, copy/surface.

`client::water` захватывает 27 неизменяемых ссылок и сертификаты точного
одноклеточного ореола. Worker классифицирует 18³ отсчётов и строит
поверхности из настоящих fluid levels. Общие углы соседних страниц
совпадают; Unknown удерживает зависимую поверхность, без генерации.
`WaterSource` читает ограниченный журнал, отбирает страницы по готовой
fluid mask, объединяет грязные задания и хранит ограниченные running /
ready очереди. Старый результат не публикуется, даже если его пакет
переписали новым сертификатом. Native задания несут Arc-снимки;
CWJ1 браузера — 7104 байта классифицированных публичных данных и tint,
без raw BlockId или seed. Упаковка браузерного задания требует 5832
ограниченных чтений/классификаций на отправляемое задание; этот расход
должен учитываться интегратором, он не является нулевой работой кадра.

Четыре pure mesh-теста и шесть owner/transport-тестов прошли. Настоящие
два `M8::fluid::plan_tick` сделали 10 и 11 чтений, изменили колонку с 6 до
14 GPU-квадов. Устаревшее задание отклонено; публикация одной страницы —
232 байта. Сто неподвижных циклов owner: 0 чтений клеток, загрузок и
аллокаций. Перенос начала координат требует только 80 байт матрицы,
при недостаточном бюджете вся старая группа матриц остаётся прежней.
Смена tint с прежними значениями не загружает квады. Полный teardown
сначала проверяет бюджет и удаляет диапазоны/handles; повторные удаления
страниц со старым worker-результатом не оставляют метаданных.

Живые View/worker hooks подключает владелец runtime. До полного начального
покрытия EnvironmentGpu сохраняет обычные водные buckets. Это ещё не
проверка минимальной задержки жидких правок H1: соседние worker-страницы
могут завершаться в разных кадрах, немедленная owner-patch вода и
атомарная публикация общих углов требуют отдельного испытания. Также
остаются waterlogged-формы, нормаль уклона четырёх углов, волновая модель
в локальной гравитации движущегося пространства и отражение облаков.
