# M8: серверные действия еды и ведра

Реальный сервер и общий ввод native/Web теперь вызывают проверенные правила M8.
Опциональный TAA в этот срез не входит. Полный UI-прогон еды/ведра остаётся отдельной проверкой.

| Контракт | Реализация |
|---|---|
| Сеть | Внутренние теги Action22 `UseFood(held, InventoryGuard)` и23 `UseBucket(Space/cell, expected, InventoryGuard)`; прежний envelope и пределы очередей |
| Владение | Точная ревизия, выбранный слот, предмет, количество, износ и payload; клиент не задаёт лечение или готовый результат |
| Еда |32 серверных тика удержания, результат на N+31; полный HP запрещает начало; отпускание, смена слота/предмета и смерть отменяют |
| Прерывания | Урон и регенерация не отменяют начатый приём пищи; движение ×0.2; атака и правки не обходят активное употребление |
| Очередь действий | Допущенное новое отпускание сразу останавливает еду, даже если подтверждение ждёт за другими действиями; старый Stop не отменяет новый Start |
| Пустое ведро | Только источник; луч пропускает течение; высота источника8/9, либо1 при той же жидкости сверху |
| Полное ведро | Обычный луч по блокам, цель строго «попадание + грань»; Unknown закрыт, чтение не генерирует страницы |
| Серверная проверка | Space, дальность и видимость проверяются до сравнения с приватной клеткой; защита спавна и4 тика cooldown сохраняются |
| Атомарность | Клетка, немедленное затвердевание лавы, обмен инвентаря, дроп растения и явный spill в одном WAL batch; квота предметов проверяется до World.commit |
| Полный инвентарь | Одно наполненное ведро выпадает, вместо потери или удвоения; Creative сохраняет оба вида ведра |
| Жидкость | Прежняя очередь после изменения: вода5, лава30 тиков |
| Звук | Еда на N+8,+12,+16,+20,+24,+28; финальная еда/отрыжка на N+31; ведро — по фактическому переходу после fsync |
| Клиент | Короткий клик ведром сохраняет исходный guard при полной очереди256 и keyup; отпускание еды повторяется под давлением; здоровье, инвентарь и жидкость ждут авторитета |
| Отказ еды | Отказ текущего Start снимает локальное замедление; удержание не повторяет запрос до отпускания. Поздний отказ старого Start или Stop не отменяет более новый Start |
| Переподключение | Незавершённый ввод отменяется; подтверждённые здоровье, инвентарь, клетки, выпавшие предметы и dedup восстанавливаются |

Источники поведения: SPEC§1.3/§2, разрешённые `game/bucket.rs`,
`game/server/survival.rs`, аспекты ASP12/15 и существующие M8 golden-тесты.
Новые действия требуют согласованной сборки клиента и сервера.
