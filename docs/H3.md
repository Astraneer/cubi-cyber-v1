# H3 — измеренное сравнение страниц 8³, 16³ и 32³

Безусловное превосходство 16³ **не подтверждено**. 8³ дешевле на одиночных правках; 16³ уменьшает число страниц и лучше группирует большой взрыв; 32³ резко увеличивает работу мелких изменений. Производственный PAGE16, World, Save и протокол оставлены по SPEC. Выбор полного продукта ещё требует аппаратного маршрута и стоимости всех владельцев страниц, а не только мешера.

В игнорируемом прототипе параметризована фактическая реализация `terrain_mesh`: сохранены классификация, бинарная видимость, greedy, прозрачные группы и AO. Меняются размер, битовые строки и упаковка геометрии. Для 8/16/32 геометрия занимает 21/26/31 бит, квад во всех случаях **16 байт**; для 32 нужны 64-битные occupancy и 32-битные строки видимости. Отдельного альтернативного производственного мешера нет.

Общий вход: настоящий лес генератора v4, seed 1337, куб 64³ от `[-192,34,-512]`, 3093 клетки листвы, одинаковая известная внешняя рамка. Далее идут 128 последовательных одиночных правок, 128 правок на общей границе 31/32 и одна транзакция с удалением ровно 10 000 непустых клеток. У взрыва есть один заранее снятый устаревший job: он реально вычисляется, отвергается по версии и не загружается. Очередь объединяет повторы по странице; работа исполняется в одном канале с повторно используемым scratch.

Три запуска меняют порядок размеров: 8/16/32, 16/32/8, 32/8/16. Счётчики, клетки и хеши детерминированы. Каждая из 64 начальных страниц варианта 16 дополнительно совпадает слово в слово с настоящим производственным мешером. Каждый дескриптор проходит roundtrip; после всех четырёх этапов совпадают нормализованные единичные грани, материал, tint и четыре значения AO всех размеров. Измеренные три запуска завершили **2322 настоящих GPU-кадра**.

GPU-проба: llvmpipe LLVM 19.1.7, 128², MSAA1, reverse-Z, vertex pulling, заранее созданный шейдер, один bounded arena, объекты по 128 Б, indirect-команды по 16 Б и настоящий native multi-draw. Загружаются только изменённые диапазоны. Используется механизм закрытия T-junction основного terrain-шейдера. Силуэты совпадают без дыр; 8/16 дают побитно одинаковый цвет. У 32 меняются максимум два из 16 384 затенённых пикселей на ≤3/255 из-за консервативного расширения края; это не объявляется побитным совпадением.

В таблице — счётчики одного запуска и медиана трёх значений времени. Для одиночных/граничных правок время — медиана трёх **p99 по 128 операциям**, не объединённый p99. Начальная загрузка и взрыв имеют по одной операции на запуск: для них это длительность, не статистически подтверждённый p99. `CPU` включает правку, очередь, мешинг и постановку загрузок; `GPU завершено` дополнительно включает submit и `device.poll(Wait)`. Генерация, подготовка pipeline, независимая проверка и readback пикселей вынесены за таймер.

Чтения включают halo и отвергнутый job взрыва. Начальная рамка прочитана 249 856 / 111 104 / 52 288 раз соответственно; это реальные дополнительные классификации. Начальные квадов 11 320 / 11 059 / 10 935: уменьшение числа страниц не устраняет стоимость полной пересборки большой страницы. У взрыва 108/25/8 публикаций вместо повторов по каждому изменению; один старый результат в каждом варианте не публикуется.

Учтённая CPU-память — конкретные собственные клетки/tint, ёмкости векторов квадов, заголовки page-mesh, очередь/версии/индекс и один полный worker scratch+halo. Это **не RSS**, не peak и не память всего приложения: временные списки правок/независимой проверки, внутренности драйвера и владельцы World/Save/AOI не включены. Общий консервативный GPU-arena резервирует одинаковые 25 165 824 Б дескрипторов; объекты, команды, framebuffer/readback и uniform учтены отдельно в логах. Фактические записанные байты равны байтам дескрипторов плюс 16 Б на опубликованный job.

Изолированный шейдер плоского материала не заменяет полный MSAA4/свет/тени/Hi-Z/LOD. Источник клеток общий; форматы World/Save/AOI для 8/32 и параллельные владельцы не переписаны. Время общего CPU/программного GPU заметно зависит от нагрузки машины. Для принятия H3 нужны тот же маршрут на RTX 3050, полный кадр и память владельцев, p99 по достаточно длинной серии, включая очередь и отмену workers. Эти данные не дают основания объявить 16 оптимальным или без измерения менять формат мира на 8.

Воспроизведение: `.local/artifacts/h3-pages-prototype.zip`, намеренно вне Git. Архив содержит самостоятельный снимок исходников, pinned Cargo.lock, три сырых лога, счётчики/диапазоны времени, пиксели, исходный SHA мешера и SHA256 файлов. Команда из распакованного корня после настройки Rust/cache и software Vulkan:

```sh
cargo run --locked --offline --manifest-path .local/experiments/h3-pages/Cargo.toml > .local/artifacts/reproduced.jsonl
python3 .local/experiments/h3-pages/verify.py .local/artifacts/reproduced.jsonl
```

Архив: **903 303 байт, 252 файлов**. SHA256: `ca08d0f44d634268aeff6c7c20a1158ee7f062e85943896592d1657991b660b4`. CRC и SHA256 каждого файла проверены. Отдельный `--locked --offline` запуск именно замороженного снимка завершил ещё 774 GPU-кадра и воспроизвёл все 12 строк счётчиков/хешей; `verify.py` прошёл. Все три варианта остаются только внутри игнорируемого эксперимента; в production не добавлялись экспорт, параллельное ядро или тестовый обход.
