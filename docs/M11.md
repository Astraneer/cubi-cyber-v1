# M11: общий Rust UI

`ui::layer::UiLayer` использует одинаковые экранные состояния, обработку ввода и wgpu
рисование в native и WASM. Проверены экраны приветствия, паузы, настроек, HUD, инвентаря,
верстака, сундука, печи, машины, NEI/рецептов, локальных ресурсов, Перекрёстка, чата и Tab.
Стиль — «Тёмный камень». Шрифт VoxelPixel из белого списка: WOFF1 распаковывается в
ограниченный SFNT, glyph atlas строится заранее; встроенное уведомление CC0 сохранено.
Текстуры блоков взяты из разрешённого атласа, символы предметов — новый код проекта.

Одна UI pipeline создаётся при подготовке; статическая геометрия и атлас сохраняются.
10 000 неизменившихся кадров не выделяют память, не строят вершины и не загружают GPU
данные. Настоящий программный Vulkan отрисовал меню с 3044 проверенными светлыми пикселями
текста. Изображение: `.local/artifacts/m11-ui-menu.png`.

Бот-сценарии проверяют переходы меню, независимость пресетов от звуковых настроек,
Unicode-поиск NEI, рецепты/применения, чат и Tab, конфликты физических клавиш, UI scale и
соответствие hit-test масштабу, атомарное чтение сохранённых предпочтений, отсутствие
выдачи творческих предметов обычному игроку. Каталог команд берётся из `net::command_catalog`,
а окончательные права проверяет сервер. Схема настроек и AutoQuality — единая ранее
подготовленная `ui::settings`; MSAA/тени не меняются автоматикой.

UI хранит копию авторитетных 41 слота, курсора, 9 клеток крафта и не более 54 слотов окна.
Нажатия создают типизированные intents с ID окна, версией окна и версией инвентаря;
реальные вещи в UI не изменяются. `server::ui::WindowState` подготавливает detached планы
переноса/половины стопки/быстрого переноса, NEI «+», единичного/массового крафта и закрытия.
Курсор, craft и контейнер имеют строгую WND1 основу 407 Б и sparse XREF для
предметов с сохранённым состоянием; legacy без ссылок сохраняет прежние байты. Планы проверяют все входы перед
атомарным apply; overflow при закрытии возвращается явными drops для той же durable
транзакции. Новое открытие получает новый server epoch, включая обычный инвентарь.

Семь тестов владельца проверяют сохранение вещей, stale/ABA, броню, запрещённую вставку в
выход печи, извлечение половины выхода, отсутствие придуманных ингредиентов, точный craft
и codec continuation/повреждения. Они дополняют 16 проверок UI (4 settings + 1 font + 9
интеграционных, включая реальный GPU, + 2 profiler). Native Clippy и WASM compilation проходят.

Отдельный браузерный бот проверил настоящее WebGPU-изображение и ввод мышью/Unicode:
3044 светлых пикселя в приветствии, 6560 в настройках, 2147 в инвентаре, 6808 в F3;
поиск уменьшил 180 предметов до 19. Артефакты: `.local/artifacts/m11-web-*.png` и
`m11-ui-browser-smoke.json`. Это отдельный проверочный shell, не основной игровой вход.

Общий F3 читает `telemetry::flight::FlightRecorder`: 8 стадий CPU, 16 GPU-проходов,
очереди/возраст заданий, память и работу. Неизмеренные значения остаются «не измерено».
График хранит максимумы 120 временных корзин за 10 секунд; краткие скачки не усредняются.
Совпавшие наблюдения помечены без утверждения причины. Два теста проверяют неизвестные
GPU-времена, сохранение скачка и отсутствие аллокаций/перестроения в 10 000 одинаковых
кадрах. `client::ui_bridge` связывает физические клавиши, захват меню/чата, чувствительность
и инверсию, категории звука и подтверждённый инвентарь; доступность протокольного маршрута
остаётся явной. Полоса еды появляется только при наличии авторитетного значения.

Основной WASM-вход теперь открывает общий Rust Welcome; явный `?scene=forest`
сохраняет диагностический H1-профиль. Игровой вход подключает настоящий WebSocket и
`RemoteSession`, получает авторитетный seed и страницы, а при переподключении заменяет
Scene/View и worker pool. ID и credential назначает сервер; локально сохраняется только
их привязка к этому адресу. Loading рисуется до готовности мира; статическое меню не
отправляет бесконечные GPU-кадры.

`tools/product_ui_smoke.mjs` прошёл на настоящих WebGPU и сервере: меню 3044 светлых
пикселя, E открывает подтверждённое окно с ненулевым ID, close подтверждается сервером,
Unicode-чат приходит только после серверного события, Tab показывает roster и измеренный
сервером ping. Бот проверил F3, настоящий F8 download (42 записанных кадра) и восстановление
личности после disconnect/reconnect. Артефакты: `.local/artifacts/product-ui-smoke.json`,
`product-{welcome,inventory,roster,profiler}.png`, `product-flight-recorder.json`.
F8 честно содержит `replayAvailable:false`: полный replay рендера/UI ещё не записан.
Отдельный `movementReplay` содержит настоящие публичные movement ticks и внешние
checkpoints. Браузерный F8 (488 шагов, 55 checkpoints) независимо воспроизведён native
утилитой до hash `55dc45bedc0357b9`; у этой записи `completeWindow:false` и видимые
capacity losses, поэтому полный 10-секундный охват не заявляется.

Настройки чувствительности, инверсии, категорий звука, FOV и Bob применяются к игре.
Сохранённые графические параметры без подготовленного backend помечены звёздочкой и
не выдаются за действующие. Реальный UI вызывает локальные file/directory picker.
Во время 422 активных WebSocket-кадров импорт canary zip и `.minecraft` не породил HTTP
запросов и не передал импортированные/учётные байты в WebSocket.

Публичный payload предмета переносится из XRF1 в курсор/craft без потери ссылки.
Дополнительный IAT1 передаёт только факты собственного слота: режим конфигуратора,
заряд планшета в Дж и тип сохранённой машины. Mapper требует точного совпадения
revision/slot/item/payload; старые данные очищаются. HUD выбранного предмета и tooltip
показывают проверенные «Режим: газ» и «Заряд: 180000 / 1000000 Дж». Два теста проводят
строгий codec→Connection→UI, stale ref/revision и 10 000 форматирований без аллокаций.
Shift+N использует физический Shift независимо от переназначения Sneak; чат захватывает N.
Без подтверждённого IAT1 подсказка показывает «Сохранённый заряд»/«Сохранённое состояние», без приватного
содержимого и выдуманной величины заряда. Тест проверяет codec→UI→carry, видимую метку и
атомарное отклонение count=2 у stateful предмета.

Основной native-вход также открывает Welcome; явные `--scene forest/sky` и `--benchmark`
сохраняют диагностический профиль. UiLayer и звуковой банк готовятся на отдельном worker;
при Connect создаются свежие View/Scene и worker pool. Реальные X11/XTest нажатия и пиксели
подтвердили настройки, авторитетные E/close, чат, Tab/ping, F3, F8, disconnect/reconnect и Quit.
Повтор всего сценария с настоящим ограничением main stack 1024 КиБ прошёл. Native F8:
158 шагов, независимый offline replay до `0814d92dfca9d4c5`,
`completeWindow:true`. Артефакты: `.local/artifacts/native-product-ui-smoke.json`,
`native-product-*.png`, `native-product-movement-replay.txt`.
Проверки NativeState/App сохраняют границы 16 КиБ / 1 КиБ за счёт Box владельцев.

Native сохраняет настройки локально, вызывает Windows picker на import worker,
применяет готовые audio/material банки и оставляет недоступный endpoint явным.
WASM Clippy, native all-target Clippy и MSVC cross-check прошли.

Настоящий Owner-сценарий уже подтвердил цепочку log → craft grid → 4 planks → cursor →
инвентарь и видимую цифру количества в результате. Разрешённый сервером сундук размещён
из собственного слота; открытие и перенос четырёх досок в его контейнер подтверждены.
Полный сценарий повторного открытия/изъятия пока не принят. Переключение capture после
чата исправлено по реальному XTest вводу; новая Scene начинает отдельную эпоху input
recorder, сохраняя строгий порядок тиков внутри неё.

Указанные законченные product smoke выполнены до подключения общего Atmo/Post/Horizon.
Новый обычный профиль загружает авторитетный Light с тенями 2048, Environment, Entities,
Props и Horizon в этом порядке; диагностический forest сохранён. Для него требуется отдельная
повторная приёмка. Перед первым кадром подготовлены все pipeline; web Horizon имеет свой
worker и независимый ограниченный transport (1 worker, 8 jobs, 16 МиБ), native — внутренний
пул общего View. Одна квота загрузки мира/эффектов равна 2 МиБ, включая uniform reserve.
Props имеет отдельный ограниченный browser worker (1 worker, 2 contexts, 4 МиБ);
его public ACTIVE hints управляют циклическим звуком машин. Vulkan-тест общего View
подтвердил model-only HDR+dynamic shadows и 1000 пустых фаз без аллокаций/загрузок.

M11 ещё требует завершённого серверного сценария craft/chest, подготовленных графических
вариантов и полного F8 replay рендера/UI. UI не выдаёт неподдерживаемые
операции и ответы сервера за успешные. Зелёный CI требуется отдельно по SPEC.

Общая схема теперь содержит 30 полей: личное время добавлено в конец, legacy 29 читаются
без сдвига индексов. Только старый Default с shadow4096 мигрирует в измеренный startup2048;
Custom/Heavy сохраняют явный выбор. Три теста проверяют миграцию и round-trip,
включая измеренный default LOD32 без изменения явного Heavy/Custom LOD4.
Кнопки «День»/«Ночь»/«Время мира» сохраняют личную настройку без изменения серверного
инвентаря или часов. Confirmed public tick сохраняет целочисленный modulo24000 и
передаёт одно направление Солнца теням, моделям, дальнему миру и Environment.

`SettingsApplication` показывает подтверждение действующего backend, pending и необходимость
перезагрузки отдельно. Экспозиция использует готовый Post pipeline и одну запись64Б из общей
квоты; 63Б/недопустимое значение отклоняются до мутации. Три GPU-теста подтвердили физические
пиксели относительно независимого расчёта, сохранение истории адаптации и tone-only обновление
без нового histogram/bloom/pipeline. MSAA1/4 и качество Cloud/GI выбираются в loading worker.
Смена такого профиля запрашивает повторную подготовку за Loading и восстановление той же
серверной личности; до активного нового View значение не объявляется применённым.
Окончательная проверка этих управляющих элементов в обычной игре пока продолжается.
TAA и прочие неподключённые параметры сохраняют pending. SSAO0/1/2 теперь выбирает
подготовленный ambient MRT backend при асинхронной загрузке, receipt читает настоящий
config владельца. Отдельные whole-View и полный граф AA1/4×AO1/2 подтвердили сохранение
direct light/sky, AO0 bitwise и1000 пустых фаз без аллокаций/работы. Product-кнопки SSAO
проверяются отдельно. Reflections0/1/2
выбирает подготовленный deferred SSR с0/32/64 шагами; отражения получают отдельный
receipt по действующему Water backend, а готовность покрытия мира проверяется отдельно.

Экран смерти посылает typed Respawn и остаётся на нём до подтверждённого живого Snapshot.
UI-тест не изменяет здоровье/вещи при нажатии; UiBridge-тест проверяет настоящий сетевой
Action::Respawn. Interface12 (включая реальный Vulkan), миграция3, quality HUD2
и UiBridge5 проходят.

Продолжение обычного профиля на программном Dawn подтвердило Game с125 raw/LIGHT
страницами,27 resident pages и пустыми near-очередями после отделения CPU/network/worker
фаз от завершения GPU. Нажатия личного дня/ночи дали138 822 изменённых пикселя выбранной
области (среднее180,14→20,56), сохранив public tick. Полный сценарий затем остановился
из-за закрытия серверного WebSocket; экспозиция дошла до подготовленного gain1,20,
но снимок после неё/MSAA/оставшиеся UI действия в этом прогоне не засчитаны.
`product-graphics-partial.json` прямо содержит `fullProfileAccepted:false`.

Контроллер качества теперь получает только фактически представленные кадры и завершённый
полный GPU-интервал с тем же ID. CPU-продолжения сохраняются в следующем настоящем кадре,
не создавая ложных60 FPS. Начальное пустое дальнее покрытие исключено; существующий
подтверждённый front остаётся пригодным во время подготовки следующего. Saved UI-настройки
отделены от временного target; загрузка
использует target, а принятие изменения ждёт реального backend receipt. F3 показывает
подтверждённые изменения качества, p95 кадра/GPU и измеренную экономию; до измерения
экономия остаётся неизвестной. Два UI-теста проверяют эти состояния и10 000 одинаковых
обновлений без аллокаций/перестроения. Реальный автоматический переход и его измеренная
экономия ещё требуют законченного живого прогона.

У обоих product smoke есть явный режим `CUBI_UI_COMPONENT_ONLY=1` вместе с
`CUBI_UI_LOW_EFFECTS=1`: бот настоящими кнопками Welcome Settings выбирает Horizon16
и SSAO/Cloud/GI/SSR0.
В артефакт попадают сохранённые значения и receipt действующего backend. Такой запуск
помечается `fullProfileAccepted:false` и служит отдельной проверкой UI/инвентаря; обычный
сценарий сохраняет исходный профиль и обязательное непустое дальнее покрытие.

Временное заполнение outbox не теряет UI-действие: общий sender удерживает одну
неотправленную операцию, не расходует ActionId и повторяет допуск после освобождения
места. Локальные меню, снятие capture и disconnect проходят независимо от неё; новая
сессия очищает старое ожидание. Тест заполняет256 мест, проводит10 000 повторов без
аллокаций и затем проверяет одну отправку исходной команды с прежним первым ActionId.
Реальная native-диагностика отдельно подтвердила enqueue открывания/закрывания окна и
чата; окончательная доставка под большой нагрузкой дальнего потока ещё проверяется.

Сырая browser-очередь64 кадров заменена приёмом каждого ограниченного сообщения в
общие Rust-кэши с объединением обновлений по странице. Scene/GPU по-прежнему меняются
в отдельной ограниченной фазе. Реальный прогон принял56 550 сообщений без отклонений,
сохранил соединение и подтвердил inventory/chat/Tab/F3; импорт/F8 в этом прогоне ещё
не завершены (`product-ui-direct-admission-partial.json`).

Pause/Settings/Resources/Crossroads используют последний готовый HDR и новый Tone/UI,
продолжая CPU/network/jobs. Непоказанные изменения камеры/мира/правок не подтверждаются.
Такой же hold защищает незавершённое атомарное соединение near/far; без прежнего HDR
показывается настоящий Loading clear с ready=false. GPU-тест64² проверил20 побитно
одинаковых изображений, сохранение старых presentation stamps,1tone/0hist+bloom/uploads,
возобновление нового изображения, отрицательный контроль, resize и отсутствие бесконечного
post-only redraw. Старые Shadow/Terrain timestamp не приписываются этим кадрам.

Завершённый browser component-прогон `product-ui-components.json` подтвердил ручной
Horizon16/SSAO0/Cloud0/GI0/SSR0,125 авторитетных LIGHT страниц, inventory/chat/Tab/F3,
локальные ZIP и `.minecraft` picker, disconnect/reconnect той же личности. Импортированный
материал дал29 777 настоящих magenta-пикселей; при наблюдении417 WebSocket сообщений
не было HTTP-запросов или утечек canary. F8 содержит13 кадров с полным завершённым
GPU-интервалом, completeWindow=true и223 шага движения, успешно повторённых offline.
Replay рендера/UI остаётся unavailable. Снимок source/WASM/server сохранён отдельно;
это WebSocket component-проверка с `fullProfileAccepted:false`, старым серверным
far-privacy профилем и без приёмки UDP/M5/M6 либо аппаратных60 FPS.

Native теперь делит один `RemoteSession` между GUI и WebSocket worker через короткий
Mutex. Worker принимает сообщения прямо в существующие bounded typed-кэши и отправляет
до64 исходящих перед чтением до32 входящих, независимо от медленного GPU-кадра.
GUI отпускает guard до acquire/encode/submit; дополнительной Replica нет. Непринятое
сообщение WriteBufferFull сохраняется ровно одно, без увеличения лимитов. Старый адаптер
с очередью32 оставлен только для сравнительного теста. All-target Clippy и тест настоящего
закрытия loopback peer проходят. Настоящий серверный comparative-тест подтвердил причину:
legacy GUI с паузой4с за20с видит только Accepted1 при уже принятых сервером2/3;
ускоренное опустошение старой очереди восстанавливает оба ответа. Shared owner при паузе4с
получает1/2/3 за два GUI-прохода без увеличения лимитов; случаи8/250/1000мс также проходят.
Живой native Owner на стеке1МиБ подтвердил все36 действий: ровно4 доски из бревна,
80мс RMB placement/audio сундука, deposit/reopen/withdraw с сохранением количества,
творческую выдачу64 stone и пять режимов конфигуратора с обратным Shift+N. Личные
день/ночь изменили215 410 пикселей. Экспозиция/MSAA/F8 нового полного сценария остаются
отдельной незавершённой проверкой; component-результат сохраняет fullProfileAccepted=false.

Scale85–100 теперь использует настоящий уменьшенный HDR/depth и bilinear Tone в
полноразмерный surface; UI остаётся в native-разрешении. Frontend повторно готовит View
через существующий Loading, diagnostics показывают effective scale/extent, receipt берётся
из активного renderer. Контроллер качества допускает Scale только с Environment,
Horizon/LOD только с committed front, стоимость теней только с Lighting; Near ждёт
отдельной проверки поддерживаемого радиуса. Автоматический MSAA и выключение теней
по-прежнему исключены. Реальный автоматический переход ещё не засчитан. Параметр
Hints теперь выключает item/state tooltip; Animations остаётся не подключённым.

Первый Loading теперь ждёт отдельно CPU-derived near inputs и successful same-budget
uploads перед дорогим HDR. Shadow/content readiness в этот предварительный gate не
входит: их подтверждает следующий настоящий scene encode. Пока inputs не готовы,
обе платформы отправляют только реальный clear и UI; CPU/network/jobs продолжаются,
