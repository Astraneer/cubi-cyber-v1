# Физические доски рецептов

Девять панелей привязаны к `net::spawn::Landmark`, опубликованному сервером после Welcome. Его центр — блок пола `SpawnSite.y0`, а не положение ног игрока. Клиент не ищет площадку по seed и не генерирует клетки. Общая таблица `rules::crossroads::PAVILIONS` задаёт три павильона; `boards()` содержит шесть двусторонних стеновых панелей 5×3, две кнопки .875×.875 и табличку 3×1. Положение и тексты взяты только из разрешённых чистых данных donor `gen/spawn.rs`.

`recipe_board_images` при загрузке составляет непрозрачные изображения из того же UiAtlas и фактической `RecipeBook`, что используются интерфейсом. Двенадцать изображённых рецептов проверяются настоящим matcher. Фиксированные иконки соответствуют текущему UiAtlas: импорт albedo блоков этот атлас интерфейса не изменяет. Новая версия интерфейсного атласа требует повторной загрузки владельца, а не покадрового обновления изображений.

`RecipeBoardGpu` хранит один массив RGBA8 sRGB 256×192×9: 1 769 472 байта. Девять записей по 64 байта и uniform 80 байт дают всего **1 770 128 байт GPU-памяти**, при локальном лимите 4 MiB. Подготовка создаёт один pipeline; во время кадров компиляций нет. Один instanced draw (до 54 вершин) добавлен в существующий непрозрачный HDR pass, использует его depth и 1/4 MSAA, совместим со вторым ambient MRT. Новый timestamp source, отдельный проход и карты теней не добавляются. Draw входит в возвращаемый счётчик extra draws Terrain; память и фактические uploads доступны в `ClientView::recipe_board_stats()`.

Каждая панель скрыта, пока все её опорные клетки не являются подтверждённой непрозрачной стеной в видимой Near-области и текущем GPU mesh. Проверка ограничена 15 клетками на большую панель, всего 95 клетками для полного плана. Halo, старый mesh и Unknown не считаются стеной. LIGHT читается из клетки перед гранью и должен быть связан с текущим публичным Raw view. Новый Raw view без нового LIGHT, потеря опорной страницы, уход из Near и отзыв landmark скрывают панель. Все GPU записи обновляются атомарно после полной проверки upload budget.

Панели получают фактические RGB, SKY visibility, атмосферную энергию, тени и необязательное GI. У них нет белого emissive фона. Собственную тень не добавляют: их опора — уже существующая непрозрачная стена. Путь TAA пока получает invalid/current-only motion для панелей; режим 2 остаётся скрытым до отдельного доказательства статической поверхности namespace 19.

Физические кнопки используют существующий луч взаимодействия игрока. Кроме попадания в опорный блок проверяются лицевая плоскость и границы .875×.875. Нажатие меняет только PersonalTime Day/Night, синхронизирует настройку ViewTime через общий UI/persistence route и подавляет server Place до отпускания кнопки. Unknown, более близкая стена и попадание в обрамление не переключают время.

Проверки компонента: 3 CPU теста общего плана/настоящих рецептов; 3 CPU теста публичной опоры и общего луча; Naga принимает 12 комбинаций Shadow/Atmosphere/GI/MRT. Native и Dawn проверили 1/4 MSAA × MRT 0/1: точные HDR цвета, перекрытие ближней панелью независимо от порядка draw, неизменность статичного изображения. Native также проверил атомарный отказ upload/memory budget, скрытые записи и 1000 статичных обновлений с нулём allocations/uploads. Dawn использует точные production sources из `recipe_board_shaders`, без собственной версии shader.

Полный Native View тест также прошёл: без landmark панелей нет, после публикации настоящей опоры появляются три панели с изменением изображения; Raw-only смена view отзывает LIGHT и скрывает панели, новый LIGHT восстанавливает их. Реальный общий input переключает день/ночь один раз, удержание не отправляет server Place. Отзыв landmark снова скрывает панели. Приёмка настоящего серверного павильона и namespace 19 motion остаются отдельными этапами; компонентные проверки не заменяют их.
