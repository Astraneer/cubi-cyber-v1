# M9 — машины и событийное ядро

Срез пока не принят: библиотека правил работает и проверена, но авторитетный сервер, окна машин, трубы фактического мира и их сетевое представление ещё подключаются. Полный игровой прогон «сундук руды → линия ×2 → сундук слитков» пока не выполнялся.

`rules::machines` содержит независимую от мира и графики реализацию поведения по разрешённым MEK-01…14 и эталонам закреплённого донора. Машины: тепловой генератор, инфузор, куб энергии, обогатитель, плавильня, ветряк, дробилка, очиститель, сепаратор и насос. Таблицы рецептов общие с NEI, без второй копии.

Проверены точные моменты завершения операций, пауза при недостатке энергии/кислорода/места, сброс при смене входа, расход кислорода с целочисленным распределением остатка, установка улучшений на 21-м тике, выключение вида с задержкой, выталкивание через 11 тиков, порядок отдачи энергии и зарядки. Тепловой генератор воспроизводит числовые последовательности из донора; ветряк проверяет небо через 20 тиков. Насос берёт бесконечную воду и убираемую лаву через интерфейс владельца мира, без синхронной генерации.

Планшет хранит заряд отдельным типизированным полем слота, кратным 20 Дж, до 1 000 000 Дж. Поле износа `ItemStack` не используется как скрытое хранилище энергии. `Machine::encode` возвращает длину используемого префикса компонента `MEK1`: 139 байт для обычной машины, плюс 12 байт за фактический узел поиска насоса, максимум 3211 байт. Передавать нужно только этот префикс. Восстанавливаются прогресс, тепло, кислород, режимы сторон, задержки и ограниченный фронт поиска. Повтор после загрузки сравнивается по каждому тику.

H2: отдельное аналитическое ядро пропускает внутренние тики стабильных рецептов и просыпается на зависимости. Два типа машин (дробилка и плавильня), заторы, разрывы питания и передачи между буферами сравниваются с подробным тикером на **120 000 границах**, побитно по полному состоянию машин. Результат: **4 559 946 подробных тиков / 259 024 событийных перехода = 17,604×** по числу операций; 20 085 завершённых рецептов, расхождений нет. Это проверка ядра, ещё не доказательство того же выигрыша для полной сети с графом труб и сервером. Времена CPU не выдаются за измерения целевого железа.

Дополнительно 2048 копий цепочки под общими отключениями и заторами: 4 096 000 подробных тиков / 81 920 событийных переходов = 50×, полные состояния совпадают. Это измерение количества выполненной работы, а не миллисекунд CPU.

`WakeQueue` — заранее выделенная индексируемая куча; нет обхода всех машин при пустом тике, повторные пробуждения объединяются. Куча сравнена с независимым BTreeMap на 50 000 событиях, 4096 спящих записей не аллоцируют память при 10 000 пустых опросах. `logistics::fair_share` воспроизводит таблицу равного деления энергии без float/аллокаций. Ограниченный транспорт предметов движется ровно на 5/100 клетки один раз за глобальный тик и удаляет груз только после подтверждённой владельцем вставки; переполнение и устаревший маршрут оставляют предметы у владельца.

`grid::Grid` инкрементально объединяет/разрезает сети кабелей, труб и трубок с двусторонними связями, стабильными поколениями дескрипторов и запретом смешивания непустых веществ. Ёмкость узла: 8000 Дж / 2000 мБ жидкости / 4000 мБ газа, PULL: 250 / 750 мБ за тик. Разрез 40 000 Дж на части из 4 и 5 кабелей воспроизводит 17 777 / 22 223 Дж; номер остаётся у большей части. Удаление проверено в окружении 100 независимых сетей: посещены только 8 узлов затронутой сети. Кэш приёмников объединяет разные грани одного владельца, фаза раздачи/свечения не аллоцирует; для 1000 передач по 100 Дж два приёмника получили по 50 000 Дж. Владелец мира должен обновлять кэш приёмников и пробуждать затронутую сеть по изменённым зависимостям. Это библиотека графа, её привязка к фактическим страницам мира ещё необходима.

Ограничения: аналитическое ядро сейчас поддерживает стабильные рецептурные машины без внешних слотов топлива/установки улучшений и без периодического выталкивателя. Неподдерживаемый режим явно возвращает `Unsupported`, вызывается подробный тикер. Поиск насоса ограничен 256 узлами и 64 удаляемыми узлами за операцию; при исчерпании бюджета он приостанавливается, содержимое не исчезает. Текущая транспортная библиотека требует уже построенный маршрут; поиск цели с прогнозом вставки, PULL-повторы предметов, динамическая перетрассировка и отображение грузов клиентом ещё необходимы. Хранилище резервуаров сетей должно сохраняться отдельными компонентами владельца мира, граф восстанавливается по передатчикам страниц.

Интеграция: владелец сервера клонирует компонент и планирует `Machine::tick(position, facing, MachineWorld)`. Обратные вызовы `push_*` и `drain_lava` должны записывать отложенные изменения в общий план. Компонент машины, списание/вставка в инвентари, изменения блоков и сетевые ACK публикуются вместе после WAL/fsync. Чтение Unknown возвращает отсутствие доступного источника, а не воздух или сгенерированную страницу.

Проверка: `source tools/env.sh && cargo test --locked -p rules --test machines_contract -- --nocapture`. На текущем срезе 24 теста; 10 000 повторных машинных/событийных фаз не аллоцируют память, считающий аллокатор проверен положительным контролем. Clippy всех targets и сборка WASM библиотеки правил проходят.
