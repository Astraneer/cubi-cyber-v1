# Полный серверный прогон §8.6

Тяжёлая проверка запускается явно из корневого графа зависимостей:

```sh
source tools/env.sh
CARGO_INCREMENTAL=0 cargo test --release --locked --offline -p server --test spec86_owner -- --ignored --nocapture
```

Обычный `cargo test` её пропускает. Это проверка настоящего `Runtime` и сохранения,
не вызов отдельного вычислительного ядра. 32 клиента используют настоящие UDP
сокеты и штатный аутентифицированный Channel. Клиенты работают в отдельном потоке;
профиль в каждом направлении — 75±20 мс, 2% потерь с переупорядочением. Лимиты
буферов и повторов не увеличиваются. Перед нагрузкой клиенты действительно входят,
получают серверную телепортацию и обмениваются ping; все 32 запроса публичных страниц
должны завершиться к концу нагрузки.

В исходном сохранении находятся 5000 настоящих Pig, 10000 Smelter-компонентов с
энергией и входными предметами и 100000 известных клеток WATER. События воды имеют
общий ближайший срок, затем должны фактически обработаться все; будущая холодная
очередь не считается выполненной работой. Снимок и подготовка отделены от замера.
В замер входят полные `Runtime::poll`, захват владельцем, кодирование, копии передачи
писателю и применение подтверждённых данных. Ручные checkpoint захватываются
отдельно тем же счётчиком аллокаций. JSONL содержит логические тики, работу, байты,
возраст исходной просрочки, фактический WAL и численные показатели каждого клиента.
Время записывается справочно, аппаратного порога миллисекунд в проверке нет.

Подтверждённые исправления:

| Проверка | До | После |
| --- | --- | --- |
| Временное состояние 2048 активных машин | 181425936 выделенных байт | 22171600 байт; те же результаты |
| 128 неподвижных известных источников WATER при бюджете 16384 чтений | 8 событий из-за невозвращённого резерва | 128 событий; следующий шаг всё ещё резервируется целиком |
| WAL активной группы | отказ при 536327750 байтах до планового checkpoint | checkpoint по долговечным 256 MiB, жёсткий предел 512 MiB сохранён |
| 16 потерянных ненадёжных UDP-снимков | надёжное сообщение получает Capacity до истечения сборок | вытесняется незавершённый ненадёжный снимок; надёжные сборки сохраняются |

В полном прогоне до обнаруженной ошибки планировщика выполнены 100000 событий
воды, 1090000 чтений воды без её изменения, 4220000 шагов существ и 1728512 шагов
машин. 13 checkpoint удержали WAL не выше 270018389 байт. 32 соединения оставались
живыми. Счётчик владельца при этом показал 90679627247 суммарно выделенных байт и
3006262296 байт передачи систем писателю; эти расходы не скрываются за чистыми
счётчиками алгоритмов. Это накопленный трафик выделений, не одновременно занятая
память.

Полная приёмка пока не пройдена: часть машин не выполнила ни одного шага за
843 тика просрочки. Ограниченная выборка событий и последующая сортировка по
порядку создания позволяют новым пробуждениям ранних машин вытеснять старые
события поздних. Простое повторение фазы на том же тике небезопасно: Resource
не имеет отдельного долговечного маркера однократного выполнения, а Transit
сейчас запускается после каждой порции. Нужна явная граница фаз с восстановлением.

Проверка сохраняет строгий oracle: выборка машин сравнивается с медленным
`rules::Machine.tick`, выполненным один раз на каждый прошедший логический тик;
все 10000 машин обязаны выполнить работу, вода сохраняется точно, изменения
существ и предметов проверяются на сохранение количества. Затем предусмотрены
32 холодных тика с сохранёнными 5000 существами и 10000 машинами без сериализации
их runtime и повторное открытие настоящего сохранения. Эти последние части
не объявляются пройденными до исправления планировщика. Переполнение публичного
AOI плотной группы также учитывается явно; пропавший кадр не считается доставкой.
